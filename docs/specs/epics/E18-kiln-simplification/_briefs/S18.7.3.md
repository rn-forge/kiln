# S18.7.3 — Shared parsing has one implementation

Brief for
[S18.7.3](../F18.7-one-owner-per-concept.md#s1873-shared-parsing-has-one-implementation),
at `e389e86`. The feature page's line numbers are stale; use the ones here.
Paths are under `src/rn_forge/kiln/`.

## Goal

Each parsing or subprocess job that kiln does in two or more places is done by
one function, and every copy calls it. Every caller keeps its current answer,
finding code and message. No rendered file changes.

## Settled

**The merge rule** (lead's ruling, 2026-11-17). A shared helper holds only the
part the copies have in common. A caller keeps whatever differs (an extra
filter, a prefix, a path conversion) at the call site. If a copy cannot use the
helper without changing an answer, leave that copy as it is and record it in
`## Result`. Never change a finding code, a message or an order to make copies
fit.

**1. Run-step scanner** — new `modules/core/steps.py`:
`step_commands(lines: list[str], keys: tuple[str, ...]) -> list[tuple[int, str]]`
returns every `<key>:` step's command as (1-indexed line, text), with block
scalars yielded line by line. That is today's `_run_values`
(`modules/tasks/checks/layout.py:369-388`, regexes `:47-48`) generalised over
the step keys. `layout.py` calls it with `("run",)`;
`modules/cicd/checks/entrypoint.py` `_check_file` (`:67-96`, regexes `:30-33`)
calls it with `STEP_KEYS` and runs `_check_command_line` on each result. The
duplicated regexes are deleted.

**2. Taskfile readers** — `task_specs` (`layout.py:51`), `task_refs` (`:102`)
and `include_map` (`:112`) move verbatim to a new `modules/tasks/taskfile.py`.
`layout.py` and `modules/tasks/surface.py:13` import them from there.

**3. Docs helpers.**

- New `modules/docs/findings.py`:
  `error(code: str, path: Path | str, message: str) -> Finding`, building
  `Finding(f"docs.{code}", Severity.ERROR, message, path=str(path))`. It
  replaces `_error` in `packages.py:112`, `structure.py:35` and `site.py:23`.
  `generate.py:41` `_error(code, message, path)` adds no prefix: its callers
  move onto `error` passing their code without its `docs.` prefix, so the
  emitted code is unchanged. If a caller's code does not start with `docs.`,
  leave `generate.py`'s `_error` (per the merge rule).
- In `modules/docs/parsed.py`: `local_links(text) -> tuple[str, ...]`, which is
  `links(text)` minus `MarkdownUtils.is_external` ones. It replaces the
  external filter in `site.py:120-132` (`linked_pages`), `nav.py:53-61`
  (`_linked_order`), `structure.py:274-283` (`_resolved_links`) and
  `packages.py` `_check_readme` (`:207-215`).
- New `modules/docs/pages.py`: `is_content_page(path)` (not `index.md`, not
  `_`-prefixed) and `content_pages(directory)` (sorted `*.md` in *directory*
  for which `is_content_page` holds). They replace `structure.py:46-51`
  `_content_pages` and `nav.py:100-101` `_is_page`. `site.py:86-94`
  `markdown_files` keeps `index.md`, so it is a different rule: leave it.
  `nav_pages(nav) -> list[str]`: every `str` leaf of a nav tree, in order. It
  replaces the walker inside `site.py:96-112` `nav_paths` (which then keeps
  its `.md` filter) and `packages.py:127-134` `_nav_names` (which becomes
  `page in nav_pages(node)`).
- Features: one pattern, `FEATURE_FILE = re.compile(r"^F(\d+)\.(\d+)-.*\.md$")`,
  and `feature_sort_key(path) -> tuple[int, int]`, in `modules/docs/work.py`,
  added to its `__all__`. They replace `work.py:95` `_FEATURE_FILE_RE` and
  `nav.py:97` `_FEATURE_FILE_RE`, and the inline sort key at `nav.py:113` and
  any equal key in `work.py` (search `split("-")[0]` and `F(\d+)`).
- `project_urls(pyproject: Path) -> dict[str, object]`, public in
  `modules/docs/packages.py`: the raw `[project.urls]` table. It replaces
  `packages.py` `_check_urls`'s `_table(_toml(path), "project", "urls")`
  (`:197-199`) and `scaffold.py:73-77` `_project_urls`. `scaffold.py` keeps
  its `str(value)` conversion at the call site.

**4. Work-layout paths.** `nav.py` (`:126-152`), `work.py:319` and
`generate.py:164` build `specs/epics` and `specs/ideas` from literals. They read
them from `POLICY` (`policy.py:116-146`): `POLICY.nested[0].path`
(`"specs/epics"`) and `POLICY.ideas` (`"specs/ideas"`), and `nav.py` uses
`POLICY.nested[0].dirname` in place of its own epic-directory regex if it is the
same pattern (`_EPIC_DIR_RE`). Where `nav.py` holds a path relative to the area
(`area_dir / "epics"`), derive it from the policy path relative to `area.key`.
If the area key and the policy path do not line up, leave that copy (per the
merge rule).

**5. devops names.** In `devops/ci.py:24-31`: `normalize` becomes
`packaging.utils.canonicalize_name`, and `requirement_name` becomes
`canonicalize_name(Requirement(requirement).name)`. `uv.Package`
(`devops/uv.py`) gains `release_requirements: tuple[str, ...]`, the raw
requirement strings it collects at `:157-161`. `devops/requirements.py:41-52`
reads each member's entries from it instead of re-reading `pyproject.toml` (it
still reads `version`). Leave `modules/python/checks/rn_forge_deps.py`'s
normaliser alone: F18.10 changes it.

**6. One process helper** — new `modules/core/process.py`:

```python
def run(
    label: str,
    *args: str | Path,
    cwd: Path | None = None,
    env: Mapping[str, str] | None = None,
    check: bool = True,
) -> Process:
```

It calls
`Process.execute(label, *(str(a) for a in args), fail_on_error=check, cwd=str(cwd) if cwd else None, env=env)`
(pass `env` only when given). Every `Process.execute(` under `modules/` and
`commands/` moves onto it, dropping its `str(...)` conversions.
`modules/core/inventory.py:46-53` and `modules/core/config/sources.py:99-107`
move from `subprocess.run` onto `run(..., check=False)` and keep their own error
handling and messages, reading `return_code`, `stdout` and `stderr` from the
`Process`.
