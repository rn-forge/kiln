# S19.3.1 — `render_epics` writes the jump links as a list

Brief for
[S19.3.1](../F19.3-epic-list-jump-links.md#s1931-render_epics-writes-the-jump-links-as-a-list),
at `feature/v1` after `2881b62`.

## Goal

`render_epics` writes the epic list's jump links as a bullet list, one range per
line, under a `Jump to:` line, so mdformat leaves the derived region alone
however many ranges there are.

## Settled

- The region opens exactly with:

    ```markdown

    Jump to:

    - [E1–E10](#e1e10)
    - [E11–E20](#e11e20)

    ## E1–E10
    ```

    One item per range that holds an epic, in range order. A single range is a
    one-item list. The link text, the slugs, the headings and the tables do not
    change.

- The empty case (`"\nNo epics yet.\n\n"`) does not change.

- Test names describe behaviour. The story's `test_s19_3_1_*` names break the
  no-spec-ID rule, so use the names below.

- Rejected (do not build): wrapping the line at 80 in the generator,
  whitespace-insensitive comparison in doctor, dropping the jump line,
  excluding the epic list from mdformat.

## Current behaviour

- `src/rn_forge/kiln/modules/docs/work/render.py:236-240` joins every link with
  `" · "` into one `f"Jump to: {jump}"` line.
- So test 1 below fails its `startswith` assertion, because the body starts
  `"\nJump to: [E1–E10](#e1e10) · …"`. Test 2 fails in `_stable`, because
  mdformat at `wrap = 80` wraps the ten-range line and the result differs from
  the input. Its `wrap = "keep"` assertion passes today and must keep passing.
- The two updated tests fail once the change is made, unless they are updated as
  below. They pass today.

## Change

- **Change:** in `render_epics` in
  `src/rn_forge/kiln/modules/docs/work/render.py`, build one
  `f"- [{label}](#{slug})"` line per range, in `sorted(ranges)` order. Replace
  `lines = ["", f"Jump to: {jump}"]` with `["", "Jump to:", "", *items]`. The
  loop below already adds the blank line before each `## ` heading.
- **Then:** run `task docs:generate`. kiln's own `docs/specs/epics/index.md`
  changes to the list form, and no other file does.
- **Leave alone:** every other renderer, `_body`, `epic_range`, `range_label`,
  every template, every other generated file, and every spec page except this
  brief's `## Result`.
