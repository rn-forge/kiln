# S18.12.1 — Doctor runs every check

Brief for
[S18.12.1](../F18.12-release-1-review-defects.md#s18121-doctor-runs-every-check),
at `5733688`. Paths are under `src/rn_forge/kiln/`.

## Goal

`kiln doctor` runs `kiln-pin`. Every check module under `modules/*/checks/` is
registered in `checks.CHECKS`.

## Settled

- Register `Check(pin.NAME, "core", pin.check, "quality")` in `checks.CHECKS`
  (`checks.py`), right after the `generated` entry, and delete the comment
  S18.8.1 left above `CHECKS` saying it is not registered yet.
- **Scope `"quality"`** (lead's ruling, 2026-11-17). `output.fail_on_errors`
  runs the `"ownership"` checks after every `kiln apply`, `kiln new` and
  `config-update --apply`, and prints every finding, warnings included. A
  missing pin is a warning (`pin.MISSING`). So with `"ownership"` those
  commands would start printing it. With `"quality"`, `kiln doctor` runs it
  and `apply` does not.
- `tests/modules/core/checks/test_pin.py:50`: drop the `xfail` on
  `test_s18_5_2_3_pin_runs_through_the_registry`; it now passes.
- `tests/modules/core/test_cycle.py:395-397`: `module_findings("core", …)` now
  includes `pin`, so drop the separate `*pin.check(...)` and its S18.10.1
  comment. The test's expected findings stay the same.

## Current behaviour

- `checks.CHECKS` (`checks.py:49-61`) has no `kiln-pin` entry. A comment above
  it says S18.10.1 adds it.
- Twelve check modules exist under `modules/*/checks/`; eleven are registered.
- A repository whose config has no `[kiln] ref` gets no `kiln.pin-missing`
  finding from `kiln doctor`.
