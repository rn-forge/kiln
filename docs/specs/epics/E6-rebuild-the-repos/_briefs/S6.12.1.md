# S6.12.1 — `umbrella` creates only the newest shipped release

Brief for
[S6.12.1](../F6.12-umbrella-releases-only-the-newest.md#s6121-umbrella-creates-only-the-newest-shipped-release),
at `21c8dc4`.

## Goal

`kiln-devops umbrella` creates a GitHub release only for the highest-numbered
shipped release page, marked Latest, and names every lower shipped release
without one on stderr instead of backfilling it at the current commit.

## Settled

- **The rule** (F6.12 "The rule", owner, 2026-11-14): create only the newest
  shipped release, and only when it has no GitHub release. Lower ones are
  skipped with a notice; never backfilled. No `--backfill` flag.
- **`--latest` is unconditional** on the one `create` command.
- **The notice**, one line per skipped release, to stderr, verbatim:
  `kiln-devops: skipped release-<n>: no GitHub release, and only the newest shipped release is created; create it by hand to backfill`
- **Dry run calls no `gh`** (F15.5), so under `--dry-run` every lower shipped
  release is listed as skipped without an existence check.
- **`--sha` is unchanged** (F6.12 "Where the tag lands").

## Current behaviour

`src/rn_forge/kiln/devops/umbrella.py` at `21c8dc4`:

- `shipped()` (`:55-66`) returns every shipped release, sorted by number.
- `run()` (`:79-102`) keeps every shipped release whose GitHub release is
  missing (`github.release_exists`, skipped under dry run) and creates each,
  in ascending order. It prints nothing per release.
- `create_command()` (`:69-76`) has no `--latest`.
- `devops/cli.py:139` help: "create a GitHub release per shipped release page".
- `tests/devops/test_umbrella.py`: `_repo(root, status, number=2)` (`:28-32`)
  writes one page; `_gh(monkeypatch, exists: bool)` fakes `gh` with one answer
  for every tag.

So, against the tests below: test 1 fails (it creates `release-1` to
`release-5`); test 2 fails (it creates 1 to 5 and 8, none with `--latest`); test
3 fails (lower releases are created); test 4 passes already (a guard); test 5
fails (three `create` lines, no `--latest`).

## Change

- **Change:**
    - `src/rn_forge/kiln/devops/umbrella.py`: `run()` takes
      `newest = shipped(releases)[-1]` (none shipped: the existing message,
      `0`). When not dry run and `newest` exists, print the existing message and
      return `0`. Otherwise create only `newest`. For each lower shipped release
      with no GitHub release (every lower one under dry run), print the notice.
      `create_command()` appends `--latest`. The module docstring and `run()`'s
      docstring say "the newest shipped release".
    - `src/rn_forge/kiln/devops/cli.py:139` help: "create a GitHub release for the
      newest shipped release page".
    - `tests/devops/test_umbrella.py`: a helper building several pages in one
      `tmp_path` (each page has its own directory, so `_repo` works as is), and
      a fake `gh` that answers `gh release view release-<n>` from a set of
      existing tags. Keep `_gh(monkeypatch, exists)` working for the F15.5
      tests.
    - Any existing F15.5 test that asserts the exact `create` argv gains
      `--latest`; that is the rule change, not a weakening. Name each in
      `## Result`.
- **Leave alone:** `github.py`; the `ci.yml` task templates; docs (S6.12.2).
