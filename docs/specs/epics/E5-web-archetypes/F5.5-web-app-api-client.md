A `python-web-app` + FastAPI repository renders `task web:client`, which writes
the API's OpenAPI document and regenerates the frontend's typed client from it,
and CI fails when the committed client differs from the one the API produces.
That check is what enforces
[ARCH-0005](../E12-architecture-baseline/design.md#arch-0005): the frontend's
API types are generated, never written by hand.
[F12.2](../E12-architecture-baseline/F12.2-web-baseline.md)'s S12.2.5 renders
ARCH-0005 once this feature closes.

## S5.5.1 — The generator and the client's home are chosen

**State:** Closed (2026-11-19) · **Owner's story:** a decision, not code

The owner decides three things. The recommendation for each is what S5.5.2's
build list assumes; a different choice rewrites S5.5.2 before it starts.

| Decision | Recommendation | Why |
| -- | -- | -- |
| The generator | `@hey-api/openapi-ts`, with its Angular client, as a dev dependency of the root `package.json` | typed services on Angular's `HttpClient`, one npm package, no Java runtime (OpenAPI Generator needs one) |
| Where the client lives | `<web_dir>/src/app/api/`: `openapi.json` and the generated `client/` beside it | inside the one Angular project, so no new Nx library and no new project boundary |
| Committed or built | committed, with a CI check that regenerating changes nothing | the frontend builds and its tests run without the API running; the diff of an API change shows in review |

**Acceptance:**

- The three decisions are recorded here, dated.

Decided 2026-11-19: the owner took all three recommendations. The generator is
`@hey-api/openapi-ts` at `0.99.0`, npm's current release that day.

## S5.5.2 — `task web:client` regenerates the client, and CI checks it

**State:** New · **Module:** `tasks`, `node`, `cicd` · **Depends on:** S5.5.1

**Build — tests first**, in `tests/modules/tasks/test_artifacts.py` and the
web-app scaffold tests:

- `test_web_app_renders_the_client_task`: a `python-web-app` + FastAPI render
  has a public `web:client` task; `python-web-api` and Django renders do not.
- `test_the_client_task_writes_the_schema_then_the_client`: its commands, in
  order, write `<web_dir>/src/app/api/openapi.json` from the API application,
  then run the generator into `<web_dir>/src/app/api/client/`.
- `test_validate_checks_the_client_is_current`: `task validate` in that render
  runs an internal `web:client:check`, which runs `web:client` and fails when
  `git status --porcelain` lists anything under `<web_dir>/src/app/api/`.
- `test_kiln_new_seeds_the_generator_and_a_first_client`: `kiln new` adds the
  generator to the root `package.json`'s dev dependencies and its config file,
  and the scaffolded repository's first `task validate` passes.

**Build:**

- `modules/tasks/templates/tasks/web.yml.j2`: a public `client` task, when
  `web_app` and `backend == "fastapi"`. Its `desc:` is "Regenerate the
  frontend's API client from the API's OpenAPI document." Its commands:
    1. `uv run --package <api_package> python -c` printing
       `json.dumps(app.openapi(), indent=2, sort_keys=True)` from
       `<api_module>.app`, redirected to `<web_dir>/src/app/api/openapi.json`;
    1. `pnpm openapi-ts`, reading the config file below.
- An internal `client:check` task in the same file runs `client`, then fails
  with `the API client is stale — run task web:client and commit the result`
  when `git status --porcelain -- <web_dir>/src/app/api/` prints anything. It
  joins the web app's `validate` composition, as the other checks of
  [E15](../E15-ci-standard/index.md) do.
- The generator's config, `openapi-ts.config.ts` at the repository root, seeded
  at `kiln new`, naming the input and output paths above and the Angular
  client.
- The root `package.json` that `kiln new` scaffolds gains the generator as a dev
  dependency, at the version S5.5.1 records. A repository already scaffolded
  keeps its `package.json` and adds it by hand.
- `.mdformat.toml`, `.prettierignore` and the lint configs the web app renders
  leave `<web_dir>/src/app/api/client/` unformatted and unlinted, because it
  is generated.
- `modules/instructions/templates/standard.md.j2`, the web app's section: one
  paragraph saying the client is generated by `task web:client`, committed,
  and checked in CI.

**Acceptance:**

- The tests pass, and `task validate` passes.
- Not scriptable, judged by the owner: in the render matrix's FastAPI + Angular
  cell, adding a route to the starter's items router and running
  `task web:client` changes the generated client, and `task validate` fails
  until that change is committed.
