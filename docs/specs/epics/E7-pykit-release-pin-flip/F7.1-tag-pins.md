## S7.1.2 — The root pyproject.toml overrides every rn-forge distribution to its tag

**State:** New

Added 2026-10-16, from S7.1.1's failed golden validate. pykit's tags sit on
different commits (ADR-0004: packages release independently), and uv resolves
each pykit package's `{ workspace = true }` sources relative to the tag it was
fetched at, so one distribution arrives under two URLs. An override names one
URL for each distribution and wins over every transitive requirement. Proved by
hand on 2026-10-16 against a copy of the rendered
`python-web-api-backend=fastapi` cell. With the override, `uv lock` resolves 89
packages, each rn-forge package at its own tag. An override for a distribution
the graph never reaches (`rn-forge-django`, `rn-forge-sqlalchemy`) adds nothing.
An override without extras keeps the extras the requirement asked for
(`pydantic` from `rn-forge-commons[pydantic]` stays locked).

**Build — tests first**, in `tests/modules/python/test_scaffold.py` (copy the
shape of the nearest test there that reads a reconciled root `pyproject.toml`):

- `test_s7_1_2_1_root_overrides_every_pinned_distribution`: for `python-app` and
  for the FastAPI `python-web-api` cell, the root `pyproject.toml`'s
  `[tool.uv] override-dependencies` equals
  `[archetypes.requirement(d) for d in sorted(archetypes.RN_FORGE_TAGS)]`.
- `test_s7_1_2_1_members_carry_no_override`: no non-root `pyproject.toml` has
  `override-dependencies`.
- `test_s7_1_2_2_own_members_are_not_overridden`: for `python-lib`, the override
  list leaves out every distribution that is one of the workspace's own
  members ([ADR-0014](../../../adr/ADR-0014.md)'s membership rule).
- `test_s7_1_2_1_build_backend_survives`: for `python-app`, `[tool.uv]` still
  holds `build-backend` beside `override-dependencies`.

**Build:**

- `src/rn_forge/kiln/modules/python/scaffold.py`, `_reconcile`: when `is_root`,
  set `tool["uv"]["override-dependencies"]` to `archetypes.requirement(d)` for
  each `d` in `sorted(archetypes.RN_FORGE_TAGS)` that is not one of the
  workspace's own member names, merged with the `build-backend` table a
  non-workspace root already gets. Pass the member names in from the caller;
  do not re-read the workspace from disk. `_multiline_lists` also makes the
  override list one entry per line.
- `docs/reference/standard-repo.md` §3: after the pin-table paragraph, add: *The
  root `pyproject.toml` lists every pinned rn-forge distribution in
  `[tool.uv] override-dependencies`. pykit's tags sit on different commits,
  and without the override uv resolves a shared dependency under each tag that
  reaches it.* Mirror the sentence in
  `modules/instructions/templates/standard.md.j2`, hand-copy it into
  `.rn-forge/kiln/standard.md`, and re-seed its `content_hash` as `README.md`
  says.

**Do not** change `rn_forge_deps.py`. Overrides are not `[tool.uv.sources]`, and
they never reach a wheel. Do not add overrides to kiln's own `pyproject.toml`,
which reaches only `f3d1757`. Do not move a pin.

**Acceptance:**
