[ADR-0021](../../../adr/ADR-0021.md) gives each file type one formatter in every
archetype. Markdown and TOML already have theirs. This feature adds YAML: choose
the tool (S19.1.1), make every template render clean for all three types
(S19.1.2), add the task pair and everything that wires it (S19.1.3), and prove
kiln's own repository passes (S19.1.4). **Build order is S19.1.1, S19.1.2,
S19.1.3, S19.1.4.**

S19.1.2 comes before the tasks on purpose. A task that fails on every fresh
repository would put a red gate in every generated repository the day it ships.
The test comes first and the templates are fixed to it, so the task arrives on
output that already passes.

Read [the board's "Building a story"](../../index.md#building-a-story) first.
For every story: tests first, named after the story ID and shown failing; only
`task` verbs (never `uv`, `pytest`, `ruff` or `kiln`), except where a story says
otherwise; commit nothing. When the story is built, paste the tail of
`task validate` into its *What the build settled* block. S19.1.2, S19.1.3 and
S19.1.4 each leave `task validate` and `task lint KILN_DOCTOR_FULL=1` green on
their own; a story that changes a template runs `task kiln:apply` here in the
same story (`AGENTS.md`, Guardrails).

## Design

**What exists.**
`src/rn_forge/kiln/modules/tasks/templates/tasks/quality.yml.j2` renders
`lint:markdown`, `lint:toml`, `format:markdown` and `format:toml` for every
archetype, each `internal: true`, each fed by the `FILES` variable
(`git grep --untracked -lz -e '' -- '<glob>'`). mdformat is in the rendered
`docs` dependency group and taplo is in the `dev` group (`_DOCS_GROUP` and
`_DEV_GROUP` in `src/rn_forge/kiln/modules/python/scaffold.py`); the Node
archetypes get both through the root `pyproject.toml` that `scaffold` writes for
`node-lib` and `python-web-app`. The root `lint` and `format` verbs in
`src/rn_forge/kiln/modules/tasks/templates/Taskfile.yml.j2` call the pairs.
`required_validate` in each `archetype.toml` names `quality:lint:markdown` and
`quality:lint:toml`.

**What YAML has.** Prettier formats it in the Node archetypes
(`pnpm exec prettier --write .` and `--check .`, in
`src/rn_forge/kiln/modules/tasks/templates/tasks/node.yml.j2`), and
`src/rn_forge/kiln/modules/node/templates/prettierignore.j2` excludes the files
kiln owns (`.github/`, `Taskfile.yml`, `tasks/`, `mkdocs.yml`, `.rn-forge/`,
`tools/ci/`) and `pnpm-lock.yaml`. Nothing formats YAML in the Python
archetypes, and nothing anywhere formats the files kiln owns: they are compared
byte for byte with templates that are not themselves checked.

**The pattern, applied.** One formatter, installed by uv into the `dev` group
beside taplo; `quality:lint:yaml` and `quality:format:yaml`; the same file list
with `'*.yml' '*.yaml'`; a seeded config next to `.taplo.toml`; the root `lint`
and `format` verbs call the pair; `required_validate` names the lint task; the
Node archetypes' `.prettierignore` block lists `*.yml` and `*.yaml`.

**Tool candidates** (checked on PyPI, 2026-11-10).

| Package | Is | Note |
| -- | -- | -- |
| `google-yamlfmt` 0.21.0 | Google's Go `yamlfmt`, repacked with platform wheels by a third party (github.com/PFCCLab/google-yamlfmt) | the expected choice; macOS x86_64 and arm64 and manylinux x86_64 and aarch64 wheels; the supply-chain caveat is the third-party repack |
| `yamlfix` 1.19.1 | pure Python, ruamel-based, keeps comments | the fallback |
| `yamlfmt` | an unrelated ruamel-based tool (mmlb), not Google's | never install this one by that name |
| `yamllint` | a linter | does not format |

## S19.1.1 — Settle the YAML formatter

**State:** Closed (2026-11-10) · **Depends on:** —

The one story in this feature that decides something, and it decides by a trial
with pass and fail criteria. It adds no dependency to this repository: the trial
runs the candidates with `uvx` from a scratch directory, which is the exception
to "only `task` verbs", for this story only. Candidate order: try
`google-yamlfmt` first; try `yamlfix` only if it fails a criterion.

**The material.** `task self:golden:render` renders the six cells (`python-app`,
`python-tool`, `python-lib`, `python-web-api-backend=fastapi`,
`python-web-app-backend=fastapi-frontend=angular`, `node-lib`) into `.goldens/`
and prints where. The trial formats **copies** of every `*.yml` and `*.yaml` in
those cells, never the originals, and the trial uses the config stated in
criterion 6.

**Criteria.** Each is pass or fail; record the command and the result of each in
*What the build settled*.

1. **Installs where kiln runs.** The package resolves to a binary wheel for
   macOS arm64 and for linux x86_64, the platforms of this machine and of
   GitHub-hosted CI. Run
   `uv pip install --dry-run --only-binary :all: --python-platform aarch64-apple-darwin <package>`
   and the same with `--python-platform x86_64-manylinux_2_28`; both exit 0.
   Then `uvx --from <package> <executable> -version` (or `--help` for a tool
   with no version flag) exits 0 here.
1. **Comments and headers survive.** For every formatted copy, the count of
   lines whose first non-space character is `#` equals the original's, and the
   first line (the `# Generated by kiln` header) is byte-identical.
1. **Data is unchanged.** For every formatted copy,
   `yaml.load(text, Loader=yaml.BaseLoader)` equals the original's.
   (`BaseLoader` reads every scalar as text and tolerates tags.) A block
   scalar (`run: |`) whose text changed fails here.
1. **Tags survive.** The line
   `format: !!python/name:pymdownx.superfences.fence_code_format` is present,
   byte for byte, in the formatted `mkdocs.yml` of every `mkdocs` cell.
1. **Idempotent.** Run the formatter on its own output; the check command exits
   0 on it, and the file is byte-identical.
1. **Few keys, no rewrapping.** The config holds at most `formatter.type` and
   two other `formatter` keys, plus `exclude`. With it, for every formatted
   copy, the count of non-blank lines equals the original's (nothing folded,
   wrapped or split). Record the number of the cells' files the formatter
   changed, out of the total.
1. **The tool does not fight the package manager.** In the `node-lib` cell, run
   `pnpm install --frozen-lockfile` and compare `pnpm-workspace.yaml` before
   and after: record whether pnpm rewrites it. Then format a copy of it with
   the config. If the formatter changes it **and** pnpm rewrites it, the
   result for the file is *excluded*; if the formatter changes it and pnpm
   leaves it alone, the result is *formatted*. `pnpm-lock.yaml` is *excluded*
   either way (pnpm writes it), whatever the trial shows.

## S19.1.2 — A fresh render of every archetype is formatter-clean

**State:** Closed (2026-11-10) · **Depends on:** S19.1.1

A template change, and the first dependency on the formatter. The task does not
exist yet: this story's test calls the formatter directly, from the virtualenv,
as `tests/modules/core/test_cycle.py` calls taplo
(`Path(sys.executable).parent / "taplo"`).

**Tests first,** new file `tests/test_formatting_clean.py`. It uses the
`rendered` fixture in `tests/conftest.py`, which runs `kiln new` for an
archetype once per session, and the same six archetypes the render matrix
renders:

```python
ARCHETYPES = [
    "python-app",
    "python-tool",
    "python-lib",
    "python-web-api",
    "python-web-app",
    "node-lib",
]
```

Module constants, from the *Settled by S19.1.1* table, verbatim: `YAML_PACKAGE`,
`YAML_EXECUTABLE`, `YAML_CHECK` (the check command, as a tuple of arguments),
`YAML_CONFIG_FILE` and `YAML_CONFIG` (the fenced block's text), and
`PACKAGE_MANAGER_FILES` (the *Excluded files* value as a set of basenames).

Helpers:

- `_files(root, *suffixes)` walks *root* with `os.walk`, pruning the directories
  `.git`, `node_modules`, `.venv`, `.uv-cache`, `.nx`, `.angular`, `dist`,
  `coverage`, `.docs-site` and `.pytest_cache`, and returns the
  repository-relative paths ending in a suffix, sorted. It does not use
  `git grep`: a `rendered` tree may have no repository of its own.
- `_run(root, argv)` is
  `subprocess.run(argv, cwd=root, capture_output=True, text=True, check=False)`;
  the tests assert `returncode == 0` with the message `stdout + stderr`.

The tests, each parametrized over `ARCHETYPES`:

1. `test_s19_1_2_1_rendered_markdown_is_mdformat_clean`:
   `_run(root, [sys.executable, "-m", "mdformat", "--check", *_files(root, ".md")])`.
   The rendered `.mdformat.toml` applies because of `cwd`.
1. `test_s19_1_2_2_rendered_toml_is_taplo_clean`:
   `_run(root, [str(Path(sys.executable).parent / "taplo"), "fmt", "--check", "--diff", *_files(root, ".toml")])`.
1. `test_s19_1_2_3_rendered_yaml_is_clean`: write `YAML_CONFIG` to a temporary
   directory as `YAML_CONFIG_FILE`, copy the rendered tree's YAML (everything
   `_files(root, ".yml", ".yaml")` returns, less `PACKAGE_MANAGER_FILES`)
   beside it keeping relative paths, and run
   `Path(sys.executable).parent / YAML_EXECUTABLE` with `*YAML_CHECK` and the
   file list, `cwd` the temporary directory. (The copy is why the config can
   be the in-test one: S19.1.3 switches this test to the rendered config.)
1. `test_s19_1_2_4_the_lists_are_not_empty`: `_files(root, ".md")` contains
   `README.md`; `_files(root, ".toml")` contains `.taplo.toml`;
   `_files(root, ".yml")` contains `Taskfile.yml`, `tasks/quality.yml` and
   `.github/workflows/ci.yml`. It guards the three tests above against passing
   on an empty list.
1. `test_s19_1_2_5_the_tools_are_locked`: `tomllib` reads `pyproject.toml`;
   `dependency-groups.dev` has one entry that starts with
   `YAML_PACKAGE + ">="`; `uv.lock` lists a package of that name (copy
   `test_s16_4_3_2_floors_match_the_lock` in
   `tests/modules/python/test_scaffold.py`, with its `_version_key`).

**Build.**

    - Run the formatter on a copy of the rendered file and read the diff.
    - Find the template: templates are `*.j2` under
      `src/rn_forge/kiln/modules/*/templates/`; search for a distinctive line
