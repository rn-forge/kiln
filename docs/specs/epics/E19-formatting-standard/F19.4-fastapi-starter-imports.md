The FastAPI starter seeds imports that pass ruff only when the package name is
short.

## Context

`task self:golden:validate` fails the
`python-web-app-backend=fastapi-frontend=angular` cell at setup+validate. ruff
reports `I001` in two seeded files, `app.py` and `http/items.py`:

```text
from python_web_app_backend_fastapi_frontend_angular_api.domain.errors import ItemNotFound
```

The line is longer than the line length, so ruff's import sorter wants it
parenthesised. The templates are
`src/rn_forge/kiln/modules/python/templates/starter/fastapi/app.py.j2` and
`items.py.j2`. A repository with a long enough name gets a starter whose
`task lint` fails on day one. The other five cells pass.

## S19.4.1 — The starter's imports are stable at any name length

**State:** Closed (2026-11-22)

Every first-party import in the FastAPI starter is parenthesised, one name per
line, with a trailing comma. ruff's magic trailing comma keeps that form at any
length.

**Acceptance:**

- A test renders the FastAPI starter for a long package name and the seeded
  files pass `ruff check` and `ruff format --check`.
- `task validate` and `task self:golden:validate` (after
  `task self:golden:render`) pass in every cell.

Outcome: the `python-web-app-backend=fastapi-frontend=angular` golden cell
passes `task lint`.
