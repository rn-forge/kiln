# F12.1 — The baseline module, and the Python records

**Status:** planned

Epic: [E12](index.md) · Design: [design.md](design.md) · **Depends on:**
[S4.3.1](../E4-generator/F4.3-concern-modules.md#s431-python) and
[S4.3.5](../E4-generator/F4.3-concern-modules.md#s435-instructions), both done;
S12.1.1 before any other story here

A new `baseline` module renders B-0001–B-0003 and their index into
`.rn-forge/kiln/baseline/`. `standard.md` and the `CLAUDE.md` block point at
them, and `.importlinter` gains the `dependencies-point-inward` contract that
enforces B-0001.

**Build a story by the [board's procedure](../../index.md#building-a-story).**
Every build story here is golden first: make the change in the goldens' real
files, prove it with each golden's own gate, then write the template that
reproduces it. The texts to copy are in [design.md](design.md). Copy them
exactly; do not rephrase a record, a comment or a contract name.

**Re-seeding a golden's `state.json`.** Each build story adds or changes managed
files in the goldens, so their `.rn-forge/kiln/state.json` changes too. Use a
throwaway script, never committed. For a managed file, `content_hash` is
`rn_forge.kiln.modules.core.checks.generated.digest(text)` of the whole file.
For the `CLAUDE.md` block, it is `digest(block_body(text, begin_marker))`, where
`begin_marker` comes from the entry itself. A new entry copies the shape of the
`.rn-forge/kiln/standard.md` entry: `begin_marker` and `end_marker` are `null`,
`kind` is `"managed"`, and `path` equals the key. Keys stay sorted as the file
has them. `metadata` does not change, because no `config.toml` changes.

## S12.1.2 — The `baseline` module renders the Python records

**Status:** planned · **Module:** `baseline` (new)

**Renders** (property 1, in this order):

| Artifact | Kind | When |
| -- | -- | -- |
| `.rn-forge/kiln/baseline/B-0001.md` | managed | `config.archetype != "python-lib"` |
| `.rn-forge/kiln/baseline/B-0002.md` | managed | `config.archetype != "python-lib"` |
| `.rn-forge/kiln/baseline/B-0003.md` | managed | `config.archetype == "python-lib"` |
| `.rn-forge/kiln/baseline/index.md` | managed | always |

**Build:**

- **Goldens first.** Add `.rn-forge/kiln/baseline/` to each golden: `index.md`,
  `B-0001.md` and `B-0002.md` in `golden/python-app` and `golden/python-tool`,
  and `index.md` and `B-0003.md` in `golden/python-lib`. Each file's first
  line is the provenance comment with `golden` as the version:
  `<!-- Generated by kiln golden from .rn-forge/kiln/config.toml — do not edit; run 'kiln apply' -->`.
  Then comes one blank line, then the text from
  [design.md](design.md#record-texts). Each index lists only its own golden's
  records. Re-seed each golden's `state.json` with the new entries, then run
  each golden's `uv sync && task validate` from inside it.

- **`src/rn_forge/kiln/modules/baseline/__init__.py`** defines `BaselineModule`
  and `BASELINE = BaselineModule()`, with the same shape as
  `modules/instructions/__init__.py`: `name = "baseline"`, `section = None`,
  `config_model = None`, `options()` returns `()`, and
  `artifacts(config, root)` deletes `root` and returns
  `artifacts.render(config)`, imported inside the method.
  `checks(config, root)` returns `()`.

- **`src/rn_forge/kiln/modules/baseline/artifacts.py`** exposes:

    - `BASELINE_DIR = ".rn-forge/kiln/baseline"`;
    - `Record`, a `@dataclass(frozen=True, slots=True)` with `id: str`,
      `title: str` and `applies: Callable[[KilnConfig], bool]`;
    - `RECORDS: tuple[Record, ...]`, holding exactly B-0001, B-0002 and B-0003 in
      that order, with the titles and predicates in
      [the catalogue](design.md#the-catalogue);
    - `render(config: KilnConfig) -> list[Artifact]`, which returns one managed
      `Artifact(f"{BASELINE_DIR}/{record.id}.md", ...)` for each record whose
      `applies(config)` holds, in `RECORDS` order, then the managed
      `Artifact(f"{BASELINE_DIR}/index.md", ...)`.

- **Templates** in `src/rn_forge/kiln/modules/baseline/templates/`:
  `B-0001.md.j2`, `B-0002.md.j2`, `B-0003.md.j2` and `index.md.j2`. Render
  them with `TemplateEngine(package="rn_forge.kiln.modules.baseline")`. The
  context is `kiln_version` (`rn_forge.kiln.__version__`) and `records`, a
  list of `(id, title)` pairs for the rendered records. Each record template
  is the provenance line with `{{ kiln_version }}`, one blank line, then the
  text from [design.md](design.md#record-texts). The index template is in
  [design.md](design.md#the-index). If Jinja's whitespace control makes the
  table rows or the blank line before `## Deviating` come out wrong, build the
  rows as one pre-joined string in `render`, as `python`'s `members_block`
  does. The rendered bytes are what count.

- **Registration.** In `modules/registry.py`, `builtin()` lists `BASELINE`
  between `CICD` and `INSTRUCTIONS`. Every `archetype.toml` under
  `src/rn_forge/kiln/archetypes/` lists `"baseline"` immediately before
  `"instructions"` in `modules`.

- **Tests enumerating modules or artifacts.** `tests/test_archetypes.py` asserts
  each manifest's module list (line 55). Add `"baseline"` there. Any other
  existing test that fails *only* because a list of modules, artifact keys or
  `state.json` keys gained the new entries gets those entries added. Record
  each such test under *What the build settled*. Any other failure stops the
  build: record it, and do not work around it.

**Tests:** `tests/modules/baseline/__init__.py` (empty) and
`tests/modules/baseline/test_artifacts.py`, named `test_s12_1_2_…`. Copy the
shape of `tests/modules/instructions/test_artifacts.py`:

- Properties 1–4 of [F4.3](../E4-generator/F4.3-concern-modules.md), for
  `python-app`, `python-tool` and `python-lib`. Property 1 is the **Renders**
  table above. Property 4 compares each rendered file to its golden
  counterpart after normalizing the version in the provenance line, with the
  regex `^<!-- Generated by kiln .*? from `.
- The rendered files are mdformat-clean. Write them into `tmp_path`, copy
  `golden/python-tool/.mdformat.toml` beside them, run
  `[sys.executable, "-m", "mdformat", "--check", str(tmp_path)]` with
  `subprocess.run`, and assert the return code is 0.
- `docs.profile = "none"` renders the same baseline artifacts as `mkdocs`.
- After an apply, a hand edit to `B-0001.md` classifies `DRIFT` on the next
  plan, as `standard.md`'s test does.

**Do not:** add a config key, an option or a check; import `baseline` from any
other module; render anything under `docs/`; or change `.mdformat.toml`, the
seeded template or any golden's copy of it.

**Acceptance:**

- Each golden's `task validate` passes with the new files and re-seeded state.
- The property tests, the mdformat test, the profile test and the drift test
  pass.
- `task validate` passes in kiln.

## S12.1.3 — `standard.md`, the `CLAUDE.md` block and the reference point at the baseline

**Status:** planned · **Module:** `instructions` · **Depends on:** S12.1.2

**Build:**

- **Goldens first.** In each golden's `.rn-forge/kiln/standard.md`, append this
  section after the last line of the file, with one blank line before it:

    ```markdown
    ## 9. The architecture baseline

    `.rn-forge/kiln/baseline/` holds the design decisions kiln's canon makes for
    this repo's product code, one managed record per file, listed in its
    `index.md`. They are part of this standard: a change to product code follows
    them, and a departure from one is an ADR of this repo's own that names the
    record it supersedes. `.importlinter` enforces the records an import contract
    can express.
    ```

    In each golden's `CLAUDE.md` block, insert this bullet immediately before the
    `- **kiln is a pinned dev dependency.**` bullet:

    ```markdown
    - **Architecture:** product code follows the baseline in
      [.rn-forge/kiln/baseline/index.md](.rn-forge/kiln/baseline/index.md). A
      departure from one of its records is an ADR of this repo's own, never an
      edit there.
    ```

    Re-seed the `standard.md` and `CLAUDE.md#rn-forge kiln` entries in each
    golden's `state.json`, then run each golden's gate.

- **Templates.** `modules/instructions/templates/standard.md.j2` ends with the
  same section, unconditionally. `modules/instructions/templates/block.md.j2`
  carries the same bullet, unconditionally, immediately before the
  `**kiln is a pinned dev dependency.**` bullet. Both texts are static: no new
  context key.

- **The reference.** In `docs/reference/standard-repo.md`:

    - Add this row to the ownership table, immediately after the
      `.rn-forge/kiln/standard.md` row:
      `` | `.rn-forge/kiln/baseline/` | kiln | managed — the architecture baseline's records and their index | ``

    - Append a section `## 10. The architecture baseline` after the last section,
      as the final section of the page. Its body is one opening paragraph and
      the two tables in [the catalogue](design.md#the-catalogue), limited to the
      rows for B-0001–B-0003 and the rows for the Python cells. F12.2 adds the
      rest. The paragraph is exactly:

        ```markdown
        kiln renders a set of architecture decision records into
        `.rn-forge/kiln/baseline/`, managed, one per file, with an `index.md` that
        lists them ([ADR-0010](../adr/ADR-0010.md)). Which records a repository
        gets depends on its archetype and flags. The records an import contract
        can express are enforced in `.importlinter`.
        ```

    - Run `task format` and `task docs:nav`.

**Tests:** extend `tests/modules/instructions/test_artifacts.py`, with names

**Acceptance:**

## S12.1.4 — `.importlinter` enforces B-0001

**Status:** planned · **Module:** `python` · **Depends on:** S12.1.2

**Build:**

- **Goldens first.** Append the `dependencies-point-inward` contract from
  [design.md](design.md#the-tiers-and-their-contracts) to
  `golden/python-tool/.importlinter` and `golden/python-app/.importlinter`,
  with one blank line after the existing last line. `golden_tool` is the
  package in the first, and `golden_app` in the second. Do not change

- **Template.** `modules/python/templates/importlinter.j2` renders that contract

  not a workspace in this template, so they get the contract too, with the API
  member's package. Use no new context key.

**Tests:** extend `tests/modules/python/test_artifacts.py`, with names
`test_s12_1_4_…`. Property 4, and
`test_s4_3_1_3_lint_imports_passes_on_the_rendered_importlinter`, must pass
unchanged. Add these tests. Each one builds a package `demo` under
`tmp_path / "src"`, renders `.importlinter` for a `python-app` config named
`demo`, and runs `importlinter.cli.lint_imports` exactly as the existing
`lint_imports` test does:

- **A fresh package passes.** `demo/__init__.py` and `demo/commands.py` only.
- **`services` importing `adapters` fails.** `demo/services/__init__.py`, and
  `demo/services/use.py` containing `import demo.adapters.store`, with
  `demo/adapters/__init__.py` and `demo/adapters/store.py`.
- **`domain` importing an entry point fails.** `demo/domain/__init__.py`, and
  `demo/domain/rule.py` containing `import demo.commands`, with
  `demo/commands.py`.

  `import demo.domain.rule`, and `demo/domain/rule.py` empty.
- **`python-lib` renders no `layers` contract.** Its rendered `.importlinter`

- **The web archetypes render it for their API member.** For a `python-web-api`

**Acceptance:**
