`kiln new` stops seeding the `AGENTS.md` and `CLAUDE.md` bodies. The
docs-pointer check reads only kiln's block. The standard and the reference
describe instruction files as owner files that tools add blocks to.

## S20.1.1 — `kiln new` seeds no instruction-file body

**State:** New

**Acceptance:**

- `modules/instructions/scaffold.py` scaffolds `README.md` only. `BODIES` drops
  `CLAUDE.md` and `AGENTS.md`, and the templates `AGENTS.md.j2` and
  `CLAUDE.md.j2` are deleted.
- After `kiln new`, `AGENTS.md` holds only the `rn-forge kiln` block, written by
  the first apply, and `CLAUDE.md` does not exist.
- `metadata.scaffolded` no longer lists `CLAUDE.md`.
- A repository whose `AGENTS.md` and `CLAUDE.md` bodies came from the old seeds
  is unchanged by `kiln apply`. Only kiln's block is reconciled.
- The scaffold goldens (`tests/fixtures/scaffold/*`) and the `kiln new` tests in
  `tests/commands/test_new_packages.py` are updated to the new tree.

## S20.1.2 — The docs-pointer check reads only kiln's block

**State:** Closed (2026-11-23)

**Acceptance:**

- `_check_instruction_pointer` in `modules/docs/structure.py` looks for the
  links to `docs/_structure.md` and `docs/index.md` inside the `rn-forge kiln`
  block of `AGENTS.md`, and nowhere else.
- `POLICY.instruction_files` in `modules/docs/policy.py` is `("AGENTS.md",)`.
  The `@path` import is no longer accepted as a pointer.
- With the block intact, deleting or rewriting any body text in `AGENTS.md` or
  `CLAUDE.md` produces no finding. A missing block reports
  `missing-docs-pointer`, as today. Tests cover both cases.
- kiln ignores other tools' blocks, such as agentkit's or Nx's, in both files. A
  test with an agentkit block and an Nx block present stays clean.
- `DocsPolicy.instruction_block` (a `ManagedBlock`, `None` reads the whole file)
  names the block; the docs module defines its own `rn-forge kiln` fence
  rather than importing the instructions module's.

Outcome: every present instruction file is checked on its own; the carrier and
`@path` rules are gone.

## S20.1.3 — The standard and the reference say tools add blocks only

**State:** New

**Acceptance:**

- `modules/instructions/templates/standard.md.j2` and
  `docs/reference/standard-repo.md` describe `AGENTS.md` and `CLAUDE.md` as
  owner files. kiln adds one block to `AGENTS.md`, agentkit adds its own
  blocks, and neither owns the body.
- The file table in `docs/reference/standard-repo.md` describes `CLAUDE.md` as
  not written by kiln, and `AGENTS.md` as a block file with no seeded body.
- The ownership text no longer lists `CLAUDE.md` or the `AGENTS.md` body among
  scaffolded files.
- `.rn-forge/kiln/standard.md` in kiln itself is regenerated by
  `task kiln:apply`, and `task lint KILN_DOCTOR_FULL=1` passes.
