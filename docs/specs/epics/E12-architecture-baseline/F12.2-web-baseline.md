Design: [design.md](design.md)

ARCH-0004 and ARCH-0005 join the catalogue, the FastAPI cells' `.importlinter`
gains the `framework-stays-at-the-edge` contract, and the FastAPI starter moves
into the tiers its records name. The web cells have no golden, so these stories
change templates only, and the render matrix
([F4.4](../E4-generator/F4.4-render-matrix.md)) is where the owner reviews their
output.

*Rewritten 2026-11-19 (owner decisions).* ARCH-0004's error rule follows
`rn-forge-web`'s `ProblemRegistry`, the starter is brought into line (S12.2.4),
and ARCH-0005 waits for the client task it names (S12.2.5,
[F5.5](../E5-web-archetypes/F5.5-web-app-api-client.md)). The earlier text is in
git history.

**Build a story by the [board's procedure](../../index.md#building-a-story).**
The texts to copy are in [design.md](design.md); copy them exactly. Every build
story ends with `task self:golden:compare BASE=HEAD`, whose diff the owner
reviews.

## S12.2.4 — The FastAPI starter follows ARCH-0002 and ARCH-0004

**State:** Closed (2026-11-20) · **Module:** `python` · **Depends on:** S12.2.1

**Why.** The FastAPI starter puts its router and its error at the package root,
and its error subclasses `Exception`
([the starter table](design.md#the-starter-follows-the-records)). A new
repository would start out departing from its own records.

**Build — tests first**, in `tests/modules/python/test_starter.py`:

- `_api_paths` expects `app.py`, `http/__init__.py`, `http/items.py`,
  `domain/__init__.py` and `domain/errors.py` under `src/demo_api/`, and
  `tests/test_app.py`. `test_fastapi_starter_artifacts` expects
  `from demo_api.http.items import router` and
  `from demo_api.domain.errors import ItemNotFound` in `app.py`.
- `test_web_api_starter_renders_only_into_a_fresh_package` passes the new names
  to `seedable`, and expects six artifacts.
- `test_the_fastapi_starter_keeps_kiln_s_contracts`: render the starter and
  `.importlinter` for a `python-web-api` config named `demo` into `tmp_path`,
  and `lint_imports` keeps every contract.
- `test_item_not_found_is_an_app_exception`: the rendered `domain/errors.py`
  defines `class ItemNotFound(AppException)`.

**Build:**

- `modules/python/starter.py`, `_API_SRC`: `app.py` (`fastapi/app.py.j2`),
  `http/__init__.py` (`fastapi/http_init.py.j2`), `http/items.py`
  (`fastapi/items.py.j2`), `domain/__init__.py` (`fastapi/domain_init.py.j2`)
  and `domain/errors.py` (`fastapi/errors.py.j2`). `routes.py` goes.

- `fastapi/routes.py.j2` is renamed `fastapi/items.py.j2`, and imports
  `ItemNotFound` from `{{ module }}.domain.errors`, which it raises as
  `ItemNotFound("No item {}", item_id, item_id=item_id)`.

- `fastapi/errors.py.j2`: `ItemNotFound` subclasses `AppException` from
  `rn_forge.commons`.

- The module docstrings, one line each:

    ```text
    http/items.py       The items resource: a paginated list and a lookup that fails as a problem.
    http/__init__.py    The HTTP edge: one router module per resource.
    domain/__init__.py  The types, rules and errors the product is about.
    domain/errors.py    The product's errors, mapped to problem responses in app.py.
    ```

- `fastapi/app.py.j2` imports from the new modules; nothing else in it changes.

- `fastapi/test_app.py.j2` does not change: the routes and the problem response
  are the same.

**Not in scope.** A repository already scaffolded keeps its seeded starter.
`api:dev` still serves `<api_module>.app:app`.

**Acceptance:**

- The tests pass, and `task validate` passes.
- Not scriptable, judged by the owner: a `kiln new` FastAPI cell from the render
  matrix passes `task setup && task validate`.
