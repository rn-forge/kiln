# S7.8.4 — Preview and apply share a plan

Brief for
[S7.8.4](../F7.8-existing-repos-take-the-pin-table.md#s784-preview-and-apply-share-a-plan),
at `871e2b1`.

## Goal

Prepare the managed changes once and use that plan for preview, execution and
upgrade. Keep ownership checks and required docs finalization inside the apply
recovery boundary.

## Settled

Settled by the reviewer on 2026-11-18. Line references are at `da03d22`.

- **The plan type.** Add a frozen dataclass `Prepared` to
  `src/rn_forge/kiln/modules/core/cycle.py` with these fields:

    - `store: StateStore[StateEntry]`
    - `plan: Plan`
    - `config: KilnConfig`
    - `candidate: bool`, which is true when `config` is not the committed config

    Export it.

- **`cycle.prepare`.** Signature:
  `prepare(root, *, config: KilnConfig | None = None, force=(), registry=None, home=None, provenance=None, starters=None) -> Prepared`.
  It replaces `_prepare` (line 134). With `config=None` it loads the
  committed config, as today. With a candidate, the `config_hash` metadata is
  the hash of the candidate as `catalog.render(config, header=CONFIG_HEADER)`
  would write it, so the hash matches what lands on disk.

- **`cycle.execute`.** Signature:
  `execute(root, prepared, *, dry_run=False, finalize: Callable[[], None] | None = None) -> ApplyResult`.

    - For a candidate, it first records the old `config.toml` bytes, or that the
      file is absent, then writes the candidate with `catalog.write`.
    - It runs `generation.apply` with `verify=finalize`.
    - On any exception it restores the old `config.toml` and re-raises. The engine
      restores the artifacts and `state.json` itself.
    - `dry_run` writes nothing, the candidate config included.

- **The old entry points stay as thin wrappers.**

    - `cycle.plan(...)` returns `prepare(...).plan`.
    - `cycle.apply(...)` is
      `execute(root, prepare(...), dry_run=..., finalize=verify)`. Keep its
      signature, so `new` and `generate package` keep their explicit `starters`.
    - Delete `cycle.preview` (line 307). Its callers use
      `prepare(root, config=candidate).plan.changes`, which applies apply's
      starter policy.

- **Callers.**

    - `commands/apply.py` prepares once, runs `_validate_force` on
      `prepared.plan`, and executes that same `prepared`.
    - `commands/config.py` `_config_reresolve` prepares with
      `config=resolution.config` and
      `provenance=resolution.provenance_metadata()`, previews from that plan, and
      with `--apply` executes it. It no longer calls `catalog.write` itself.
    - `commands/diff.py` uses `prepare`.

- **Docs finalization.** Add
  `finalizer(root: Path, config: KilnConfig) -> Callable[[], None] | None` to
  a new module, `src/rn_forge/kiln/commands/finalize.py`. It returns `None`
  unless `config.docs_profile == "mkdocs"`. Otherwise it returns a callable
  that does three things:

    1. Snapshots the bytes and existence of every file under `docs/`, plus
       `mkdocs.yml`.
    1. Runs `docs_generator.generate`, the same call `commands/new.py:120` makes.
    1. Runs the ownership checks that `output.fail_on_errors` runs, raising on an
       error. If anything inside it raises, it restores its snapshot before
       re-raising.

    `apply` and `config --apply` pass it as `finalize`.

    - **Ownership checks before `state.json` exists:** the checks read
      `state.json`, which the engine writes after `verify`. If they cannot see
      the candidate state at that point, run them against `prepared.store`'s
      pending entries. If the engine offers no way to read those, stop and
      report rather than changing `rn-forge-commons`.
    - **Where finalization does not run:** `new` and `generate package` keep their
      own finalization and pass no `finalize`.

- **What S7.8.2 needs exposed:** `prepared.plan.changes` (the artifact actions)
  and a `Prepared.write_paths()` method. It returns every repository-relative
  path `execute` can write: each change's path, `config.toml` for a candidate,
  `state.json`, and, under MkDocs, `docs/` and `mkdocs.yml`.

- **Test names** describe behaviour, `test_<subject>_<behaviour>`, and carry no
  spec ID.

## Current behaviour

- `commands/apply.py:33` plans to validate force paths, then calls
  `cycle.apply`, which plans again.
- `modules/core/cycle.py:208` applies starter policy, but the separate preview
  at line 307 renders all artifacts directly.
- `commands/config.py:90` writes the candidate config before invoking apply.
- `commands/new.py:118` finalizes derived docs after rendering. Existing-repo
  apply does not, so enabling MkDocs can leave an incomplete first render.

## Change

- Consolidate artifact preparation in `modules/core/cycle.py`. Reuse the
  existing engine for classification and writes. Allow the committed config or
  an already validated candidate. Keep force, provenance and starter policy in
  the shared preparation and execution path.
- Route ordinary apply, diff and config preview through that preparation. Pass a
  prepared plan into execution so the classification checked and displayed is
  the one used. Keep explicit starter creation for `new` and package
  generation. Preserve their sequencing for package docs.
- For config update and upgrade, include the pending config write with the
  apply, so a refused or failed apply leaves the previous config and state.
- Use the existing derived-docs implementation to initialize the required
  regions when apply enables MkDocs. Include those writes and the ownership
  checks in the apply recovery boundary. Account for the candidate state in
  post-write checks. Preserve the read-only behavior of ordinary doctor.
- Expose the prepared artifact changes and all paths the apply can write to the
  upgrade coordinator. Keep pin resolution, range edits, clean Git checks and
  the full task gate in S7.8.2.

## Tests first

- Through the normal commands, compare config preview, dry-run and the apply
  result for the same candidate, including a missing starter. Assert the
  preview and dry-run leave the tree byte-for-byte unchanged.
- Verify ordinary apply reuses its plan after checking force paths. Cover drift
  refusal and an explicitly forced path.
- Enable MkDocs on an existing repo, apply once, and run doctor. Inject a docs
  finalization or ownership-check failure and assert restoration of the
  candidate config, managed files, derived docs and state.
- Keep existing coverage for new and package starter behavior.
