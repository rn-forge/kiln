After `kiln init`, an adopted repository can run its own gate: `config.toml`
passes kiln's TOML lint, the tools the rendered tasks run are in its dependency
groups (kiln excepted, with a warning), and the adopt prompt and a runbook say
what is left to the adopter, `task format` included. Today `init` writes a
`config.toml` that kiln's own lint rejects, leaves out `taplo`, and nothing in
kiln's docs says how a developer is meant to use the prompt.

## Context

Found 2026-10-19 by the owner. `kiln init --force` was run from the kiln working
tree (`feature/v1`, after `1c6cfe2` S4.10.1) on pykit `feature/kiln-adoption`
(`69d79bf`), as `python-lib`, with nine packages and `import_contracts = "own"`.
Every file `init` rendered matches the config. The run exited 1 with 27
findings, all in pykit's `main.yml`: 20 `ci-entrypoint` (direct `uv` steps) and
7 jobs with no `permissions:` key. That is expected, because `main.yml` retires
in pykit's cutover.

Repository-owned findings from the same run, for pykit's own specs (F16.3), not
kiln's:

- `docs/_areas.yml` has no `nav: include` area, so the derived nav dropped every
  package site, and `specs` is not `nav: work`. Two shipped pages link to
  `_structure.md`. The adopt prompt's §6 and §7 cover all of this.
- `uv run` gates remain in `CLAUDE.md`, `README.md` and
  `docs/guides/development.md` (prompt §5).

**Owner decisions, 2026-10-19:**

- `init` adds each task tool the repository lacks to its dependency groups,
  rather than warning about it. `apply` still never edits `pyproject.toml`.
- `init` runs neither `task setup` nor `task format`. Reformatting the
  repository's own files is a separate commit made by the adopter, so `init`'s
  commit holds only kiln's change and the history stays readable. S5.3.6's
  rule that kiln does not reformat repository-owned files stands.
- `rn-forge-kiln` is the exception, and keeps a warning. Its requirement depends
  on the repository: a git tag pin, an editable checkout before kiln is
  released, and, in a workspace that publishes the libraries kiln depends on,
  an `override-dependencies` entry written before it (ADR-0006, adopt prompt
  §8). If `init` guessed wrong, `task setup` would fail.
- `kiln new` does not run `task format` either. Its output already passes
  `task lint` with no prior format: S4.10.1's acceptance and
  `task self:golden:validate` on every cell prove it.
- `doctor` stays off repository-owned dependency content (S4.6.5). No doctor
  check is added.

## S6.6.1 — `init` and `config-update` write a taplo-clean `config.toml`

`tests/modules/python/test_scaffold.py:49`:

1. `test_s6_6_1_1_written_config_is_taplo_clean`. Copy `lib_fresh`'s
   `.rn-forge/kiln/config.toml` into `tmp_path / "src"`, and replace its
   `[archetype.python-lib] packages` with nine paths
   `packages/rn-forge-package-<n>`, for `n` 1 to 9. Load it with
   `KilnConfig.load`, then call
   `commands._write_config(tmp_path / "out", config)`. Copy `lib_fresh`'s
   `.taplo.toml` into `tmp_path / "out"`. Run
   `[str(TAPLO), "fmt", "--check", "--diff", ".rn-forge/kiln/config.toml"]`
   with `cwd=tmp_path / "out"`, and assert `returncode == 0`, with
   `stdout + stderr` in the assertion message.
1. `test_s6_6_1_2_init_writes_packages_one_per_line`. On `lib_repo`, run
   `commands.init` as `test_s6_1_5_1_…` does. The written `config.toml`'s text
   contains
   `packages = [\n    "packages/lib-alpha",\n    "packages/lib-beta",\n]`.

**Build:**

- `src/rn_forge/kiln/commands.py`, `_write_config`: parse the text it currently
  builds (`DocumentUtils.dumps(config.to_document(), ConfigFormat.TOML)`) with
  `tomlkit.parse`. Call `.multiline(True)` on every non-empty array, at any
  depth, and write `_CONFIG_HEADER + tomlkit.dumps(document)`. Put the walk in
  a new private function, `_multiline_arrays(container)`, that recurses into
  tables. Leave empty arrays (`includes = []`) inline. tomlkit's multi-line
  form (4-space indent, trailing comma) is the one S4.10.1's `.taplo.toml`
  accepts, as `python/scaffold.py`'s `_multiline_lists` already relies on.
- `new`, `init` and `config-update` all write through `_write_config`
  (`commands.py:280`, `:417`, `:1106`), so nothing else changes.
- Do not change `_report`'s console output.

**Acceptance:**

- Both tests pass, and `task validate` passes.
- `task self:golden:render`, then `task self:golden:compare BASE=HEAD~1`: the
  only file that changes is `.rn-forge/kiln/config.toml`, and only in cells

- Re-running `init` on pykit leaves `.rn-forge/kiln/config.toml` taplo-clean.

## S6.6.2 — `init` adds the task tools the repository lacks

**State:** New · **Depends on:** S6.6.1

**Build — tests first.** In `tests/modules/python/test_scaffold.py`,
parametrized over the `_TAPLO_CELLS` archetypes:

1. `test_s6_6_2_1_missing_task_tools`. Scaffold the cell:
   `missing_task_tools(root, config) == []`. Remove `ruff` from the dev group,
   and the result is `["ruff"]`. Remove `mdformat` from every group, and it is
   named too. With the docs profile set to `none`, `mdformat` is not named.
   The result never names `rn-forge-kiln`.
1. `test_s6_6_2_2_add_task_tools_appends_bare_names`. Scaffold, remove `taplo`
   from `dev` and `mdformat` from `docs`, then call
   `add_task_tools(root, config)`. It returns `["taplo", "mdformat"]`. `dev`
   ends with `"taplo"` and `docs` ends with `"mdformat"`. Every other entry
   and comment in `pyproject.toml` is unchanged, and the file passes
   `taplo fmt --check` as in `test_s4_10_1_5_…`.
1. `test_s6_6_2_3_add_task_tools_creates_a_missing_group`. Delete the
   `[dependency-groups]` table. `add_task_tools` creates `dev` with every
   `TASK_TOOLS` entry except `rn-forge-kiln`, and `docs` with `mdformat`.
1. `test_s6_6_2_4_add_task_tools_is_idempotent`. A second call returns `[]` and
   leaves the file byte-identical.

In `tests/test_init.py`:

1. `test_s6_6_2_5_init_adds_missing_tools_and_warns_only_for_kiln`. On
   `lib_repo`, delete `taplo` and the `rn-forge-kiln` entry from the root
   `pyproject.toml`'s `dev` group, `_commit(lib_repo)`, then run
   `commands.init` as `test_s6_1_5_1_…` does. `dev` contains `taplo` again.
   `capsys.readouterr().err` contains `init.kiln-dev-dependency-missing` and
   does not contain `taplo`. `rn-forge-kiln` is not added.
1. `test_s6_6_2_6_nothing_added_when_every_tool_is_present`. The same, with
   `pyproject.toml` left as `new` wrote it: the file is byte-identical after
   `init`, and `err` contains no `init.kiln-dev-dependency-missing`.

**Build:**

- `src/rn_forge/kiln/modules/python/scaffold.py`:

    - A public tuple `TASK_TOOLS`, with the distributions the rendered
      `tasks/quality.yml` runs:
      `("import-linter", "pyright", "pytest", "pytest-cov", "ruff", "taplo", "rn-forge-kiln")`.
      Its docstring says these are the tools `task lint`, `task typecheck` and
      `task test` invoke. `pyyaml` is in `_DEV_GROUP` but no task runs it, so it
      is not listed.
    - A public tuple `DOCS_TASK_TOOLS = ("mdformat",)`, which counts only when
      `config.docs_profile != "none"`. It belongs in the `docs` group, which
      `quality:lint:markdown` runs with `--group docs`.
    - A public function
      `missing_task_tools(root: Path, config: KilnConfig) -> list[str]`. It
      reads the root `pyproject.toml` and collects the normalized names
      (`rn_forge_deps.distribution`) of every string entry in every
      `[dependency-groups]` group, skipping `{ include-group = … }` tables. It
      returns, in tuple order, each tool from `TASK_TOOLS` (then
      `DOCS_TASK_TOOLS`, where they count) that is not among those names,
      leaving out `rn-forge-kiln`. A missing `[dependency-groups]` table means
      every tool is missing.
    - A public function `has_kiln(root: Path) -> bool`: whether any group names
      `rn-forge-kiln`, read the same way.
    - A public function
      `add_task_tools(root: Path, config: KilnConfig) -> list[str]`. It appends
      each name `missing_task_tools` returns, bare and without a version, as
      `_DEV_GROUP` writes them: a `DOCS_TASK_TOOLS` name to the `docs` group,
      every other to `dev`. It creates either group when absent. It edits
      through `DocumentUtils.read_document` and `DocumentUtils.write_document`
      so comments survive, then calls `_multiline_lists`, and returns the names
      it added. With nothing missing it does not write the file.
    - Add all five names to `__all__`.

- `src/rn_forge/kiln/commands.py`, `init`: right after the
  `generate.generate(...)` branch, when `"python"` is in
  `archetypes.for_config(resolved).modules`:

    - Call `add_task_tools(root, resolved)`. For a non-empty result,
      `console.info("added {} to pyproject.toml's dependency groups", ", ".join(added))`.

    - When `has_kiln(root)` is false, print:

        ```python
        console.warning(
            "init.kiln-dev-dependency-missing: `task lint` runs kiln, and no "
            "dependency group names rn-forge-kiln — add it pinned "
            "(kiln prompt --name adopt, section 8)"
        )
        ```

    It is a warning, not a `Finding`. It does not change the exit status or the
    JSON payload.

- Do not change `apply`. Do not add a doctor check.

**Acceptance:**

- The six tests pass, and `task validate` passes.
- `task self:golden:compare BASE=HEAD~1` shows no change. `new` already writes
  every tool, so `add_task_tools` adds nothing in any cell.
- Re-running `init` on pykit adds `taplo` to `dev`, and warns
  `init.kiln-dev-dependency-missing`.

1. `test_s6_6_3_2_adopt_says_where_quality_findings_appear`. Section 6's

**Build — `src/rn_forge/kiln/prompts/adopt.md`.** Edit only these places:

- The opening paragraph's list of what `init` settles: add "the task tools the
  repository lacks are added to its dependency groups".
- §2, the `--config` bullet. Append: "`init` records the file as `[source]`, and
  `kiln config-update` re-reads it from there. For a one-off file kept outside
  the repository or git-ignored, delete the `[source]` table from
  `.rn-forge/kiln/config.toml` after `init` (run 3: pykit's
  `dist/pykit-kiln.toml`, which `task clean` also deletes)."
- §4, after "Read them in section 9; do not re-run `init`." Add: "Commit
  `init`'s change on its own. Then run `task setup` and `task format`, and
  commit the formatting as a separate commit: `init` formats nothing, and a
  repository that predates kiln's TOML and Markdown style fails
  `quality:lint:toml` until then (run 3: pykit's member `pyproject.toml` files
  and its seeded `.mdformat.toml`)."
- §6, the `_areas.yml` bullet. Change "`docs.packages-area-missing` reports it"
  to "`docs.packages-area-missing` reports it in `task lint`
  (`kiln doctor --only docs-structure`), not in `init`'s closing check".
- §8. Replace the first sentence with: "`task validate` runs kiln's checks, so
  kiln must be a dev dependency of the repository, and it is the one tool
  `init` does not add: it warns `init.kiln-dev-dependency-missing` instead,
  because the requirement depends on the repository." After the override
  paragraph, add: "The override is not temporary. A workspace that publishes
  the libraries kiln depends on needs it for as long as kiln is a dev
  dependency, whether kiln is editable or pinned to a tag."
- §9, after the code block, add the sentence: "`init`'s closing check, like a
  plain `kiln doctor`, runs only the ownership checks; `task lint` also runs
  `rn-forge-deps`, `docs-structure` and `docs-site`, so read its findings
  too."

**Build — `docs/runbooks/adopting-a-repo.md`, new.** Copy the shape of
`creating-a-repo.md`. Title `# Adopting an existing repo`. It says, in this
order:

1. When to adopt in place and when to rebuild: one line, pointing at the
   prompt's section 1.
1. A prompt is a procedure for a coding agent. kiln ships no skills (D30), so
   `kiln prompt --name adopt` prints the procedure and nothing else. Hand it
   to the agent working in the repository, either by asking the agent to run
   that command and follow it, or by piping it in, for example
   `kiln prompt --name adopt | claude`. `kiln prompt` with no name lists the
   prompts.
1. What the developer decides, which the agent must ask about: adding kiln as a
   dev dependency (and the override), and every judgement the prompt marks as
   the owner's.
1. The commits: `init`'s change, then the `task format` commit, then the
   reconciliation the prompt walks through.
1. Done when `task validate` and `kiln doctor . --full` exit 0.

Add the page to `docs/runbooks/index.md` beside `creating-a-repo.md`. Run
`task docs:generate`.

- `src/rn_forge/kiln/modules/python/checks/rn_forge_deps.py`, module docstring.
