A runbook, `docs/runbooks/cutover.md`, for the one-time move of a repository
with a pre-kiln lineage onto kiln. It holds the steps and the format of the
absorb/extend/drop table. Each repository's verdict table lives in its own specs
and links to the runbook. pykit and ngkit are the only users. A repository too
far from its archetype's shape for `kiln init` takes the rebuild route instead
([F16.5](F16.5-rebuild-and-port.md)), a section of the same runbook.

## S16.3.1 — The runbook exists

**State:** Closed (2026-11-04) · **Depends on:** S16.1.1, S16.1.3

**Build — tests first,** in `tests/test_docs_runbooks.py` (new):

1. `test_s16_3_1_1_runbook_steps`: `docs/runbooks/cutover.md` exists, opens with
   `# Cutting a repository over to kiln`, and has these seven numbered steps
   in order, matched by their first words: `Branch`, `Run kiln init`,
   `Read the diff file by file`, `Record a verdict`,
   `Land the absorb stories`, `Bump [kiln] ref and run kiln apply`, `Merge`.
1. `test_s16_3_1_2_table_format`: it contains the table header
   `| File | What is lost | Verdict | Where it went |`.
1. `test_s16_3_1_3_listed`: `docs/runbooks/index.md` links it.
1. `test_s16_3_1_4_sequence_runs`: the runbook's command sequence, on a pre-kiln
   fixture repository (a `git` repository with a hand-written `Taskfile.yml`,
   `mkdocs.yml` and CI workflow): `commands.init(..., yes=True)` succeeds; the
   result is committed; the config's `[kiln] ref` is changed;
   `commands.apply(...)` succeeds and leaves `git status` clean apart from
   `config.toml` and `state.json`; and a second `commands.init(..., yes=True)`
   raises `AppException` containing "use `kiln apply`", which is why step 6
   does not rerun `init`.

**Build:** `docs/runbooks/cutover.md`, in the shape of `creating-a-repo.md`
(ordered steps; decision points called out). Content, in order:

1. **Branch.** From the repository's default branch, with a clean worktree.
1. **Run kiln init.** `kiln init --archetype <archetype> --docs mkdocs --yes`
   with `kiln` run from the `[kiln] ref` the cutover targets. It overwrites
   kiln-shaped files and backs each up under `.rn-forge/kiln/backups/`; it
   runs `task format` and `task docs:generate`.
1. **Read the diff file by file.** `git diff` and `git status`; every file
   `init` deleted or replaced is a row.
1. **Record a verdict** for each behaviour the repository loses, in a table in
   the repository's own spec with the header above: **absorb** (a kiln story,
   so every repository gets it), **extend** (keep it through an extension
   point: `[ci.checks]`, `[[ci.jobs]]`, `[ci.hooks]`, `_areas.yml`,
   `[docs.mkdocs]`) or **drop** (cite the decision). Known rows for pykit: its
   `[tool.workspace-ci.postgres]` and `[tool.workspace-ci.redis]` tables
   become `[tool.workspace-ci.integration.<name>]` service declarations
   ([S15.8.2](../E15-ci-standard/F15.8-one-workflow-contract.md)); kiln does
   not read the old keys.
1. **Land the absorb stories** in kiln.
1. **Bump `[kiln] ref` and run kiln apply.** `init` wrote `state.json` in step
   2, so the repository is under kiln and `init` refuses it; `kiln apply`, run
   from the new ref, takes the absorbed behaviour, and its diff is only that
   behaviour. To rehearse `init` itself again, start over from step 1 in a
   fresh worktree of the default branch.
1. **Merge** when no absorb row is open. The cutover pull request deletes the
   old CI workflow in the same change that adds `ci.yml`: both share the
   concurrency group and a ruleset requires the context `ci-ok`, so a
   follow-up would leave two.

The runbook ends with a "Rebuild and port" section, written by
[S16.5.2](F16.5-rebuild-and-port.md#s1652-the-cutover-runbook-gains-the-rebuild-route),
for repositories `kiln init` cannot adopt; its diff tool for step 3 is
`kiln diff --from` (S16.5.1).

Add it to `docs/runbooks/index.md`. Run `task docs:generate`.

**Acceptance:**

- The four tests pass, and `task validate` passes.

**What the build settled that the story did not say:**

- `init` is described as F16.1 settled it: no `--force`, backups under
  `.rn-forge/kiln/backups/<stamp>/`, a dirty tree is refused, then
  `task setup`, `task format` and `task docs:generate` run. Step 2 names
  `task setup` too, which the story's wording left out.
- Test 4 departs from "leaves `git status` clean apart from `config.toml` and
  `state.json`": the pinned ref is rendered into `tasks/ci.yml`,
  `tasks/docs.yml` and `tasks/kiln.yml`, so a ref bump changes those three as
  well. The test allows exactly those five paths. The runbook's "its diff is
  only that behaviour" is read as: only the absorbed behaviour and the ref.
- Test 4 commits after `apply` before the second `init`, because the dirty-tree
  refusal (`init.dirty-tree`) comes before the "use `kiln apply`" one. It uses
  a recording `_run_task` double and a fixture built from the session
  `python-app` render with kiln's state and blocks removed, then
  `Taskfile.yml`, `mkdocs.yml` and `ci.yml` replaced by hand-written files.
  The helpers are copied into `tests/test_docs_runbooks.py` because test
  modules are not importable from each other.
- The runbook has no "Rebuild and port" heading: S16.5.2 adds the section whole.
  It links F16.5 from its opening paragraph instead.
- The S15.8.2 link points at the story's heading anchor in the F15.8 page, which
  exists.
- The steps are numbered `1.` throughout (mdformat renumbers a list that way);
  the test checks their count and order. The verdict table sits inside step 4
  as a header-only example; test 1 reads the steps as `N. **Heading.**` lines,
  matching a heading with backticks stripped.
- `docs/runbooks/adopting-a-repo.md` now links the runbook; the shipped
  `adopt.md` prompt keeps the path as text.
