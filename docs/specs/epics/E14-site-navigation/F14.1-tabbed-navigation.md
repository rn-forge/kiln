Each docs area becomes a top tab with its own sidebar. An area's `index.md` is
the tab's landing page. The specs tab lists every epic in ranges of ten, with
each epic's features and design beneath it. A derived epic list page tabulates
every epic. The code lives in `rn_forge.kiln.modules.docs`, plus three
templates. It is then applied to kiln's own site.

**Build each story by the
[board's procedure](../../index.md#building-a-story).** Tests go in
`tests/modules/docs/test_docs.py` (nav), `tests/modules/docs/test_work.py`
(regions) and `tests/test_new.py` (what `kiln new` writes). Copy the shape of
the `test_s13_1_1_*` and `test_s13_2_2_*` tests.

## S14.1.1 — Area tabs, with the index as the tab's page

**State:** Closed (2026-10-14)

**Build:**

- `modules/docs/templates/mkdocs.yml.j2`, and kiln's own `mkdocs.yml`, which is
  seeded and repo-owned, so edit it by hand. Replace `theme.features` with
  this list, in this order:

    ```yaml
      # Each area is a tab with its own sidebar (kiln ADR-0013); an area's
      # index.md is the tab's page, so no area's pages stack on another's.
      features:
        - navigation.tabs
        - navigation.tabs.sticky
        - navigation.indexes
        - navigation.top
        - content.code.copy
        - search.suggest
        - search.highlight
    ```

    `navigation.sections` is removed.

- `modules/docs/nav.py`:

    - `_children_entries` returns `list[tuple[str | None, str]]`. The area's
      `index.md` comes first, with the title `None`. Every other page keeps its
      `page_title`. The literal `"Overview"` is deleted.

    - `_area_entry`, for `children`, builds each list item as the bare path when
      the title is `None`, and as `{title: rel}` otherwise. For a guides area
      holding `index.md` and `a.md`, the derived nav is:

        ```yaml
        - Guides:
          - guides/index.md
          - A: guides/a.md
        ```

    - `index-only` and `include` areas are unchanged.

    - Update the module docstring: index first, untitled, so that
      `navigation.indexes` makes it the section's page.

- In `tests/modules/docs/test_docs.py`, the existing assertion
  `"Overview: adr/index.md" in body` becomes a check for the bare index entry.
  Find and update every other test that expects `Overview:`.

- Run `task docs:generate` on kiln.

**Do not:** change `package/mkdocs.yml.j2`; add a plugin, a dependency or a
`theme.features` entry not listed; change `_areas.yml`.

**Acceptance:**

- `build_nav` emits every `children` area's `index.md` as the area's first item,
  with no title, and the string `Overview:` appears nowhere in its output.
- `kiln new … --archetype python-tool --docs mkdocs --yes` writes a `mkdocs.yml`
  whose features include `navigation.tabs` and `navigation.indexes`, and not
  `navigation.sections`. The new repository's `task validate`, including the
  strict docs build, passes.
- kiln's own `task docs:build` passes, and `kiln doctor --only docs-generate` is
  clean.

**What the build settled that the story did not say:**

- `NavEntry` is widened to `dict[str, "str | list[str | NavEntry]"]`, so a list
  item can be a bare path. This is what pyright strict needs for the untitled
  index.
- The tests are `test_s14_1_1_1_an_area_index_is_the_first_untitled_item` in
  `tests/modules/docs/test_docs.py` and
  `test_s14_1_1_2_new_writes_tabbed_navigation_features` in
  `tests/test_new.py`. The existing `Overview: adr/index.md` assertion became
  `"  - adr/index.md\n" in body`. No other test expected `Overview:`.
- The `theme.features` comment from the story is in both the template and kiln's
  own `mkdocs.yml`.
- A repository generated by `kiln new` runs the kiln it pins (`feature/v1` at
  the time of the build), so until the pin moves past this change its own
  `task validate` reports a stale nav. The acceptance was checked with the
  repository's kiln replaced by this tree (`uv pip install -e`,
  `UV_NO_SYNC=1`), after which `task validate` passed there. The generated
  `src/tool/product.py` also fails `ruff format --check` on a fresh
  repository; that file is untouched by this story.

## S14.1.2 — The epic list page

**State:** Closed (2026-10-14)

**Build:**

- `modules/docs/work.py`:

    - `EPICS_BLOCK = ManagedBlock("derived epics", comment=HTML_COMMENT)`.

    - `EPIC_RANGE = 10`.

    - `epic_range(number: int) -> tuple[int, int]` returns
      `(lo, lo + EPIC_RANGE - 1)`, where
      `lo = (number - 1) // EPIC_RANGE * EPIC_RANGE + 1`. Epic 4 gives `(1, 10)`,
      epic 10 gives `(1, 10)` and epic 13 gives `(11, 20)`.

    - `range_label(lo: int, hi: int) -> str` returns `f"E{lo}–E{hi}"`, with an en
      dash (U+2013).

    - `render_epics(work: Work) -> str` returns the region body. It emits only the
      ranges that hold at least one epic, in ascending order:

        ```markdown

        Jump to: [E1–E10](#e1e10) · [E11–E20](#e11e20)

        ## E1–E10

        | Epic | State | Features | Iterations |
        | -- | -- | -- | -- |
        | [E4 — The generator](E4-generator/index.md) | Active | 1 Active · 3 New · 5 Closed | release-1 |

        ## E11–E20

        …
        ```

        - Build every anchor with `markdown.slugify(label)`, never hard-coded.
        - Epic: a link to the epic's `index.md`, with the epic's H1 as text.
        - State: the epic's `State`, with ` (deferred)` appended when its `Tags`
          include `deferred`.
        - Features: the count of each state, in `_COUNT_ORDER`, joined by `·`, which
          is the board's format. For an epic with feature files, count those
          files' `State`s. For an epic without them, count `epic.rows`' states.
          When there are none, `—`.
        - Iterations: the distinct `Feature.iteration` values of the epic's
          features, sorted by release number and joined by `, `, or `—` when there
          are none.
        - With no epics at all, as in a fresh repository, the body is
          `"\nNo epics yet.\n"`.

- `modules/docs/generate.py`, `_work_regions`, after the board: when
  `docs/specs/epics/index.md` exists, check for a complete `EPICS_BLOCK`
  fence.

    - When the fence is missing or incomplete, append the error
      `docs.epics-markers` with the message
      `has no complete derived epics fence`.
    - When it is complete, call
      `region(path, EPICS_BLOCK, render_epics(work), "docs.epics-stale")`.
    - When the file does not exist, do nothing. A repository seeded before this
      story is not a finding.

- A new seed, `modules/docs/templates/docs/specs/epics/index.md.j2`. Add
  `"docs/specs/epics/index.md"` to `artifacts.SEEDS`, after
  `"docs/specs/ideas.md"`:

    ```markdown
    # Epics

    Every epic, by number, in ranges of ten. The tables below are derived from
    each epic and its features by `task docs:generate`; never edit inside the
    fence. What ships when is on [the board](../index.md).

    <!-- BEGIN derived epics -->
    <!-- END derived epics -->
    ```

    `kiln new` leaves the region current, as it already does for the board.

- `templates/docs/specs/index.md.j2`, and kiln's own `docs/specs/index.md`:
  after the ideas sentence under the board fence, add this line:

    ```markdown
    Every epic, by number, is on [the epic list](epics/index.md).
    ```

- `templates/docs/specs/_structure.md.j2`:

    - "The board" names the epic list page as a derived region too.
    - "Belongs here" gains `` `epics/index.md`, the derived epic list ``.

- `templates/docs/_structure.md.j2`: the `docs-generate` paragraph under
  "Checks" lists "the nav, the spec board, the epic list and each release's
  Scope table".

- In kiln's own tree, create `docs/specs/epics/index.md` from the seed. Then
  re-render the managed `_structure.md` files as `README.md` says for
  kiln-owned files, and run `task docs:generate`.

**Do not:** add the epic list to the board region; link epics from any other
page; add a config key for the range size.

**Acceptance:**

- `render_epics` puts E1–E10 and E11–E20 under their own headings. A tree with
  only E3 emits one range, and its jump line has one link.
- The `Features` cell counts feature-file states for an epic with files, and row
  states for one without. A deferred epic's state reads `New (deferred)`.
- A seeded tree whose `epics/index.md` lacks the fence reports
  `docs.epics-markers`. A tree with no `epics/index.md` reports nothing new.
- After `task docs:generate`, `kiln doctor --only docs-generate` and
  `kiln doctor --only docs-structure` are clean on kiln. The jump-line anchors
  resolve.
- `kiln new … --docs mkdocs --yes` writes `docs/specs/epics/index.md`, and its
  `kiln doctor --only docs-generate` is clean.

**What the build settled that the story did not say:**

- **The empty body has a second newline.** `render_epics` of a tree with no
  epics returns `"\nNo epics yet.\n\n"`, not the story's
  `"\nNo epics yet.\n"`. With one newline, `mdformat --check` fails on a
  freshly generated repository's `docs/specs/epics/index.md`, because it wants
  a blank line before the END comment. The seed carries the same body, so
  `kiln new` leaves the region current.
- **The seed holds the rendered empty body between its fence markers**, as the
  board seed does, rather than an empty fence. An empty fence would be stale
  as soon as it was created.
- `work.py` imports `slugify` from `modules/docs/markdown.py` for the jump-line
  anchors.
- `.rn-forge/kiln/state.json`: the hashes of `docs/_structure.md` and
  `docs/specs/_structure.md` are re-seeded, and `docs/specs/epics/index.md` is
  added as a seeded entry. The two `_structure.md` files were re-rendered from
  the templates with `kiln_version` `golden`, so only the changed lines
  differ.
- Tests: `test_s14_1_2_epic_range_groups_by_tens`, `test_s14_1_2_1_*` (ranges,
  one range), `test_s14_1_2_2_*` (counts, deferred),
  `test_s14_1_2_iterations_are_distinct_and_sorted_by_release`,
  `test_s14_1_2_no_epics_says_so` and
  `test_s14_1_2_seeded_epic_list_is_current` in `test_work.py`;
  `test_s14_1_2_3_*` and `test_s14_1_2_4_*` in `checks/test_derived.py`;
  `test_s14_1_2_5_*` in `test_new.py`.
- The new repository's own `task validate` runs the kiln its `pyproject.toml`
  pins, so it reports a stale nav and epic list until that pin moves past this
  change. It was checked with this tree installed editable
  (`uv pip install -e`, `UV_NO_SYNC=1`), after `ruff format src` for the known
  `product.py` defect, and passed.

## S14.1.3 — The specs tab lists the epics in ranges

**State:** Closed (2026-10-14) · **Depends on:** S14.1.1, S14.1.2

**Build:**

- `modules/docs/areas.py`: `NAV_VALUES` gains `"work"`. The `Area.nav` docstring
  says `"work"` lists the area's index, its epic list, its epics in ranges of
  ten with each epic's pages beneath it, and then the area's other pages.

- `modules/docs/nav.py`: `_area_entry`, for `nav == "work"`, returns
  `{area.title: items}`. `items` holds, in order:

    1. `"<key>/index.md"`, bare.
    1. `{page_title(epics/index.md): "<key>/epics/index.md"}`, when that page
       exists.
    1. One `{range_label(lo, hi): [...]}` per range that holds an epic, in
       ascending order, using `work.epic_range` and `work.range_label`. Inside a
       range, one entry per epic directory `<key>/epics/E<n>-*/`, by `n`:
        - When the directory holds only `index.md`, the entry is
          `{page_title(index): rel}`.
        - Otherwise it is `{page_title(index): [rel_of_index, …children]}`, with
          the index bare and first. The children are the feature files
          (`F<n>.<m>-*.md`) by numeric ID, then every other `*.md` in the
          directory except `index.md` and `_*.md`, by filename, each as
          `{page_title(page): rel}`.
    1. Every other `*.md` directly under `docs/<key>/`, except `index.md` and
       `_*.md`, by filename, each as `{page_title(page): rel}`. In kiln, that is
       `ideas.md`.

    For kiln, the start of the specs entry reads:

    ```yaml
    - Specs:
      - specs/index.md
      - Epics: specs/epics/index.md
      - E1–E10:
        - E1 — <its H1>: specs/epics/E1-canon-and-golden-repos/index.md
        - E3 — <its H1>:
          - specs/epics/E3-realign-goldens-and-canon/index.md
          - F3.1 — <its H1>: specs/epics/E3-realign-goldens-and-canon/F3.1-goldens-on-part-e-api.md
    ```

- `templates/docs/_areas.yml.j2`: `specs` gets `nav: work`. Its comment lists
  `work` among the values. In kiln's own `docs/_areas.yml`, which is seeded
  and repo-owned, change `specs` to `nav: work` by hand. Run
  `task docs:generate`.

- `templates/docs/specs/_structure.md.j2`: the sentence on how specs pages are
  reached says the specs tab lists every epic in ranges of ten, with its
  features and design.

**Do not:** apply `work` to any area but `specs`; nest ranges; list a story;
read `work.load_work` from `nav.py`, since a glob is enough and the nav needs no
metadata.

**Acceptance:**

- `build_nav` on a tree with E1, E3 (holding F3.1 and `design.md`) and E12
  emits, in order: the bare index, `Epics`, `E1–E10` (holding E1 as a single
  page, and E3 as a section with its index, then F3.1, then design), `E11–E20`
  (holding E12), and then `ideas.md`.
- An area with `nav: work` and no `epics/` directory emits only its index and
  root pages.
- `load_areas` accepts `nav: work`, and rejects any other unknown value as it
  does today.
- On kiln, after `task docs:generate`, `mkdocs.yml` lists every epic and feature
  page, and `task docs:build` passes under `strict: true`.

**What the build settled that the story did not say:**

- **No sentence to edit in `specs/_structure.md`.** The template had no sentence
  on how specs pages are reached, so the build added the statement to the
  "Belongs here" bullet for `epics/index.md`: "The specs tab lists every epic
  in ranges of ten, with its features and design." Both the template and
  kiln's rendered `docs/specs/_structure.md` carry it, and the `_structure.md`
  hash in `.rn-forge/kiln/state.json` is re-seeded.
- `_areas.yml.j2` has no list of `nav` values in its comment, so a short
  paragraph naming the four values (`children`, `index-only`, `include`,
  `work`) was added to it. kiln's own `docs/_areas.yml` is changed only on the
  `specs` line.
- An epic directory counts only when it holds an `index.md`. `nav.py` imports
  `epic_range` and `range_label` from `work.py` and reads no metadata.
- Tests: `test_s14_1_3_1_work_area_lists_epics_in_ranges` and
  `test_s14_1_3_2_a_work_area_without_epics_lists_index_and_root_pages` in
  `TestNav`, and `test_s14_1_3_3_a_work_area_loads` in `TestAreas`. The
  existing `test_unknown_nav_value_raises` covers the rejection of any other
  value.
- The new repository's `task validate` was checked with this tree installed
  editable, as for S14.1.1 and S14.1.2.
