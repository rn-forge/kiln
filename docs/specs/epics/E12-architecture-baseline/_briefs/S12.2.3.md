# S12.2.3 — `.importlinter` enforces ARCH-0004's framework boundary

Brief for
[S12.2.3](../F12.2-web-baseline.md#s1223-importlinter-enforces-arch-0004s-framework-boundary).

## Goal

A FastAPI cell's `.importlinter` gains the `framework-stays-at-the-edge`
contract, which forbids FastAPI and Starlette in `<package>.domain.**` and
`<package>.services.**`.

## Settled

- S12.2.1 closed 2026-11-20: the contract text in
  [design.md](../design.md#the-tiers-and-their-contracts) ("**FastAPI**") is
  approved. Copy it exactly, with `{{ package }}` for `demo_api`.
- It renders inside kiln's block when `framework_edge` is true and
  `own_contracts` is false, after `dependencies-point-inward`, with one blank
  line between them.
- The known gap (an import in `domain/__init__.py` passes) is by design and not
  tested.
- `frameworks-come-from-rn-forge`'s forbidden list does not change.

## Current behaviour

- `src/rn_forge/kiln/modules/python/artifacts.py:_importlinter` (line 53) builds
  the context: `kiln_version`, `workspace`, `own_contracts`, `members_block`,
  `forbidden_block`, and `package` when not a workspace. There is no
  `framework_edge`.
- `src/rn_forge/kiln/modules/python/templates/importlinter.j2` ends with the
  `dependencies-point-inward` contract inside `{% else %}` (not workspace) of
  `{% if own_contracts %}`. Its indented lines (`    {{ package }}`, the
  `layers` lines) are literal in the template, so four-space indentation
  inside the template survives; check the rendered output, and pre-join the
  two `source_modules` lines in `_importlinter` (as `members_block` is) only
  if whitespace control strips it.
- `tests/modules/python/test_artifacts.py`: `_web_root` (line 123) and
  `test_lint_imports_passes_on_the_rendered_importlinter` (line 75, calls
  `importlinter_cli.lint_imports(config_filename=...)`) and the helper near
  line 374 are the shape to copy. `lint_imports` returns a non-zero exit code
  when a contract is broken.
- Before the change: the "breaks" tests fail because `lint_imports` returns 0
  (the contract is absent); the "keeps" tests already pass and must keep
  passing; `test_only_fastapi_cells_carry_the_framework_contract` fails on its
  presence assertion for the FastAPI config.

## Tests first

In `tests/modules/python/test_artifacts.py`, named exactly as the story names
them. Each builds `demo_api` under `tmp_path / "src"`, renders `.importlinter`
for a `python-web-api` config named `demo` with `backend = "fastapi"`, and runs
`lint_imports`:

1. `test_a_fresh_api_package_keeps_the_framework_contract`:
   `demo_api/__init__.py` and `demo_api/app.py` only → exit 0.
1. `test_domain_importing_fastapi_breaks_the_framework_contract`:
   `demo_api/domain/__init__.py` (empty) and `demo_api/domain/rule.py` with
   `import fastapi` → non-zero.
1. `test_services_importing_starlette_breaks_the_framework_contract`:
   `demo_api/services/__init__.py` (empty) and `demo_api/services/use.py` with
   `import starlette` → non-zero.
1. `test_http_importing_fastapi_keeps_the_framework_contract`:
   `demo_api/http/__init__.py` (empty) and `demo_api/http/items.py` with
   `import fastapi` → exit 0.
1. `test_only_fastapi_cells_carry_the_framework_contract`: the rendered text
   holds `[importlinter:contract:framework-stays-at-the-edge]` for the FastAPI
   config, and not for `backend = "django"` nor for `python-app`.

For the "breaks" tests, assert that the broken contract is this one, not another
(e.g. capture output and check the contract's `name` appears with `BROKEN`), so
a failure of `dependencies-point-inward` cannot pass them.
