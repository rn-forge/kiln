# ADR-0013 — The docs site navigates by area tabs, and work pages open with derived summaries

**Status:** proposed (2026-10-13) · **Scope:** the MkDocs site of every
repository kiln generates, and kiln's own

## Decision

Each docs area in `docs/_areas.yml` is a top tab with its own sidebar. An area's
`index.md` is the tab's landing page, not an "Overview" child.

The specs tab's sidebar lists every epic, grouped in fixed ranges of ten
(E1–E10, E11–E20, …), with each epic's features and design beneath it. Its first
entry after the board is an epic list that tabulates every epic. Decisions,
releases and other areas keep their index table as the way in.

Every epic page and every feature page opens with a derived summary table that
`task docs:generate` writes from the pages underneath it. An epic's table shows
its features, and a feature's table shows its stories. The summary is the only
place a child's state is shown on its parent page, so an epic no longer
hand-writes a feature table for features that have their own files.

## Consequences

- The sidebar scrolls only within the open area. With the current single
  sidebar, every area's pages stack on top of each other.
- The ranges are fixed by number, so an epic's group and its sidebar position
  never move as epics are added. A group can be partly empty.
- The specs sidebar grows with the work, by about one line per feature. Closed
  work is never deleted, so this growth is accepted. The range groups
  collapse.
- A hand-written `Scope` column on an epic's feature table is dropped. A
  feature's title and its own opening paragraph carry its scope.
- Three more derived regions mean three more stale-region findings that
  `task lint` can raise.
- `navigation.indexes` needs an area's index to be the first entry, with no
  title. The nav generator changes shape, and every rendered `mkdocs.yml`
  changes once.

## Influences

- [E14 — Docs site navigation and work summaries](../specs/epics/E14-site-navigation/index.md)

- [ADR-0003](ADR-0003.md): one source per fact. Derived regions keep it.

## Alternatives considered

- **One sidebar with `navigation.sections`, which is today's choice.** It fails
  as soon as an area has more than a handful of pages: kiln's sidebar already
  stacks nine sections. Epics were also kept out of the nav to hold the
  sidebar short, so no page listed them all.
- **Hand-written nav, as apollo does.** Its tabs work well, and they are adopted
  here. A hand-written nav is not, because a nav that has to be edited for
  every epic goes stale. kiln derives its nav ([ADR-0003](ADR-0003.md)).
- **A nav plugin such as awesome-pages or literate-nav.** It adds a dependency
  to every generated repository for ordering that `kiln docs-generate` already
  owns.
- **Ranges sized to fit, such as halves of the current list.** The labels would
  move whenever an epic was added, and links to a group would break.
- **Keep the hand-written feature table, and add a derived one.** The same state
  would then be shown twice on one page, kept in step by a check rather than
  by construction.
