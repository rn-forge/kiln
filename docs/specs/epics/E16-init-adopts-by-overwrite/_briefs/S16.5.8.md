# S16.5.8 — The dependency table matches pykit and ngkit as they stand

Brief for
[S16.5.8](../F16.5-rebuild-and-port.md#s1658-the-dependency-table-matches-pykit-and-ngkit-as-they-stand),

## Goal

kiln's pin table, the archetype dependency sets, the ngkit pin and the
reference's §3 follow pykit `release-10` and ngkit v0.5.0. A web repository may
then declare `rn-forge-sqlalchemy` and `rn-forge-data`, and `kiln doctor`
accepts them.

## Settled

All settled by the owner on 2026-11-19. The story's **Design** and **Tests**
on the feature page are this brief's build list. The specifics:

- **Pin table** (`src/rn_forge/kiln/archetypes/__init__.py`, lines 46-58):
    - `rn-forge-fastapi` becomes `rn-forge-fastapi-v0.5.1`.
    - Add `"rn-forge-data": "rn-forge-data-v0.1.5"` as the last entry, after
      `rn-forge-sqlalchemy`.
    - The docstring reads `pykit's release tags, read from pykit on 2026-11-19
      (`release-10`).`, with the rest of the sentence unchanged.
    - All four releases are on PyPI: fastapi 0.5.1, data 0.1.5 and
      sqlalchemy 0.2.4.
- **Allowed sets** (`archetype.toml` `[dependencies]`; `required` stays as it
  is in every manifest):

      "rn-forge-cli", "rn-forge-web", "rn-forge-auth", "rn-forge-sqlalchemy",

      "rn-forge-data"]`.

  `NGKIT_URL` becomes
  `https://github.com/rn-forge/ngkit/releases/download/v0.5.0/rn-forge-ng-0.5.0.tgz`.

  rxjs `~7.8.2`). It still exports the two symbols kiln's starter imports,
  `provideRnForgeCoreConfig` and `LocalStorageService` from

- **The reference, §3** (`docs/reference/standard-repo.md`, lines 243-312).
  Replace the table at lines 248-257, and only that table, with these two
  tables, byte for byte. Keep the intro sentence and every paragraph after
  them unchanged.

  ```markdown
  | Archetype | Required | Allowed | Dev |
  | -- | -- | -- | -- |
  | `python-lib` | `rn-forge-commons`, in each distributable | `rn-forge-commons`, `rn-forge-tooling` | — (the `docs` group adds `mkdocs-monorepo-plugin`) |
  ```

## Current behaviour

Observed or read at `017dd81`:

- `test_web_archetypes_allow_auth_sqlalchemy_and_data` fails its `allowed`
  equality: the web sets end at `rn-forge-auth`.
- `test_app_and_tool_allow_data` fails: neither set has `rn-forge-data`.
- `test_a_web_root_may_declare_sqlalchemy` fails: `run_check` reports
  `rn-forge-deps.not-allowed` for `rn-forge-sqlalchemy`. That is apollo's
  failure.
- `test_no_archetype_allows_devops` passes before the change too, and guards
  it.
- `test_every_tag_is_pinned` and `test_floors_are_pykit_release_10` fail:
  there is no `rn-forge-data` key, and fastapi is at `v0.5.0`.
- `test_ngkit_pin_is_v0_5_0` fails: the URL is at v0.4.0.
- `test_reference_dependency_table_matches_manifests` fails on `python-lib`,
  whose row does not name `rn-forge-tooling`. It fails on the web archetypes
  too, whose rows name neither `rn-forge-auth` nor `rn-forge-commons`.
