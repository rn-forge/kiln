## S5.3.1 — A fresh generated repo passes its own gate

**State:** Closed (2026-09-17)

**Acceptance gap found 2026-09-18:** the owner's fresh `web-app` has no API
`tests/` directory, so the explicit `src tests` paths below make Ruff fail.
S5.3.5 supersedes that path prescription and adds formatter stability proof. The
historical completion here does not prove that an untouched scaffold passes the
full gate: pytest also needs repo-owned tests. **Resolved since:**
[S4.5.10](../E4-generator/F4.5-cli.md#s4510-kiln-new-seeds-a-sample-test) seeds
a sample test, and S4.4.1's run shows untouched web cells passing the full gate.

Close the cross-archetype defects found by S5.2.1 before the render matrix or a
real project is asked to diagnose them again.

**Build:**

- Seed `.mdformat.toml` for every archetype from the existing golden file. It is
  a seeded, repo-owned file: kiln writes it only when absent. Its exclusions
  cover generated state and tool outputs, including
  `.rn-forge/kiln/rendered/**`, `node_modules/**`, `.uv-cache/**`, `.nx/**`
  and the existing Python/docs caches.
- In `tasks/quality.yml.j2`, scope every web member's ruff lint and format
  command to `src tests`, matching the single-package tasks. A cache created
  under `api_dir` is never lint input.
- Make selector defaults effective when `kiln new` receives no explicit
  selector: both web archetypes default to FastAPI, and `python-web-app`
  defaults to Angular. Add `backend = ["django"]` to both web manifests;
  retain React and Svelte as untested frontends.
- Add regression tests in the owning module suites. Do not hide a generated repo
  failure with an acceptance-only environment variable or exclude.

**Acceptance:**

- A fresh `python-lib`, `python-web-api` and `python-web-app` each contain a
  seeded `.mdformat.toml`; a pre-existing file is unchanged by `kiln apply`.
- The web ruff commands name `src tests`. A member-local `.uv-cache` containing
  an invalid `.py` file does not affect `task lint`.
- `kiln new` with either web archetype and no selector records FastAPI; the app
  also records Angular. Explicit supported selectors still override defaults.
- Both web manifests refuse Django without `--allow-untested`.
- `task validate` passes in each fresh repo after its package managers sync.

**What the build settled that the story did not say:**

- `.mdformat.toml` is a `core` seeded artifact, alongside the other
  repository-root ownership files. Its template is the shared golden content;
  the three golden files and kiln's own hand-kept skeleton gained the new
  `.nx/**` and `.rn-forge/kiln/rendered/**` exclusions too.
- Web defaults are materialized only for the selected web archetype in
  `ConfigManager`'s defaults layer. That makes an omitted selector write and
  render FastAPI (and Angular for the app), without introducing a foreign
  `[archetype.*]` table that the config validator correctly refuses.

## S5.3.2 — Ship the FastAPI API cell

**State:** Active · **Depends on:** S5.3.7, S4.4.1

`python-web-api --backend fastapi --docs mkdocs` is already a render-matrix cell
(S4.4.1), and it already passes its gate there. What is left is one change to
how the matrix validates a cell, the proofs a shipped cell needs, and the
owner's approval.

*Evidence at elaboration (2026-10-04).* The cell was rendered at `56f9ea6`. Its
dependencies resolved to kiln `feature/v1` at `f1dc319` and pykit `main` at
`cba6d84`. A copy of the cell passed `uv sync` and `task validate` against those
remote pins. With S5.3.7's module as `app.py`, `task api:dev` answered `/livez`
(`{"status":"pass"}`), `/readyz` and `/openapi.json` with 200, and
`task validate` still passed (pyright: 0 errors).

**Build:**

- In `scripts/golden_matrix.py` `_check`, replace
  `run(["uv", "sync"], cell_dir)` with `run([*task, "setup"], cell_dir)`. Each
  cell's own `setup` verb is the bootstrap its README documents. For
  `python-web-app`, its `workspace:install` also runs
  `pnpm install --frozen-lockfile`, which S5.3.3 needs. In `validate`, rename
  the column header `sync+validate` to `setup+validate`. Change nothing else in
  the script.
- Write the test first, in `tests/test_golden_matrix.py`:
  `test_s5_3_2_1_validate_runs_setup_then_validate`. Monkeypatch `run` as
  `test_s4_4_1_3_validate_reports_every_cell` does, and record `(cmd, cwd)`.
  For every cell directory, the first recorded command is
  `["task", "-t", "Taskfile.yml", "setup"]` and the second is
  `["task", "-t", "Taskfile.yml", "validate"]`. No recorded command is
  `["uv", "sync"]`, and the printed header contains `setup+validate`. The
  existing S4.4.1 and S4.4.3 tests must pass unchanged.
- Do not edit the closed S4.4.1 story's notes, any template, or any golden.
- Run `task test`, `task typecheck` and `task lint`. Do not run `task format`,
  because it rewrites `.goldens/`. A `quality:lint:markdown` failure that
  names only files under `.goldens/` is S4.4.1's known finding, not this
  story's.

**Acceptance (the owner runs it at the ref being approved, `R`):**

- `test_s5_3_2_1_validate_runs_setup_then_validate` passes, and `task validate`
  passes.
- `feature/v1` is pushed, and `git ls-remote origin feature/v1` equals
  `git rev-parse HEAD` (`R`), so the cell's remote kiln dev dependency is the
  kiln that rendered it. `task self:golden:render` and
  `task self:golden:validate` then report this cell `PASS` in every column.
- **Clean clone.** `clean_clone` (below) commits the rendered cell into a
  throwaway repository and clones it. In the clone, no `pyproject.toml` has a
  `[tool.uv.sources]` table, and `task setup` and `task validate` pass.
- **Refs.** The clone's `uv.lock` resolves `rn-forge-kiln` from
  `https://github.com/rn-forge/kiln?rev=feature%2Fv1#R`. Record `R` and the
  pykit commit it resolves (`rev=main#<sha>`) on this story.
- **API dev loop.** In the clone, the `app.py` that `kiln new` seeded
  ([S4.9.2](../E4-generator/F4.9-seeded-starter-source.md#s492-fastapi-backend-starter))
  is served as written:
  `smoke <clone> api:dev 8000 /livez '"status":"pass"'` passes.
- The owner approves the rendered cell and records the date and `R` here.

```bash
clean_clone() {  # clean_clone <cell dir> <clone dir>
  git -C "$1" init -q && git -C "$1" add -A
  git -C "$1" -c user.name=kiln -c user.email=kiln@invalid commit -qm cell
  git clone -q "$1" "$2"
  ! grep -l 'tool.uv.sources' $(find "$2" -name pyproject.toml -not -path '*/node_modules/*')
  (cd "$2" && task -t Taskfile.yml setup && task -t Taskfile.yml validate)
}
smoke() {  # smoke <dir> <task> <port> <path> <expected text>
  (cd "$1" && task -t Taskfile.yml "$2") >/dev/null 2>&1 &
  local out=""
  for _ in $(seq 1 90); do out=$(curl -sf "http://localhost:$3$4") && break; sleep 2; done
  lsof -ti "tcp:$3" | xargs kill 2>/dev/null || true
  grep -F -- "$5" <<<"$out" >/dev/null
}
c=.goldens/working; s=$(mktemp -d)
clean_clone "$c/python-web-api-backend=fastapi" "$s/api"
grep -o 'rn-forge/kiln?rev=feature%2Fv1#[0-9a-f]*' "$s/api/uv.lock" | sort -u
grep -o 'rn-forge/pykit?[^#]*#[0-9a-f]*' "$s/api/uv.lock" | sed 's/.*#//' | sort -u
smoke "$s/api" api:dev 8000 /livez '"status":"pass"'
```

**What the build settled that the story did not say:**

- The `task` prefix the script builds, `["task", "-t", "Taskfile.yml"]`, matches
  the story's command lists exactly; the build changed nothing else in the
  script.
- The build is done; the owner acceptance is still open: push, golden render and
  validate, clean clone, refs, API dev loop, and approval. The state is
  `Active` until the owner closes it.

## S5.3.3 — Ship the FastAPI + Angular cell

**State:** New · **Depends on:** S5.3.2

renders from the live, pinned Nx scaffold (`NX_VERSION = "23.2.1"` in
`modules/frontend/angular.py`). After S5.3.2, its validation runs
`pnpm install --frozen-lockfile` through `task setup`. If anything below fails,
treat it as a kiln defect: reproduce it in the owning module's tests, fix it
there, record it here, and then rerun this story.

*Evidence at elaboration (2026-10-04).* The test copy of the rendered cell had
no `node_modules`, `.venv` or `.nx`. In it, `task setup`, `task validate`,
`task web:lint web:test web:build` and `kiln doctor .` all exited 0, and

**`kiln doctor --full` is not used here.** The flag does not exist yet
([S4.6.1](../E4-generator/F4.6-doctor.md#s461-one-report-across-modules) is
New), so this story and S5.3.4 run `kiln doctor .`. S4.6.1's own acceptance runs
`--full` over freshly created repositories. It is not a prerequisite: a cell
rendered at `R` has no stale output for `--full` to find.

**Acceptance (the owner runs it at S5.3.2's `R`):**

- `task self:golden:validate` reports this cell `PASS` in every column.
- In `clean_clone` of the cell (S5.3.2's helpers), `task setup` (which includes
  `pnpm install --frozen-lockfile`), `task validate`,
  `task web:lint web:test web:build` and `uv run kiln doctor .` all exit 0.
  `uv run kiln` here is the clone's own pinned kiln at `R`.
- **Both dev loops.** With the seeded `app.py` as written,
  `smoke <clone> api:dev 8000 /livez '"status":"pass"'` passes, and so does
  `smoke <clone> web:dev 4200 / '<app-root>'`.
- **Refs.** Record `R`, the pykit commit from `uv.lock`, the Nx version from
  `package.json` (`23.2.1` unless `NX_VERSION` changed), and the `pnpm` and
  `node` versions used.
- The owner approves the rendered cell and records the date here.

```bash
c=.goldens/working; s=$(mktemp -d); app="$s/app"
clean_clone "$c/python-web-app-backend=fastapi-frontend=angular" "$app"
```

## S5.3.5 — Fresh scaffold quality commands match the generated tree

**State:** Closed (2026-09-26) · **Depends on:** S5.3.1

The 2026-09-18 owner trial found a missing `tests/` input and Markdown that
changed on the first `task format`. Fix the generated commands and bytes;
editing a consumer's managed `tasks/quality.yml` is only a temporary workaround.

**Build:**

- In `modules/tasks/templates/tasks/quality.yml.j2`, lint and format `src/` and
  include `tests/` only when present, for single packages and workspace
  members. Keep member-local caches outside the input set; do not replace the
  paths with an unrestricted repository scan or create placeholder tests.
- Make instruction templates and scaffolded README prose clean under the emitted
  `.mdformat.toml`, including interpolated names and web selectors. Fix
  rendering rather than excluding `README.md` or `CLAUDE.md`, or re-baselining
  formatter-induced changes to managed blocks.
- Add regressions in `tests/modules/tasks/test_artifacts.py`,
  `tests/modules/instructions/test_artifacts.py` and
  `tests/modules/instructions/test_scaffold.py`. Exercise emitted commands
  against trees both with and without tests, not just command-string matches.
- Update the corresponding Python goldens first where their shared commands or
  instruction templates change, and re-seed affected managed baselines.

**Acceptance:**

- On fresh Python and web scaffolds without `tests/`, Python lint and format
  succeed; adding a test file makes it subject to the same checks. An invalid
  Python file under a member-local cache remains outside their inputs.
- The first and second `task format` leave the freshly generated tracked files
  byte-identical, including README and managed instruction blocks; generated
  drift checks still pass afterwards. Record any upstream scaffold formatting
  discrepancy instead of silently excluding it.
- Full-gate proofs explicitly supply repo-owned tests as acceptance fixtures. Do
  not suppress pytest's no-tests exit or describe a fixture-assisted gate as
  an untouched-scaffold pass.
- `task validate` passes in kiln after these regressions are added.

**What the build settled that the story did not say:**

- Ruff's inputs are `src` plus `$(test -d <dir>/tests && echo tests)`, evaluated
  by `task`'s shell at the repo root: `tests` for a single package,
  `<api_dir>/tests` for the web API member and `packages/{{.ITEM}}/tests` for
  each workspace member. Workspace members no longer run ruff over the whole
  member directory. The three Python goldens, kiln's own `tasks/quality.yml`
  and their `state.json` baselines moved with the template.
- The variable bullets of the `CLAUDE.md` block (archetype, entrypoint,
  frontend, external docs) are filled in Python (`_bullet` in
  `instructions/artifacts.py`), not hand-wrapped in the template. The right
  break depends on the interpolated values, so a template cannot get it right
  for every name. `_bullet` matches mdformat as configured here: a bullet's
  first line holds 80 characters, later lines 78 (`mdformat-mkdocs` reserves
  four columns of indent), and a code span is never broken.
- An external docs URL renders as a `docs` link to the URL, not a bare autolink:
  mdformat indents an autolink by four columns when it lands at the start of a
  wrapped line, so a long URL made the block unstable.
- The mdformat regressions run `python -m mdformat --check` over the rendered
  block and scaffolded bodies against kiln's own `.mdformat.toml`, so they
  depend on the `docs` group being installed, as `task validate` already does.
- Verified live for `python-tool` only: a fresh `kiln new` repo, `uv sync`, then
  `task format` twice left every tracked file byte-identical and `task lint`
  passed with no `tests/`. The web cells were not run live; their commands and
  block are covered by the offline regressions.
- No upstream scaffold formatting discrepancy was found for `uv init`'s output.

## S5.3.6 — Complete the repository setup experience

**State:** Closed (2026-09-27) · **Depends on:** S5.3.5

The same owner trial found missing Python ignore rules, dense reconciled TOML
and no VS Code workspace file. These are repository scaffolding concerns.

**Build:**

- Compose `.gitignore` in this order: the real uv-generated body, then the real
  Nx-generated body for frontend repos, then core's single kiln block.
  Python's current `uv init --vcs none` path supplies no ignore body in the
  observed scaffold. Capture uv's Git-enabled output in an isolated scratch
  repository, with its exact command and the uv version it was captured with
  recorded beside a fixture under `tests/fixtures/scaffold/`. Use that
  upstream output as the source, not a hand-maintained imitation. Do not
  initialize Git in the target or in each workspace member merely to obtain
  ignore rules.
- Pin the uv scaffolder version used by this contract, as Nx already is; verify
  it before scaffolding. Preserve each upstream body's comments, patterns and
  ordering. Normalize line endings to LF and join nonempty sections with one
  blank line and a final newline. Do not sort or deduplicate rules: negations
  and their order affect Git's interpretation. Seed the uv body once at the
  root, even for a multi-member workspace; append Nx once.
- Keep kiln-specific state, cache, coverage and docs-output exclusions in kiln's
  block, including tool outputs the upstream generators omit. The upstream
  bodies are seeded and repo-owned after creation; `apply` updates only kiln's
  fenced block and never reruns either scaffolder. Upstream version changes
  require explicit fixture review, not silent rewriting of existing
  repositories.
- Write readable root and member `pyproject.toml` files during Python
  reconciliation: normal table spacing and multiline dependency lists, using
  the existing TOML writing facilities. Preserve values and comments; do not
  introduce a formatter dependency or make repo-owned TOML managed by apply.
- Seed `<repo-name>.code-workspace` from core with a single relative folder
  `{ "path": "." }`. It is repo-owned after creation, with no absolute paths
  or personal settings, and an existing file is preserved by apply.
- In the seeded README, state that `task api:dev` expects
  `<api_dir>/src/<api_module>/app.py` exposing `app`; include the concrete
  selected path and explain that the application and tests are repo-owned. Add
  an actionable missing-file precondition to the API task. Keep
  application-code generation in [E10](../E10-kiln-generators/index.md).
- Explain `--docs none` in the creation runbook: it omits the MkDocs tree and
  site tasks, while root instructions and Markdown formatting remain. Keep git
  initialization and the first commit explicit user steps.
- Record the local kiln path override as a pre-release development workaround in
  that runbook. Keep remote dependency resolution a shipping requirement; do
  not silently emit the generator machine's checkout path.
- Update the existing Python goldens first for shared artifacts, then the owning
  core, Python, tasks and instructions tests and templates. Update the
  normative ownership inventory for the seeded workspace file.

**Acceptance:**

- Two fresh scaffolds with identical config and pinned generator versions
  produce byte-identical `.gitignore` files, exactly matching uv + Nx + kiln
  composition (uv + kiln without a frontend). Offline tests use captured
  upstream bodies; live capture proves their provenance. No duplicate uv body

- Two successive applies preserve the seeded bodies and user additions, leave

- `git check-ignore` confirms root and nested Python outputs are ignored, while

- Root and member TOML round-trip to the same data, use readable multiline
  dependency lists and retain existing comments. Apply does not reformat
  repo-owned TOML.
- The workspace file parses as JSON and resolves the repo from a different

- Without an application, `task api:dev` names the missing file and `app`

- `--docs none` produces no `docs/` or `mkdocs.yml`, and no MkDocs site tasks.
- The generated README passes Markdown formatting and names the correct API path
  for both default and custom `api_dir` values. `task validate` passes.

**What the build settled that the story did not say:**

- uv's body is captured at scaffold time by `uv_gitignore()` in
  `modules/python/scaffold.py`: `uv init --vcs git --bare` in a temporary
  directory, whose `.gitignore` is written once to the raw backend root. The
  target and its members still run `uv init --vcs none`. The captured fixture

  `test_s5_3_6_1_live_uv_capture_matches_the_fixture` proves it live.

  `uv init` writes fails the live fixture test until the fixture is reviewed.

  lines, so sections join with exactly one blank line and apply's block
  follows after one more.
- kiln's block now carries its state paths plus `.DS_Store`, the tool caches,
  coverage outputs and docs outputs: the goldens' former hand-written body
  minus what uv's body covers. `.DS_Store` sits in kiln's block because uv
  omits it and the goldens ignored it.
- The three goldens' and kiln's own `.gitignore` are now uv's body plus kiln's
  block, and their `state.json` block hashes are re-seeded. Each golden gained

  state entry. kiln's existing `kiln.code-workspace` is repo-owned and was
  left as it was.
- Readable TOML: after each `DocumentUtils.update`, `_multiline_lists` rewrites
  the non-empty `project.dependencies` and every `dependency-groups` list with
  tomlkit's `multiline` (four-space indent, trailing comma). Other arrays are
  untouched. tomlkit already separated the tables; a test holds that.
- The README's `## Running the API` section appears for web archetypes only. It
  is filled by `_paragraph` in `instructions/artifacts.py`, which wraps at 80

  API task derives it.
- The `api:dev` precondition is rendered for FastAPI only; Django's command runs
  `manage.py` and stays deferred.
- `--docs none` already behaved; the story added its regressions.
- Not proved live: `task api:dev` serving a request. That needs a web cell's
  `uv sync`, which does not resolve while the pykit pin is open. Offline tests
