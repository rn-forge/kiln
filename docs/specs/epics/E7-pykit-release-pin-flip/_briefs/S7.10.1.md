# S7.10.1 — kiln and the starter take `rn-forge-tooling` 0.4.0

Brief for [S7.10.1](../F7.10-shell-completion.md#s7101-kiln-and-the-starter-take-rn-forge-tooling-040), at `4b7c67f`.

## Goal

Move kiln's pykit pins to pykit's Release 11 (`release-11`, pykit `7b63ef85`),
whose `rn-forge-tooling` 0.4.0 links a `completions/_<tool>` script for every
`PythonTool`, and make the starter's test assert that second link.

## Settled

- The pins move to Release 11's tags: owner, 2026-11-20 ("take pykit's latest
  release"). All seven versions below are on pypi.org (checked 2026-11-20).
  `rn-forge-django` (0.7.0) and `rn-forge-sqlalchemy` (0.2.4) did not change.
- A requirement's floor is its tag's version
  ([ADR-0018](../../../../adr/ADR-0018.md)); the ceiling is the next breaking
  version (`archetypes.ceiling`).
- `Kiln(PythonTool)` and the starter's `Tool(PythonTool)` do not override
  `artifacts()`; pykit's default now returns the command link and the completion
  link, in that order.

## Current behaviour

- `src/rn_forge/kiln/archetypes/__init__.py` `RN_FORGE_TAGS` holds Release 10
  tags and its docstring says `release-10`.
- `pyproject.toml:20-22` requires `rn-forge-commons[pydantic,markdown,templates]>=0.10.0,<0.11`,
  `rn-forge-cli>=0.2.0,<0.3`, `rn-forge-tooling>=0.3.3,<0.4`;
  `.rn-forge/kiln/standard.md:153-155` repeats them. `standard.md` is
  generated from `standard.md.j2`, so it follows `task kiln:apply`.
- `tests/test_archetypes.py` has `test_floors_are_pykit_release_10` (line ~232)
  asserting the Release 10 tags, and `test_requirement_is_a_range` (line 194)
  asserting `rn-forge-cli>=0.2.0,<0.3`; `test_requirement_is_a_range` stays
  true (cli's floor moves 0.2.0 → 0.2.1 so it must become `>=0.2.1,<0.3`).
- `src/rn_forge/kiln/modules/python/templates/starter/test_product.py.j2`
  asserts one link, `Link("bin/{{ name }}", "bin/{{ name }}")`, in
  `test_the_one_artifact_is_the_command_on_path`.
