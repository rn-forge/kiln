The `.nx/workflows/agents.yaml` that `node-lib` renders installs go-task on
every Nx Cloud agent, so any Nx target whose command calls `task` runs on the
cloud path as it does on a GitHub runner.

## Context

kiln seeds `targetDefaults.pack` in `nx.json` (`modules/node/scaffold.py`) with
the command `task ci:dist:resolve -- dist/{projectRoot} && … npm pack …`. On a
GitHub runner `task` comes from the setup action's `setup-task` step. On an Nx
Cloud agent the launch template, `cicd/templates/agents.yaml.j2`, installs Node,
pnpm, the browsers and uv, but not go-task. So any task that depends on `pack`
fails on the agent with `/bin/sh: 1: task: not found`.

ngkit found this when its atomized `e2e-ci` started running its specs on Nx
Cloud. ngkit's `ng-tailwind-e2e` web server starts
`ng-tailwind:consumer-fixture`, which depends on `pack`. Both of its spec
targets failed before running a single test, while `ng-demo-e2e`, which does not
pack, passed. The same run on the `test-local` path has `task` and is
unaffected. Before that run ngkit's `e2e-ci` had an empty `dependsOn` that kept
every spec from running, which is why nothing showed the gap earlier.

A repository cannot work around it: `agents.yaml` is generated, an edit in place
is drift, and `config.toml` has no setting for extra init steps.

## S9.6.1 — The agent launch template installs go-task

**State:** Closed (2026-11-17)

**Build:**

1. Add an `Install go-task` init step to `linux-medium` in `agents.yaml.j2`,
   after `Install uv`. It installs one exact go-task 3.x release into
   `$HOME/.local/bin` with the official installer
   (`sh -c "$(curl --location https://taskfile.dev/install.sh)" -- -d -b "$HOME/.local/bin" v<version>`),
   appends `PATH=$HOME/.local/bin:$PATH` to `$NX_CLOUD_ENV`, and prints
   `task --version`. Unlike the uv step it is unconditional, because every
   `node-lib` has `targetDefaults.pack`.
1. Write the version once, beside the uv version the template already writes,
   with a comment that it tracks the `3.x` the setup action's `setup-task`
   step resolves.
1. `test_s9_1_2_7_agents_yaml_is_ngkits_under_t1` compares the rendering with
   ngkit's `agents.yaml` at `NGKIT_REF`, which has no such step. Keep the
   comparison for every line outside the new step, and assert the step's name,
   its exact version and the `$NX_CLOUD_ENV` line separately.

**Acceptance:**

- A rendered `node-lib` `agents.yaml` has the `Install go-task` step after
  `Install uv`, with an exact version and the `$NX_CLOUD_ENV` PATH line.
- Every other line of the rendering is unchanged.
- In ngkit, after `[kiln] ref` moves to the change and `task kiln:apply` runs, a
  `workflow_dispatch` CI run on the Nx Cloud path passes `test-cloud`, with
  `ng-tailwind-e2e:e2e-ci--src/accessibility.spec.ts` and
  `ng-tailwind-e2e:e2e-ci--src/cascade.spec.ts` run on agents, not served from
  cache.
- `task validate` passes. Tests: `test_agents_install_go_task_after_uv`,
  `test_agents_go_task_is_an_exact_version_on_the_path`, and
  `test_agents_yaml_is_ngkits_under_t1`, which compares every line before the
  step with ngkit's.

The step installs go-task `v3.54.0`. The ngkit Nx Cloud run is the owner's,
after ngkit moves its pin.

**Files:** `src/rn_forge/kiln/modules/cicd/templates/agents.yaml.j2`,
`tests/modules/cicd/test_node_ci.py`.
