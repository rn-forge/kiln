# S21.2.3 — The umbrella release attaches the record

Brief for
[S21.2.3](../F21.2-evidence-page.md#s2123-the-umbrella-release-attaches-the-record),
at `feature/v1` `51f6c55a`.

## Goal

With both `umbrella-release` and `release-evidence` on, the `release-<n>` GitHub
release that `kiln-devops umbrella` creates carries `security-evidence.json` and
`security.md` as assets: the durable copy of the release's evidence. Without
them it still creates the release and warns.

## Settled

### The source of the record (owner decision, 2026-11-25)

The record comes from **the run named on the committed evidence page**, not from
a search over runs. `docs/releases/release-<n>/security.md` (rendered by
`task release:evidence`, S21.2.1) has the metadata row

```text
| **Run** | [<run>, attempt <attempt>](https://github.com/<repo>/actions/runs/<run>/attempts/<attempt>) |
```

The umbrella reads `<run>` from it (regex `actions/runs/(\d+)` on the line
starting `| **Run** |`), downloads that run's `security-evidence` artifact with
the existing `github.download_artifact(run, "security-evidence", dest)`, and
attaches `dest / "security-evidence.json"` and the page itself. So the
attachment is exactly the record the page was rendered from.

### `src/rn_forge/kiln/devops/umbrella.py`

- `create_command(release, notes_file, sha, files: Sequence[str] = ())` puts
  `files` right after the tag:
  `["gh", "release", "create", release.tag, *files, "--title", …]`. With no
  files the command is unchanged.

- New:

    ```python
    def evidence_files(releases: Path, tag: str, dest: Path) -> tuple[list[str], str | None]:
        """Return the evidence assets for release `tag`, downloaded into `dest`, or `[]` and why not."""
    ```

    Reasons, as returned text: `no security.md` (the page is missing),
    `security.md names no run` (no `**Run**` row or no run ID in it),
    `run <id> has no security-evidence artifact` (download failed or the JSON is
    absent). On success:
    `([str(dest / "security-evidence.json"), str(page)], None)`.

- `run(releases, sha, dry_run, evidence=False)`: after choosing `newest` and
  before building the command, when `evidence` is true:

    - with `dry_run`, it does not download: when the page exists and names a run,
      the files are `["security-evidence.json", str(page)]`, else the warning
      below and no files;
    - otherwise it calls `evidence_files` with the same temp directory the notes
      file goes in.
    - When there are no files, print to stderr
      `kiln-devops: {newest.tag}: no security evidence attached ({reason})`,
      then create the release as today. The release is never held back.

- `evidence=False` behaves exactly as today (every existing umbrella test passes
  unchanged).

The page-parsing regex repeats what S21.2.1's page template writes, as
`umbrella.py` already repeats the docs patterns (`kiln-devops` may not import
kiln's other modules: `tests/devops/test_boundary.py`).

### `cli.py`

The `umbrella` parser gains `--evidence` (`store_true`), passed to
`umbrella.run`.

### The rendered task and job

- `src/rn_forge/kiln/modules/tasks/templates/tasks/ci.yml.j2`,
  `release:umbrella`: the command becomes
  `'{{.DEVOPS}} umbrella --sha "$GITHUB_SHA"{% if "release-evidence" in checks %} --evidence{% endif %}'`.
- `src/rn_forge/kiln/modules/cicd/templates/ci.yml.j2`, the `umbrella` job's
  `permissions`: add
  `actions: read # download the run's security-evidence artifact` under
  `contents: write` when `"release-evidence" in checks`. Nothing else in the
  job changes.

Rejected (do not build): searching runs for the record; holding the release
back; re-rendering the page in CI; attaching anything when `--evidence` is not
passed.
