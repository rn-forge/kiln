`init` writes `new`'s file set over the tree, backs up every file it overwrites,
refuses a dirty worktree with no override, and runs `task format` and (with the
`mkdocs` profile) `task docs:generate` last, so `task lint` passes. The adopt
prompt keeps judgement only.

## Context

The `mkdocs.yml` row of the overwritten set takes effect when
[F16.2](F16.2-kiln-owns-mkdocs.md) lands; until then `init` keeps placing the
nav fence in it.

Today `init` keeps what exists: `_areas.yml`, `_structure.md` pages and the
epics index are seeded only when absent, `mkdocs.yml` gets a nav fence placed in
it, and `--force` is needed to overwrite a conflict. That is code for two
repositories, and it caused findings #2, #4, #9 and #12. Overwriting is simpler;
git is the review tool, and `_archive` keeps a copy.

## S16.1.1 — `init` refuses a dirty worktree, always

**State:** Closed (2026-11-04)

**Build — tests first,** in `tests/test_init.py`:

1. `test_s16_1_1_1_dirty_tree_is_refused`: on `lib_repo` with an untracked file,
   `commands.init(..., yes=True)` raises `AppException` containing
   `init.dirty-tree` and writes nothing.
1. `test_s16_1_1_2_dry_run_does_not_need_a_clean_tree`: the same with
   `dry_run=True` succeeds and writes nothing.
1. `test_s16_1_1_3_force_is_gone`: `commands.init` has no `force` parameter;
   `kiln init --force` exits with the CLI's unknown-option error.

**Build:** `commands.py`, `init`: delete the `force` parameter and every use
(`state_path.exists() and not force` becomes a plain refusal when `state.json`
exists, with the message "this repository is under kiln; use `kiln apply`");
`_require_clean` is already called under `yes and not dry_run`, so keep it and
drop the `--force` mention from its message. The two other refusals `--force`
overrode go the way of the overwrite (owner decision, 2026-11-04): an unfenced
`.importlinter` is always archived (`-unfenced`) and fenced, with no
`CycleRefused` from `init`, and an unmarked `mkdocs.yml` is always archived
(`-nav`) and marked (moot once F16.2 makes `mkdocs.yml` managed). Remove `force`
from `archetypes`/`cli.toml`'s `init` entry and the `init` docstring.

**Acceptance:**

- The three tests pass, and `task validate` passes.

**What the build settled that the story did not say:**

- The tests use `lib_repo` and the `python-lib` selectors, as the story says.
  `test_s16_1_1_3_force_is_gone` checks the signature and runs
  `main.app(["init", "--archetype", "python-app", "--force"])`, which returns
  exit code `2`.
- `cli.toml` never named `--force`: the command line is derived from `init`'s
  signature, so only the signature and docstring changed there.
- The `state.json` refusal reads "this repository is under kiln; use
  `kiln apply`". `_require_clean`'s message never mentioned `--force`; it is
  unchanged.
- The conflict gate stays, with the message "N conflict(s), nothing written:
    <paths>" and no override. `cycle.apply` no longer gets `force=`, since a
    conflict now stops `init` first.
- `CycleRefused` is no longer raised from `init`; it stays in `cycle.py`. An
  unfenced `.importlinter` is archived (`-unfenced`) and fenced, and an
  unmarked `mkdocs.yml` is archived (`-nav`) and marked, both in `init` before
  the gate runs.
- `_archive`'s warning lost its `--force:` prefix and now reads "archiving N
  target(s) to <dir> before overwriting". S16.1.2 drops it.
- Consequence of keeping the gate: a fenced `.importlinter` that carries its own
  contracts has a block with no state entry, which is a `CONFLICT`, and a
  marked `mkdocs.yml` that differs from its render is one too. `init` then
  refuses after archiving and fencing or marking; the dirty-tree rule means
  git shows and reverts it. S16.1.2 removes the gate.
- The existing tests that used `--force`, and what became of them:

      `--force`.
    - `test_s4_5_8_4_force_archives_every_overwritten_target`: removed. Archiving
      conflicts is S16.1.2 (`test_s16_1_2_2_backups`).
    - `test_s4_5_8_5_a_second_unforced_init_fails_naming_the_state`: renamed
      `…_a_second_init_is_refused_naming_apply`, and matches `kiln apply`.
    - `test_s4_5_8_5_a_forced_reinit_archives_state_and_applies_the_new_selectors`:
      removed; a re-init is a refusal now.
    - `test_s4_5_8_6_neither_path_runs_a_scaffold`: now `…_init_runs_no_scaffold`,
      one plain `init` with no hand-made file.
    - `test_s4_5_8_force_does_not_imply_yes_and_dry_run_beats_yes`: now
      `…_without_yes_and_with_dry_run_nothing_is_written`.
    - `test_s4_5_8_a_failing_check_keeps_the_writes_and_the_archive`: no hand-made
      conflict; renamed `…_keeps_the_writes`, and the backup assertion went.
    - `test_s6_1_7_1_force_fences_and_keeps_the_contracts`: now
      `…_an_unfenced_importlinter_is_fenced_and_keeps_the_contracts`. It expects

## S16.1.2 — `init` overwrites kiln-shaped files and archives them

**State:** Closed (2026-11-04) · **Depends on:** S16.1.1

**Build — tests first,** in `tests/test_init.py`, on `lib_repo` with a
hand-edited `Taskfile.yml`, `docs/_areas.yml`, `docs/specs/_structure.md`, an
empty-content `docs/specs/epics/index.md` and `.github/workflows/ci.yml`:

1. `test_s16_1_2_1_overwrites`: after `init --yes`, each of those files equals a
   fresh `new` render of the same config (compare with `cycle.adoption_plan`
   showing no change).
1. `test_s16_1_2_2_backups`: each file's previous bytes are under
   `.rn-forge/kiln/backups/<stamp>/<path>`, and the command prints the backup
   directory.
1. `test_s16_1_2_3_content_is_never_touched`: `README.md`, a `docs/guides/x.md`
   page, `docs/adr/ADR-0001.md`, a source file and a test file are
   byte-identical afterwards, and `docs/specs/epics/index.md` is overwritten
   only when it has no epic rows.
1. `test_s16_1_2_4_pyproject_and_gitignore_merge`: a repository's own
   `[project]` table and `.gitignore` lines outside kiln's block survive.
1. `test_s16_1_2_5_no_conflict_stage`: `init` with differing managed files exits
   `0`; there is no `conflict(s), nothing written` error.

**Build:** `commands.py`, `init`: archive every path in `planned.changes` whose
action is `CONFLICT` or an overwrite, plus the seeded paths it will replace,
before writing (reuse `_archive`; drop its `--force` warning text and print
`console.info("backed up {} file(s) to {}", …)`); remove the conflict gate and
`cycle.CycleRefused`; call
`cycle.apply(root, force=<every conflicting key>, …)`. The seeded files that now
overwrite are `docs/_areas.yml`, every `_structure.md`,
`docs/specs/epics/index.md` (only with no epic rows), `docs/index.md` and each
area `index.md` that holds no content beyond the seed text. `seeds` becomes
"render, overwrite": drop `_missing_seeds` in favour of
`_seed(root, resolved, every_seed)`; its `Skipping existing` rule is replaced by
the content test named here (a helper `_has_content(path)`: the file differs
from the seed render in more than whitespace).

**Acceptance:**

- The five tests pass, and `task validate` passes.

**What the build settled that the story did not say:**

- `_missing_seeds`, `_seed` and `_seed_rows` stay, for the one thing they still
  do: create a `node-lib`'s `pyproject.toml` when it is absent
  (`test_s16_1_2_4` needs an existing `pyproject.toml` to survive, so it is
  not an overwrite). The `mkdocs.yml` row was already gone (F16.2). Departure
  from "drop `_missing_seeds`".
- The docs seeds are `SEEDED` artifacts the plan already carries (`SKIP` when
  present), so they overwrite through the plan, not through `_seed`.
  `_replaced_seeds(root, planned)` in `commands.py` picks them from the
  `SEEDED`/`SKIP` changes among `docs.artifacts.SEEDS`: `docs/_areas.yml`
  always; `docs/specs/epics/index.md` unless it holds a line starting
  `| [E<n>`; any other `index.md` seed for which `_has_content(path, seed)` is
  false (`_has_content` compares the file with the seed render with all
  whitespace removed). `_has_content` lives in `commands.py` beside it:
  nothing else needs it. Seeds such as `development.md`, `.mdformat.toml`,
  `.taplo.toml`, the workspace file and starters are not in the story's list
  and stay as they were.
- An overwritten seed is archived, then rewritten in place with its render
  before `cycle.apply` (not deleted), because `mkdocs.yml`'s nav is built from
  the tree and a deleted page would make it differ. For the same reason
  `mkdocs.yml` is archived and approved whenever any seed is replaced, whether
  or not it differed. The dry-run preview reports a replaced seed as
  `overwrite`.
- The conflict gate, `_settle_nav` and `mark_nav` are removed (nothing else used
  `mark_nav`): a conflicting `mkdocs.yml` is now an ordinary conflict,
  archived and overwritten. `cycle.CycleRefused` stays, since `cycle` still
  raises it for a legacy kiln tree. The `.importlinter` fencing step stays in
  `init`: it archives (`-unfenced`) and fences, so the repository's own
  contracts survive below the block, and the fenced block is then an ordinary
  conflict.
- `cycle.apply` is given `force=` for every `CONFLICT` change (by key and by
  path) plus `mkdocs.yml`; a prior `config.toml` is archived and overwritten
  by `_write_config`. `_archive` now returns the directory and the paths
  copied (`None` when none existed), prints nothing, and creates nothing when
  nothing is there; `init` prints `backed up N file(s) to <dir>`. The paths
  already archived as `-unfenced` are not archived a second time.
- Test 1 compares each file with the fresh `new` render's bytes and checks
  `cycle.adoption_plan` leaves none of them stale. Its hand-edit appends a
  comment to `docs/_areas.yml` rather than replacing it, because
  `mkdocs.yml`'s nav is built from that file and `init` fails on one that is
  not a mapping. Test 3 cannot assert the fence of an epics index that lists
  an epic, since `docs-generate` rewrites the fence; it asserts the prose
  outside it survives. One extra test,
  `test_s16_1_2_3_whitespace_only_differences_are_not_content`, covers
  `_has_content`.
- Existing tests that asserted refusal, and what became of them:
    - `test_s4_5_8_3_conflicts_are_all_named_and_nothing_changes`: now
      `…_conflicts_are_overwritten_and_archived`; init succeeds, the files equal
      the render and are under `backups/`.
    - `test_s4_5_8_3_a_block_without_a_state_entry_is_a_conflict_even_if_equal`:
      now `…_is_archived_even_if_equal`.
    - `test_s4_5_8_3_an_existing_config_without_state_is_a_conflict`: now
      `…_is_archived_and_replaced`.
    - `test_s6_1_7_1_…`, `test_s6_1_9_3_…`: dropped the `pytest.raises` on the
      conflict; the rest of each assertion stands (the `-nav` archive glob is
      now `*/mkdocs.yml`).
    - `test_s9_1_15_2_an_existing_mkdocs_yml_is_a_conflict`: now
      `…_is_archived_and_overwritten`, comparing with the `node-lib` render.

## S16.1.3 — `init` formats and generates last

**State:** New · **Depends on:** S16.1.2

**Build — tests first,** in `tests/test_init.py` (the fixture repository runs
`task setup` first; skip the test when `task` is missing, as the other
subprocess tests do):

1. `test_s16_1_3_1_lint_passes_after_init`: on `lib_repo`, after `init --yes`,
   `task lint` exits `0`.
1. `test_s16_1_3_2_order`: a recording `run_task` double shows the order
   `task setup`, `task format`, `task docs:generate`.
1. `test_s16_1_3_3_dry_run_runs_nothing`.
1. `test_s16_1_3_4_no_docs_profile`: with `--docs none` and with
   `--docs external`, the double records `task setup`, `task format` and no
   `task docs:generate` (the root `Taskfile.yml` includes `docs` only for
   `mkdocs`), and `task lint` exits `0` afterwards.

**Build:** `commands.py`, `init`: just before the closing
`_fail_on_errors(root)`, run in order through
`subprocess.run(["task", name], cwd=root, check=True)`: `setup`, `format`, and
`docs:generate` only when `config.docs_profile == "mkdocs"`. A failing step
raises `AppException` naming the step. This supersedes F6.6's "`init` formats
nothing" and S5.3.6's rule for kiln-shaped files (S5.3.6 still holds for
content: `task format` is the only thing that rewrites a content page, and it
does so only for formatting).

**Acceptance:**

- The four tests pass, and `task validate` passes.
- On a throwaway clone of a kiln-shaped fixture, `kiln init --yes` followed by
  `task lint` exits `0`. Not scriptable on pykit; the cutover (F16.3) is the
  proof.
