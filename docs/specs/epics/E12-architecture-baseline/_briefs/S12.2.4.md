# S12.2.4 — The FastAPI starter follows ARCH-0002 and ARCH-0004

Brief for
[S12.2.4](../F12.2-web-baseline.md#s1224-the-fastapi-starter-follows-arch-0002-and-arch-0004).

## Goal

The seeded FastAPI starter moves its router to `http/items.py` and its error to
`domain/errors.py`, and `ItemNotFound` subclasses `AppException`.

## Settled

- S12.2.1 closed 2026-11-20: the starter table in
  [design.md](../design.md#the-starter-follows-the-records) is approved.
- The story's **Build** list is verbatim: the five `_API_SRC` entries, the
  template names, the `ItemNotFound("No item {}", item_id, item_id=item_id)`
  call and the four one-line docstrings.
- `from rn_forge.commons import AppException` is the import: `rn_forge.commons`
  exports it, and `rn-forge-commons` is a required dependency of both web
  archetypes (`archetypes/python_web_api/archetype.toml`).
- New templates: `fastapi/http_init.py.j2` and `fastapi/domain_init.py.j2` hold
  only their one-line docstring and `from __future__ import annotations` is
  not needed in them.
- S12.2.3 is merged: a FastAPI cell's `.importlinter` already carries
  `framework-stays-at-the-edge`.

## Change

- `starter.py` `_API_SRC`, exactly: `app.py` → `fastapi/app.py.j2`,
  `http/__init__.py` → `fastapi/http_init.py.j2`, `http/items.py` →
  `fastapi/items.py.j2`, `domain/__init__.py` → `fastapi/domain_init.py.j2`,
  `domain/errors.py` → `fastapi/errors.py.j2`.
- `git mv` `routes.py.j2` to `items.py.j2`; import `ItemNotFound` from
  `{{ module }}.domain.errors`; raise
  `ItemNotFound("No item {}", item_id, item_id=item_id)`; docstring per the
  story.
- `errors.py.j2`: `from rn_forge.commons import AppException`;
  `class ItemNotFound(AppException)`; docstring per the story.
- `app.py.j2`: import from `{{ module }}.domain.errors` and
  `{{ module }}.http.items`; nothing else changes.
- `test_app.py.j2` does not change.
- **Leave alone:** every other starter, `.importlinter`, `api:dev`, every spec
  page except `## Result` below.
