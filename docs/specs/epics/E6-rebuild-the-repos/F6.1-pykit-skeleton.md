## S6.1.1 — A pykit-shaped repository passes its own gate

**State:** New

Build a scratch `python-lib` repository with the shape that makes pykit hard to
host:

- Seven packages named as pykit's are: `rn-forge-commons`, `rn-forge-cli`,
  `rn-forge-tooling`, `rn-forge-web`, `rn-forge-django`, `rn-forge-fastapi`
  and `rn-forge-sqlalchemy`. Each is added with `kiln generate package`.
- The workspace dependencies run cli → commons, tooling → cli, and web, django,
  fastapi and sqlalchemy → commons, all as `{ workspace = true }`.
- Three of the member names are also dependencies of `rn-forge-kiln`. The root
  sets `[tool.uv] override-dependencies` so that kiln resolves to the
  workspace copies ([ADR-0006](../../../adr/ADR-0006.md)).
- A root guide links a page in each package's site.

**Elaborated 2026-10-14.** This story builds the script and runs it. It does not
fix kiln. A failure the run finds is triaged by the owner: one that also
reproduces in an empty `python-lib` repository becomes its own kiln story
(S6.1.2 onward), with a regression test, and this story is rerun after it. One
known risk: pykit's members declare `[tool.uv.sources] … = { workspace = true }`
for rn-forge packages, and `kiln doctor`'s `rn-forge-deps` check rejects an
`[tool.uv.sources]` entry for an rn-forge package
([standard §3](../../../reference/standard-repo.md)). Expect that to be the
first finding.

**Build:**

- Create `tests/e2e/pykit_shape.sh`, mode `0755`, with exactly this content:

    ```bash
    #!/usr/bin/env bash
    # Build a pykit-shaped python-lib repository from a fresh `kiln new` (kiln S6.1.1).
    # Usage: tests/e2e/pykit_shape.sh <scratch dir> <kiln checkout>
    set -euo pipefail
    dir=$1
    kiln_root=$(cd "$2" && pwd)
    kiln() { uv run --project "$kiln_root" kiln "$@"; }

    kiln new "$dir" --archetype python-lib --docs mkdocs --yes </dev/null
    [ -d "$dir/.git" ] || git -C "$dir" init -q
    git -C "$dir" remote remove origin 2>/dev/null || true
    git -C "$dir" remote add origin https://github.com/rn-forge/pykit-shape

    packages=(rn-forge-commons rn-forge-cli rn-forge-tooling rn-forge-web
              rn-forge-django rn-forge-fastapi rn-forge-sqlalchemy)
    for p in "${packages[@]}"; do
      kiln generate package "$p" --path "$dir"
    done

    add() { (cd "$dir" && uv add --quiet --no-sync --package "$1" "$2"); }
    add rn-forge-cli rn-forge-commons
    add rn-forge-tooling rn-forge-cli
    for p in rn-forge-web rn-forge-django rn-forge-fastapi rn-forge-sqlalchemy; do
      add "$p" rn-forge-commons
    done

    # kiln (a dev dependency) requires commons, cli and tooling from pykit's git
    # source; the overrides make it take the workspace copies (ADR-0006).
    python3 - "$dir/pyproject.toml" <<'PY'
    import sys
    path = sys.argv[1]
    text = open(path, encoding="utf-8").read()
    line = 'override-dependencies = ["rn-forge-commons", "rn-forge-cli", "rn-forge-tooling"]\n'
    assert "[tool.uv]\n" in text and "override-dependencies" not in text
    open(path, "w", encoding="utf-8").write(text.replace("[tool.uv]\n", "[tool.uv]\n" + line, 1))
    PY

    {
      printf '# Packages\n\nEach package has its own site.\n\n'
      for p in "${packages[@]}"; do
        printf -- '- [%s](../%s/index.md)\n' "$p" "$p"
      done
    } >"$dir/docs/guides/packages.md"

    (cd "$dir" && task docs:generate)
    ```

    Change nothing in it except to fix a defect in the script itself (a typo, a
    wrong flag name you can confirm with `--help`). Record every such fix.

- Add `tests/e2e/` to nothing else: no pytest wiring, no Taskfile verb, no CI
  job. The script is run by hand and by the feature's acceptance block.

- Run it: `s=$(mktemp -d); tests/e2e/pykit_shape.sh "$s/pykit-shape" "$PWD"`,
  then, inside `$s/pykit-shape`: `uv sync`, `task validate`,
  `uv run kiln doctor --full`, and the feature's acceptance block. Note:
  `kiln doctor --full` may not exist yet (S4.6.1 is New); if it does not, run
  `uv run kiln doctor .` and record that.

- Under the story, record: the kiln ref (`git rev-parse HEAD`), each command
  above with its exit status, and for every failure the first error lines
  verbatim. For each failure, also run the same command in a plain
  `kiln new … --archetype python-lib --docs mkdocs --yes` repository with one
  `kiln generate package demo-pkg`, and record whether it reproduces there.

- Do **not** change anything under `src/`, any template, `tests/` other than the
  new script, or any spec but this story. Fixes are separate stories.

**Acceptance:**

- `tests/e2e/pykit_shape.sh` builds the repository from a fresh `kiln new`, with
  `origin` set to `https://github.com/rn-forge/pykit-shape`, and with no edits
  to generated files.
- In it, `uv sync`, `task validate` and `kiln doctor --full` pass.
- Its `uv.lock` records `rn-forge-kiln`, and `rn-forge-tooling` resolves to the
  editable workspace member.
- Its generated nav includes all seven package sites, and the root guide's links
  into them pass `docs-structure` and `docs-site`.
- This story records the kiln ref it passed at.

The story stays `Active` until every bullet holds; a run that finds failures
records them and stops.
