## S11.5.1 — CI deploys versioned package sites

**State:** New · **Entry criterion:** pykit's default branch publishes versioned
package sites, with each package's `latest` site served under
`https://rn-forge.github.io/pykit/packages/`
([ADR-0009](../../../adr/ADR-0009.md): a pin on something observable, not
pykit's stories)

The `python-lib` CI template gains the docs deploy. After the package jobs, one
`docs` job builds the root site. It then deploys each package tagged at the
pushed commit with `mike --deploy-prefix packages/<pkg>` to a `gh-pages` storage
branch. Last, it uploads the root site plus that branch's `packages/` tree as
the Pages artifact. The application archetypes keep deploying the root site
only.

**Open question**, answered before this story is built: `mike` needs a task to
run it, because workflows call only `task`. The two options are adding a public
`docs:publish` verb to `python-lib`'s vocabulary, which is a compatibility
surface under [ADR-0007](../../../adr/ADR-0007.md), or an internal CI-only task.

**Acceptance:**

- The rendered `python-lib` `docs.yml` deploys each tagged package with
  `mike --deploy-prefix packages/<pkg>`, and `actionlint` passes on it.
- The rendered `docs.yml` of every other archetype is unchanged.
- A throwaway `python-lib` repository's run publishes `packages/<pkg>/latest/`,
  and the run is linked here.
