## S4.8.2 — A single-package repository declares its import module

**State:** Closed (2026-10-19)

Found 2026-10-16, reviewing whether agentkit can be generated by kiln. A
`python-app` or `python-tool` repository's import module is derived from its
repository name (`kiln` → `kiln`, `agentkit` → `agentkit`), in every place that
names it: the `uv init` layout, `module-name`, the script entry, the starter
source, the sample test, `.importlinter`'s `root_package`, `--cov=`, and
`docs/reference/python-api.md`. A repository whose module is a namespace package
(`rn_forge.kiln`, `rn_forge.agentkit`) cannot be described, so S4.8.1 would
render `root_package = kiln` for kiln itself, and `lint-imports` would fail with
`Could not find package`. S6.1.3 solved this for `python-lib` members; this
story is the same solution for the one package of a single-package archetype.
The module is declared in config, never read from `pyproject.toml`
([ADR-0004](../../../adr/ADR-0004.md)).

**Build — tests first.** Copy the shape of S6.1.3's tests (`test_s6_1_3_*` in
`tests/modules/python/test_artifacts.py` and `tests/test_generate_package.py`).

## S4.8.3 — kiln's own CI survives self-hosting, with Node where its tests need it

**State:** Closed (2026-10-19)

Found 2026-10-18, from the first CI run of `feature/v1` (run 39129929811).
`validate` failed in `test_s4_6_2_3_every_rendered_cell_passes[python-web-app]`,
which calls `commands.new()` for real and so runs
`pnpm dlx create-nx-workspace`. kiln's setup action installs uv and go-task
only; just the pull-request-only `golden-render` job adds pnpm and Node, with
steps of its own. The interim fix guards that case with
`pytest.mark.skipif(shutil.which("pnpm") is None, ...)`, as
`test_s4_9_3_4_new_records_seeded` already is, so neither test runs in CI, and
`sonar`, which runs the same tests for coverage, counts their lines as
uncovered.

Two gaps make this S4.8.1's problem, not a hand edit's. kiln's `ci.yml` and
`.github/actions/setup` are hand-copied with `kiln_version = "golden"` in
`state.json`, so an edit in place fails `lint:generated`. And no template
renders `golden-render`, so S4.8.1's regeneration would delete it, and the Node
steps with it. The fix goes through config and the templates, per
[ADR-0016](../../../adr/ADR-0016.md): no repository hand-maintains its CI.

### Design

- **`[ci] node: bool = False`** in `CiConfig`. When true, the setup action's
  existing pnpm and Node steps (`action.yml.j2`, today gated on
  `python-web-app`) render, so every job that uses the action gets them:
  `validate` and `sonar` both run the tests. The condition becomes
  `web_app or ci.node`; `python-web-app` keeps them without the key. The cost
  is about 10–20 seconds a job, with pnpm's cache.
- **`[[ci.jobs]]`**: a repository-declared job that runs one `task`. Fields:
  `name` (kebab-case, not a generated job's name), `task` (a task that
  resolves, checked by `taskgraph`), `events` (a subset of `pull_request`,
  `push`, `workflow_dispatch`; default all). Each renders after `validate`
  (`needs: validate`), with checkout, the setup action and `task setup`, then
  `task <task>`; `ci-ok` needs it. The step calls `task`, so `ci-entrypoint`
  holds. kiln declares
  `{ name = "golden-render", task = "self:golden:render", events = ["pull_request"] }`.
- **The network.** `validate` already depends on it (PyPI, the setup actions);
  the new risk is `pnpm dlx`'s npm download. `validate`'s `timeout-minutes`
  stays 20 unless the recorded run below needs more.
- **The skip guard stays for local runs only.** Both pnpm tests skip when pnpm
  is missing **and** `CI` is unset. GitHub sets `CI=true`, so in CI a missing
  pnpm fails the test instead of skipping it.

### Build — tests first

- `tests/modules/cicd/test_artifacts.py`:
    - `test_s4_8_3_1_node_off_renders_no_node_steps`: a `python-tool` config
      without `node`: the setup action has no `pnpm/action-setup` or
      `setup-node`.
    - `test_s4_8_3_1_node_on_renders_node_steps`: `[ci] node = true` on
      `python-tool`: both steps render, pinned as `python-web-app`'s are.
    - `test_s4_8_3_1_web_app_keeps_node`: `python-web-app` without the key renders
      both steps, byte-identical to before.
    - `test_s4_8_3_2_declared_job_renders`: one `[[ci.jobs]]` entry renders a job
      with `needs: validate`, the event `if:`, the setup action, `task setup`
      and `task <task>`, and `ci-ok`'s `needs` includes it.
    - `test_s4_8_3_2_declared_job_name_collision_is_refused`: `name = "sonar"`
      raises `AppException` at config resolution.
    - `test_s4_8_3_2_no_declared_jobs_is_unchanged`: every golden cell's `ci.yml`
      renders byte-identical.
- `tests/modules/tasks/checks/test_layout.py` and
  `tests/modules/frontend/test_starter.py`: the two pnpm guards become
  `skipif(shutil.which("pnpm") is None and not os.environ.get("CI"), ...)`.

### Build

  generated job uses.

- `docs/reference/standard-repo.md` §9: the two keys, one example each.
- kiln's `.rn-forge/kiln/config.toml`: `[ci] node = true` and the
  `golden-render` job. S4.8.1's apply then renders kiln's CI with both.

**Acceptance:**

### What the build settled that the story did not say

- **Pending: the CI runs.** The last acceptance bullet needs S4.8.1's
  regenerated workflows; no run is recorded yet.
- **Every cell's `config.toml` gains `node = false` and `jobs = []`**, because
  the written config carries every default (as `release` already does). No
  managed file changes, and `task self:golden:compare` passes, but it compares
  only `state.json`'s managed entries, so it does not see `config.toml`. Until
  this change is on the remote `feature/v1` that the cells pin,
  `task self:golden:validate` fails in every cell at `quality:lint:generated`
  (`ci.node`, `ci.jobs`: extra inputs). With kiln installed editable from the
  working tree, `python-app`'s `task validate` passes.
- **The taskgraph check needed no wiring.** `_check_owned_text` already reads
  every `run:` line of a managed `.github/` workflow and reports
  `taskgraph.unresolved-ref` for a `task <name>` that does not resolve, so a
  declared job's `run: task <task>` is covered. An added test
  (`test_s4_8_3_2_declared_job_task_must_resolve`) proves it end to end; the
  check is not otherwise changed. A `task` value with a space or an argument
  is not rejected by the schema.
- **Name rules.** `CiJob.name` must be kebab-case
  (`^[a-z][a-z0-9]*(-[a-z0-9]+)*$`), not one of `GENERATED_JOBS` (`validate`,
  `plan`, `verify`, `postgres`, `smoke`, `suites`, `sonar`, `release`,
  `external-install`, `docs`, `ci-ok`, whether or not the archetype renders
  it), and unique among declared jobs. A violation is a schema error, so it
  surfaces as `AppException` at config load.
- **Events.** `events` must be non-empty. With all three (the default) no `if:`
  renders; otherwise
  `if: ${{ github.event_name == 'a' || github.event_name == 'b' }}`.
- **Job shape.** Every declared job renders `timeout-minutes: 20` and
  `permissions: {contents: read}` and no `fetch-depth`. It sits after the
  generated jobs and before `ci-ok`, whatever the archetype, and is appended
  to `ci-ok`'s `needs` after the generated names. The step is named
  `Run <task>`.
- **`node` on a `python-web-app`** changes nothing: the condition is
  `web_app or node`.
- **`no_declared_jobs_is_unchanged`** compares an absent `jobs` with `jobs = []`
  and checks the job set against `GENERATED_JOBS`, since a test cannot render
  HEAD. The byte-identity proof is `task self:golden:compare BASE=HEAD`: all
  five cells PASS.
- **kiln's config uses a `[[ci.jobs]]` table**, not an inline array, because
  `taplo` wraps the inline form unreadably.
- **Risk for S4.8.1's CI run.** The rendered Node steps carry no `version:` for
  pnpm and no `node-version:` for Node, as `python-web-app` renders them,
  because that repository has `packageManager` and a lockfile. kiln has
  neither a `package.json` nor a lockfile, so `pnpm/action-setup` and
  `setup-node`'s `cache: pnpm` may fail there. The hand-copied job passes
  `version: 12` and `node-version: 24`. Not changed here, since the story
  lists no key for it; decide when the first CI run shows it.
- **The feature's State is now `Active`**, because `docs-generate` refuses a
