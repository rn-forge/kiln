## S6.1.1 — Build a real pykit candidate beside the current repo

**Status:** planned

Use pykit as the first real `python-lib` proof without replacing its working
tree. Prepare a config source whose `[archetype.python-lib].packages` lists the
existing members, then run:

```bash
kiln new pykit-kiln-candidate --archetype python-lib --docs mkdocs --config <source>
```

Port the existing package source, tests, docs and repo-owned configuration into
the candidate. Do not copy pykit's current Taskfiles, generated instructions or
workflows.

pykit takes `rn-forge-kiln` in its dev group like every generated repo, and sets
`[tool.uv] override-dependencies` naming every pykit member kiln reaches, so
kiln resolves to the workspace copies ([ADR-0010](../../../adr/ADR-0010.md)).
Use `extra_refs` only for a current workflow step the generated matrix does not
cover, and record that mapping on this story.

Any failure that also reproduces in an empty `python-lib` repo is fixed in kiln
with a regression test before this story continues. The candidate must remain
outside pykit's working tree; this story proves the archetype and does not cut
over the repository.

**Acceptance:**

- The candidate config records `python-lib`, and its package list exactly
  matches pykit's `packages/*` project directories.
- Nothing under the candidate's `packages/*/src` or `packages/*/tests` differs
  from the recorded pykit baseline ref.
- The candidate's `uv.lock` records `rn-forge-kiln`, and `rn-forge-tooling`
  resolves to the editable workspace member.
- In the candidate, `uv sync`, `task validate` and `kiln doctor --full` pass.
- This story records the pykit baseline ref, kiln ref, exact scaffold command,
  and any `extra_refs` mapping.

## S6.1.2 — Replace pykit's skeleton

**Status:** planned

After kiln self-hosts, rebuild the S6.1.1 candidate from the approved kiln ref
and replace pykit's skeleton on a branch. Package source, tests, docs and plans
remain pykit's; only the repository skeleton changes.

**Acceptance:**

- Nothing under `packages/*/src` or `packages/*/tests` differs from the baseline
  recorded by S6.1.1.
- `_package-ci.yml` is gone. Each former step is in the generated matrix or in
  the reviewed `extra_refs` mapping from S6.1.1.
- In pykit, `task validate` and `kiln doctor --full` pass.
- CI passes on the replacement branch and its run is linked here.

## Acceptance

```bash
set -euo pipefail
: "${BASE:?set BASE to pykit's baseline recorded by S6.1.1}"
cd rn-forge/pykit
rg -q '^archetype = "python-lib"' .rn-forge/kiln/config.toml                         # S6.1.2
git diff --quiet "$BASE" -- 'packages/*/src' 'packages/*/tests'                     # S6.1.1, S6.1.2
test ! -e .github/workflows/_package-ci.yml                                           # S6.1.2
task validate                                                                         # S6.1.2
rg -q '^name = "rn-forge-kiln"$' uv.lock                                             # S6.1.1, S6.1.2
rg -A2 '^name = "rn-forge-tooling"$' uv.lock | rg 'editable = "packages/rn-forge-tooling"' >/dev/null
uv run kiln doctor --full                                                             # S6.1.2
```

Not scriptable: S6.1.1's recorded refs and command; S6.1.2's reviewed workflow
mapping and linked CI run.
