# S7.7.5 — The rendered floors admit pykit's Release 9

Brief for
[S7.7.5](../F7.7-kiln-installs-as-a-tool.md#s775-the-rendered-floors-admit-pykits-release-9),
at `99154d0`.

## Goal

`RN_FORGE_TAGS` and kiln's own `pyproject.toml` move to pykit's `release-9`
tags, so every rendered repository, and kiln itself, resolves `rn-forge-commons`
0.10.0, `rn-forge-cli` 0.2.0 and `rn-forge-tooling` 0.3.3. This is the same move
S16.5.4 made for `release-8`; copy its shape.

## Settled

- **The whole table moves.** Release 8's `rn-forge-web` 0.3.1, `rn-forge-auth`
  0.1.1, `rn-forge-fastapi` 0.4.1 and `rn-forge-django` 0.6.1 all require
  `rn-forge-commons<0.10`, so moving commons alone breaks every web cell.
  `RN_FORGE_TAGS` becomes exactly:

    | Distribution | Tag |
    | -- | -- |
    | `rn-forge-commons` | `rn-forge-commons-v0.10.0` |
    | `rn-forge-cli` | `rn-forge-cli-v0.2.0` |
    | `rn-forge-tooling` | `rn-forge-tooling-v0.3.3` |
    | `rn-forge-web` | `rn-forge-web-v0.3.2` |
    | `rn-forge-auth` | `rn-forge-auth-v0.2.0` |
    | `rn-forge-django` | `rn-forge-django-v0.7.0` |
    | `rn-forge-fastapi` | `rn-forge-fastapi-v0.5.0` |
    | `rn-forge-sqlalchemy` | `rn-forge-sqlalchemy-v0.2.4` |

    Every version above is pypi.org's current release (checked 2026-11-18), and
    each Release 9 package requires `rn-forge-commons>=0.8.0,<0.11`, so the set
    resolves together.

- The ranges follow from the table through `archetypes.requirement` (floor = tag
  version, ceiling = next minor before 1.0): `rn-forge-commons>=0.10.0,<0.11`,
  `rn-forge-cli>=0.2.0,<0.3`, `rn-forge-tooling>=0.3.3,<0.4`,
  `rn-forge-web>=0.3.2,<0.4`, `rn-forge-auth>=0.2.0,<0.3`,
  `rn-forge-django>=0.7.0,<0.8`, `rn-forge-fastapi>=0.5.0,<0.6`,
  `rn-forge-sqlalchemy>=0.2.4,<0.3`.

- `RN_FORGE_TAGS`'s docstring reads "pykit's release tags, read from pykit on
  2026-11-18 (`release-9`)." with the ADR-0018 sentence kept.

- **ADR-0018's example changes** (unlike S16.5.4, the story asks for it): line
  21, `rn-forge-commons>=0.8.1,<0.9` becomes `rn-forge-commons>=0.10.0,<0.11`.
  Change nothing else in the ADR.

- Tests are named for behaviour, `test_<subject>_<behaviour>`, with no spec ID
  in a name, docstring or comment.
