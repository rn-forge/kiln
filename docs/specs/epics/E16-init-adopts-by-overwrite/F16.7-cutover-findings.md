These are the **absorb** rows of the real cutover, after
[F16.6](F16.6-cutover-rehearsal-findings.md)'s rehearsals: what pykit and ngkit
still had to do by hand that kiln should do for every repository. Each closes
before
[S7.2.2](../E7-pykit-release-pin-flip/F7.2-kiln-release-and-config-upgrade.md#s722-v010-is-tagged)
(the tag). The findings that need no kiln change are listed at the end.

Read [the board's "Building a story"](../../index.md#building-a-story) first.
Three things hold for every story here:

- **Tests first.** Each test is named after its story ID (`test_s16_7_1_…`),
  written before the code, and shown failing.
- **Goldens.** The rendered cells are not in git (S4.4.9). They are regenerated
  by `task self:golden:render`, which writes `.goldens/working/<cell>` for
  `python-app`, `python-lib`, `python-tool`, `node-lib`,
  `python-web-api-backend=fastapi` and
  `python-web-app-backend=fastapi-frontend=angular`. Prove a template change
  against the base with `task self:golden:compare BASE=HEAD` (it lists only
  the kiln-owned files that differ, per cell). `task self:golden:validate`
  runs `task setup`, `task validate`, `actionlint` and `docs:build` in every
  cell, and needs the network and `pnpm`. `task self:golden:parity` must exit
  0 for the `node-lib` and `python-web-app` cells. Each story says which files
  it expects to differ.
- **This repo follows its templates in the same change** (README): after a
  template or `config.py` edit, run `task kiln:apply` here, then
  `task lint KILN_DOCTOR_FULL=1`. Never hand-edit a generated file.

## S16.7.1 — `[docs] site_dir` is honoured everywhere

**State:** Closed (2026-11-09) · **Depends on:** —

`DocsConfig.site_dir` (`src/rn_forge/kiln/modules/docs/config.py:69`, default
`".docs-site"`) is rendered into `mkdocs.yml` (`site_dir:` via
`modules/docs/templates/mkdocs.yml.j2:6`, omitted when it is `""`), the
`.gitignore` block and `workspace:clean`, but four places spell `.docs-site`
instead of reading it, so a repo with `site_dir = "out/site"` builds into one
directory and uploads another:

| File | Line | Hard-coded |
| -- | -- | -- |
| `src/rn_forge/kiln/modules/tasks/templates/tasks/docs.yml.j2` | 13 | `desc: Build the MkDocs site into .docs-site/ …` |
| `src/rn_forge/kiln/modules/tasks/templates/tasks/ci.yml.j2` | 281, 284 | the `docs:site` desc, and `node tools/ci/assemble-site.mjs .docs-site` |

| `src/rn_forge/kiln/modules/core/templates/gitignore.j2` | 20-22 | a comment, `{{ site_dir }}/`, then a fixed `site/` |

`modules/docs/checks/site.py` is **not** one of them: its only `docs-site` is
the check's name, and it reads no output directory. Do not touch it.

**Decisions (owner, 2026-11-09, and the cases it left):**

- The default stays `".docs-site"`.
- The effective build directory is `site_dir`, or `site` (mkdocs's own default)
  when `site_dir = ""`. One property computes it: `KilnConfig.docs_site_dir`

  consumer below reads that property; none reads `DocsConfig.site_dir` itself.
  `mkdocs.yml.j2` is the one exception and stays as it is: it must keep
  omitting the key for `""`.

  directory: `{{ site_dir }}/`, where the value is `docs_site_dir`. The fixed
  `site/` line is deleted. With `site_dir = ""` the single line is `site/`, so
  mkdocs's default is still covered; with any other value `site/` is no longer
  ignored (a repo that keeps something at `site/` can now commit it).
- The comment above it becomes `# Docs build output ([docs] site_dir)`.
- `_docs.yml.j2` lines 91, 97 and 141 (`SITE_DIR: ${{ runner.temp }}/site`) are
  the workspace pipeline's temp directory, not the configured one. Leave them.
- `modules/cicd/templates/tools/ci/assemble-site.mjs.j2` keeps its behaviour
  (default `dist/site/` when called with no argument; kiln always passes the
  argument). Only its header comment (lines 3-6) changes, to say "into the

## S16.7.2 — `task version` writes and formats `CHANGELOG.md`

**State:** Closed (2026-11-09) · **Depends on:** —

Applies to `node-lib` only: `version` is rendered under `{% if node_lib %}` in
`src/rn_forge/kiln/modules/tasks/templates/tasks/node.yml.j2` (line 64), and the
root `version` calls `node:version` only for `node_lib`
(`modules/tasks/templates/Taskfile.yml.j2:105-113`). `python-web-app` has no Nx
release and is unchanged.

**The gap.** With an argument, the task runs only (`node.yml.j2:72`)
`pnpm exec nx release version {{.CLI_ARGS}} --git-commit=false --git-tag=false --stage-changes=false`.
Nothing writes `CHANGELOG.md`, yet the release's `release:github` task
(`tasks/ci.yml.j2:226-236`) runs `node tools/ci/release-notes.mjs "${tag#v}"`,
which exits 1 with `No section for version … in CHANGELOG.md` when there is no
`## … <version>` heading
(`modules/cicd/templates/tools/ci/release-notes.mjs.j2`: a line starting `## `
that contains the version as a whole token). The release then fails after the
tag is pushed.

**Verified against the pinned Nx.** kiln pins `NX_VERSION = "24.0.4"`
(`modules/node/angular.py:27`); ngkit's `node_modules/nx` is 24.0.4. Its CLI
(`nx/dist/src/command-line/release/command-object.js:140-190`) is
`nx release changelog [version]`; the version is **required** ("An explicit
target version must be specified"), so a `patch|minor|major` specifier cannot be
passed through and the new version must be read back. Options: `--from`
(default: the latest tag), `--to` (default `HEAD`), the shared git options
`--git-commit`, `--git-tag`, `--stage-changes`, and `--first-release` (use when
no tag exists). `nx.json`'s `release.changelog.workspaceChangelog.createRelease`
is `false` (kiln writes it, `modules/node/scaffold.py:57`), so Nx does not call
GitHub. The heading Nx writes is `## <version> (<date>)` (ngkit's
`CHANGELOG.md`: `## 0.3.0 (2026-10-25)`), and ngkit's file is mdformat-clean in
that shape, so the markdown formatter keeps the heading release-notes.mjs
matches.

**Decisions:**

- One task does bump, changelog and format: `version` in `node.yml.j2`. The bump
  branch becomes, in order: `nx release version` (as today); read the new
  version back;
  `nx release changelog <version> --git-commit=false --git-tag=false --stage-changes=false`,
  plus ` --first-release` when `git tag --list 'v*'` prints nothing (the
  same derivation `ci:release:state` uses, `ci.yml.j2:184`); then the markdown
  format task.
- The read-back reuses the existing no-argument script, defined once as a shell
  function `read_version` inside the one `bash` block, so the script text is
  not duplicated. The no-argument branch calls `read_version` and nothing else
  (still no side effects).
- The format step is a second `cmds` entry, `- task: :quality:format:markdown`
  with `if: '[ -n "{{.CLI_ARGS}}" ]'` (precedent for `:`-prefixed calls and
  `if:`: `ci.yml.j2:90`, `kiln.yml.j2:18`). It formats every Markdown file, as
  `task format` does; the release PR carries a formatted section.
- Both task descriptions say so: `node.yml.j2:65` and `Taskfile.yml.j2:107`
  become
  `Print the publishable projects' version, or bump it, write its CHANGELOG.md section and format it (pass -- patch|minor|major|x.y.z).`
  (the `node.yml.j2` one keeps its trailing "the root version task runs
  it").

**Build — tests first,** in `tests/modules/tasks/test_node_release.py`. Shape:
`test_s15_8_5_7_version_with_a_bump_runs_nx_and_nothing_else` (line 293, which
this story changes) and the `run` fixture (line 90). The `run` fixture gains a
fake `uv` that logs `uv $*` to the same log and discards stdin, so
`quality:format:markdown`'s `uv run --group docs mdformat` pipeline runs without
the network.

1. `test_s16_7_2_1_a_bump_writes_the_changelog_then_formats`: in the temporary
   repository (no tags), `task version -- minor` logs these lines, in this


    The third line is checked by its `uv run --group docs mdformat` prefix. This

    `test_s15_8_5_7_version_with_a_bump_runs_nx_and_nothing_else`; keep its

## S16.7.3 — Prettier for the node archetypes

**State:** Closed (2026-11-09) · **Depends on:** S16.7.1

`node-lib` and `python-web-app` have no formatter for their TypeScript, HTML,
SCSS, JSON or YAML: the scaffold's `package.json` has `eslint-config-prettier`
(`.goldens/working/node-lib/package.json:31`) but no `prettier`, kiln renders no
Prettier configuration (E9 says so, below), and `task format` formats only
Python (not in `node-lib`), Markdown and TOML. ngkit runs Prettier already
(`~3.9.10`, a `.prettierrc`, a `.prettierignore`). Owner decisions, 2026-11-09:
`.prettierrc` is a managed file; `.prettierignore` is a fenced file; both
archetypes with the node runtime get Prettier; `prettier` is a dev dependency.

**Decisions (the owner's, and the ones this story makes):**

1. **Which archetypes.** `node-lib` and `python-web-app` (every archetype where
   `tasks/node.yml` is rendered). The python archetypes get neither file.
1. **`.prettierrc`: managed, YAML, with a provenance header.** Prettier reads a
   `.prettierrc` as JSON or YAML. JSON cannot carry the
   `# Generated by kiln …` header, so the file is YAML and the first line is
   the standard header
   (`# Generated by kiln {{ kiln_version }} from .rn-forge/kiln/config.toml — do not edit; run 'kiln apply'`,
   as `modules/core/templates/editorconfig.j2:1`). The path is ngkit's, so
   adoption overwrites it in place. Content, seeded from ngkit's
   `.prettierrc`:
    ```yaml
    singleQuote: true
    bracketSameLine: true
    overrides:
    ```

  `ci-entrypoint` and workflow findings it prints, `_fail_on_errors`). The
  runbook's step 3 deletes them before step 4; this is the signal, not a bug.
- **`apps/.gitkeep` is not needed in adopted repositories.** `reconcile_node`
  writes it for `new` only, so Sonar's `sonar.sources` exists; an adopted
  repository has its own sources.
- **pykit's root `pyproject.toml` is repo-owned after scaffolding.** Aligning it
  with what kiln would now scaffold is pykit's own story, not kiln's
  ([ADR-0009](../../../adr/ADR-0009.md)).
