# S9.5.5 — The one-entrypoint rule allows project-scoped native commands

Brief for
[S9.5.5](../F9.5-node-lib-release-findings.md#s955-the-one-entrypoint-rule-allows-project-scoped-native-commands),
at `80f9fc2`.

## Goal

For `node-lib`, the rendered standard and the `AGENTS.md` block say that
workflows and the gate go through `task`, and that a document may name a
project-scoped native command (`nx serve <app>`, `nx g …`,
`nx show project <name>`) where the ten verbs have nothing for it. Every other
archetype's rendering is unchanged.

## Settled

- Owner, 2026-11-17: narrow the rule; no pass-through verb.

- **Only `node-lib` changes.** Every other archetype, kiln's own `python-app`
  included, renders byte-for-byte as before.

- `standard.md.j2` §1, the `node_lib` branch, becomes exactly:

    ```markdown
    `task` is the only entrypoint for CI and for the gate. A workflow step, and
    everything `validate`, `lint`, `test` and `build` run, goes through `task`;
    nothing there invokes `uv`, `mkdocs`, `pnpm`, `npx`, `nx`, `ng` or `kiln`
    directly. A document may name a native command that is scoped to one
    project and that no verb covers, such as `pnpm exec nx serve <app>`,
    `pnpm exec nx g …` or `pnpm exec nx show project <name>`, where it says what
    the command is for.
    ```

    The non-`node_lib` branch keeps today's sentence. Restructure the Jinja
    `{% if node_lib %}` so each branch holds its whole paragraph.

- The `AGENTS.md` block's entrypoint bullet
  (`modules/instructions/artifacts.py::_entrypoint_bullet`) for `node-lib`
  becomes:
  `**Entrypoint:** `task`. Workflows and the gate never invoke <tools> or `kiln` directly; a document may name a project-scoped native command no verb covers — the ten root verbs are <verbs>.`
  For every other archetype the bullet is unchanged. Use
  `config.is_node_lib` (or the archetype check the module already uses) to
  choose.

- `docs/reference/standard-repo.md` §1: add one paragraph after the first,
  saying that for `node-lib` the rule covers workflows and the gate, and a
  document may name a project-scoped native command no verb covers, with the
  same three examples.

- The `ci-entrypoint` check, which rejects a wrapped tool in a workflow, does
  not change.

- Tests are named for behaviour, `test_<subject>_<behaviour>`, with no spec ID
  in a name, docstring or comment.
