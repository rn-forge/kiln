# S18.8.2 — The sibling-import allow-list is empty

Brief for
[S18.8.2](../F18.8-modules-meet-through-composition.md#s1882-the-sibling-import-allow-list-is-empty),
at `f74a1d6`. Paths are under `src/rn_forge/kiln/`.

## Goal

No concern module imports a sibling. `.importlinter`'s
`concern-modules-are-independent` contract ignores only its two composition
entries. No rendered file and no doctor finding changes.

## Settled

**`KilnConfig` is the composition seam** (lead's ruling, 2026-11-17). The
contract already lets `rn_forge.kiln.config` import any module
(`rn_forge.kiln.config -> rn_forge.kiln.modules.**`), and every module's
artifacts and checks receive a `KilnConfig`. So the facts one module needs from
another become `KilnConfig` members. There is no other "render context" to pass
them through.

The five ignores left at `f74a1d6` (`.importlinter`, in the contract below the
`# END rn-forge kiln` marker, which is repo-owned) and their replacements:

| Ignore | Used for | Replacement |
| -- | -- | -- |
| `tasks.artifacts -> cicd.registry` | `registry.enabled_names(ci, archetype, len(packages))` (`tasks/artifacts.py:75`) | `KilnConfig.ci_checks -> frozenset[str]`: `registry.enabled_names(self.ci, self.archetype, len(self.packages))`. `licenses_enabled` (`config.py`) uses it. Check that `tasks`' `len(packages)` is `len(config.packages)`; if not, record it and keep `tasks`' count by passing it in. |

Check `pyproject.toml`'s package-data or build config still ships `pins.toml`. |

  `rn_forge.kiln.config -> rn_forge.kiln.modules.**` and
  `rn_forge.kiln.modules.registry -> rn_forge.kiln.modules.**`. Update the
