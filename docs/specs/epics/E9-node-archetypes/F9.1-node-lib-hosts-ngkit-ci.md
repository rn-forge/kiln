Added 2026-10-13, while E9 is deferred, so that the gap is written down before
the epic unparks. ngkit's CI is written as a portable template. Its
`docs/architecture/ci-template.md` lists template-owned files that name no
project, and repository-owned declarations (`nx.json`, project targets and tags,
`.nvmrc`, `packageManager`). That split maps onto kiln's split between generated
and seeded files. The commands are what do not fit: ngkit has no `Taskfile.yml`
(`package.json` `scripts` is `{}`), and its workflows call `pnpm exec nx`,
`pnpm dlx nx`, `npm pack` and `node tools/ci/*.mjs` directly. `ci-entrypoint`
fails each of those calls once `pnpm npx nx ng` are in a node archetype's
`forbidden_tools`
([F5.1](../E5-web-archetypes/F5.1-web-library-sets-and-modules.md)).

The shared patterns are F6.3's for every archetype: timeouts, `ci-ok`, the
published release as the record, and pins. What follows is node-only. The
evidence is ngkit's `.github/` and `tools/ci/`, read on 2026-10-13.

**Elaborated 2026-10-28** against ngkit `0c2cd2a`, which is this feature's
golden ([Design](#design)). The stories outlined on 2026-10-13 keep their IDs
and topics; S9.1.7–S9.1.12 were added for what the outline left out: the owner
decisions, the archetype itself, the root verbs, the generated helpers, the one
Pages site and the bootstrap compare.

## Audit against the CI contract

`node-lib` must meet [ADR-0016](../../../adr/ADR-0016.md)'s contract. Each open
question this page carried until 2026-10-28, answered from ngkit at `0c2cd2a`
(2026-10-27). **Meets** means the golden is kept as it is; **diverges** names
the story that closes the gap, or the S9.1.7 decision it waits on.

| Contract rule | ngkit at `0c2cd2a` | Verdict |
| -- | -- | -- |
| A pull request diffs against its base, a push against the last green run | `nrwl/nx-set-shas` sets `NX_BASE` to the last successful `ci.yml` run on the branch for a push, and to the merge base for a pull request | meets |
| A dispatch selects all | `ci.yml` runs `nx affected` on dispatch too | diverges: S9.1.2 runs `run-many` on dispatch |
| A change outside every unit and outside docs selects all | `nx affected` marks all only for files in `namedInputs.sharedGlobals` (`ci.yml` alone) or root manifests; a change to `tools/ci/*.mjs` or the setup action selects nothing | diverges: S9.1.2's `ci:targets` widens to all, as the decision below says |
| Docs-only selects none | `docs/` is in no project, so nothing is affected | meets |
| `validate` gates everything | no `validate` job; `ci-cloud`/`ci-local` start at once | diverges: S9.1.2 adds kiln's `validate`, and every job needs it |
| Sonar waits on the gate, skipped for fork pull requests | `sonar.qualitygate.wait=true`; skipped for forks and for `dependabot[bot]` | meets. The `dependabot[bot]` skip is kept: GitHub gives Dependabot runs no secrets either |
| Nothing publishes from a pull request | `package` packs on every run, but only uploads a workflow artifact; nothing reaches a registry or a release | meets |
| Publishing only for units whose every check passed | one fixed group, gated on a green `ci.yml` run for the commit, so any failed check holds back every library | meets (stricter than per unit) |
| Release from the default branch only, after the quality gate | the gate is a successful `ci.yml` run, which includes `sonar` and `ci-ok`; but `release.yml` can be dispatched from any branch | diverges: S9.1.7 decision 1 |
| After release: install from outside, then deploy docs once | `published-install` installs the released tarballs; docs deploy from `ci.yml` on every push to `main`, as kiln's own `docs.yml` does | meets for install. Docs: S9.1.7 decision 2 |
| `ci-ok` is the one required check; skipped is not failure | `ci-ok` fails only on `failure`/`cancelled`, and also when neither `ci-*` path succeeded | meets |
| Every step goes through `task` | most `run:` steps are inline `pnpm exec nx`, `node tools/ci/*.mjs`, `gh` and `git` shell | diverges: every story below moves each body into a `ci:*` task, verbatim |
| Triggers: default branch, pull requests, dispatch | adds `release/**` pushes and pull requests | diverges: S9.1.7 decision 1 |

## Decisions

Answered by the owner on 2026-10-14, and recorded in
[ADR-0015](../../../adr/ADR-0015.md).

1. **Release tag:** `v<version>` for one fixed group, as ngkit's ADR-0003 has
   it. There is no per-package option.
1. **Nx Cloud:** `nx start-ci-run` and `nx fix-ci` get a named exemption from
   `ci-entrypoint` for `node-lib`, and nothing else does.
1. **Release trigger:** `[ci] release = "nx-dispatch"`, the default for
   `node-lib`. The release commit is pushed with a GitHub App token
   (`actions/create-github-app-token`), as ngkit's `release.yml` does since
   `1934be3` (2026-10-14).
1. **`tools/ci/` helpers:** generated files. The generated-path list gains
   `tools/ci/*.mjs` for `node-lib`.
1. **Task verbs:** as proposed. The root verbs map onto Nx, and the CI-only
   steps are internal `ci:*` tasks. The Nx primitives live in
   `tasks/node.yml`, the file
   [S4.12.3](../E4-generator/F4.12-task-files-by-owner.md#s4123-nodeyml-holds-the-frontend-toolchain-and-webyml-keeps-webdev)
   creates for `python-web-app` (2026-10-21). `node-lib` extends that file
   and does not add a second Nx file.

Decided 2026-10-28, while elaborating:

1. **ngkit at a pinned commit is the golden.** The release-0 goldens were
   hand-authored repositories that kiln's templates were rendered to match
   ([S4.4.3](../E4-generator/F4.4-render-matrix.md#s443-bootstrap-exit-the-kiln-owned-files-match)).
   For `node-lib` that repository already exists: ngkit's template-owned
   files name no project, by ngkit's own rule, so they are the templates'
   source. Nothing is copied into kiln as a fixture; S9.1.12 compares against
   an ngkit checkout at `NGKIT_REF`.
1. **A transform is the only allowed difference.** Every hunk between a rendered
   `node-lib` file and its ngkit source is one of the transforms in the design
   (T1–T17). A hunk that is none of them is a template defect.

## S9.1.7 — Decide: `node-lib`'s release branches and its Pages site

**State:** Closed (2026-10-29)

The two contract divergences that are the owner's to answer. Recommendations are
given; S9.1.2, S9.1.5 and S9.1.11 are written against them, and change with
them.

1. **`release/**` triggers and release from a non-default branch.** ngkit
   triggers CI on `release/**` and may dispatch a release from one, for
   hotfixes to an older major (its `dist-tag` input names `v<major>-lts`). The
   contract names the default branch only. ngkit has no `release/**` branch
   (`git branch -r`, 2026-10-28).
    - Option A: drop them. `node-lib` triggers on `main` only, and
      `ci:release:gate` fails when `GITHUB_REF_NAME` is not the default branch.
    - Option B: revise ADR-0016 so a `release/**` branch is a default branch for
      triggers and release, for every archetype.
    - **Recommendation: A.** No repository has the branch, and B changes the
      contract for every archetype. The `dist-tag` input stays; a hotfix line
      is a later ADR when one is needed.
1. **One Pages site.** A repository has one Pages site. ngkit deploys Compodoc
   and Storybook there; [ADR-0012](../../../adr/ADR-0012.md) says every
   repository publishes one MkDocs site. Both cannot deploy.
    - Option A: the idea `node-docs-site-assembly` becomes this feature's: the
      `docs` job builds MkDocs (`task docs:build`) into `.docs-site/`, then
      `assemble-site.mjs` writes Compodoc under `api/<project>/` and Storybook
      under `storybook/<project>/` in it, and deploys once.
    - Option B: MkDocs only; Compodoc and Storybook stop being published.
    - **Recommendation: A.** ngkit loses nothing, and ADR-0012 already describes
      this assembly. The `ideas/index.md` row is removed.

**Acceptance:**

- The owner's answer to each is recorded here, with the date. Decision 2, option
  A, revises ADR-0012 with a dated `## Background` line; decision 1, option B,
  revises ADR-0016.

**Owner's answers, 2026-10-29:**

1. **Option A.** `node-lib` triggers on `main` only, and `ci:release:gate` fails
   off `main` unless the run is a dry run. ADR-0016 is unchanged.
1. **Option A.** One Pages site: MkDocs, with Compodoc and Storybook assembled
   under it. ADR-0012 gains a dated `## Background` section saying so.

Also decided that day: the `frontend` module is renamed `node`, so a module is
named for its toolchain, as `python` is, and a `java` module would be. That is
[S9.1.13](#s9113-the-frontend-module-is-renamed-node), and S9.1.8 waits on it.

## S9.1.13 — The `frontend` module is renamed `node`

**State:** Closed (2026-10-29) · **Depends on:** S9.1.7

The module scaffolds the pnpm/Nx toolchain, and `node-lib` has no frontend
application. Its task file is already `tasks/node.yml`.

**Build:**

- `src/rn_forge/kiln/modules/frontend/` moves to `modules/node/`; the module's
  `name` is `"node"`, `FrontendModule` becomes `NodeModule` and `FRONTEND`
  becomes `NODE`. `scaffold_frontend` and `reconcile_frontend` become
  `scaffold_node` and `reconcile_node`.
- Every importer follows: `modules/registry.py`, `commands.py`, the
  `python-web-app` `archetype.toml` `modules` list, and the
  `concern-modules-are-independent` contract in this repo's import contracts.
- `tests/modules/frontend/` moves to `tests/modules/node/`. Test names keep
  their story IDs.
- Unchanged: the `--frontend` flag, the `frontend` key of
  `[archetype.python-web-app]`, `config.frontend`, the
  `.staging/<name>/frontend` directory, and every rendered file. These name
  the framework a repository chose, not the toolchain.
- Current-state docs that name the module follow (`docs/reference/`,
  `docs/architecture/`, `docs/runbooks/`). Closed stories and ADRs keep the
  name they were written with.

**Acceptance:** `task validate` passes, and `task self:golden:compare BASE=HEAD`
shows no rendered file changed in any cell.

**What the build settled that the story did not say:**

- **The import contract** lives in this repo's own tail of `.importlinter`,
  below the END marker, not in generated output; the module line was edited
