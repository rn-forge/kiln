Makes the generated task surface match the rules in
[ADR-0007](../../../adr/ADR-0007.md) without renaming anything: the matrix bug,
the override rule, the gate, the descriptions, the generated task tables in the
standard, and the docs. F17.2 renames tasks, after E15.

Every story is built in the worktree `../kiln-task-standard` (branch
`feature/task-standard`), never in the shared checkout. F17.1 lands on
`feature/v1` as one commit, `F17.1`, rebased onto E15's close (`8202297`). The
rebase resolves the overlaps with E15 in `cicd/registry.py`,
`tasks/artifacts.py`, `Taskfile.yml.j2` and `standard.md.j2`, and then
re-renders the generated files (`task kiln:apply`) and the derived regions
(`task docs:generate`) rather than merging them by hand.
`docs/architecture/tasks.md` is then brought up to E15's task names: every
Python archetype now renders `ci:validate`, `ci:plan`, `ci:test`,
`ci:integration`, `ci:smoke`, `ci:suite` and `ci:verify-release`, and `node-lib`
renders `ci:release:finalize` and the internal `ci:version`, with no
`ci:release:gate`, `ci:release:version` or `ci:published-install`. The board's
[Building a story](../../index.md#building-a-story) procedure applies. Commit
nothing.

## S17.1.1 — The full matrix fills `{stack}` per row

**State:** Closed (2026-11-05)

`registry.render_matrix(None)` calls `_verb_cell(c.verb, "python")` for every
row, so `docs/architecture/ci.md` shows the `node-lib`-only pnpm audit as
`task python:lint:audit`, and the licences row names only `python:`.

**Build — tests first,** in `tests/modules/cicd/test_registry.py`:

1. `test_s17_1_1_1_node_only_row_uses_node`: in `render_matrix(None)`, the
   `pnpm-audit` row's verb cell is `` `task node:lint:audit` ``.
1. `test_s17_1_1_2_both_stacks_name_both`: the `licenses` row's verb cell is
   `` `task python:lint:licenses`; `node-lib`: `task node:lint:licenses` ``.
1. `test_s17_1_1_3_plain_verbs_unchanged`: every row whose verb has no `{stack}`
   renders exactly as before (compare against `_verb_cell(c.verb, "python")`
   for those rows).

**Build:** in `src/rn_forge/kiln/modules/cicd/registry.py`, add
`_verb_cell_all(check: CiCheck) -> str`, used by the `archetype is None` branch
in place of `_verb_cell(c.verb, "python")`:

- If `check.verb` is `None` or has no `{stack}`, return
  `_verb_cell(check.verb, "python")`.
- Otherwise, the stacks are `"node"` for `node-lib` and `"python"` for every
  other archetype in `check.archetypes`. With one stack, return
  `_verb_cell(check.verb, stack)`. With both, return
  `` f"{_verb_cell(check.verb, 'python')}; `node-lib`: {_verb_cell(check.verb, 'node')}" ``.

Then run `task docs:generate` so the derived `ci-matrix` region of
`docs/architecture/ci.md` is rewritten.

**Acceptance:**

- The three tests pass, and `task validate` passes (including
  `tests/modules/docs/test_ci_matrix.py` and `test_s15_1_1_5`).
- `docs/architecture/ci.md` shows `` `task node:lint:audit` `` on the
  `pnpm-audit` row.

**What the build settled that the story did not say:**

- `_verb_cell_all` decides the stacks from `check.archetypes`: `node-lib` maps
  to `node`, every other archetype to `python`. A set of one stack renders
  that stack's cell; both render the `` ; `node-lib`: … `` form from the
  story.
- The tests find a row by its first cell and read the second, using
  `registry._name_cell`; `test_s17_1_1_3` compares every verb without
  `{stack}` to `_verb_cell(verb, "python")`.
- The tests were written and the build made in one step, so the red run of the
  three tests was not observed separately.
- `task docs:generate` rewrote `docs/architecture/ci.md` (two rows).

## S17.1.5 — The standard's task tables are generated from the task files

Design decisions 1 and 6; findings 2 and 3. The rendered standard's verb table
is copied by hand, and it says every other task is internal, which no archetype
holds to.

**State:** Closed (2026-11-05)

**Build — tests first,** in `tests/modules/tasks/test_surface.py` (new) and
`tests/modules/instructions/test_artifacts.py`:

1. `test_s17_1_5_1_surface_is_what_task_lists`: for each archetype, apply a
   rendered repository and run `task --list --json` the way
   `test_s4_3_3_1_task_list_json_lists_exactly_the_ten_root_verbs` does; the
   set of `(name, desc)` pairs equals `surface.public_tasks(config)`.
1. `test_s17_1_5_2_developer_table`: for each archetype, every public task not
   under `ci:` appears in the rendered `.rn-forge/kiln/standard.md` as the row
   `` | `task <name>` | <desc> | ``, and the phrase
   `The public surface for this repo is exactly` is gone.
1. `test_s17_1_5_3_ci_table`: every `ci:` task appears as a row of the second
   table. For `node-lib`, the `ci:release:state` row has its `|` escaped as
   `\|`.
1. `test_s17_1_5_4_internal_sentence`: the standard says
   `` Every other task is `internal: true` `` only after both tables.

**Build:**

- `src/rn_forge/kiln/modules/tasks/surface.py` (new):
  `class PublicTask(NamedTuple)` with `name: str` and `desc: str`, and
  `def public_tasks(config: KilnConfig) -> list[PublicTask]`. It calls
  `tasks.artifacts.render(config)`, keys the artifacts by `path`, and parses
  `Taskfile.yml` and each `tasks/<ns>.yml` it includes, with the YAML loader
  and `task_specs` that `modules/tasks/checks/layout.py` already use. It skips
  repository-owned includes, which are seeded artifacts: their tasks are not
  kiln's. It returns every task without `internal: true`, as `<name>` for the
  root file and `<ns>:<name>` for an include, sorted by name.

- `src/rn_forge/kiln/modules/instructions/artifacts.py`, `context()`: add
  `"developer_tasks"` and `"ci_tasks"`, splitting `public_tasks(config)` on
  the `ci:` prefix. Add a Jinja filter or a context helper `md_cell` that
  escapes `|` as `\|`.

- `src/rn_forge/kiln/modules/instructions/templates/standard.md.j2`, §1: replace
  everything from `The public surface for this repo is exactly:` through the
  `{% endif %}{% endif %}` that closes the `web:dev` row with:

    ```text
    The developer surface for this repo is exactly:

    | Verb | What it does |
    | -- | -- |
    {% for t in developer_tasks %}| `task {{ t.name }}` | {{ t.desc | md_cell }} |
    {% endfor %}
    The CI surface, `ci:*`, is public only because a workflow step runs it from
    the command line, which go-task refuses for an internal task. It is CI's;
    a developer has no reason to call it:

    | Task | What it does |
    | -- | -- |
    {% for t in ci_tasks %}| `task {{ t.name }}` | {{ t.desc | md_cell }} |
    {% endfor %}
    ```

    Keep the `web_app` frontend paragraph and the workspace `build`/`version`
    paragraph after the tables. In the sentence after them, replace
    `` `kiln:diff` and `kiln:apply` are public too. Every other task is `internal: true`. ``
    with `` Every other task is `internal: true`. ``.

- Update the existing instructions tests that asserted rows of the old
  hand-written table, and record each one under this story.

- Run `kiln apply` here (`task kiln:apply`), then `task self:golden:render`.

**Acceptance:**

- The four tests pass, and `task validate` passes.
- In every golden cell, the rendered `standard.md` passes the markdown check.
  Run `task self:golden:validate`. If it fails only because a cell runs
  `kiln doctor` from the pushed `[kiln] ref` (see F16.4's acceptance note),
  record that, and show that `task lint`'s markdown step passes on each cell's
  `standard.md`. If mdformat rewrites a description, extend `md_cell` until
  every cell is stable, and record what it escapes.

**What the build settled that the story did not say:**

- `public_tasks` keeps a task only if it has a non-empty `desc:` as well as no
  `internal: true`, because `task --list` hides a task without a description.
  Repository-owned includes are those named in `[tasks] includes`; an include
  path that kiln did not render is skipped as well.
- `md_cell` escapes `|` everywhere, and `<` and `*` outside a code span, with a
  backslash. mdformat rewrote `ci:release:tag`'s description
  (`name=<the one v* tag at HEAD>`) to `name=\<the one v\* tag at HEAD>`, so
  the filter does the same. Nothing else in any archetype's descriptions was
  rewritten.
- `md_cell` is a Jinja filter, registered on the cached template engine in
  `instructions.artifacts.render`. It is exported from that module so the
  tests can import it.
- `modules/instructions/artifacts.py` now imports `modules.tasks.surface`, a
  sibling concern module. The story names that edge, and the
  `concern-modules-are-independent` contract needed one more `ignore_imports`
  line in `.importlinter` (`instructions.artifacts -> tasks.surface`). The
  comment above that contract says to add no fifth edge; the story's design
  needs this one.
- `test_s17_1_5_1` is `tests/modules/tasks/test_surface.py`'s only test (six
  archetype cells, including both web ones). Tests 2 to 4 are parametrised the
  same way in `tests/modules/instructions/test_artifacts.py` and read the
  tables from section 1 split at `The CI surface` and `Every other task is`. I
  added `test_s17_1_5_5_task_tables_are_mdformat_clean`, which runs mdformat
  over the two tables of each cell.
- No existing instructions test failed: the old table tests read the same
  descriptions from the new rows.
- The rest of `standard.md` is not mdformat-stable today (a double blank line
  before "kiln is not a dependency", and the old hand-padded tables, now
  gone), and this repository's `.mdformat.toml` excludes the file. I did not
  change that: the generated tables are stable, the rest is as it was.
