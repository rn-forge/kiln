# ADR-0010 — The canon carries an architecture baseline, as managed records

**Status:** proposed (2026-09-28) · **Scope:** the product code of every
generated repository

## Decision

kiln renders an architecture baseline into every generated repository: a small
set of decision records that fix the design of the product code, not only the
repository around it. They are managed artifacts under `docs/adr/kiln/`, named
`ARCH-<nnnn>`, hash-checked like any other kiln file, and linked from a kiln
block in the repository's `docs/adr/index.md`. They render with the `mkdocs`
docs profile only; a repository with another profile has no `docs/` tree and
gets the import contracts without the records.

A record belongs in the baseline only if it follows from the repository's
topology and stack, never from its domain. The test: it holds for a business API
and for a dashboard microsite alike. Auth schemes, storage engines and
domain-modelling styles fail that test and stay with each repository.

Records are composed from the configuration's dimensions, as the task vocabulary
is ([ADR-0007](ADR-0007.md)): each record says which archetypes and flags it
applies to, and a repository gets the union. A record enforceable by an import
contract is enforced by one, in kiln's block of `.importlinter`. Records and
contracts reach every repository on kiln at its next pin.

A repository departs from a record through an ADR of its own that names the
record and the part it supersedes. It never edits the record.

kiln may also write minimal starter source into `src/` and `tests/`, once, at
`kiln new`: working plumbing that uses the rn-forge libraries the repository's
dependencies already declare. A starter file is seeded
([ADR-0003](ADR-0003.md)): written once, repo-owned afterwards, never
drift-checked and never re-rendered by `apply`. Managed and rendered files stay
out of `src/` and `tests/`. Ongoing code generation stays with the frameworks.

## Consequences

- A new repository starts with a stated architecture, and an agent building its
  first feature has a design to follow and a contract that fails when it
  strays.
- A record is written once and reaches every repository it applies to. Changing
  one changes the architecture of every repository at its next
  `kiln config upgrade`, so a changed record ships as a noted, breaking
  release change.
- Record identifiers (`ARCH-<nnnn>`) are global, so `ARCH-0001` means the same
  thing in every repository. They are never renumbered or reused, and they
  cannot be mistaken for the repository's own `ADR-<nnnn>`.
- The cost: a baseline must stay generic, so it says less than a repository's
  own design would. And starter source is deliberately small, so it proves the
  contracts render and pass and the libraries are wired, not that the patterns
  are right.
- A starter file is the repository's after `kiln new`; improving the starter
  reaches new repositories only, never existing ones.

## Alternatives considered

- **Seeded records.** The repository would own them after scaffolding, and
  doctor ignores seeded files ([ADR-0003](ADR-0003.md)). Each repository's
  copy would drift, and nothing would notice. This rejects seeding the
  *records*, not the starter source, which no contract depends on.
- **Seeded but drift-checked.** ADR-0003 rejected enforcing seeded files: a file
  doctor checks but the repository may edit has two owners, and neither can
  tell an intended change from drift.
- **One comprehensive record per archetype.** It would enumerate layers, names
  and patterns, which makes it a spec, not a decision. Every archetype × flag
  cell would also need its own copy of the shared parts.
- **Records under `.rn-forge/kiln/baseline/`** (this ADR's first choice). They
  would render for every docs profile, but mkdocs `--strict` fails a link out
  of `docs/`, so the repository ADR that departs from a record could not link
  it, and the records would never appear on the site. Every repository on kiln
  uses the `mkdocs` profile.
- **Records directly in `docs/adr/`.** They would share the repository's own ADR
  listing and numbering. The `kiln/` subfolder and the `ARCH-` prefix keep
  them apart.
- **`B-<nnnn>` or `KILN-<nnnn>` identifiers.** `B-` says nothing to a reader who
  has not met the word "baseline"; `KILN-` reads as kiln's own ADRs, which
  rendered files already cite as "kiln ADR-<nnnn>".
- **Prose in `standard.md` only.** It carries no identifier a repository's ADR
  can cite and supersede.

## Background

2026-10-12 (owner): the earlier stance that kiln writes nothing inside `src/`,
and that the goldens keep trivial product code, is replaced by the seeded
starter rule. Every generated repository should start with minimal working
plumbing that uses the rn-forge libraries its dependencies declare.

2026-11-02: `kiln generate package` seeds the package it creates, and `init`,
`apply` and `config-update` write no starter.

2026-11-19 (owner): the records move from `.rn-forge/kiln/baseline/` to
`docs/adr/kiln/`, with `ARCH-<nnnn>` identifiers and the `mkdocs` profile only;
every repository on kiln receives records and contracts at its next pin.
