# F13.1 — Derived regions, starting with the nav

**Status:** planned

Epic: [E13](index.md) · Design: [E13 design](design.md#derived-regions) ·
**Depends on:** [S4.3.2](../E4-generator/F4.3-concern-modules.md#s432-docs)
(done); [ADR-0003](../../../adr/ADR-0003.md)'s revision,
[ADR-0011](../../../adr/ADR-0011.md) and [ADR-0012](../../../adr/ADR-0012.md)
accepted

The nav stays generated, but it stops being an apply artifact with a stored
hash. It becomes the first derived region: written by `kiln docs-generate`,
checked by the `docs-generate` check, and titled from page H1s. The command,
check, task and lint task named `docs-nav`/`docs:nav` are renamed, not kept as
aliases. Its fence is renamed from `generated nav` to `derived nav`. That
separates it from the old block's `state.json` key, and from the `generated`
check, which hash-checks managed artifacts. No repository generated by kiln has
applied a `state.json` outside kiln and its goldens, so no migration code is
needed. The entry is deleted by hand from those four baselines.

This feature also gives the reference one complete
[ownership model](design.md#the-ownership-model), in place of the three-kind
table that the ownership table already outgrew.

[board's procedure](../../index.md#building-a-story).**

## S13.1.1 — The nav is a derived region

**Status:** planned

**Build:**

- New `modules/docs/generate.py`:

    - `generate(root: Path) -> list[Path]` rewrites every stale derived region
      under *root* and returns the files it wrote. In this story that is only
      `mkdocs.yml`'s nav, through `nav.update_nav`. It does nothing unless
      `root / "mkdocs.yml"` exists.
    - `stale(root: Path) -> list[Finding]` returns `docs.nav-stale` when
      `update_nav` reports a change, with `path="mkdocs.yml"` and the message
      `` the derived nav is stale — run `task docs:generate`  ``.
    - F13.2 adds the board and Scope regions to both functions, and S11.1.1 adds a
      `packages: Sequence[str] = ()` parameter to both.

- `modules/docs/nav.py`: `NAV_BLOCK = ManagedBlock("derived nav", indent="  ")`.
  Add `page_title(path: Path) -> str`, which returns the first line starting
  `# `, stripped of `# ` and surrounding whitespace, or
  `title_from_filename(path.name)` when there is none. `_children_entries`
  titles every page except `<area>/index.md` with `page_title`, and the area's
  own index stays `"Overview"`.

- Rename `modules/docs/checks/nav.py` to `modules/docs/checks/derived.py`, with
  `NAME = "docs-generate"`. Its `check(config, root)` returns `[]` unless
  `config.docs_profile == "mkdocs"`, and `generate.stale(root)` otherwise.
  Update `DocsModule.checks` in `modules/docs/__init__.py`, and the expected
  name in `tests/test_checks_registry.py`.

- `modules/docs/artifacts.py`: `render` returns the seeds only. Delete the
  `BLOCK` artifact, `_nav`, and the now-unused imports (`shutil`, `tempfile`,
  `NAV_BLOCK`, `build_nav`). The module docstrings in `artifacts.py` and in
  `DocsModule.artifacts` say "the seeded docs tree" only.

- `modules/docs/templates/mkdocs.yml.j2`: end with the empty fence, so that
  generation never has to insert one:

    ```yaml
    # The nav below is derived by `kiln docs-generate` from docs/_areas.yml and
    # the tree — do not hand-edit between the markers; run `task docs:generate`
    # after adding a page. `task lint` fails on a stale nav.
    nav:
      # BEGIN derived nav
      # END derived nav
    ```

    Update `modules/docs/scaffold.py`'s docstring to match: the body carries the
    empty fence.

- `commands.py`: rename `docs_nav` to `docs_generate(path: Path) -> None`. It
  calls `generate.generate(path)`, then prints `updated <file>` for each file
  written, or `no change`. Update `__all__`. In `cli.toml` **and** in kiln's
  own `.rn-forge/kiln/config.toml` (`[[cli.commands]]`):
  `name = "docs-generate"`, `target = "rn_forge.kiln.commands:docs_generate"`.

- `commands.new`: after `cycle.apply(...)` and before `_fail_on_errors`, call
  `generate.generate(workspace)` when `resolved.docs_profile == "mkdocs"`.

- Tasks: in `modules/tasks/artifacts.py`, `_DOCS_TASKS` has `"docs:generate"` in
  place of `"docs:nav"`, and `"quality:lint:docs-nav"` becomes
  `"quality:lint:docs-generate"`. Make the same change in
  `archetypes/__init__.py`. In the templates:

    - `tasks/docs.yml.j2`: the task `nav` becomes `generate`, with
      `desc: Regenerate the docs' derived regions.`, the override key
      `docs:generate`, and the command `uv run kiln docs-generate .`.
    - `tasks/quality.yml.j2`: `lint:docs-nav` becomes `lint:docs-generate`, with
      the override key `quality:lint:docs-generate` and the command
      `uv run kiln doctor . --only docs-generate`.
    - `Taskfile.yml.j2`: `task: quality:lint:docs-generate`.

- Instructions: `_DOCS_VERBS` in `modules/instructions/artifacts.py` reads
  `` `docs:build docs:serve docs:generate docs:structure` ``, and
  `block.md.j2` says `task docs:generate`. In `standard.md.j2`, which renders
  `.rn-forge/kiln/standard.md`:

    - the docs-profile line says "a derived nav", not "a generated nav block";
    - both task rows read `` `task docs:generate` `` with "regenerate the docs'
      derived regions";
    - §2's kinds table and the lines under it are the design's
      [ownership model](design.md#the-ownership-model), with "Derived regions
      here: the `# BEGIN derived nav` region in `mkdocs.yml`" in place of the
      nav in "Blocks here";
    - the `task validate` paragraph says "the derived nav is current".

- Docs templates: `_areas.yml.j2` (comment), `_structure.md.j2` (the nav bullet:
  "`mkdocs.yml`'s `nav:` is a derived region, written by `task docs:generate`
  from `docs/_areas.yml`, the tree and each page's title — do not hand-edit
  it."), `specs/_structure.md.j2` (`task docs:generate`) and
  `prompts/port-docs.md`.

- **Goldens first.** In each of the three goldens, make every one of these
  changes to its rendered copy: the `mkdocs.yml` comment and fence,
  `tasks/docs.yml`, `tasks/quality.yml`, `Taskfile.yml`,
  `.rn-forge/kiln/standard.md`, `CLAUDE.md`, `docs/_structure.md`,
  `docs/_areas.yml` and `docs/specs/_structure.md`. In its
  `.rn-forge/kiln/state.json`, delete the `"mkdocs.yml#generated nav"` entry
  and re-seed the hash of every changed managed file and block, as `README.md`
  says. Compute each hash with the helpers the `generated` check itself uses:
  for a managed file,
  `uv run python -c "import sys, pathlib; from rn_forge.kiln.modules.core.checks.generated import digest; print(digest(pathlib.Path(sys.argv[1]).read_text(encoding='utf-8')))" <path>`;
  for a block, `digest(block_body(text, begin_marker))` with the entry's
  recorded `begin_marker`. `config_hash` is `digest` of `config.toml`'s text.
  `task lint` names every entry that is still wrong. The goldens'
  `docs/guides/development.md` name `docs:nav` twice; rename both. Then run
  `task docs:generate`.

- kiln's own repository: the same file changes (root `Taskfile.yml`,
  `tasks/docs.yml`, `tasks/quality.yml`, `mkdocs.yml`, `CLAUDE.md`,
  `.rn-forge/kiln/standard.md`, `docs/_structure.md`, `docs/_areas.yml`,
  `docs/specs/_structure.md`), the same `state.json` deletion and re-seed, and
  the `.rn-forge/kiln/config.toml` change above.
  `docs/architecture/workspace.md`'s module list says "the derived mkdocs nav;
  docs content is seeded". Because `config.toml` changed, re-seed
  `state.json`'s `config_hash` too. `README.md`'s "`kiln docs-nav` writes the
  nav" becomes "`kiln docs-generate` writes the derived regions". Run
  `task docs:generate`. The nav's titles become page H1s, and the second
  "Overview" under Plans becomes "Reviews".

- `docs/reference/standard-repo.md`:

    - Replace §2's opening ("Three artifact kinds, and they are the whole model")
      and its kinds table with the design's
      [ownership model](design.md#the-ownership-model), verbatim. In the
      ownership table, use the model's kind names in the last column.
    - The `mkdocs.yml` row: "repo body, scaffolded by `kiln new`; the
      `# BEGIN derived nav` region → kiln, rewritten by `task docs:generate`" |
      **derived region**.
    - The doctor sections that name `docs.nav` or the nav block name
      `docs-generate` and `docs.nav-stale`.

- Then sweep the whole repository and rename every remaining hit:

    ```bash
    rg -n --hidden --glob '!.git' --glob '!docs/specs/**' --glob '!docs/plans/**' \
      --glob '!adr-refactor.md' --glob '!tests/modules/core/checks/test_generated.py' \
      'docs-nav|docs:nav|docs_nav|nav block' .
    ```

    `--hidden` matters: without it, `rg` skips `.rn-forge/` and each golden's
    `.rn-forge/`. The excluded paths keep the old words on purpose. Closed
    stories and plans record what was built, `adr-refactor.md` is history, and
    `test_generated.py`'s "nav block" is a generic example of an indented block.

**Do not:** keep `docs-nav` as an alias; add an `ArtifactKind`; touch the
`include` area or `packages` (S11.1.1 does that); add the board or Scope regions
(F13.2); rename the `generated` check in `modules/core`.

**Tests:** rename `tests/modules/docs/checks/test_nav.py` to `test_derived.py`.
Use `tests/modules/docs/test_docs.py` for `page_title` and nav titles,
`tests/modules/docs/test_artifacts.py` for the artifact list, and
`tests/test_new.py` for the nav that `kiln new` writes. Copy the shape of the
existing tests in those files.

**Acceptance:**

- `checks.run(..., only="docs-generate")` reports `docs.nav-stale` for a stale
  nav, and nothing for a repository without an MkDocs site.
- `DocsModule.artifacts` returns no artifact whose kind is `BLOCK`, for any
  archetype.
- `page_title` returns the H1 text for a page with one, and the
  `title_from_filename` title for a page without one. In a `children` area,
  `guides/choosing-packages.md` with H1 `# Choosing packages` is titled
  `Choosing packages`, and `plans/reviews/index.md` with H1 `# Reviews` is
  titled `Reviews`.
- `kiln new ... --docs mkdocs --yes` writes a `mkdocs.yml` whose nav is current
  (`kiln doctor --only docs-generate` passes), and its `state.json` has no nav
  entry.
- Adding a page to a golden and running `task docs:generate` changes only
  `mkdocs.yml`'s nav, and `task lint` then passes with no `state.json` change.
- The CLI has a `docs-generate` command and no `docs-nav` command (tested in
  `tests/test_cli_surface.py`).
- `.rn-forge/kiln/standard.md`, in kiln and in each golden, carries the
  ownership model, with `derived region` in its kinds table.
- `task validate` passes in kiln and in each golden.
