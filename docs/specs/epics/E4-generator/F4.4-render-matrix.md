## Template review policy

Jinja templates are the authored source once bootstrap ends. Review their
rendered output as complete runnable repositories: placeholder diffs alone can
hide missing gates or incorrect pins. Every shipped archetype and flag cell is
rendered in CI, and a template change requires owner approval of its rendered
output. Generated cells stay gitignored; compare refs by rendering both.

Until S4.4.3 proves equivalence, the hand-authored goldens remain the bootstrap
reference: change and validate the real repository first, then update its
templates. Permanent hand-maintained goldens or committed rendered snapshots
would duplicate the source across the expanding configuration matrix.

## S4.4.1 — Render and validate every cell

**State:** Closed (2026-10-04) · every cell renders and validates; see the
findings below

kiln's repo-owned `tasks/self.yml`: `self:golden:render [REF=<git-ref>]` writes
every shipped archetype × flag cell to
`.goldens/<ref>/<archetype>[-<flag>=<value>…]/` (gitignored in the repo body);
`self:golden:validate` runs `uv sync && task validate`, `actionlint` and
`mkdocs build --strict` per cell and prints one pass/fail table. A `python-lib`
repository starts with no packages ([ADR-0008](../../../adr/ADR-0008.md)), so
its cell is `kiln new` with `origin` set to
`https://github.com/rn-forge/golden-lib`, then
`kiln generate package golden-alpha` and `kiln generate package golden-beta`.

**Acceptance:**

- `self:golden:render` writes one directory per shipped cell, and `.goldens` is
  gitignored.
- `REF=<ref>` renders that ref's templates into its own directory, so two refs
  can be diffed.
- `self:golden:validate` prints one row per cell and exits non-zero if any cell
  fails. A cell broken on purpose shows `FAIL`, and the other cells are still
  validated and reported.

What the build settled that the story did not say:

- **Files.** `tasks/self.yml` (repo-owned; public `golden:render` and
  `golden:validate`, each with a `desc:`, `REF` optional and empty by
  default), `scripts/golden_matrix.py` (stdlib only, typed for pyright
  strict), the `self: tasks/self.yml` include in `Taskfile.yml` (no root
  wrapper; `self:*` tasks are invoked directly), `[tasks] includes` in the
  repo's `config.toml`, and `.goldens` in `.gitignore`. `state.json` re-seeded
  by hand for the `Taskfile.yml` entry and `config_hash`.
- **The ignore pattern is `.goldens`, not `.goldens/`.** With a trailing slash,
  `git check-ignore -q .goldens` fails while the directory does not exist, and
  the feature's acceptance block runs it before any render. It sits in the
  repo body, above the kiln block.
- **Five cells, all at the default docs profile (mkdocs):** `python-app`,
  `python-tool` (archetype `python-tool`, which is python-app with
  `lifecycle`), `python-lib`, `python-web-api-backend=fastapi` and
  `python-web-app-backend=fastapi-frontend=angular`. The `[untested]` values
  (django, react, svelte) are not cells, and neither are the other docs
  profiles (`external`, `none`).
- **`=` cannot be in a repository name**, and `kiln new` takes the name from the
  directory. A cell is rendered under its name with `=` replaced by `-` and
  renamed to the cell name afterwards. The rendered repository therefore
  carries the `-` name.
- **`origin` is a git remote, not a config key.** The `python-lib` cell runs
  `git init`, `git remote add origin https://github.com/rn-forge/golden-lib`,
  then `kiln generate package golden-alpha` and `golden-beta` inside the cell.
- **Refs.** The empty ref is `working` (this checkout, uncommitted changes
  included); any other ref is a detached `git worktree` in a temp directory,
  `uv sync`ed, rendered with that worktree's kiln, and removed afterwards,
  also on failure. `/` in a ref becomes `-` in the directory name.
- **Validation runs `task -t Taskfile.yml`.** A cell with no Taskfile would
  otherwise run kiln's own Taskfile from an ancestor directory and pass. If
  `uv sync` fails, `task validate` is skipped for that cell; the other columns
  still run. A missing cell directory is a `FAIL` row.
- **Docs column** is the cell's own `task docs:build`, which is strict.
- **`render_cell(cell, dest, kiln_cmd)` and `run(cmd, cwd)`** are the seams the
  tests use; `render` stops at the first cell that fails to render.
- **Findings, not fixed here (template or scaffold territory):**
    - The Angular cell initially hung for over ten minutes at
      `create-nx-workspace`'s `nx g` step. **Cause found 2026-10-04:** Nx
      inherited ancestor ignore rules and scanned zero files; its native
      `FilesWorker::get_files` waits indefinitely for a nonempty list. Anchoring
      `.staging/.gitignore` to `/*` fixed the `/tmp` reproduction but was
      insufficient inside `.goldens`, which the checkout also ignores.
      `scaffold_angular` now runs `git init -q` in the raw frontend directory
      before Nx starts. This establishes the Git boundary at which Nx stops
      reading ancestor ignore files; the temporary `.git` stays in raw staging
      and is not copied into the assembled repository. The complete Angular
      scaffold, including native-build approval and final installation,
      completed in 15.4 seconds inside `.goldens` with Nx 23.2.1 and pnpm
      12.8.1. A separate CLI run rendered the complete Angular cell beneath
      `.goldens/nx-proof` in 10.2 seconds. No launcher or version change was
      needed. `render` still has no timeout.
    - Once rendered, the Angular cell failed its own `task validate` on
      `quality:lint:markdown`: reconcile had copied Nx's stock `README.md` (not
      mdformat-clean) into the root, and `instructions` seeds kiln's README only
      when absent. **Fixed here:** `README.md` joins `.editorconfig` in
      `frontend/scaffold.py`'s `_DROPPED`. Dropped files still count as
      conflicts, so F5.2's "refuses a root that already holds `README.md`"
      holds. Test: `test_s4_4_1_reconcile_drops_scaffolder_readme`.
    - The `python-web-api-backend=fastapi` cell failed `task validate` on an
      over-long `assert` line in `tests/test_package.py`; fixed by S4.4.4.
    - `rmtree` of a previously validated cell fails now and then with "Directory
      not empty" on `.uv-cache`; a retry succeeds. Seen twice, and still not
      fixed.
    - kiln's own `task lint` (and `task format`) reaches into `.goldens/`:
      mdformat walks `.` and does not honour `.gitignore`, so a rendered cell's
      unformatted Markdown fails kiln's lint, and `task format` rewrites it.

## S4.4.2 — CI renders every cell

**State:** New

kiln's CI runs the render for every cell per pull request; validate is local.

**Acceptance:**

- kiln's CI workflow runs `task self:golden:render` on every pull request.
- A pull request whose template does not render fails that job. This is shown
  once on a throwaway branch, and the run is linked here.

**Build:**

- kiln's own `.github/workflows/ci.yml` is still hand-seeded (not self-hosting
  yet), so edit it in place, as S4.4.1 did `Taskfile.yml`, and re-seed its
  `content_hash` in `.rn-forge/kiln/state.json`. First confirm how the
  existing hash is computed by reproducing the current value from the
  committed file. Do not touch `src/rn_forge/kiln/modules/cicd/` or its
  templates. The job is kiln's, not a template feature.

- Add this job after `validate` and before `sonar`, with one blank line on
  either side. Do not change `sonar` or `release`; release must not need it:

    ```yaml
      golden-render:
        # Every shipped archetype x flag cell must still render (S4.4.2). Validating
        # the cells stays local: `task self:golden:validate`.
        if: github.event_name == 'pull_request'
        runs-on: ubuntu-latest
        permissions:
          contents: read
        steps:
          - name: Set up the toolchain
            uses: ./.github/actions/setup
            with:
              github-token: ${{ secrets.GITHUB_TOKEN }}

          # The python-web-app cell scaffolds its Angular frontend with pnpm and
          # Node, which kiln's own setup action does not install.
          - name: Install pnpm
            uses: pnpm/action-setup@a7487c7e89a18df4991f7f222e4898a00d66ddda # v4.1.0
            with:
              version: 12

          - name: Install Node
            uses: actions/setup-node@49933ea5288caeca8642d1e84afbd3f7d6820020 # v4.4.0
            with:
              node-version: 24

          - name: Install dependencies
            run: task setup

          - name: Render every golden cell
            run: task self:golden:render
    ```

- No new tests. Run `task lint` (generated-file drift and the ci-entrypoint rule
  must pass) and `task test`. A `quality:lint:markdown` failure that names
  only files under `.goldens/` is a pre-existing local artifact, not this
  story's. Report it and carry on.

- Leave the state at New. The failing-render demonstration needs a pushed
  throwaway branch, which the owner runs.

*What the build settled that the story did not say*: the `content_hash` in
`state.json` is the plain sha256 hex digest of the file's bytes; it was
reproduced from the committed `ci.yml` (`91c25dda…`) before the edit and
re-seeded from the edited file after it.

## S4.4.3 — Bootstrap exit

**State:** New

Each rendered cell for `python-app`, `python-app` + `lifecycle` and `python-lib`
equals its hand-authored golden apart from name and provenance-version lines;
the owner approves the rendered output; then `tests/fixtures/golden/` is
deleted.

**Acceptance:**

- `task self:golden:compare`, a repo-owned task, diffs each of the three cells
  against its golden after normalizing name and provenance-version lines. It
  exits 0 at the ref being approved.
- The owner's approval is recorded on this story, with the date and that ref.
- `tests/fixtures/golden/` is deleted, and `task validate` passes.

**Build (the compare task only; approval and deletion are the owner's):**

- In `scripts/golden_matrix.py` (stdlib only, pyright strict), add:
    - `GOLDEN_FIXTURES = ROOT / "tests" / "fixtures" / "golden"` and
      `COMPARED: tuple[tuple[str, str], ...] = (("python-app", "golden-app"), ("python-tool", "golden-tool"), ("python-lib", "golden-lib"))`:
      cell name, then the golden's repository name. The golden directory has
      the cell's name.
    - `_SKIP_DIRS = frozenset({".git", ".venv", ".docs-site", ".uv-cache", ".ruff_cache", ".pytest_cache", ".import_linter_cache", "__pycache__", "node_modules"})`
      and
      `_SKIP_FILES = frozenset({".DS_Store", "uv.lock", ".rn-forge/kiln/state.json"})`.
      Skip `state.json` because its hashes depend on the name, and `uv.lock`
      because uv resolves it, not kiln. Match `_SKIP_FILES` against the POSIX
      relative path and against the basename.
    - `normalize(text: str, name: str) -> str`: replace `name`, then
      `name.replace("-", "_")`, with `<name>` and `<module>`. Then rewrite
      `re.sub(r"\b(Generated|Seeded) by kiln \S+", r"\1 by kiln <version>", text)`.
    - `_files(root: Path) -> dict[str, Path]`: every regular file beneath `root`,
      keyed by POSIX relative path, skipping any path with a component in
      `_SKIP_DIRS` or a match in `_SKIP_FILES`. Normalize the key with
      `normalize(key, name)` so `golden-app.code-workspace` and
      `python-app.code-workspace` pair up. `_files` therefore takes `name` too:
      `_files(root, name)`.
    - `compare_cell(cell_dir: Path, golden_dir: Path, cell_name: str, golden_name: str) -> list[str]`:
      return one line per difference, sorted. `only in golden: <key>` and
      `only in cell: <key>` for unpaired keys. For paired files whose normalized
      texts differ, return `differs: <key>` and then the `difflib.unified_diff`
      lines (fromfile `golden/<key>`, tofile `cell/<key>`, `lineterm=""`). Read
      text as UTF-8. A file that does not decode is compared as bytes and
      reported `differs: <key>` without a diff. A missing `cell_dir` gives the
      single line `missing cell: <cell_dir>`.
    - `compare(ref: str, out_root: Path, golden_root: Path = GOLDEN_FIXTURES) -> int`:
      for each `COMPARED` pair, print the `compare_cell` lines, then one table
      `cell | result` (PASS/FAIL), formatted like `validate`'s. Return 1 if any
      pair has lines, else 0.
    - `main` accepts `compare` beside `render` and `validate`, with the same
      `[REF]`. Update the usage strings and the module docstring.
- `tasks/self.yml`: add `golden:compare`, with
  `desc: Diff the python-app, python-tool and python-lib cells against their hand-authored goldens, ignoring name and provenance-version lines (REF=<git-ref>).`
  and `cmds: - uv run python scripts/golden_matrix.py compare {{.REF}}`. The
  file is repo-owned, so nothing is re-seeded.
- Tests in `tests/test_golden_matrix.py`, loading the script the way the file
  already does, with names `test_s4_4_3_<n>_…`. Write them first:
    1. `normalize` maps `golden-app`, `golden_app` and
       `# Generated by kiln 1.2.3 from` to `<name>`, `<module>` and
       `# Generated by kiln <version> from`. The same holds for `Seeded`.
    1. Two `tmp_path` trees that differ only by name (in one file's text and in
       one `<name>.code-workspace` filename) and by provenance version give
       `compare_cell(...) == []`.
    1. A changed line gives `differs: <key>` followed by diff lines, and an extra
       file on each side gives `only in golden:` and `only in cell:`.
    1. Files under `.venv/`, `.docs-site/` and `__pycache__/`, a `uv.lock`, and
       `.rn-forge/kiln/state.json` on one side only give no lines.
    1. A missing cell directory gives `["missing cell: …"]`, and `compare` returns
       1 for it. A matching set of three tmp cells and goldens returns 0.
- Run `task test` and `task typecheck`, plus `task lint` (the `.goldens/`
  markdown caveat in S4.4.2 applies). Then run `task self:golden:compare`
  against the existing `.goldens/working` render. Record its exit code and,
  under *What the build settled*, a short summary of the differing and
  unpaired files per cell. Do not fix templates or goldens; that work is
  follow-up. Set the state to
  `Active · compare built <date>; open until the owner approves and the goldens are deleted`.
  Do not delete `tests/fixtures/golden/`.

## S4.4.4 — The sample test fits the formatter at any repo name

**State:** Closed (2026-10-04) · Found by S4.4.1's
`python-web-api-backend=fastapi` cell

`sample_test()` in `src/rn_forge/kiln/modules/python/scaffold.py` names the
module twice on the assert line, so a module name longer than about 30
characters gives a line over ruff's 88 columns, and a fresh repository fails
`ruff format --check` in its own `task validate`.

**Build:**

- `sample_test(name)` returns, for `module = name.replace("-", "_")`, exactly:
  `import <module>\n\n\ndef test_package_imports():\n    assert <module>.__spec__ is not None\n`.
  Keep the function's name, signature and docstring; change nothing else in
  `scaffold.py`.
- Change the four golden files to the same body first, as the README's bootstrap
  rule says (golden, then template):
  `tests/fixtures/golden/python-app/tests/test_package.py`,
  `tests/fixtures/golden/python-tool/tests/test_package.py`,
  `tests/fixtures/golden/python-lib/packages/golden-alpha/tests/test_package.py`
  and
  `tests/fixtures/golden/python-lib/packages/golden-beta/tests/test_package.py`.
  They are scaffolded files with no `state.json` entry; nothing is
  re-seeded.
- Tests, in `tests/modules/python/test_scaffold.py`, beside the S4.5.10 tests:
  `test_s4_4_4_1_sample_test_fits_at_a_long_name` — for a name of 56
  characters with dashes, every line of `sample_test(name)` is at most 88
  characters, and `ruff format --check` would leave it unchanged (assert on
  the line lengths; do not shell out to ruff). The existing S4.5.10 and
  S11.3.1 tests, which compare each golden with `sample_test`, stay as they
  are and must pass.
- Do not touch `scripts/golden_matrix.py`, `.goldens/`, or the cell names.

**Acceptance:**

- `sample_test` names the module once on the assert line, and its lines fit 88
  columns for a 56-character name.
- The four goldens equal `sample_test` for their package names, and
  `task validate` passes.
- In a rendered `python-web-api-backend=fastapi` cell, `task validate` no longer
  fails on `tests/test_package.py` (checked by the owner with
  `task self:golden:render` and `task self:golden:validate`; not scriptable
  here).

*What the build settled that the story did not say*

The story first said 60 characters. With this body the assert line is 32
characters plus the module name, so 56 is the longest name that fits 88 columns
(60 gives 92). The Build list and acceptance now say 56, and the test uses a
56-character dashed name (`abcdefgh` six times joined by dashes, plus `xyz`).
