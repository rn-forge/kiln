## Template review policy

Jinja templates are the authored source once bootstrap ends. Review their
rendered output as complete runnable repositories: placeholder diffs alone can
hide missing gates or incorrect pins. Every shipped archetype and flag cell is
rendered in CI, and a template change requires owner approval of its rendered
output. Generated cells stay gitignored; compare refs by rendering both.

Until S4.4.3 proves equivalence, the hand-authored goldens remain the bootstrap
reference: change and validate the real repository first, then update its
templates. Permanent hand-maintained goldens or committed rendered snapshots
would duplicate the source across the expanding configuration matrix.

## S4.4.1 — Render and validate every cell

**State:** Active · built 2026-10-04; open until the angular cell renders (first
acceptance bullet) — see the findings below

kiln's repo-owned `tasks/self.yml`: `self:golden:render [REF=<git-ref>]` writes
every shipped archetype × flag cell to
`.goldens/<ref>/<archetype>[-<flag>=<value>…]/` (gitignored in the repo body);
`self:golden:validate` runs `uv sync && task validate`, `actionlint` and
`mkdocs build --strict` per cell and prints one pass/fail table. A `python-lib`
repository starts with no packages ([ADR-0008](../../../adr/ADR-0008.md)), so
its cell is `kiln new` with `origin` set to
`https://github.com/rn-forge/golden-lib`, then
`kiln generate package golden-alpha` and `kiln generate package golden-beta`.

**Acceptance:**

- `self:golden:render` writes one directory per shipped cell, and `.goldens` is
  gitignored.
- `REF=<ref>` renders that ref's templates into its own directory, so two refs
  can be diffed.
- `self:golden:validate` prints one row per cell and exits non-zero if any cell
  fails. A cell broken on purpose shows `FAIL`, and the other cells are still
  validated and reported.

What the build settled that the story did not say:

- **Files.** `tasks/self.yml` (repo-owned; public `golden:render` and
  `golden:validate`, each with a `desc:`, `REF` optional and empty by
  default), `scripts/golden_matrix.py` (stdlib only, typed for pyright
  strict), the `self: tasks/self.yml` include in `Taskfile.yml` (no root
  wrapper; `self:*` tasks are invoked directly), `[tasks] includes` in the
  repo's `config.toml`, and `.goldens` in `.gitignore`. `state.json` re-seeded
  by hand for the `Taskfile.yml` entry and `config_hash`.
- **The ignore pattern is `.goldens`, not `.goldens/`.** With a trailing slash,
  `git check-ignore -q .goldens` fails while the directory does not exist, and
  the feature's acceptance block runs it before any render. It sits in the
  repo body, above the kiln block.
- **Five cells, all at the default docs profile (mkdocs):** `python-app`,
  `python-tool` (archetype `python-tool`, which is python-app with
  `lifecycle`), `python-lib`, `python-web-api-backend=fastapi` and
  `python-web-app-backend=fastapi-frontend=angular`. The `[untested]` values
  (django, react, svelte) are not cells, and neither are the other docs
  profiles (`external`, `none`).
- **`=` cannot be in a repository name**, and `kiln new` takes the name from the
  directory. A cell is rendered under its name with `=` replaced by `-` and
  renamed to the cell name afterwards. The rendered repository therefore
  carries the `-` name.
- **`origin` is a git remote, not a config key.** The `python-lib` cell runs
  `git init`, `git remote add origin https://github.com/rn-forge/golden-lib`,
  then `kiln generate package golden-alpha` and `golden-beta` inside the cell.
- **Refs.** The empty ref is `working` (this checkout, uncommitted changes
  included); any other ref is a detached `git worktree` in a temp directory,
  `uv sync`ed, rendered with that worktree's kiln, and removed afterwards,
  also on failure. `/` in a ref becomes `-` in the directory name.
- **Validation runs `task -t Taskfile.yml`.** A cell with no Taskfile would
  otherwise run kiln's own Taskfile from an ancestor directory and pass. If
  `uv sync` fails, `task validate` is skipped for that cell; the other columns
  still run. A missing cell directory is a `FAIL` row.
- **Docs column** is the cell's own `task docs:build`, which is strict.
- **`render_cell(cell, dest, kiln_cmd)` and `run(cmd, cwd)`** are the seams the
  tests use; `render` stops at the first cell that fails to render.
- **Findings, not fixed here (template or scaffold territory):**
    - The Angular cell did not render in this session:
      `pnpm dlx create-nx-workspace` hung for over ten minutes at its `nx g`
      step, with and without `AI_AGENT` and `NX_DAEMON=false`. Cause not found;
      it may be this session's sandbox. The cell shows `FAIL` as a missing
      directory, and `self:golden:render` does not return, because `render` has
      no timeout.
    - The `python-web-api-backend=fastapi` cell fails `task validate`: with `=`
      mapped to `-` the repository name is long, so the generated
      `tests/test_package.py` has an `assert` line over the formatter's width
      and `ruff format --check` fails. Its actionlint and docs build pass.
    - `rmtree` of a previously validated cell once failed with "Directory not
      empty" on `.uv-cache`; a retry succeeded. Not reproduced.

Real run (this checkout, `working`; after the table's `python-web-app` cell
failed to render, and the web-api cell failing for the finding above):

## S4.4.2 — CI renders every cell

**State:** New

kiln's CI runs the render for every cell per pull request; validate is local.

**Acceptance:**

- kiln's CI workflow runs `task self:golden:render` on every pull request.
- A pull request whose template does not render fails that job. This is shown
  once on a throwaway branch, and the run is linked here.

## S4.4.3 — Bootstrap exit

**State:** New

Each rendered cell for `python-app`, `python-app` + `lifecycle` and `python-lib`
equals its hand-authored golden apart from name and provenance-version lines;
the owner approves the rendered output; then `tests/fixtures/golden/` is
deleted.

**Acceptance:**

- `task self:golden:compare`, a repo-owned task, diffs each of the three cells
  against its golden after normalizing name and provenance-version lines. It
  exits 0 at the ref being approved.
- The owner's approval is recorded on this story, with the date and that ref.
- `tests/fixtures/golden/` is deleted, and `task validate` passes.
