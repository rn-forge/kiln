# S20.1.2 — The docs-pointer check reads only kiln's block

Brief for
[S20.1.2](../F20.1-blocks-only.md#s2012-the-docs-pointer-check-reads-only-kilns-block),
at `feature/v1` after `bb7cf86`.

## Goal

The `missing-docs-pointer` check looks for the links to `docs/_structure.md` and
`docs/index.md` only inside the `rn-forge kiln` block of `AGENTS.md`. Body text
in `AGENTS.md` or `CLAUDE.md`, and other tools' blocks, never affect it.

## Settled

- `DocsPolicy` in `src/rn_forge/kiln/modules/docs/policy.py` gains one field,
  `instruction_block: ManagedBlock | None = None` (from
  `rn_forge.commons.fs.blocks`), documented in the class docstring: "The
  fenced block of each instruction file that must carry the docs links; `None`
  reads the whole file."
- `POLICY` sets `instruction_files=("AGENTS.md",)` and
  `instruction_block=ManagedBlock("rn-forge kiln", comment="<!--")`. Drop the
  comment above it that mentions `CLAUDE.md`. The docs module does **not**
  import `KILN_BLOCK` from the instructions module (modules meet through
  composition); the two definitions name the same fence.
- `_check_instruction_pointer(repo_root, docs_root, policy)` takes the policy
  (the call in `check_structure` passes `policy`). For each present
  instruction file it reads the text, and when `policy.instruction_block` is
  set, takes `block.extract(text)`; a `None` extract means no links. Links
  resolve relative to the file's directory, as now.
- The `@path` import no longer counts as a pointer: delete `_IMPORT` and its
  comment, and the "other instruction files may point at the carrier" branch.
  The rule is now: at least one listed file exists (else
  `missing-instruction-file`, unchanged); every present file whose block (or
  text) lacks either link gets `missing-docs-pointer`, message
  `f"kiln's block does not link both {docs_root.name}/_structure.md and {docs_root.name}/index.md"`
  when a block is set, else
  `f"does not link both {docs_root.name}/_structure.md and {docs_root.name}/index.md"`.
- `_resolved_links` stays for the ideas check; give the pointer check a small
  helper over text (e.g. `_links_in(text, base)`) rather than re-reading the
  file.
- Test names describe behaviour, with no spec IDs.

## Current behaviour

- `POLICY.instruction_files == ("AGENTS.md", "CLAUDE.md")`. The check reads the
  whole of each file, and a `CLAUDE.md` passes if it links or `@`-imports the
  carrier.
- So with the links only in `AGENTS.md`'s body (outside any block), the check is
  clean today; after the change, with `instruction_block` set, it reports
  `missing-docs-pointer`. With the links inside the block and the body
  deleted, it is clean both before and after.
- Kiln's own `AGENTS.md` block already links both pages (the "Docs rules"
  bullet), so kiln's own `task lint` stays clean.
