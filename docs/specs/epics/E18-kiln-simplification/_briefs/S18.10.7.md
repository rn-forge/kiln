# S18.10.7 — Test arguments keep their quoting

Brief for
[S18.10.7](../F18.10-review-defects.md#s18107-test-arguments-keep-their-quoting),
at `feature/v1` after `86e36ef`.

## Goal

A plan that carries `-m 'not slow'` runs pytest with `-m` and `not slow` as two
arguments, in both the per-member `ci:test` task and the `ci:suites` task.

## Settled

- `devops/ci.py` keeps `shlex.join` for `PYTEST_ARGS` and `SUITE_ARGS`; the plan
  output does not change.

- In `src/rn_forge/kiln/modules/tasks/templates/tasks/ci.yml.j2`, the two
  commands that expand those variables become block scalars that re-split the
  shell-quoted value with `eval "set -- ..."` and pass `"$@"`:

    ```yaml
      - |
        eval "set -- $PYTEST_ARGS"
        uv run --directory "$PACKAGE_DIR" --package {{.CLI_ARGS}} pytest -q "$@"
    ```

    and

    ```yaml
      - |
        eval "set -- $SUITE_ARGS"
        uv run pytest "$@"
    ```

    The first replaces the `pytest -q $PYTEST_ARGS` line (the third `cmds` entry
    of `test`); the other two entries stay. `go-task`'s shell runs this form: an
    empty variable leaves `"$@"` empty, and `-m 'not slow'` yields two arguments
    (verified in a scratch Taskfile).

- The value is repository-owned config that `shlex.join` quoted, so `eval`
  reproduces exactly the list the plan held.

- Rejected (do not build): changing the plan to emit JSON, and `xargs`.

## Current behaviour

- Probed on a rendered `python-lib` with a stub `uv` first on `PATH` that
  records its argv, running `task ci:suites` with
  `SUITE_ARGS="-m 'not slow'"`: the recorded argv is
  `run pytest -m 'not slow'` with the quotes literal, three words after
  `pytest`. `ci:test` has the same flaw through `$PYTEST_ARGS`.
- `test_commands_follow_the_story` pins `["uv run pytest $SUITE_ARGS"]`, and
  fails after the change until updated.

## Change

- **Change:** the two commands in `ci.yml.j2`.
- **Then:** run `task kiln:apply`; kiln's own repository is not a workspace, so
  it should change no file. If it changes one, commit it with this story and
  list it.
- **Leave alone:** `devops/ci.py`, `ci.yml.j2` in the `cicd` module, and every
  other template.

and the `requires` import pattern from `tests/conftest.py`; its helpers come

   `@requires("task")`, parametrized over `("suites", "SUITE_ARGS", [])` and
   `("test", "PYTEST_ARGS", ["alpha"])`. It is the end-to-end test, through
   `task` itself:

      `cycle.apply(root, home=tmp_path / "home")`.

      `printf '%s\n' "$@" >> argv; printf -- '--end\n' >> argv`, with `argv` an
      absolute path. Put that directory first on `PATH`. `ruff` and `pyright`
      are `uv` arguments here, so the stub serves all three `test` commands.
    - Run `["task", f"ci:{name}", *(["--", *cli])]` with `cwd=root` and an env
      holding `PATH`, `<VAR>="-m 'not slow'"` and, for `test`,
      `PACKAGE_DIR="packages/alpha"`.
    - Split `argv` on `--end`. Assert the last call ends with
      `["pytest", "-m", "not slow"]` for `suites` and
      `["pytest", "-q", "-m", "not slow"]` for `test`, and the return code is
      0\. A second assertion runs the same with the variable empty and expects
      the call to end `["pytest"]` or `["pytest", "-q"]`. Before: the suites

   changes to
   `tasks["suites"]["cmds"] == ['eval "set -- $SUITE_ARGS"\nuv run pytest "$@"\n']`,
