Renames every test named after a story to the behaviour it proves, and stops new
ones. This is a mechanical change, so it suits Sonnet. Each story is one commit
that contains only renames, so a review checks names, not logic.

Every story keeps these properties:

1. A test's body, parameters and fixtures are unchanged, and only its name
   moves.
1. A new name says what the test proves, `test_<subject>_<behaviour>`. It is
   unique within its module, and no part of it is a spec ID.
1. The number of collected tests is unchanged (`task test -- --collect-only -q`,
   before and after).

## S18.1.4 — A new story-named test fails the gate

**State:** New · **Depends on:** S18.1.1, S18.1.2, S18.1.3

**Acceptance:**

- A test function whose name starts `test_s<digits>_` makes `task validate`
  fail, with a message naming the function and the rule.
- Step 2 of "Building a story" in `specs/index.md` no longer asks for
  story-named tests.

## Acceptance

```bash
set -euo pipefail
absent() { local rc=0; rg -q --hidden --glob '!.git' "$@" </dev/null || rc=$?; [ "$rc" -eq 1 ]; }
absent -e 'def test_s[0-9]+_' tests                     # S18.1.1–S18.1.3
absent -e 'test_<story id' docs/specs/index.md          # S18.1.4
task validate
```

Not scripted: the collected-test count matches the count before the rename
(property 3), and a story-named test fails the gate (S18.1.4).
