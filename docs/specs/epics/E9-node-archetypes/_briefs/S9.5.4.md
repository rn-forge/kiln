# S9.5.4 — `workspace:*` in a fixed group

Brief for
[S9.5.4](../F9.5-node-lib-release-findings.md#s954-workspace-in-a-fixed-group),
at `80f9fc2`.

## Goal

`kiln-devops requirements --stack node` accepts `workspace:*` between members
when the workspace releases as one fixed group, and still rejects it when the
group is independent.

## Settled

- Owner, 2026-11-17: the first option. A fixed group may use `workspace:*`.
- The group is read from `nx.json` under `--root` (default `.`):
  `release.projectsRelationship`. It is independent only when that value is
  `"independent"`; a missing key, a missing `release` block or a missing
  `nx.json` is fixed, which is Nx's own default.
- `requirements.check_node(members, *, fixed: bool = False)`. With `fixed=True`,
  `workspace:*` is not a problem. `workspace:^` and `workspace:~` pass either
  way. A literal version fails either way, with the message it has today.
- The independent message stays `workspace:* publishes as an exact pin`.
- The `ci:internal-ranges` task's `desc:` becomes
  `"CI only: Check that members depend on each other by workspace:^ or workspace:~, or also workspace:* in a fixed release group."`.
  Its command does not change.
- Tests are named for behaviour, `test_<subject>_<behaviour>`, with no spec ID
  in a name, docstring or comment.

## Current behaviour

At `80f9fc2`:

- `src/rn_forge/kiln/devops/requirements.py`: `_node_problem(spec)` returns
  `"workspace:* publishes as an exact pin"` for `workspace:*`;
  `check_node(members)` takes no group.
- `src/rn_forge/kiln/devops/cli.py::_requirements` calls
  `requirements.check_node(json.load(sys.stdin))`. `--root` exists (default
  `.`) and only the python stack reads it.
- `tests/devops/test_requirements_node.py::test_cli_exit_code_follows_the_node_findings`
  expects exit `1` for `workspace:*`, run with no `--root`, so from the test's
  working directory (this repository, which has no `nx.json`). After the
  change that run reads as fixed and exits `0`, so the test must pass `--root`
  pointing at a directory with an independent `nx.json`.
- `src/rn_forge/kiln/modules/tasks/templates/tasks/ci.yml.j2` (line 82) holds
  the `internal-ranges` `desc:`.

## Change

- `src/rn_forge/kiln/devops/requirements.py`: `check_node`'s keyword `fixed`,
  passed through to `_node_problem`; the docstring says what `fixed` allows.
  Add `release_is_fixed(root: Path) -> bool`, which reads `root / "nx.json"`
  as settled.
- `src/rn_forge/kiln/devops/cli.py::_requirements`: for `node`,
  `check_node(json.load(sys.stdin), fixed=requirements.release_is_fixed(Path(args.root)))`.
  The `--stack` help text says node also reads `nx.json` under `--root`.
- `src/rn_forge/kiln/modules/tasks/templates/tasks/ci.yml.j2`: the `desc:`.
- `tests/devops/test_requirements_node.py`: the tests below, and
  `test_workspace_star_is_reported_as_an_exact_pin` and
  `test_cli_exit_code_follows_the_node_findings` adjusted to the independent
  case.
- Any test that asserts the old `internal-ranges` `desc:` text expects the new
  one; list each in `## Result`.
- **Leave alone:** the python stack, every other task, every generated file in
  this repository.

## Tests first

In `tests/devops/test_requirements_node.py`:

1. `test_workspace_star_passes_in_a_fixed_group`:
   `check_node(_workspace(tmp_path, dependencies={"@s/b": "workspace:*"}), fixed=True) == []`.
   Fails before (the keyword does not exist).
1. `test_workspace_star_fails_in_an_independent_group`: the same members with
   `fixed=False` give the exact-pin line.
1. `test_a_literal_version_fails_in_a_fixed_group`: `^1.0.0` with `fixed=True`
   still gives `use workspace:^ or workspace:~, found ^1.0.0`.
1. `test_release_is_fixed_reads_nx_json`, parametrized: no `nx.json` → `True`;
   `{}` → `True`; `{"release": {"projectsRelationship": "fixed"}}` → `True`;
   `{"release": {"projectsRelationship": "independent"}}` → `False`.
1. `test_cli_reads_the_group_from_nx_json`: with `workspace:*` on stdin,
   `cli.main(["requirements", "--stack", "node", "--root", <dir with fixed nx.json>])`
   is `0`, and with an independent `nx.json` it is `1` and prints the
   exact-pin line.
