Each story splits files and functions that do several jobs, so that every unit
does one. This feature leaves the docs work-item model itself alone. Whether the
model should be seeded rather than enforced is still an open question on the
idea page.

Every story keeps these properties:

1. No rendered file, finding, message or exit code changes.
1. A docstring states the contract only, per `README.md`. ADR references,
   decision tags and design rationale are removed from the files a story
   touches.

## S18.9.1 — The docs module

**State:** New · **Depends on:** —

**Build.**

- `docs/work.py` (827 lines) becomes a `work/` package. `model.py` holds the
  dataclasses, `load_work` and the metadata reading. `validate.py` holds
  `validate`, split into `_validate_epic`, `_validate_feature` and
  `_validate_release` around one `_Report` (list, `err`, `rel`) in place of
  four closures and two `err` copies (`:354-485`). `render.py` holds the

  render helpers (`title_markup`, `epic_range`, `range_label`), which move to
  `parsed.py`.
- `generate.py:75-242`: one `Region(path, text, stale, markers)` list, built
  from a table of (page, block, renderer, name). `generate` writes the
  regions, `stale` reports them, and the 3-tuple and the closures go.

  `excluded_docs`, `package_mounts`, `resolve_link`) moves to `mkdocs.py`.
- `artifacts.py:51-86`: one archetype-to-excluded-prefixes table replaces the
  three tuples and the if.
