# S7.7.3 — An installed kiln knows its ref, and the pin check uses it

Brief for
[S7.7.3](../F7.7-kiln-installs-as-a-tool.md#s773-an-installed-kiln-knows-its-ref-and-the-pin-check-uses-it),
at `b4801b2`.

## Goal

When `kiln` runs from an install under `$RNF_HOME`, `kiln version` prints
`<version> (<ref> @ <commit 12>)`, and the pin check compares a SHA pin with the
installed commit. Run from `uvx`, a checkout or a venv, both behave as they do
now.

## Settled

- **One helper, in `src/rn_forge/kiln/product.py`:**

    ```python
    @dataclass(frozen=True)
    class Installed:
        """The install the running kiln was started from, as `state.json` records it."""

        ref: str
        commit: str | None


    def running_install(home: ToolHome | None = None) -> Installed | None:
        """The install kiln is running from, or `None` when it runs from anywhere else."""
    ```

    `home` defaults to `ToolHome("kiln")` (which reads `$RNF_HOME` when it is
    built). It returns an `Installed` only when all of these hold, else `None`:

    1. `Path(sys.prefix).resolve()` is inside `home.versions_dir.resolve()`;
    1. the first path part under `versions_dir` equals `home.current_version()`
       (the running install is the active one; `state.json` describes only the
       active one);
    1. `home.state_path` reads as a JSON object whose `ref` is a non-empty string.
       `commit` is that object's `commit` when it is a non-empty string, else
       `None`.

    Any `OSError` or `ValueError` reading the state gives `None`. Add `Installed`
    and `running_install` to `__all__`.

- **`kiln version`** (`src/rn_forge/kiln/commands/info.py`): with
  `installed = running_install()`, when `installed` has a `commit`, the text
  form is `f"{version} ({installed.ref} @ {installed.commit[:12]})"` and the
  JSON payload is `{"version": …, "ref": …, "commit": …}` (full commit).
  Otherwise, a tag install (`commit` is `None`) included, both are exactly
  what they are now: the text is the version, the JSON is `{"version": …}`.

- **The pin check** (`src/rn_forge/kiln/modules/core/checks/pin.py`):

    - a tag pin compares versions, exactly as now, whether or not kiln runs from
      an install;
    - a SHA pin, when `running_install()` returns an `Installed` with a `commit`,
      is `kiln.pin-mismatch` (ERROR) when `pin.ref != commit`, with the message
      `f"[kiln] ref pins kiln {pin.ref[:12]}, but kiln {commit[:12]} is running — run kiln through `task`, or move [kiln] ref"`;
    - a SHA pin is not compared when kiln is not running from an install, or the
      install has no commit (today's behaviour);
    - a branch pin cannot reach the check: `KilnPin` refuses a branch (F18.14).
      The story's "not reported for a branch pin" is that refusal; add no branch
      case to the check.

    Update the module docstring: drop "A branch ref is the interim before kiln's
    first release and is not compared"; say a SHA pin is compared with the
    installed commit when kiln runs from an install.

- `pin.py` importing `rn_forge.kiln.product` keeps the render-free contract:
  `product` imports `rn_forge.tooling.install`, never Jinja or the generator.
  `tests/suite/test_checks_are_render_free.py` must still pass; if it does
  not, stop and report.

- Tests are named for behaviour, `test_<subject>_<behaviour>`, with no spec ID
  in a name, docstring or comment.

## Tests first

The fake install, a fixture in each test file that needs it (or one in
`tests/conftest.py` if both use it): under `tmp_path / "home"` set as
`RNF_HOME`, make `kiln/versions/<sha12>/tool/`, point `kiln/current` at
`versions/<sha12>` (relative symlink), write `kiln/state.json` as
`{"version": "0.1.0", "ref": "feature/v1", "commit": <sha>, "schema_version": 1}`,
and `monkeypatch.setattr(sys, "prefix", str(<version dir>/"tool"))`.

In a new `tests/test_product.py`:

1. `test_running_install_reads_the_active_state`: the fake install gives
   `Installed("feature/v1", <sha>)`.
1. `test_running_install_is_none_outside_the_home`: no `sys.prefix` patch gives
   `None`.
1. `test_running_install_is_none_for_an_inactive_version`: `sys.prefix` under
   another version directory than `current` gives `None`.

In `tests/commands/test_diff.py` (beside the existing version test):

1. `test_version_names_the_installed_ref_and_commit`: with the fake install,
   `commands.version()` prints `0.1.0 (feature/v1 @ <sha[:12]>)`; with
   `json=True` the payload has `ref` and the full `commit`.
1. `test_version_outside_an_install_is_the_version_alone`: no fake install, the
   text is exactly the distribution version.

In `tests/modules/core/checks/test_pin.py`:

1. `test_sha_pin_other_than_the_installed_commit_is_a_mismatch`: fake install at
   commit A, pin `kiln_remote_sha` (≠ A) → one `(MISMATCH, ERROR)`; the
   message holds both 12-character prefixes, `task` and `[kiln] ref`.
1. `test_sha_pin_matching_the_installed_commit_is_clean`: fake install at
   `kiln_remote_sha`, pin `kiln_remote_sha` → `[]`.

   `v0.0.1` → `(MISMATCH, ERROR)`.

   not-from-an-install case.
