A configured check, on by default (`node-lib` also gets `pnpm audit`, a standard
check, in S15.2.4): `task` fails when a dependency's licence matches the deny
list (default `GPL`, `GPL-*`, `AGPL`, `AGPL-*`, `UNKNOWN`) and the package is
not in the ignore list. It is a step of `task lint`, so `validate` runs it, with
no job of its own. Python uses `pip-licenses`; `node-lib` uses `pnpm licenses`,
which understands pnpm's layout. Both feed one matcher, `kiln-devops licenses`.

**What the producers emit.** `pip-licenses` defaults to `--from=mixed`, which
prefers a package's Trove classifiers to its `License` field. So a GPL package
usually reports `GNU General Public License v3 (GPLv3)`, not `GPL-3.0-only`, and
several classifiers come joined by `; `. The `License` field and pnpm's keys are
free text too, though usually SPDX. The deny list is written in SPDX terms, so
the matcher normalises each value to an SPDX-style identifier before matching. A
value it cannot normalise is matched as written.

## S15.2.1 — `kiln-devops licenses` applies the policy

**State:** Closed (2026-11-05)

**Build — tests first,** in `tests/devops/test_licenses.py`, calling
`licenses.run(text, fmt, deny, ignore)` which returns the offender lines:

1. `test_s15_2_1_1_pip_licenses_json`: input
   `[{"Name":"a","Version":"1","License":"MIT License"},{"Name":"b","Version":"2","License":"GNU General Public License v3 (GPLv3)"}]`
   (the classifier form that `pip-licenses` prints by default),
   `fmt="pip-licenses"`, `deny=["GPL-*"]` returns
   `["b 2 GNU General Public License v3 (GPLv3)"]`. An offender line keeps the
   producer's value; the identifier is used only for matching.

1. `test_s15_2_1_1b_normalise`: parametrised over `licenses.normalise(value)`:

    | Value | Identifier |
    | -- | -- |
    | `GNU General Public License (GPL)` | `GPL` |
    | `GNU General Public License v2 (GPLv2)` | `GPL-2.0` |
    | `GNU General Public License v2 or later (GPLv2+)` | `GPL-2.0-or-later` |
    | `GNU General Public License v3 (GPLv3)` | `GPL-3.0` |
    | `GNU General Public License v3 or later (GPLv3+)` | `GPL-3.0-or-later` |
    | `GNU Affero General Public License v3` | `AGPL-3.0` |
    | `GNU Affero General Public License v3 or later (AGPLv3+)` | `AGPL-3.0-or-later` |
    | `GNU Lesser General Public License v3 (LGPLv3)` | `LGPL-3.0` |
    | `GNU Library or Lesser General Public License (LGPL)` | `LGPL` |
    | `GPLv3`, `GPL v3`, `GPL-3` | `GPL-3.0` |
    | `GPLv2+` | `GPL-2.0-or-later` |
    | `AGPLv3` | `AGPL-3.0` |
    | `GPL` | `GPL` |
    | `GPL-3.0-only` | `GPL-3.0-only` |
    | `MIT License` | `MIT License` |
    | `UNKNOWN`, `Unknown`, empty | `UNKNOWN` |

1. `test_s15_2_1_2_pnpm_json`: input
   `{"MIT":[{"name":"a","versions":["1.0.0"]}],"Unknown":[{"name":"c","versions":["3.0.0"]}]}`,
   `fmt="pnpm"`, `deny=["UNKNOWN"]` returns `["c 3.0.0 Unknown"]`.

1. `test_s15_2_1_3_matching_is_case_insensitive_and_whole_string`: `LGPL-3.0`
   and `GNU Lesser General Public License v3 (LGPLv3)` are not matched by
   `GPL-*`; `gpl-2.0-only` and `GNU General Public License v2 (GPLv2)` are.
   The bare family `GPL` is matched by the default deny list, which names it
   (`GPL` and `GPL-*`), and not by `GPL-*` alone.

1. `test_s15_2_1_4_multiple_licences`: a pip-licenses licence
   `MIT License; GNU General Public License v3 (GPLv3)` is an offender, and
   each `;`-separated part is normalised and matched alone.

1. `test_s15_2_1_5_ignore`: a package named in `ignore` is never an offender.

1. `test_s15_2_1_6_cli`:
   `main(["licenses", "--format", "pip-licenses", "--deny", "GPL-*"])` with
   the offender input on stdin returns `1` and prints the offender line to
   stderr; with a clean input it returns `0`; with `not json` it returns `2`.

1. `test_s15_2_1_7_real_pip_licenses_output`: the producer's actual output, not
   a hand-written fixture. Write two distributions into `tmp_path`, each a
   `<name>-1.0.dist-info/METADATA`: `gplpkg`, whose only licence is the
   classifier
   `License :: OSI Approved :: GNU General Public License v3 (GPLv3)`, and
   `mitpkg`, with `License: MIT` and no classifier. Run
   `sys.executable -m piplicenses --format=json --packages gplpkg mitpkg` with
   `PYTHONPATH=tmp_path`, and pipe its stdout into `licenses.run` with the
   default deny list. The result is exactly `gplpkg`'s line. Skip when
   `piplicenses` cannot be imported, which holds until S15.2.2 adds it to the
   dev group.

**Build:** new `src/rn_forge/kiln/devops/licenses.py` with `run`, and a
`licenses` subparser in `devops/cli.py` (`--format {pip-licenses,pnpm}`
required, `--deny` and `--ignore` repeatable, JSON on stdin). `normalise` runs
first: the GNU classifier names map through a table, one row per classifier in
the test above. Free-text short forms match
`^(A|L)?GPL[ -]?v?(\d)(\.0)?(\+| or later)?$` (case-insensitive) and become
`<family>-<n>.0`, plus `-or-later` for `+`; `GPL`, `AGPL` and `LGPL` alone stay
the bare family; `UNKNOWN`, `Unknown` and empty become `UNKNOWN`; every other
value passes through unchanged. Then match with `fnmatch.fnmatchcase` on
`casefold()`ed strings. An offender line is `<name> <version> <licence>`; a pnpm
package with several versions yields one line each. `main` follows the other
subcommands' error style (`kiln-devops: <message>` on stderr).

**Acceptance:**

- The eight tests pass, and `task validate` passes. The real-output test runs,
  and does not skip, once S15.2.2 has landed.

**What the build settled that the story did not say:**

- `--deny` omitted means the default deny list, `licenses.DEFAULT_DENY`; test 7
  and the CLI share it. `--ignore` omitted is empty.
- Test 7 skips through `pytest.importorskip("piplicenses")` until S15.2.2. It
  was run once with `uv run --with pip-licenses` (not added to the project)
  and passed, giving exactly
  `gplpkg 1.0 GNU General Public License v3 (GPLv3)`.
- The pnpm and pip-licenses shapes are not otherwise validated: JSON that does
  not have the producer's shape is `kiln-devops: not <format> JSON: …`, exit
  2\.
- Added `test_s15_2_1_2b_pnpm_one_line_per_version` for the several-versions
  sentence of the Build list; the story's eight tests are otherwise as
  written.
- Matching treats `;` parts independently; names in `--ignore` match exactly
  (case-sensitive, no globs).

## S15.2.2 — Python repositories run it in `lint`

**What the build settled that the story did not say:**

- The command variable is `DEVOPS`, not `KILN_DEVOPS`: `tasks/python.yml` did
  not define it (only `tasks/ci.yml` does), so `python.yml.j2` gains its own
  `vars: DEVOPS` entry, rendered only when the task renders. The command and
  test 1 use `{{.DEVOPS}}`.
- `"pip-licenses"` sits in sorted position after `"pip-audit"` in `_DEV_GROUP`
  and `TASK_TOOLS` (the story said after `"import-linter"`; `pip-audit` sorts
  between). The dev-group specifier is `pip-licenses>=5.5.5`.
- The task and the `lint` call render only when
  `licenses_enabled and not node_lib`: `node-lib` has no Python toolchain (its
  task is S15.2.3).
- The root `lint` calls `python:lint:licenses` right after `python:lint:audit`.
- Policy flags render single-quoted, one per line in the folded scalar.
- kiln's own repository: `kiln apply` does not edit `pyproject.toml`, so
  `pip-licenses` was added to its dev group with `add_task_tools` and
  `uv.lock` refreshed by `task setup`. `task lint` runs the check on kiln's
  516 dependencies and passes with no `ignore` entry. Test 7 of S15.2.1 now
  runs.
- `tasks.artifacts` now imports `cicd.registry` and `cicd.config`; both are
  recorded in the repo-owned `ignore_imports` of `.importlinter`, as S15.1.4
  did.
- The task always passes `--ignore` for the repository's own distributions
  (`[repository] name`, each package, and the `-api` package of a web
  archetype), after the configured `ignore`: an unreleased project carries no
  licence metadata and `pip-licenses` lists it as `UNKNOWN`. It also always
  ignores `text-unidecode` (`_LICENSES_ALWAYS_IGNORED`), which is
  dual-licensed Artistic or GPL and is reached through kiln's own docs group
  (`mkdocs-monorepo-plugin` -> `python-slugify`), so every fresh `python-lib`
  repository failed its own `lint`. Owner to review the policy.
- Tests that run kiln inside a freshly generated repository use the pushed
  `[kiln] ref`; they were run against this checkout's committed `feature/v1`
  through a git `url.<local>.insteadOf` redirect set in the environment
  (`GIT_CONFIG_COUNT`/`GIT_CONFIG_KEY_0`/`GIT_CONFIG_VALUE_0`), which writes
  nothing to the repository.
- Existing tests that enumerate `python.yml`'s tasks, its `vars` and the root
  `lint` order (`s4_12_4_1`, `s4_12_4_5`, `s4_12_6_2`) now include
  `lint:licenses`, `DEVOPS` and `python:lint:licenses`.
