# S18.10.6 — Task overrides are serialised

Brief for
[S18.10.6](../F18.10-review-defects.md#s18106-task-overrides-are-serialised), at
`feature/v1` after `c8b6b075`.

## Goal

A `[tasks.command_overrides]` value reaches the rendered task file as one quoted
YAML scalar, whatever characters it holds, and the list of overridable tasks is
declared once.

## Settled

- New `src/rn_forge/kiln/modules/tasks/templates/tasks/_overrides.j2` holds one
  macro, written with the engine's `[[ ]]` delimiters:
  `{% macro override(name) -%}[[ overrides[name] | tojson ]]{%- endmacro %}`.
  `tojson` writes a JSON string, which is a valid YAML double-quoted scalar.
  Its escapes of `<`, `>`, `&` and `'` (`>`) decode to the same text.
- Each of the six templates that interpolate an override (`node`, `quality`,
  `python`, `workspace`, `ci`, `docs`; 28 sites) imports it on the line after
  the provenance header with
  `{%- from "tasks/_overrides.j2" import override with context -%}` (the macro
  reads the `overrides` context variable), keeps the
  `{% if overrides.get(X) %}` guard, and replaces `[[ overrides[X] ]]` by
  `[[ override(X) ]]`. The import must leave no blank line: `task kiln:apply`
  must change no file in this repository.
- In `src/rn_forge/kiln/modules/tasks/artifacts.py`, the six tuples
  `_WORKSPACE_TASKS`, `_QUALITY_TASKS`, `_PYTHON_TASKS`, `_CI_TASKS`,
  `_DOCS_TASKS` and `_NODE_TASKS` become one tuple `OVERRIDABLE` (same names,
  same order, exported). `render` builds `known` as the names whose namespace
  (text before the first `:`) is `workspace`, `quality`, `python` or `ci`, or
  `docs` when the docs profile is `mkdocs`, or `node` when the repository has
  node. A task kiln never lets be overridden (`python:lint:audit`) stays out
  of the tuple, as today.
- Rejected (do not build): escaping by hand in the template, and a Python
  context function in place of the macro.

## Current behaviour

- Probed on a `python-tool` repo with
  `[tasks.command_overrides] "python:typecheck" = 'echo "a: b"'`: the rendered
  `tasks/python.yml` loads with `cmds == [{'echo "a': 'b"'}]`, a mapping, not
  a command, so go-task cannot run it.
- Today's `known` and the templates agree exactly (probed: no name is in one and
  not the other), so test 3 below passes before and after; it keeps them so.

## Tests first

New file `tests/modules/tasks/test_task_overrides.py`, with `_root`, `_load` and
`_run_task` from `tests/modules/tasks/support.py` and `requires` from
`tests.conftest`:

1. `test_an_override_with_a_colon_runs_as_one_command`, `@requires("task")`:
   `_root(tmp_path, "python-tool", extra='\n[tasks]\n[tasks.command_overrides]\n"workspace:clean" = \'echo "a: b"\'\n')`,
   `cycle.apply(root, home=tmp_path / "home")`. Assert
   `_load(root, "tasks/workspace.yml")["tasks"]["clean"]["cmds"] == ['echo "a: b"']`,
   then `_run_task(root, "clean")` returns 0 with `a: b` in its stdout.
   Before: the `cmds` assertion fails with the mapping above.
1. `test_an_override_round_trips_through_yaml`, parametrized over `echo a: b`,
   `- echo x`, `# not a command`, `{{.X}} run`, `echo "q" 'r' \ s`,
   `echo >&2 x`, and a non-ASCII `echo café`: the same render, then
   `cmds == [text]`. Before: the colon, leading `- `, leading `#` and leading
   `{{` rows fail; the rest pass.
1. `test_every_overridable_task_is_used_by_a_template_and_no_other_is`: collect
   `override\("([^"]+)"\)` over `templates/tasks/*.j2` and assert the set
   equals `set(artifacts.OVERRIDABLE)`.

Existing override tests (`test_command_override_is_accepted`,
`test_an_unknown_override_key_is_still_refused`, the node and CI
`test_overrides_take_the_new_keys`) must pass unchanged: they load the YAML, so
quoting does not show.
