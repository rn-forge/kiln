Design: [design.md](design.md)

kiln renders ARCH-0001–ARCH-0003 and their index into `docs/adr/kiln/`, links
them from a block in `docs/adr/index.md`, points `standard.md` and the
`AGENTS.md` block at them, and gains the `dependencies-point-inward` contract
that enforces ARCH-0001.

*Rewritten 2026-11-19 (owner decisions).* The records live under
`docs/adr/kiln/` as `ARCH-<nnnn>`, there is no `baseline` module, and the
goldens are no longer in git, so a template's output is reviewed through the
render matrix ([F4.4](../E4-generator/F4.4-render-matrix.md)). The earlier text
is in git history.

**Build a story by the [board's procedure](../../index.md#building-a-story).**
The texts to copy are in [design.md](design.md); copy them exactly. Every build
story ends with `task kiln:apply` here, then `task lint KILN_DOCTOR_FULL=1`, and
`task self:golden:compare BASE=HEAD`, whose diff the owner reviews. kiln is a
`python-tool` with the `mkdocs` profile, so its own repository takes ARCH-0001,
ARCH-0002 and the contract like any other.

## S12.1.2 — The `docs` module renders the Python records

**State:** New · **Module:** `core`, `docs` · **Depends on:** S12.1.1

**Renders**, after the existing `docs` artifacts, for `docs.profile = "mkdocs"`:

| Artifact | Kind | When |
| -- | -- | -- |
| `docs/adr/index.md#rn-forge kiln` | block | at least one record applies |
| `docs/adr/kiln/ARCH-0001.md` | managed | `not config.is_workspace and not config.is_node_lib` |
| `docs/adr/kiln/ARCH-0002.md` | managed | `not config.is_workspace and not config.is_node_lib` |
| `docs/adr/kiln/ARCH-0003.md` | managed | `config.is_workspace` |
| `docs/adr/kiln/index.md` | managed | at least one record applies |

**Check first.** `docs/adr/index.md` is already a seeded artifact of the `docs`
module. Write the test *a seeded file and kiln's block on the same path plan as
create then insert* (below) before anything else. If the planner refuses two
artifacts on one path, stop and report; do not work around it.

**Build — tests first:**

- `tests/modules/core/test_architecture.py`:
    - `test_each_cell_gets_its_records`: `records_for` returns ARCH-0001 and
      ARCH-0002 for `python-app` and `python-tool`, ARCH-0003 for `python-lib`,
      and nothing for `node-lib`.
    - `test_record_ids_are_unique_and_in_order`.
- `tests/modules/docs/test_architecture.py`, copying the shape of
  `tests/modules/docs/test_artifacts.py`:
    - `test_renders_the_records_for_each_python_cell`: the **Renders** table, for
      `python-app`, `python-tool` and `python-lib`.
    - `test_a_seeded_file_and_kiln_s_block_on_the_same_path_plan_as_create_then_insert`:
      into an empty directory, `docs/adr/index.md` is created and the block
      inserted; a second apply changes nothing.
    - `test_the_block_survives_an_edit_to_the_seeded_index`: a line added above
      the block is kept, and the block is unchanged.
    - `test_profiles_other_than_mkdocs_render_no_records`: `external` and `none`.
    - `test_node_lib_renders_no_records_and_no_block`.
    - `test_the_rendered_files_are_mdformat_clean`: write them into `tmp_path`
      with kiln's `.mdformat.toml`, run
      `[sys.executable, "-m", "mdformat", "--check", str(tmp_path)]`, and assert
      the return code is 0.
    - `test_docs_checks_pass_with_the_records`: after `kiln new` into `tmp_path`
      and `task docs:generate`'s generator, the `docs` module's checks report no
      `orphan-page` and no broken link.
    - `test_a_hand_edit_to_a_record_is_drift`, as `standard.md`'s drift test does.

**Build:**

- **`src/rn_forge/kiln/modules/core/architecture.py`** exposes `Record`, a
  `@dataclass(frozen=True, slots=True)` with `id: str`, `title: str` and
  `applies: Callable[[KilnConfig], bool]`; `RECORDS: tuple[Record, ...]`
  holding ARCH-0001, ARCH-0002 and ARCH-0003 in that order, with the titles
  and predicates in [the catalogue](design.md#the-catalogue); and
  `records_for(config: KilnConfig) -> tuple[Record, ...]`, the records whose
  `applies(config)` holds, in `RECORDS` order. It does not look at the docs
  profile.
- **`src/rn_forge/kiln/modules/docs/architecture.py`** exposes
  `ADR_BLOCK = ManagedBlock("rn-forge kiln", comment="<!--")` and
  `render(config: KilnConfig, engine: TemplateEngine) -> list[Artifact]`.
  `render` returns `[]` unless `records_for(config)` is non-empty. Otherwise
  it returns, in order: the block artifact for `docs/adr/index.md`
  (`ArtifactKind.BLOCK`, template `docs/adr/index.block.md.j2`,
  `block=ADR_BLOCK`), one managed `docs/adr/kiln/<id>.md` per record, then the
  managed `docs/adr/kiln/index.md`. The context adds `records`, a list of
  `(id, title)` pairs.
- **`modules/docs/artifacts.py:render`** appends
  `architecture.render(config, engine)` to what it returns. Its early return
  for a profile other than `mkdocs` already covers that case.
- **Templates** in `modules/docs/templates/docs/adr/`: `index.block.md.j2`, and
  `kiln/ARCH-0001.md.j2`, `kiln/ARCH-0002.md.j2`, `kiln/ARCH-0003.md.j2` and
  `kiln/index.md.j2`, each exactly as [design.md](design.md) gives it. If
  Jinja's whitespace control makes the index's rows or the blank line before
  `## Deviating` come out wrong, build the rows as one pre-joined string in
  `render`, as `python`'s `members_block` does. The rendered bytes are what
  count.
- Any existing test that fails *only* because a list of artifact keys or
  `state.json` keys gained the new entries gets them added; record each under
  *What the build settled*. Any other failure stops the build.

**Do not:** add a module, a config key, an option or a check; import `docs` from
another concern module; change `docs/adr/index.md.j2` or `.mdformat.toml`.

**Acceptance:**

- The tests above pass, and `task validate` passes.
- `task kiln:apply` here renders `docs/adr/kiln/ARCH-0001.md`, `ARCH-0002.md`
  and `index.md`, and appends the block to kiln's `docs/adr/index.md`;
  `task lint KILN_DOCTOR_FULL=1` passes.
- Not scriptable, judged by the owner: the render matrix diff, and the records
  read correctly on kiln's built site.
