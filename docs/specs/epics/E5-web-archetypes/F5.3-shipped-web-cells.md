## S5.3.1 — Ship three cells

**Status:** planned

Shipped cells: `python-web-api` + fastapi; `python-web-app` + django + angular;
`python-web-app` + fastapi + angular — the last is the shape the
[intellibuild plan](../../../plans/intellibuild.md) builds on, though
intellibuild does not gate this feature. `react`, `svelte` and `python-web-api`
\+ django stay `untested = true`.

**Acceptance:**

- `task self:golden:render` renders the three web cells alongside the Python
  cells, and `task self:golden:validate` passes for each.
- `kiln new` with `react`, with `svelte`, or with
  `python-web-api --backend django` exits non-zero without the override,
  naming the value.
- The owner's approval of the rendered web cells is recorded on this story.
- The open question is answered, and the shipped list above matches the answer.

## Acceptance

```bash
set -euo pipefail
fails_with() { local out rc=0; out=$("${@:2}" 2>&1) || rc=$?; [ "$rc" -ne 0 ] && grep -qF -- "$1" <<<"$out"; }
cd rn-forge/kiln
task self:golden:render                                                               # S5.3.1
task self:golden:validate                                                             # S5.3.1
s=$(mktemp -d)
fails_with react uv run kiln new "$s/r" --archetype python-web-app --backend fastapi --frontend react --docs none --yes </dev/null    # S5.3.1
fails_with svelte uv run kiln new "$s/s" --archetype python-web-app --backend fastapi --frontend svelte --docs none --yes </dev/null  # S5.3.1
fails_with django uv run kiln new "$s/d" --archetype python-web-api --backend django --docs none --yes </dev/null                    # S5.3.1
```

Not scriptable: the owner's approval and the answered question.

## Open questions

**Answer before E5 starts.** This is an entry criterion of
[release-2](../../../releases/release-2/index.md).

1. **`python-web-app --backend django`** (open question 4) is a shipped flag
   value, templated from `rn-forge-django`'s conventions — confirm it ships,
   or mark it untested until a repo uses it. **Proposed (2026-09-16): mark it
   `untested` for release-2.** No repo in scope uses it, the owner's next
   repositories are `fastapi` + `angular`, and shipping it costs a django
   scaffold ([S5.2.3](F5.2-kiln-new-web-end-to-end.md#s523-the-django-scaffold))
   plus a third validated cell. Under this answer the shipped list is the
   two `fastapi` cells, `[untested]` gains `backend = ["django"]` on both web
   manifests, and the `fails_with django` line above applies to both
   archetypes. Untested is not removed: the templates keep their `django`
   branches, and a repo that needs them promotes the value with one cell.
