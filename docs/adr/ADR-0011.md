# ADR-0011 — Work is tracked as Azure DevOps-shaped work items

**Status:** accepted (2026-10-01), revision proposed (2026-10-21) · **Scope:**
the specs and releases of every repository kiln generates, and kiln's own

## Decision

Epics, features and stories follow Azure DevOps's Agile process. Their state is
`New`, `Active`, `Closed` or `Removed`. An epic, feature or release page opens
with a metadata table, and each page type has a fixed set of keys in a fixed
order. A feature's `Iteration` is the only place its release is recorded, and
`deferred` is a tag. A release keeps its own `Status` (`planned`, `in progress`,
`shipped`), because a release closes on scope, not on a date.

Ideas not yet agreed as work live in `specs/ideas/`, with no IDs and no state.
Every idea is a row in `ideas/index.md`, the one list of them. An idea that
needs more than its row also has its own page beside the index, named after the
row and linked from it. Promoting an idea moves its page into the new epic or
feature and deletes the page and the row.

The spec board's Releases and Backlog sections, and each release page's Scope
table, are derived regions ([ADR-0003](ADR-0003.md)). `kiln docs-generate`
writes them, and the same pass validates every page's metadata. No repository
carries a script for this.

## Consequences

- A release's scope and a feature's state are each written once. The release
  page and the board can no longer disagree with the features.
- Moving to Azure DevOps later is a field-by-field mapping, not a remodelling.
- kiln's own epics, features and release pages are rewritten once (F13.3).
- Cost: a metadata table is stricter than a `**Status:**` line. A page with a
  key out of order fails `task lint`.
- A large idea can be written up in full, linked and shown in the nav, without
  being agreed as work. The ideas table stays short enough to read.
- A repository that still has `specs/ideas.md` must move it to
  `specs/ideas/index.md`. `kiln doctor` reports the old file until it does,
  and reports any idea page the index does not link to (F13.4).

## Influences

[E13](../specs/epics/E13-docs-work-model/index.md) builds it, and
[F13.4](../specs/epics/E13-docs-work-model/F13.4-ideas-folder.md) adds the ideas
folder; its [design](../specs/epics/E13-docs-work-model/design.md) lists the
keys and rules. The seeded `docs/specs/_structure.md` and
`docs/releases/_structure.md` state them for each repository.

## Alternatives considered

- **Keep kiln's status lines** (`elaborating`, `planned`, `in progress`, `done`,
  `deferred`). Each feature's status is copied by hand onto its release page's
  scope row. The "keeping it honest" list asks a reviewer to check that by
  eye, and it is the check most often missed.
- **Seed a repository-owned board script.** The working version was 637 lines of
  POSIX shell and awk. kiln's test suite cannot exercise it, it is the kind of
  `scripts/**` file [ADR-0006](ADR-0006.md) moved into kiln, and every
  repository's copy would drift.
- **One `ideas.md`, with a section per large idea.** This was the rule until
  2026-10-21. A large idea, such as a proposal with costs, an order of work
  and its own open questions, turns the parking lot into a long page with the
  table lost at the top. A section also cannot appear in the nav as a page of
  its own.
- **A `specs/backlog/` folder holding `ideas.md`, one page per large idea and an
  `index.md` joining them.** The spec board's Backlog section already means
  agreed features with no release, so one word would name two states. An
  `ideas.md` beside an `index.md` would also be two lists of the same ideas.
- **Write a large idea straight up as a deferred epic.** An epic means agreed
  work, so this would agree to the idea just to give it a page. Agreed work
  that is not ready is still a deferred epic.
- **Use Azure DevOps itself now.** No tracker is chosen
  ([E8](../specs/epics/E8-ado-provider/index.md) is deferred). The files stay
  the record until one is.

## Background

The model was first used in pykit on 2026-09-30, where its own board script
validated every page. A docs alignment review that day recommended it as the
standard. That review is now
[E13's design](../specs/epics/E13-docs-work-model/design.md).

Revised on 2026-10-21 to replace `ideas.md` with the `ideas/` folder. The prompt
was a proposal to move rn-forge-devops into its own repository, which was too
large for a row and would have been the first idea with a full section. kiln's
docs structure is settled before other repositories adopt it.
