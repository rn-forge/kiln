# S18.11.1 — `task-layout` reads only what the repository owns

## Owner decisions (2026-11-24)

The story's text could not be built as written in three places. The owner chose
the recommendation in each, and the brief below is written for them.

1. **`extra_refs` cannot break reachability.** In `Taskfile.yml.j2` each verb's
   `extra_refs` are appended to the verb's steps (`validate` adds them after
   `lint`, `typecheck`, `test` and `docs:build`). They only add edges, so no
   `extra_refs` value can remove a required task from `validate`'s reachable
   set. What decides reachability is the template, the archetype's
   `required_validate`, the docs profile and the checks that are switched on.
   Decided: the reachability rule becomes a render test over every cell (that
   is where it can fail), and the config-load refusal the acceptance asks for
   is a different `extra_refs` rule: a target whose namespace kiln does not
   generate and `tasks.includes` does not declare is refused, naming the key.
   The acceptance line then reads "an `extra_refs` target that names no
   namespace is refused at config load".
1. **Cycles through repository-owned includes.** Today `doctor` finds a cycle
   such as owned task -> root verb -> `extra_refs` -> the same owned task by
   reading the whole committed graph. `doctor` is render-free
   (`render-free-checks` in `.importlinter`) and must not read managed files,
   so it can model only the edges it owns: the owned files, and each verb's
   `extra_refs` from the config. Decided: accept that. Cycles that pass
   through other managed tasks are no longer reported by kiln; `go-task` stops
   them at run time.
1. **The normative page.** `docs/reference/standard-repo.md:417-420` lists
   `taskgraph.*` and `gate.shrunk` as doctor findings, and it is the page the
   rendered `.rn-forge/kiln/standard.md` states. Decided: the same change
   edits that page (and, if a template carries the sentence, the template,
   then `task kiln:apply`). Say so in `## Result`.

## Goal

`task-layout` reads only the repository's own task files and the config. Every
rule it applied to kiln's rendered Taskfiles becomes a named render test over
every cell, or a config-load error; no rule is lost.

## Settled

- `src/rn_forge/kiln/modules/tasks/checks/layout.py` is under 150 lines and
  keeps three findings, all about repository-owned includes (the
  `tasks.includes` entries):
    - `taskgraph.missing-include`: an owned include's `taskfile` is absent.
    - `taskgraph.unresolved`: an `extra_refs` target in an owned namespace names a
      task the owned file does not define. It reads the owned file with
      `task_specs`.
    - `taskgraph.cycle`: a cycle in the graph of owned tasks plus one node per
      root verb whose edges are that verb's `extra_refs`; an owned task's
      `task:` reference to a root verb (bare or `:`-prefixed) is an edge to that
      node. The graph needs no managed file.
    - `check` returns `[]` when the config declares no includes. It never opens
      `Taskfile.yml` or `tasks/<managed>.yml`.
- Config load: `TasksConfig` (`modules/tasks/config.py`) gains a
  `model_validator(mode="after")` that refuses an `extra_refs` target whose
  namespace (text before the first `:`, after any leading `:`) is not in
  `GENERATED_NAMESPACES` or the declared include namespaces. A bare target
  must be a root verb. The error is
  `ValueError(f"tasks.extra_refs.{verb} target {target!r} names no namespace kiln generates or tasks.includes declares")`.
- Deleted from `layout.py`: `_check_surface`, `_check_desc`,
  `_check_wrapper_only`, `_check_internal`, `_check_refs`,
  `_check_owned_text`, `_unresolved_in`, `load_graph`, `resolve`,
  `reachable_from`, `_check_gate`, `RESERVED_NAMESPACES`, `PUBLIC_KILN_TASKS`
  and `_TASK_CALL`. The codes `taskgraph.surface`, `.no-desc`, `.not-a-wrapper`,
  `.not-internal`, `.unresolved-ref`, `.no-gate`, `.missing` and `gate.shrunk`
  stop existing in `src/`.
- The deleted helpers move, unchanged, to `tests/modules/tasks/graph.py`
  (`load_graph`, `resolve`, `reachable_from`, `unresolved_in`) with the two
  constants, for the render tests. Production has no caller left.
- Rejected (do not build): rendering inside `doctor`, and keeping the managed
  rules behind a flag.

## Current behaviour

- `layout.py` is 411 lines and reads `Taskfile.yml`, every managed
  `tasks/*.yml`, `state.json` and every managed workflow and block.
- A hand edit of a managed Taskfile is reported twice today: by `generated`
  (`artifact.drift`) and by `task-layout`.
- `TasksConfig` accepts `extra_refs = { validate = ["nowhere:build"] }`;
  `doctor` then reports `taskgraph.unresolved` only after a render. The new
  config test fails before the change with `DID NOT RAISE`.

## Tests first

New file `tests/modules/tasks/test_task_layout.py`, parametrized over
`RENDER_CELLS = [*ALL_CELLS, ("node-lib", "")]` (the list
`tests/modules/tasks/test_task_ci.py` builds; import it from `support.py`, where
you move it). Each builds the root as `_ci_root` or `_node_lib_root` does,
applies it (`cycle.apply(root, home=tmp_path / "home")`) and reads files:

1. `test_the_root_taskfile_holds_exactly_the_root_verbs`: the root tasks equal
   `ROOT_VERBS` (plus `WEB_APP_VERBS` for `python-web-app`).
1. `test_every_task_has_a_desc`: root and every `tasks/*.yml`.
1. `test_the_root_taskfile_holds_wrappers_only`: every root `cmds` entry is a
   `task:` call and no root task is shell shorthand.
1. `test_inner_tasks_are_internal`: tasks in `quality`, `workspace`, `node`,
   `python` and `kiln` carry `internal: true`, except the `kiln` tasks in
   `PUBLIC_KILN_TASKS`.
1. `test_every_task_reference_resolves`: every `task:` target, through
   `graph.resolve`, is in the graph, skipping targets with `{{` or `$`.
1. `test_the_task_graph_has_no_cycle`.
1. `test_every_required_validate_task_is_reachable_from_validate`: the cell's
   `archetypes.for_config(config).required_validate` is within
   `reachable_from("validate", ...)`. Add cells with `docs = "mkdocs"` and
   with `[ci.checks] licenses = true` for `python-app`, and an `extra_refs`
   cell.
1. `test_managed_workflows_and_blocks_call_existing_tasks`: the logic of the
   deleted `_check_owned_text`, over the applied repo's `state.json` entries.

These pass before and after (they move rules, they do not fix one); say so in
