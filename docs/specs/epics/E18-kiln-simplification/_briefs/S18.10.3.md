# S18.10.3 — A config source ref may contain `/`

Brief for
[S18.10.3](../F18.10-review-defects.md#s18103-a-config-source-ref-may-contain),
at `feature/v1` after `523016f`.

## Goal

`Source.parse` splits `git+<url>@feature/profile` into the URL and the ref
`feature/profile`, and still leaves a `git+ssh://git@host/...` URL with no ref
whole.

## Settled

- In `src/rn_forge/kiln/modules/core/config/sources.py`, `Source.parse` splits
  on the last `@` as today. The text after it is a ref when it holds no `:`
  and the text before it has a `/` after the scheme's `://`. In code:
  `"/" in head.partition("://")[2]` replaces `"/" not in ref`.
- So the `@` of `git+ssh://git@github.com/o/r.git` is not a split (the head is
  `git+ssh://git`, with nothing after `://` but `git`), and the `@` of
  `git+ssh://git@github.com/o/r.git@v1` is.
- A value with no `://` never splits, which is today's result for `git+<path>`
  forms with no scheme.
- Rejected (do not build): a regex over the whole URL, and a `--ref` flag.

## Current behaviour

- Probed: `Source.parse("git+file:///t/p.git@feature/profile")` returns
  `Source(location="git+file:///t/p.git@feature/profile", ref=None)`.
- `ConfigManager().resolve(flags=FLAGS, source=Source.parse(...@feature/profile))`
  against a real bare repo with branch `feature/profile` then clones the URL
  with the suffix glued on, and raises `AppException` ("config source ...").
- `git+ssh://git@github.com/o/r.git` and `...r.git@v1` already parse as the
  settled rule says; they are regression guards.

## Change

- **Change:** the one condition in `Source.parse`, and its docstring.
- **Leave alone:** `fetch`, `_git`, `SourceConfig` and every other file.
