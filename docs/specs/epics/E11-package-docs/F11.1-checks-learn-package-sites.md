## S11.1.1 — The `include` area kind

**State:** New

**Build:**

- `modules/docs/areas.py`: `NAV_VALUES` gains `"include"`. The `Area` docstring
  says: `"include"` declares an area that is not a directory under `docs/`,
  and its nav is one `!include` entry per package.
- `modules/docs/nav.py`:
    - `build_nav(docs_root, packages: Sequence[str] = ())` and
      `update_nav(mkdocs_path, docs_root, packages: Sequence[str] = ())` pass
      `packages` through to `_area_entry`.
    - For an `include` area, `_area_entry` returns `None` when `packages` is
      empty. Otherwise it returns
      `{area.title: [{Path(p).name: f"!include {p}/mkdocs.yml"} for p in packages]}`,
      in `packages` order.
- `modules/docs/structure.py`: `_check_areas` skips an `include` area, so it
  needs no directory, `index.md` or `_structure.md`.
- `modules/docs/generate.py`: `generate(root, packages: Sequence[str] = ())` and
  `stale(root, packages: Sequence[str] = ())` pass `packages` to `update_nav`.
  The callers pass `packages`: `checks/derived.py:check` and
  `commands.py:docs_generate`. `docs_generate` loads the repository's config
  with `ConfigManager().load(path)`, as `doctor` does, and so does
  `commands.new`'s call.

**Tests:** `tests/modules/docs/test_docs.py` for `load_areas` and `build_nav`,
and `tests/modules/docs/checks/test_structure.py` for `_check_areas`.

**Acceptance:**

- An `_areas.yml` declaring `nav: include` loads, and an unknown `nav` value
  still raises `AppException`.
- `build_nav` with an `include` area titled `Packages` and packages
  `("packages/a", "packages/b")` renders `Packages` with two entries, `a` then
  `b`. Their values are the strings `!include packages/a/mkdocs.yml` and
  `!include packages/b/mkdocs.yml`, quoted in the YAML so that they are not
  read as tags.
- With no packages, `build_nav` renders no `Packages` entry, and
  `docs-structure` reports nothing for the absent `docs/packages/`.
- A web archetype's config, whose `config.packages` is `(api_dir,)`, renders no
  `include` entry.
- In kiln's repository, `kiln doctor --only docs-generate` passes.

## S11.1.2 — Links into and inside package sites

**State:** New · **Depends on:** S11.1.1

**Build:**

- New `modules/docs/packages.py`, shared by both link checkers:
    - `package_mounts(root: Path, packages: Sequence[str]) -> dict[str, Path]`
      maps each package's `site_name` to its resolved docs directory. Both are
      read from `<root>/<pkg>/mkdocs.yml`, and `docs_dir` defaults to `docs`. A
      package without a `mkdocs.yml` is left out; S11.2.3 reports it.
    - `resolve_link(page: Path, target: str, docs_root: Path, mounts: Mapping[str, Path]) -> Path`
      resolves *target* against *page*'s directory. The result is remapped only
      when all three of these hold: it does not exist, it lies under
      *docs_root*, and its first path segment relative to *docs_root* is a key
      of *mounts*. It is then remapped to `mounts[segment] / <rest>`.
- `modules/docs/structure.py`:
  `check_structure(repo_root, docs_root, policy, packages: Sequence[str] = ())`.
  `_check_links` resolves through `resolve_link` with the mounts, so that
  anchors into a package page are checked against that page.
- `modules/docs/site.py`:
    - `Site(root, *, docs_dir="docs", packages: Sequence[str] = ())`.
      `linked_pages` and `check_links` resolve through `resolve_link`.
    - `check_site(root, *, docs_dir="docs", packages=())` runs the root checks,
      then, for each package with a `mkdocs.yml`, a
      `Site(root / pkg, docs_dir=<its docs_dir>)`. On a package site it runs
      `check_nav_targets_exist`, `check_orphans` and `check_links`.
    - In a package site, `check_links` reports `docs.package-link-escapes`, with
      the message `links outside <pkg>/<docs_dir>: <link>`, for any link that
      resolves outside that package's docs directory. It does so even when the
      target exists.
- `checks/structure.py` and `checks/site.py` pass `packages`.

**Tests:** `tests/modules/docs/checks/test_structure.py` and a new
`tests/modules/docs/checks/test_site.py`. One fixture repository under
`tmp_path` has packages `packages/alpha` (`site_name: alpha`) and
`packages/beta`.

**Acceptance:**

- A root page linking `alpha/index.md#usage`, where the heading exists, gives no
  finding in `docs-structure` or `docs-site`.
- A root link to `alpha/missing.md` is `docs.broken-link`, and a root link to
  `alpha/index.md#nope` is `docs.broken-anchor`, in both checks.
- A page in `packages/alpha/docs/` that links `../../beta/docs/index.md` or
  `../../../docs/index.md` reports `docs.package-link-escapes`, although both
  files exist.
- A package page that its nav does not name and no reachable page links to
  reports `docs.orphan-page` with its package path. A package nav entry that
  names a missing page reports `docs.nav-missing-page`.
- With `packages=()`, every existing structure and site test passes unchanged.

## S11.1.3 — Check only what ships

**State:** New · **Depends on:** S11.1.2

**Build:**

- Add `pathspec` to `[project] dependencies` in kiln's `pyproject.toml`. It is
  already in `uv.lock` through MkDocs, which reads `exclude_docs` with it, so
  this matches what MkDocs does rather than approximating it.
- `modules/docs/packages.py` gains
  `excluded_docs(mkdocs_yml: Path) -> pathspec.PathSpec`. It reads
  `exclude_docs` (a gitignore-style block string) with the `gitwildmatch`
  syntax, and returns an empty spec when the key or the file is absent.
- `modules/docs/site.py`: `Site.markdown_files` drops pages whose path relative
  to `docs_dir` matches the site's own `mkdocs.yml` spec. For a package site,
  that is the package's `mkdocs.yml`. `check_orphans` and `check_links`
  therefore skip them. A shipping page that links an excluded page reports
  `docs.broken-link` with the message
  `links to a page excluded from the site: <link>`, which is what
  `mkdocs build --strict` fails on.
- `modules/docs/structure.py`: `_check_links` and `_check_no_underscore_refs`
  skip pages matching `<repo_root>/mkdocs.yml`'s spec.

**Tests:** `tests/modules/docs/checks/test_site.py` and `test_structure.py`,
with a fixture whose `mkdocs.yml` has:

```yaml
exclude_docs: |
  _*
  plans/archive/
```

**Acceptance:**

- A broken link inside `docs/plans/archive/old.md` gives no finding in
  `docs-structure` or `docs-site`. The same link in `docs/plans/new.md` gives
  `docs.broken-link`.
- `docs/plans/archive/old.md` is not reported as an orphan.
- `docs/plans/new.md` linking `archive/old.md` reports `docs.broken-link` naming
  the exclusion.
- The seeded `exclude_docs: "_*"` keeps today's behaviour. Every existing test
  passes unchanged.
