# S21.2.2 — The releases standard names the page

Brief for
[S21.2.2](../F21.2-evidence-page.md#s2122-the-releases-standard-names-the-page),
at `feature/v1` `d6f82b56`.

## Goal

With `[ci.checks] release-evidence` on, the rendered
`docs/releases/_structure.md` names `release-<n>/security.md` and its exit
criterion, a release page may link it from its metadata table, and `kiln doctor`
fails when the newest shipped release has no `security.md`.

## Settled

### Context

- `release-evidence` is a configured CI check (F21.1, closed):
  `"release-evidence" in config.ci_checks` is whether it is on. It is off by
  default and needs `[ci] release` other than `none`.
- The page itself is rendered by `task release:evidence -- <run-id> <n>`
  (S21.2.1, in flight in another worktree; this story only names it).

### The structure page

- `src/rn_forge/kiln/modules/docs/artifacts.py` `seed_context` gains
  `"release_evidence": "release-evidence" in config.ci_checks` (widen its
  return type to `dict[str, object]`; fix any caller pyright then flags).
- In `src/rn_forge/kiln/modules/docs/templates/docs/releases/_structure.md.j2`:
    - Inside the **Exit criteria** sub-bullet, after the Dependabot sentence,
      append, under `{% if release_evidence %}…{% endif %}`:
      `A second stands when CI records release evidence: the release's`
      `` `security.md` exists and every row's result is `passed` or `not run`, ``

    - A new top-level bullet, after the `release-<n>/index.md` bullet and before
      the `index.md` bullet, under `{% if release_evidence %}`:

        ```markdown
        - `release-<n>/security.md`: the release's security evidence, one row per
        ```

### The metadata key

In `src/rn_forge/kiln/modules/docs/work/validate.py`,
`RELEASE_KEYS = ("Status", "Start Date", "Finish Date", "Security Evidence")`.
Nothing else in the work rules changes.

### The doctor check

New `src/rn_forge/kiln/modules/docs/checks/evidence.py`, shaped like
`checks/structure.py` (`__all__ = ["NAME", "check"]`):

```python
NAME = "release-evidence"


def check(config: KilnConfig, root: Path) -> list[Finding]:
    """Fail when the newest shipped release has no `security.md`, for a repo recording release evidence."""
```

- Returns `[]` when `config.docs_profile != "mkdocs"` or
  `"release-evidence" not in config.ci_checks`.
- Else `load_work(root / "docs")` (from `rn_forge.kiln.modules.docs.work`); the
  shipped releases are those whose `page.get("Status") == "shipped"`; with
  none, `[]`. Only the one with the highest `number` is checked: when
  `root / "docs" / "releases" / release.dir / "security.md"` does not exist,
  one finding:
  `Finding("docs.release-evidence-missing", Severity.ERROR, f"{release.dir} is shipped but has no security.md; run task release:evidence -- <run-id> {release.number}", path=f"docs/releases/{release.dir}/index.md")`.
- Register it in `src/rn_forge/kiln/checks.py` `CHECKS` after `site`:
  `Check(evidence.NAME, "docs", evidence.check, "quality")`, importing
  `evidence` from `rn_forge.kiln.modules.docs.checks`.
- Rejected (do not build): checking older shipped releases; reading the page's
  rows (the exit criterion is the owner's judgement, recorded on the release
  page); any check when the switch is off.

## Current behaviour

- The rendered structure page never mentions `security.md`, so the new structure
  test fails on its assertion.
- A release page with a `**Security Evidence**` row gets `docs.work-unknown-key`
  (`has unknown key 'Security Evidence'`) from `task docs:generate`.
- `rn_forge.kiln.modules.docs.checks.evidence` does not exist (import error).
- Tests that list every check by name (`tests/test_checks_registry.py`,
  `tests/test_doctor.py`, `tests/commands/test_cli_surface.py`; read each)
  fail once the check is registered until `release-evidence` is added to them.
  If the rendered standard lists the doctor checks, `task kiln:apply`
  re-renders it; that is expected.
