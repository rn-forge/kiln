Every feature page opens with a derived table of its stories, and every epic
whose features have files opens with a derived table of those features. Both sit
right under the page's metadata table, so its scope and status read at a glance.
A release's Scope rows gain the feature's title. All three are derived regions
written by `task docs:generate`. The code lives in `rn_forge.kiln.modules.docs`.
It is then applied to kiln's own specs.

S14.1.2 extends `_work_regions` first. Build on it rather than in parallel.

**Build each story by the
[board's procedure](../../index.md#building-a-story).** Tests go in
`tests/modules/docs/test_work.py` and
`tests/modules/docs/checks/test_derived.py`. Copy the shape of the
`test_s13_2_2_*` tests.

## Design

**Where a summary goes.** A summary region's fence is inserted when a page has
neither of its markers. It goes immediately after the page's metadata table, at
the line index that `work._metadata` returns as the table's end, with one blank
line on each side. An author may then move the fence. `ManagedBlock.render`
rewrites it wherever it is. A page with half a fence gets a `*-markers` error
and is not rewritten. A page with no metadata table gets no fence; validate
already reports `docs.work-no-metadata`. When the fence is inserted, the page is
stale, so `task lint` fails until `task docs:generate` runs. That is how
existing repositories adopt it.

Add one private helper to `generate.py` for this:

```python
def _with_fence(text: str, block: ManagedBlock) -> str | None:
    """*text* with an empty *block* fence after its metadata table.

    Returns *text* unchanged when it already holds both markers, and `None` when
    it holds exactly one, or has no metadata table.
    """
```

Write the empty fence exactly as `ManagedBlock` writes one: render an empty body
into a two-marker string. Do not hand-build the marker text.

**Counting.** A story's state word is the first word of its `**State:**` value,
so `Closed (2026-09-16)` counts as `Closed`. Counts use `_COUNT_ORDER`, joined
by `·`, as the board does. `—` stands for none.

## S14.2.1 — A feature opens with its stories

**State:** Closed (2026-10-14)

**Build:**

- `modules/docs/work.py`:
    - `STORY_HEADING_RE = re.compile(r"^## (S\d+\.\d+\.\d+) — (.+?)\s*$")`.

    - A frozen dataclass
      `Story(id: str, title: str, state: str, depends_on: str)`.

    - `read_stories(text: str) -> tuple[Story, ...]` finds every heading that
      matches outside fenced code. Run `markdown.strip_fenced_code` first if it
      keeps line positions; otherwise track fences yourself.

        - `state` is the first line after the heading that starts with `**State:**`.
          Take the text after the label, up to the first `·`, and strip it.
        - `depends_on` is the text after `**Depends on:**` on that same line, up to
          the next `·` or the end of the line.
        - A missing part is `""`.

    - `Feature` gains `stories: tuple[Story, ...]`, which `load_work` fills.

    - `STORIES_BLOCK = ManagedBlock("derived stories", comment=HTML_COMMENT)`.

    - `render_stories(feature: Feature) -> str`:

        ```markdown

        **Stories:** 2 New · 8 Closed

        | Story | State | Depends on |
        | -- | -- | -- |
        | [S4.5.1 — `kiln new`: creation](#s451-kiln-new-creation) | Closed (2026-09-16) | — |

        ```

        - The link text is the heading text verbatim, with any `|` escaped as `\|`.
        - The anchor is `markdown.slugify(f"{id} — {title}")`.
        - An empty `state` or `depends_on` renders as `—`.
        - A feature with no stories renders `"\nNo stories yet.\n"`.
- `generate._work_regions`: for each feature page, apply `_with_fence` with
  `STORIES_BLOCK`.
    - On `None` with a metadata table present, add `docs.stories-markers` with
      `has an incomplete derived stories fence`.
    - Otherwise call `region(...)` on the fenced text with
      `render_stories(feature)` and `"docs.stories-stale"`. `region` reads the
      current text from disk, so give it the fenced text explicitly; extend its
      signature with an optional `current: str | None = None`.
- `templates/docs/specs/_structure.md.j2`:
    - The feature template shows the empty `derived stories` fence right under the
      metadata table.
    - "The board" names the stories region.
    - Add one rule: "A feature page's stories table is derived from its story
      headings and `**State:**` lines; never edit inside its fence."
- On kiln, re-render the managed `_structure.md` files and run
  `task docs:generate`.

**Do not:** validate story states (that is not this story); change a story
heading; give a story its own file.

**Acceptance:**

- `read_stories` reads the ID, title, state and depends-on of `## S4.5.9 — x` /
  `**State:** Closed (2026-09-26) · **Depends on:** S4.5.1, S5.2.4`. It
  ignores a `## S…` line inside a fenced code block, and stops the state at
  `·` for `**State:** Closed (2026-09-26) · **Unblocked 2026-09-25:** pykit`.
- A feature page with no fence gets one after its metadata table on `generate`.
  The result is stable: a second `generate` writes nothing.
- A page with only a BEGIN marker reports `docs.stories-markers` and is not
  rewritten.
- On kiln, every feature page carries the region, and
  `kiln doctor --only docs-structure` resolves every story anchor in it.

**What the build settled that the story did not say:**

- **A public `work.metadata_end(lines)`.** `_with_fence` needs the line index
  `_metadata` returns, and pyright strict rejects importing a private name
  from another module. `metadata_end` wraps it and is exported.
- **The empty body has a second newline**, as in S14.1.2: `render_stories` of a
  feature with no stories returns `"\nNo stories yet.\n\n"`, so
  `mdformat --check` accepts the fence.
- `Feature.stories` has a default of `()`, so existing constructors need no
  change. `read_stories` stops looking for a story's `**State:**` line at the
  next `## ` heading, so a story with no state line does not take the next
  story's.
- `_with_fence` writes the empty fence with `block.render("", "")`. A page that
  holds both markers is returned as it is, wherever the fence sits.
- A feature page with no metadata table gets no fence and no
  `docs.stories-markers` finding; `docs.work-no-metadata` already covers it.
- Existing tests that pinned the regions of a feature page changed:
  `test_s13_2_2_an_unwritten_board_and_scope_are_stale` now also expects
  `docs.stories-stale`, and
  `test_s13_2_2_generate_writes_the_regions_and_then_nothing_is_stale` now
  expects the feature page among the files written.
- Tests: `test_s14_2_1_1_*` (reading), `test_s14_2_1_2_*` (rendering) in
  `test_work.py`; `test_s14_2_1_3_*` (insertion, stability, a moved fence),
  `test_s14_2_1_4_*` (half a fence) and
  `test_s14_2_1_a_feature_without_a_metadata_table_gets_no_fence` in
  `checks/test_derived.py`.
- On kiln, every feature page now carries the region, including the two with no
  stories (`F6.4`, `F9.1`), which read "No stories yet.". The managed
  `docs/specs/_structure.md` is re-rendered and its hash in
  `.rn-forge/kiln/state.json` re-seeded.
- The derived stories table links every story anchor, which exposed a page that
  MkDocs did not render to the end. S11.4.1's notes quoted a less-than-sign
  redirect in inline code, which Python-Markdown read as an HTML tag, so
  S11.4.2's heading never rendered. `kiln doctor --only docs-structure` did
  not catch it, because its renderer is `toc` alone. The reviewer rephrased
  that sentence in F11.4.
- The new repository's `task validate` was checked with this tree installed
  editable, as before.

## S14.2.2 — An epic opens with its features

**State:** Closed (2026-10-14) · **Depends on:** S14.2.1

**Build:**

- `modules/docs/work.py`:
    - `FEATURES_BLOCK = ManagedBlock("derived features", comment=HTML_COMMENT)`.

    - `render_features(work: Work, epic: Epic) -> str` lists the epic's feature
      files by numeric ID:

        ```markdown

        | Feature | State | Iteration | Stories |
        | -- | -- | -- | -- |
        | [F4.1 — Checks by module](F4.1-checks-by-module.md) | Closed | release-1 | 4 Closed |

        ```

        - Feature: the feature's H1, linked.
        - State: its `State`.
        - Iteration: `Feature.iteration`, or `deferred` when its `Tags` include
          `deferred`, or else `—`.
        - Stories: the story counts, or `—`.

    - `_feature_rows` skips every line inside a `FEATURES_BLOCK` fence. The rows
      it returns are hand-written ones only.
- `generate._work_regions`: for each epic with at least one feature file, apply
  `_with_fence` with `FEATURES_BLOCK`. It reports `docs.features-markers` and
  `docs.features-stale` the way S14.2.1 does. An epic without feature files
  gets no fence.
- `validate` and `_identities`:
    - `no-state-column` is reported only for an epic with no feature files.
    - A new error, `docs.work-feature-table`, is reported on an epic when a
      hand-written row lists an ID that has a feature file in that epic, with
      `lists <ID> by hand; its derived features table shows it`.
    - The `state-mismatch` check then has nothing left to compare for file-backed
      epics. Keep it for rows whose ID has no file.
- `templates/docs/specs/_structure.md.j2`:
    - The epic template replaces its hand-written feature table with the empty
      `derived features` fence under the metadata table.
    - "An epic's feature table has a `State` column, and each row's `State` equals
      its feature's own" becomes "An epic whose features have files shows them
      only in its derived features table. An epic whose features predate the
      taxonomy keeps a hand-written table with a `State` column."
    - "The board" names the features region.
- Migrate kiln's own epics that have feature files: E3, E4, E5, E6, E11, E12,
  E13 and E14.
    - Delete the hand-written feature table. When its heading (`## Features`) held
      nothing else, delete the heading too.
    - Before deleting, compare each row's `Depends on` or `Scope` text with the
      feature's `Predecessors` and opening paragraph. Where the row says more,
      such as a cross-epic ordering note, append that text verbatim to the
      epic's **Dependencies.** paragraph.
    - Leave E1, E2, E7, E8, E9 and E10 unchanged.
    - Run `task docs:generate`.

**Do not:** derive anything for an epic without feature files; move an epic's
prose; add a Scope column to the derived table.

**Acceptance:**

- An epic with two feature files gets the region with both rows, in ID order,
  with their states, iterations and story counts. A deferred feature's
  iteration reads `deferred`.
- An epic that hand-lists a file-backed feature reports
  `docs.work-feature-table`. A pre-taxonomy epic whose table has no `State`
  column still reports `no-state-column`.
- The board and the epic list are unchanged by the migration: running
  `task docs:generate` again writes nothing.
- On kiln, `kiln doctor --only docs-generate` is clean, and no migrated epic
  hand-lists a feature that has a file.

**What the build settled that the story did not say:**

- **E9 is migrated too.** The story leaves E9 unchanged, but E9 has a feature
  file (F9.1) and hand-listed it, so the build gave it the derived features
  region and `kiln doctor --only docs-generate` reported
  `docs.work-feature-table` until the hand-written table went. E9's table row
  said `F6.3; the entry criterion`, which F9.1's `Predecessors` already says.
  Its `## Features` heading held nothing else and is deleted. E1, E2, E7, E8
  and E10 have no feature files and are unchanged.
- **Rows compared with `Predecessors` before deletion.** Every row's
  `Depends on` text is in its feature's `Predecessors`, or in the derived
  stories table (S5.2.4 on S5.2.1, the F5.3 chain, Django deferred as S5.2.3
  `New`). The one row that said more is F11.4's, `S13.3.1, for S11.4.2`: F11.4
  has `Predecessors` of none, and the dependency is in the story's own body.
  The text appended to E11's **Dependencies.** paragraph, after "F11.4 needs
  nothing.", is "The features table also said: S13.3.1, for S11.4.2." Nothing
  was appended to E3, E4, E5, E6, E12, E13, E14 or E9.
- **E4's Phase step column.** F4.9's row said `D.9`, and F4.9 has no Phase step
  line, unlike F4.1 to F4.8. The derived table has no Phase step column, so
  `D.9` is no longer written anywhere. It was not added to F4.9, which the
  story does not allow.
- **One word of E4's prose changed.** Its Dependencies paragraph said "Features
  follow the column below", which pointed at the deleted column. It now says
  "Features follow their `Predecessors` rows".
- **`state-mismatch` is kept for rows with no feature of that ID.** A row whose
  ID has a file in its epic is `docs.work-feature-table` and is not compared.
  A row that has no such ID but links a feature file by name is still compared
  with that file's `State`, which is the only case left.
- `work.validate` computes "has feature files" from `Work.features`. Test
  fixtures in `test_work.py` and `checks/test_derived.py` changed: `EPIC` no
  longer hand-lists its features, and `EPIC_ROWS` is the old text for the
  board tests. The `no-state-column` and `state-mismatch` cases left the
  parametrised table for their own tests.
- Tests: `test_s14_2_2_*` in `test_work.py` (hand-listed rows, state column,
  `render_features`, rows inside the fence) and `checks/test_derived.py` (the
  region, no fence without files, half a fence).
- **The `_structure.md` template was rewrapped** to match what `mdformat` writes
  for a generated repository; kiln's own copy and the hash in `state.json` are
  re-rendered and re-seeded.
- The board, the epic list and every release page are unchanged by the
  migration, and a second `task docs:generate` writes nothing.
- The new repository's `task validate` was checked with this tree installed
  editable, as before.
