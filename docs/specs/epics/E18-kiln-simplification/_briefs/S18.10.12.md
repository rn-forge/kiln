# S18.10.12 — Every name kiln renders is reserved

Brief for
[S18.10.12](../F18.10-review-defects.md#s181012-every-name-kiln-renders-is-reserved),
at `feature/v1` after `523016f`.

## Goal

The reserved job names cover every top-level job of a rendered `ci.yml`, the
stage names are declared once, and a declared task include may not take a
namespace kiln generates. Each refusal happens at config load and names the key.

## Settled

- In `src/rn_forge/kiln/modules/cicd/config.py`, add
  `STAGES = ("integration", "smoke", "sonar", "release", "verify-release", "docs")`,
  export it, and build both sets from it:
  `STAGE_WORKFLOWS = frozenset(f"./.github/workflows/_{stage}.yml" for stage in STAGES)`
  and
  `GENERATED_JOBS = frozenset({"validate", "dependency-review", "secret-scan", "plan", "test", "test-cloud", "test-local", "suites", "umbrella", "scorecard", "checks-ok", "ci-ok", *STAGES})`.
- In `modules/cicd/artifacts.py`, the workflow rows iterate
  `for stage in STAGES`, reading `stages[stage]`; the `stages` dict keeps its
  keys, and a stage missing from it fails with a `KeyError`.
- In `modules/tasks/config.py`, add
  `GENERATED_NAMESPACES = frozenset({"quality", "python", "kiln", "docs", "workspace", "ci", "sonar", "api", "web", "node"})`
  (the keys of the `includes:` map in `Taskfile.yml.j2`, for every
  archetype), export it, and add `@field_validator("namespace")` to
  `TaskInclude`. It raises
  `ValueError(f"tasks.includes namespace {value!r} is a namespace kiln generates")`.
  `KilnConfig.load` wraps it, naming `tasks.includes.0.namespace`.
- The `taskgraph.reserved-namespace` finding in `modules/tasks/checks/layout.py`
  is now unreachable, because every check loads the config first. Delete that
  `findings.extend(...)` block in `_check_includes`, and the `tasks_config`
  parameter it alone used (update the one call). `RESERVED_NAMESPACES` there
  keeps its other use.
- Rejected (do not build): reserving include taskfile paths, and a runtime
  registry of rendered names.

## Current behaviour

- Probed: `ci.yml` rendered for `node-lib` has jobs outside `GENERATED_JOBS`:
  `test-cloud` and `test-local`. `python-tool` with
  `[ci.checks] umbrella-release = true` has `umbrella`. The other archetypes
  are clean.
- So a declared job named `test-cloud`, `test-local` or `umbrella` loads without
  error today.
- A `tasks.includes` entry with namespace `ci` (or `docs`, `sonar`, `api`,
  `web`) loads; only `taskgraph.reserved-namespace` flags some of them, after
  render.

## Change

- **Change:** the three modules above, as settled, and `_check_includes`.
- **Leave alone:** templates, `checks/hooks.py` (it keeps importing
  `STAGE_WORKFLOWS`), the check registry and every generated file.
