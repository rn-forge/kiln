**Status:** done (2026-09-13)

kiln is a pinned dev dependency of every generated repo, and CI runs it
read-only: `kiln check` on every run, `kiln doctor` where the workflow asks
([ADR-0010](../../../adr/ADR-0010.md)). ADR-0010 is revised in place — its
original checks package, organized by module in D74, is rejected there with the
regression-workflow option, and kept under its History — and ADR-0003 is
narrowed.

### Spike result

Run on 2026-09-13 in scratch clones of kiln `feature/v1` and pykit
`feature/upgrade` (`08c6bff`), with uv 0.12.12. `uv lock` only: nothing was
synced or run, because kiln has no code yet. kiln was referenced as
`rn-forge-kiln @ git+file://…/kiln@<branch>`, and the consumer repo was a copy
of `golden/python-app`.

| kiln declares tooling as | pykit dev group | consumer dev group |
| -- | -- | -- |
| direct URL (`rn-forge-tooling @ git+…pykit@feature/upgrade#subdirectory=…`) | **fails** | resolves |
| bare name, git source in kiln's own `[tool.uv.sources]` | **fails**, same error | resolves |

```text

╰─▶ Requirements contain conflicting URLs for package `rn-forge-tooling` in
    split `python_full_version >= '3.14' and sys_platform == 'win32'`:
```

The conflict is one package name with two sources: pykit's workspace member, and
whatever source kiln brings. uv applies a git dependency's own sources, so
moving the URL into kiln's `[tool.uv.sources]` changes nothing. The override
replaces kiln's requirement with a bare name, which pykit's workspace source
then satisfies. It must list every pykit member kiln reaches: tooling today, and
commons and cli once kiln names them directly
([F6.1](../E6-rebuild-the-repos/F6.1-pykit-skeleton.md)).

## S4.1.1 — kiln has an entry point and a `check` command

**Status:** done

kiln stays one distribution, `rn-forge-kiln` with a root `src/`, and its config
stays `python-tool`. kiln's `.rn-forge/kiln/config.toml` declares a `[cli]`
table with a `check` command, and `[project.scripts]` names
`kiln = "rn_forge.kiln.main:app"`, where `main.py` is
`app = CliApp.from_config(CONFIG)` — the goldens' shape. F4.5 adds the rest of
the surface to the same table.

**The declaration is in two places, on purpose.** A golden resolves its `[cli]`
table relative to its checkout, because a repo runs from where it lives. kiln
does not: it is a pinned dev dependency of every repo it generates
([ADR-0010](../../../adr/ADR-0010.md)), so an installed kiln has no checkout
beside it. The table therefore also ships inside the wheel as
`src/rn_forge/kiln/cli.toml`, which is what `main.py` reads, and
`tests/test_cli_surface.py` fails if the two disagree. F4.8 makes one render the
other and the copy goes.

**Acceptance:**

- `uv run kiln --help` exits 0 and lists `check`.
- `task build` produces one wheel.
- kiln's config still records `python-tool`, and `task validate` passes.

## S4.1.2 — Port the policy checkers into their modules

**Status:** done

Port the four policy checkers from the goldens' `scripts/` into the module that
owns each rule, replacing each `# BEGIN kiln config` header with a read of
`.rn-forge/kiln/config.toml`: `modules/core/checks/generated.py` (`generated`),
`modules/python/checks/rn_forge_deps.py` (`rn-forge-deps`),
`modules/tasks/checks/layout.py` (`task-layout`),
`modules/cicd/checks/entrypoint.py` (`ci-entrypoint`), plus
`modules/docs/checks/policy.py` — the docs policy object tooling's docs checkers
take (A2). `kiln check [PATH]` runs all four and `--only <name>` runs one. These
are the **render-free** checks: an `.importlinter` contract forbids
`rn_forge.kiln.modules.*.checks` from importing `jinja2` or
`rn_forge.tooling.generation`, so `kiln check` stays cheap enough for every CI
run. Refuse an unknown `state.json` `schema_version` loudly.

Two things the port settled that the story did not say:

- **`PATH` is a required positional**, not the design's optional `[PATH]`. An
  optional positional needs `typer.Argument`, `.importlinter` forbids
  importing Typer in product code ([ADR-0002](../../../adr/ADR-0002.md)), and
  pykit's CLI exports no typer-free equivalent. Every acceptance block already
  passes a path. F4.5 revisits it, with an upstream option.
- **The render-free contract is half `.importlinter` and half a test.**
  import-linter rejects subpackages of external packages — the same limitation
  `.importlinter`'s own header records — so `rn_forge.tooling.generation`
  cannot be a forbidden module. The contract carries the `jinja2` half;
  `tests/test_checks_are_render_free.py` imports the checks in a clean
  interpreter and asserts neither renderer loaded.

**Acceptance:**

- `kiln check --only <name>` exits 0 on each golden, for each of the four.
- Each check exits non-zero and names the offending path on a fixture that
  breaks one of its rules. There is one test per rule the original script
  enforced, and the script's existing tests are ported with it.
- `kiln check` runs all four and exits non-zero if any fails.
- A `state.json` with an unknown `schema_version` makes `kiln check` exit
  non-zero with a message naming that version.
- No `# BEGIN kiln config` header remains under `src/`.
- `lint-imports` keeps the render-free contract.
- tooling's docs checkers pass on kiln's docs when given
  `modules.docs.checks.policy`.

## S4.1.3 — The goldens and kiln drop `scripts/**`

**Status:** done

In the three goldens and in kiln itself: delete `scripts/**`, point
`tasks/quality.yml` at `uv run kiln check` (and tooling's docs checkers), delete
`tests/support/assert_generated_bodies.py` and its test, re-seed `state.json`.
The goldens take `rn-forge-kiln` in their dev group from a path source to this
checkout: they live inside kiln and are validated by kiln's own CI, so the path
is CI-capable here, and it goes when the goldens leave git
([F4.4](F4.4-render-matrix.md)). kiln runs its own project install and declares
no dependency on itself.

Two things the drop settled that the story did not say:

- **`rn-forge-kiln` is outside the dependency contract.** A path source in
  `[tool.uv.sources]` for an `rn-forge-*` package is exactly what
  `rn-forge-deps` rejects, three ways. kiln is the dev tool running that
  check, not a library the repo is built on, and its pin is doctor's
  `kiln.pin` ([F4.6](F4.6-doctor.md)), so the check skips it by name.
- **The docs tasks call tooling's `rn-forge-docs`**, with
  `--policy rn_forge.kiln.modules.docs.checks.policy:POLICY` on `structure`.
  Its `nav` indents nested entries by four spaces where the retired script
  used six, so every `mkdocs.yml` nav block was regenerated once and its state
  re-seeded.

**Acceptance:**

- `git ls-files scripts` is empty in kiln and in each golden.
- No task file runs `python scripts/`.
- `tests/support/assert_generated_bodies.py` is gone.
- `uv run kiln check .` and `task validate` pass in kiln and in each golden.
- Each golden's `uv.lock` records `rn-forge-kiln`.
