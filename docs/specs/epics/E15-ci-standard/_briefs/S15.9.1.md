# S15.9.1 — The Pages artifact is named per attempt

Brief for
[S15.9.1](../F15.9-pages-artifact-per-attempt.md#s1591-the-pages-artifact-is-named-per-attempt),
at `feature/v1` `acc3c936`.

## Goal

Every rendered `docs` job uploads its Pages artifact as
`github-pages-${{ github.run_attempt }}` and deploys that same name, so a re-run
of a failed `docs` job no longer finds two `github-pages` artifacts.

## Settled

- The one file to change is
  `src/rn_forge/kiln/modules/cicd/templates/workflows/_docs.yml.j2`. It has
  three branches (`{% if node_lib %}`, `{% elif workspace %}`, `{% else %}`),
  each with one `upload-pages-artifact` step and one `deploy-pages` step.

- In each branch, the upload step's `with:` gains, as its **first** key:
  `name: github-pages-${{ github.run_attempt }}`. The existing keys stay, in
  their order (`path`, and in `node-lib` also `include-hidden-files: true`).

- In each branch, the deploy step gains, after its `uses:` line:

    ```yaml
            with:
              artifact_name: github-pages-${{ github.run_attempt }}
    ```

    (same indentation as the upload step's `with:`). Mind the Jinja tag that ends
    the deploy `uses:` line (`{% elif workspace %}`, `{% else %}`,
    `{% endif %}`): the new `with:` block goes between the `uses:` text and that
    tag, so the tag still closes the branch and no blank line is added.

- The `node-lib` upload and deploy steps have no `name:` today; do not add one.
  Change nothing else: not the environment name `github-pages`, the
  concurrency group, the permissions, the pins, or any other step.

- `${{ github.run_attempt }}` is passed through by kiln's `[[ ]]` engine as
  literal text; it is not a Jinja expression.

- Rejected (do not build): deleting the earlier attempt's artifact, a retry or
  wait step, and naming after `github.run_id`.

## Current behaviour

- Upload steps' `with` is `{"path": ...}` (plus `include-hidden-files` in
  `node-lib`), and deploy steps have no `with` at all. So each new assertion
  below fails: the upload one with an `AssertionError` on the dict, the deploy
  one with a `KeyError: 'with'`.
- kiln's own `.github/workflows/_docs.yml` is rendered from this template (the
  single-package branch) and will change on `task kiln:apply`.

## Change

- **Change:** `_docs.yml.j2`; the three tests below; kiln's own rendered
  `.github/workflows/_docs.yml` and `.rn-forge/kiln/state.json`, **only** via
  `task kiln:apply`.
- **Leave alone:** every other template and test; `pins`.

## Tests first

Edit these three existing tests; do not add new test functions.

1. `tests/modules/cicd/test_pages.py`, `test_docs_job_steps_in_order`
   (`node-lib`): replace
   `assert upload["with"] == {"path": ".docs-site", "include-hidden-files": True}`
   with
   `assert upload["with"] == {"name": "github-pages-${{ github.run_attempt }}", "path": ".docs-site", "include-hidden-files": True}`,
   and add
   `assert deploy["with"] == {"artifact_name": "github-pages-${{ github.run_attempt }}"}`
   next to the existing `deploy` assertions.
1. `tests/modules/cicd/test_stages.py`,
   `test_docs_job_permissions_and_environment`: after the `uses[-1]`
   assertion, add
   `assert steps[-2]["with"]["name"] == "github-pages-${{ github.run_attempt }}"`
   and
   `assert steps[-1]["with"] == {"artifact_name": "github-pages-${{ github.run_attempt }}"}`.
1. `tests/modules/cicd/test_pipeline.py`, `test_python_lib_docs_job`: it finds
   the upload and deploy `uses` strings. Find the step dicts the same way
   (`next(s for s in steps if str(s.get("uses", "")).startswith(...))`) and
   assert the upload's `with["name"]` and the deploy's
   `with == {"artifact_name": ...}` with the same value. Keep the existing
   ordering assertion.

Run them
(`task test -- tests/modules/cicd/test_pages.py tests/modules/cicd/test_stages.py tests/modules/cicd/test_pipeline.py`)
and record that they fail as described before changing the template.
