kiln stops rendering `tools/ci/*.mjs`. The four helpers become `kiln-devops`
subcommands, and the generated tasks and `nx.json` call them. A helper fix then
reaches a repository through the kiln pin bump it already takes, with no
regeneration commit. This is release-1 work so that ngkit adopts kiln without
files that are retired right after.

## Context

[ADR-0015](../../../adr/ADR-0015.md) (2026-10-14) made the helpers generated
files. Its only alternative was an npm package. Twelve days later
[ADR-0017](../../../adr/ADR-0017.md) moved CI logic into `kiln-devops`: "CI and
release logic that is more than calling a task lives in `kiln-devops`". ADR-0015
was not revisited, so the helpers stayed templates. The owner's decision on
2026-11-10 moves them. ADR-0015's Background records it.

Read on 2026-11-10 at `f9aabdc`:

| Helper | Called from | What it does |
| -- | -- | -- |
| `resolve-dist-workspace-deps.mjs` | `nx.json` `targetDefaults.pack` (`modules/node/scaffold.py` `_RELEASE_TARGET_DEFAULTS`) | Rewrites `workspace:` ranges in a dist `package.json` to the local package's version; reads versions through `pnpm exec nx show projects --json` and `nx show project <p> --json` |
| `verify-dist-manifest.mjs` | `nx.json` `targetDefaults.verify-dist` | Fails on a `workspace:` range, a missing `name` or `version`, or no entry point or types |
| `assemble-site.mjs` | `tasks/ci.yml` `docs:site` | Copies each `compodoc` and `build-storybook` project's output under the MkDocs site, writes `index.html` when absent and `.nojekyll` |
| `release-notes.mjs` | `tasks/ci.yml` `release:github` | Prints the `CHANGELOG.md` section whose `## ` heading holds the version as a whole token |

Two findings shape the stories:

- `kiln-devops notes` already prints a changelog section, but it matches only
  Keep a Changelog headings (`## [0.3.0] - <date>`). `nx release` writes
  `## 0.3.0 (2026-10-25)`, which is ngkit's `CHANGELOG.md`. So `notes` learns
  that heading (S9.4.3); a second notes command would duplicate it.
- `reconcile_node` writes the `pack` and `verify-dist` defaults into `nx.json`
  for **both** `node-lib` and `python-web-app`, but `cicd` renders `tools/ci/`
  only for `node-lib`. A `python-web-app` project that declares `pack` calls a
  script that is not there. Calling `kiln-devops` through a task rendered for
  both cells fixes that too.

Each story is sized for one session on a Sonnet-class model. Every decision is
made on this page. S9.4.1 to S9.4.3 each edit `devops/cli.py`, so build them one
at a time. S9.4.4 follows them, then S9.4.5, then S9.4.6.

S9.4.5 adds a fifth command that ngkit had as its own script:
`tools/scripts/verify-consumer.mjs` (ngkit, 506 lines) installs a packed tarball
into a throwaway project for each cell of a peer-version matrix and imports
every entry point. Its matrix, entry points and Tailwind app builds are
hardcoded for `@rn-forge/ng` and `@rn-forge/ng-tailwind`. The install, the
matrix loop and the import smoke are the same for every published library, and
kiln's `ci:package` already runs a `verify-consumer` target. A library declares
its matrix in its own `package.json`, as a Python member declares its
integration services under `[tool.workspace-ci]` in `pyproject.toml`.

## Design

### Decisions

1. **Subcommands.** `kiln-devops dist-resolve <dist-dir>`,
   `kiln-devops dist-verify <dist-dir>`,
   `kiln-devops site-assemble [<site-dir>]` and the existing
   `kiln-devops notes <changelog> <version>`. `<dist-dir>` is the built
   package's directory, such as `dist/libs/ng`, for both dist commands. The
   JavaScript `resolve-dist-workspace-deps.mjs` took the `package.json` path;
   one argument shape for both is simpler.
1. **Modules.** `devops/nx.py` is the Nx adapter: it alone runs `pnpm exec nx`.
   `devops/dist.py` and `devops/site.py` take plain data and paths, and never
   run a process, as `notes.py` and `requirements.py` do. The boundary in
   `tests/devops/test_boundary.py` does not change: the standard library only.
1. **Behaviour is the JavaScript's.** Messages, exit codes and output keep the
   `.mjs` files' wording, so a CI log reads the same. Each story names the
   template to read; S9.4.4 deletes them, so read them before then, or with
   `git show f9aabdc:<path>`.
1. **`nx.json` calls a task, not `uvx`.** The `kiln-devops` command line carries
   the kiln pin (`kiln_command(ref, "kiln-devops")`), and `tasks/ci.yml`
   already holds it as `DEVOPS`. A `nx.json` command that held it would be a
   second copy, in a scaffolded file that `apply` never rewrites. So `pack`
   and `verify-dist` run `task ci:dist:resolve -- dist/{projectRoot}` and
   `task ci:dist:verify -- dist/{projectRoot}`, and those tasks run
   `{{.DEVOPS}}`. A repository's `pack` now needs `task` and `uv` on the path;
   a node repository has both already ([ADR-0015](../../../adr/ADR-0015.md):
   docs run through uv).
1. **The two `ci:dist:*` tasks render for `node`**, the context key true for
   both node cells, not only `node_lib`.
1. **Retired files are deleted by `apply`.** A clean state entry that no
   artifact renders is planned `delete` (`modules/core/settle.py`). S9.4.4
   proves it on the four paths.

### What ngkit does when it adopts

ngkit's `nx.json` is its own. `reconcile_node` keeps a `pack` or `verify-dist`
default that is already there (S9.3.5 item 3), so kiln does not rewrite ngkit's.
In the same commit that takes the kiln ref with S9.4.4, ngkit sets its two
commands to the values in S9.4.4 item 3. Without that, `nx pack` calls a deleted
file. This belongs to ngkit's cutover story
([ADR-0009](../../../adr/ADR-0009.md)); kiln states it here only.

## S9.4.1 — `kiln-devops dist-resolve` and `dist-verify`

**State:** Closed (2026-11-10)

**Build — tests first** in `tests/devops/test_dist.py`, named
`test_s9_4_1_<n>_…`. Copy the shape of `tests/devops/test_notes.py` (pure
functions) and `tests/devops/test_cli.py` (the command line). Read
`src/rn_forge/kiln/modules/cicd/templates/tools/ci/resolve-dist-workspace-deps.mjs.j2`
and `verify-dist-manifest.mjs.j2` first: they are the behaviour.

**Acceptance:**

1. `dist.resolve(manifest, versions)` returns the manifest with each
   `workspace:` range in `dependencies`, `peerDependencies` and
   `optionalDependencies` rewritten: `workspace:*` and `workspace:` to
   `<version>`, `workspace:^` to `^<version>`, `workspace:~` to `~<version>`,
   any other `workspace:<range>` to `<range>`. Other ranges are untouched.
1. It raises `ValueError` with
   `Cannot resolve "<range>" for "<dep>": no local package version found` when
   the dependency is not in `versions`.
1. `dist.problems(manifest)` returns, in this order, the JavaScript's messages:
   each
   `<field>["<dep>"] uses "workspace:" protocol (<range>) in dist manifest`,
   `missing required field "name"`, `missing required field "version"`,
   `missing both "module" and "exports" (no entry point referenced)`,
   `missing both "typings" and "exports" (no type declarations referenced)`;
   and `[]` for a valid manifest.
1. `kiln-devops dist-resolve <dir>` with a stub `pnpm` on `PATH` (it prints the
   `nx show` JSON the test gives it) rewrites `<dir>/package.json`, written as
   `json.dumps(manifest, indent=2) + "\n"`, prints
   `Resolved workspace: protocol dependencies in <dir>/package.json`, and
   exits 0.
1. With no `workspace:` range it prints
   `No workspace: protocol dependencies found in <dir>/package.json`, leaves
   the file byte-identical, and does not run `pnpm` (the stub records its
   calls; none).
1. `kiln-devops dist-verify <dir>` exits 0 and prints
   `Dist manifest verification passed for <dir>` for a valid manifest. For an
   invalid one it exits 1 and prints to stderr
   `Dist manifest verification failed for <dir>:`, a blank line, and each
   problem as `  - <problem>`.
1. Both commands exit 1 with a one-line stderr message, no traceback, when
   `<dir>/package.json` is missing or is not JSON.
1. The existing `tests/devops/test_boundary.py` passes unchanged.

**Build:**

- `devops/nx.py`: `projects(root: Path, target: str | None = None) -> list[str]`
  runs `pnpm exec nx show projects --json`, adding `--with-target <target>`
  when given; `project_root(root: Path, project: str) -> str` runs
  `pnpm exec nx show project <project> --json` and returns its `root`. Both
  use
  `subprocess.run(..., cwd=root, check=True, capture_output=True, text=True)`.
  `local_versions(root: Path) -> dict[str, str]`: for each project, the `name`
  and `version` of `<project_root>/package.json` when it has both; a project
  with no readable `package.json` is skipped, as in the JavaScript.
- `devops/dist.py`:
  `resolve(manifest: dict, versions: Mapping[str, str]) -> tuple[dict, bool]`
  (the new manifest and whether anything changed), and
  `problems(manifest: dict) -> list[str]`. `resolve` takes the versions
  lazily: the caller passes a callable,
  `versions: Callable[[], Mapping[str, str]]`, called at most once and only
  when a `workspace:` range is found, as the JavaScript's `??=` does.
- `devops/cli.py`: the `dist-resolve` and `dist-verify` subparsers, each with
  one positional `dist_dir`, and `_dist_resolve` and `_dist_verify` handlers
  beside `_notes`. The working directory is the workspace root.

**What the build settled that the story did not say:**

- **Tests.** `tests/devops/test_dist.py` holds one test per acceptance item,
  `test_s9_4_1_<n>_…`, with item 1 parametrised over the five range forms. The
  stub `pnpm` is a shell script on `PATH` that logs its arguments and serves
  `nx show` JSON for projects `core` (has a `package.json`) and `app` (has
  none, so it is skipped). Item 7 is parametrised over a missing and a
  non-JSON `package.json` for both commands.
- **`resolve` copies.** It deep-copies the manifest and returns the copy, so the
  caller's dict is not mutated.
- **`devDependencies` is not touched**, as in the JavaScript (item 1 lists three
  fields); a test pins it.
- **Error handling in the CLI.** `dist-resolve` also exits 1 with the message on
  a `ValueError` (unknown dependency) or a failing `pnpm`
  (`CalledProcessError`); the story names only the unreadable manifest. The
  unreadable message is `Could not read/parse <path> (<error>)`, the
  JavaScript's wording.
- **Typing.** `nx.py` uses `# type: ignore` where strict pyright cannot see the
  JSON shape; `cli.py` and `dist.py` annotate the manifest as
  `dict[str, Any]`.
- **No `_validate` check** on `dist_dir`: the commands read and write only
  `<dir>/package.json` under the working directory, as the JavaScript did.

  where `projects` maps each target (`compodoc`, `build-storybook`) to its

  in place of `escapeHtml`. Existing content of the site is kept.

**What the build settled that the story did not say:**

  per assertion set, and adds items 2 to 4. The stub `pnpm` on `PATH` serves

  `--json --with-target <t>`, the order `nx.projects` uses. The fixture is the

  workspace of `core` (a description with `&`, `<`, `>` and `"`) and `ui`,
  with `GITHUB_REPOSITORY=rn-forge/demo`; the template's `kiln_version`
  placeholder was the only thing substituted. The test sets the same variable.
- **`assemble` takes a fourth, optional argument `name`**, the title of a
  generated `index.html`. The JavaScript read `GITHUB_REPOSITORY` and the
  directory name; `site.py` stays free of the environment, so the command line
  passes the repository name and `assemble` falls back to `root.name`.
- **A project whose output is missing** makes `assemble` copy the others and
  raise `FileNotFoundError` with one JavaScript-worded line per project,
  before `index.html` and `.nojekyll`; the command prints it to stderr and
  exits 1, as the JavaScript did. A failing `pnpm` also exits 1 with its
  message.
- **`description` is read for every copied project**, from
  `<project_root>/package.json`; an unreadable file gives no `<p>`.
  `encodeURIComponent` is `urllib.parse.quote` with `!~*'()` safe, and
  `html.escape(quote=False)` plus `"` to `&quot;` matches `escapeHtml` (the
  stdlib would also escape `'`).
- **The existing `assemble-site.mjs` tests are untouched**; S9.4.4 retires them.

## S9.4.5 — `kiln-devops consumer` smoke-tests a packed library across its peer matrix

**State:** Closed (2026-11-10) · **Depends on:** S9.4.4

**Build — tests first** in `tests/devops/test_consumer.py` (pure parts and the
command line, with stub `npm` and `node` on `PATH` that record their calls) and
`tests/modules/node/test_scaffold.py` and
`tests/modules/tasks/test_artifacts.py` (the defaults), named
`test_s9_4_5_<n>_…`. Read ngkit's `tools/scripts/verify-consumer.mjs` first:
`resolveTarball`, `writeFixturePackageJson`, `writeSmokeTest`, `runFixture` and
`checkNoWorkspaceOrLocalArtifacts` are the behaviour this ports. Its
`ng-tailwind` branch (`writeAngularApp`, `assert*Build`) is not ported; it
becomes a hook in ngkit.

A library declares, in its source `package.json`:

```json
{
  "workspace-ci": {
    "consumer": {
      "dependencies": { "rxjs": "~7.8.0" },
      "preload": ["@angular/compiler"],
      "cells": {
        "22.1-zone": {
          "dependencies": {
            "@angular/common": "22.1.7",
            "@angular/compiler": "22.1.7",
            "@angular/core": "22.1.7",
            "zone.js": "~0.16.0"
          },
          "preload": ["zone.js"]
        },
        "22.1-zoneless": {
          "dependencies": {
            "@angular/common": "22.1.7",
            "@angular/compiler": "22.1.7",
            "@angular/core": "22.1.7"
          }
        }
      },
      "hook": "tools/consumer/ng-smoke.mjs"
    }
  }
}
```

`dependencies` and `preload` at the top apply to every cell, and a cell's own
are added after them. A cell's dependency overrides a top-level one of the same
name. `hook` is optional, and so are both `preload` lists. `cells` is required
and has at least one entry.

**Acceptance:**

1. `consumer.load(manifest)` returns one `Cell(name, dependencies, preload)` per
   cell, in declaration order, merged as above, and the `hook`. It raises
   `ValueError` naming the package and the key for: no `workspace-ci.consumer`
   table, no `cells` or an empty one, a `dependencies` value that is not a
   string, a `preload` that is not a list of strings, or a cell name that is
   not `[A-Za-z0-9._-]+`.

1. `consumer.tarball_name("@rn-forge/ng", "0.3.0")` is `rn-forge-ng-0.3.0.tgz`,
   and `consumer.tarball_name("plain", "1.0.0")` is `plain-1.0.0.tgz` (npm
   pack's naming).

1. `consumer.entry_points(exports)` returns, sorted, each subpath of the
   installed package's `exports` whose value resolves to a JavaScript file (a
   string ending `.js` or `.mjs`, or a condition map with `import` or
   `default` that does), as the import specifier: `.` gives the package name,
   `./core` gives `<name>/core`. `./package.json`, wildcard subpaths and
   non-JavaScript targets (`.css`, `.scss`) are left out.

1. `consumer.smoke_script(name, entry_points, preload)` is an ES module that
   imports each `preload` in order with `await import(...)`, then each entry
   point with `import * as`, and throws
   `Entry point "<specifier>" resolved but exported nothing` for one whose
   namespace has no keys. Snapshot-tested.

1. `kiln-devops consumer <project-root>`, run from the workspace root, reads
   `<project-root>/package.json`, finds
   `dist/tarballs/<tarball_name(name, version)>`, and for each cell: writes
   `dist/consumer-fixtures/<tarball stem>/<cell>/package.json` (`name`
   `consumer-<cell>`, `private`, `"type": "module"`, the merged dependencies
   plus `"<name>": "file:<absolute tarball path>"`), runs
   `npm install --no-audit --no-fund` there, fails the cell when the installed
   `node_modules/<name>/package.json` holds a `workspace:` range (the
   JavaScript's message), writes `smoke.mjs` and runs `node smoke.mjs`, then
   runs `node <workspace root>/<hook> <fixture dir> <cell>` when a hook is
   set. The fixture directory is deleted first if it exists.

1. A missing tarball exits 1 with
   `Expected packed tarball at <path> (found: <names or "(missing dir)">). Run "nx run <project>:pack" first.`,
   before any `npm` call.

1. A failing cell does not stop the others. When every cell has run, the command
   prints `consumer: <n> of <m> cells failed: <cell>, …` and exits 1, or
   `consumer: <m> cells passed` and exits 0.

1. `--cell <name>` runs only that cell; an unknown name exits 2 and lists the
   declared cells.

1. `dist.resolve` (S9.4.1) also drops a top-level `workspace-ci` key from the
   dist manifest, and counts that as a change, so the matrix is not published.

1. `nx.json` `targetDefaults["verify-consumer"]`, set by `reconcile_node` for
   both node cells and kept when present (as S9.3.5 item 3), is exactly:

    ```json
    {
      "executor": "nx:run-commands",
      "dependsOn": ["pack"],
      "cache": false,
      "options": {
        "cwd": "{workspaceRoot}",
        "command": "task ci:consumer -- {projectRoot}"
      }
    }
    ```

1. Rendered `tasks/ci.yml` for `node-lib` and `python-web-app` has `ci:consumer`

## S9.4.6 — A consumer hook runs inside its fixture

**State:** Closed (2026-11-13) · **Depends on:** S9.4.5

the fixture as its working directory. Node resolves a bare import from the
importing file's location, not the working directory, so a hook's
`import '@rn-forge/ng/core'` reaches the workspace's `node_modules` (the
workspace's source build) instead of the tarball installed in the fixture.
ngkit's first hook works around it by writing a second script into the fixture
and running that (ngkit F17.5, S17.5.2). Found while writing ngkit's F17.5 on
2026-11-11.

## Considered and rejected

- **Call `uvx … kiln-devops` from `nx.json` directly.** A second copy of the
  kiln pin, in a file `apply` never rewrites.
- **A new `release-notes` subcommand for nx's heading.** It would duplicate
  `notes`.
- **Keep the helpers in JavaScript and ship them in the kiln wheel.** The
  generated task would have to locate a file inside uv's cache, and
  `kiln-devops` would carry a second language.
- **The consumer matrix in `config.toml`.** `kiln-devops` reads a workspace's
  own manifests, never kiln's config, and a matrix belongs to one library.
- **The consumer matrix in `project.json`.** Nx's schema gives custom keys no
  home there. `package.json` is where Node tools keep their config, and
  `dist-resolve` keeps it out of the published manifest.
- **Port the Angular app builds into `consumer`.** They assert on one library's
  CSS. The hook keeps them in the library that owns them.
- **Leave `tools/ci/` rendered.** Every helper fix costs a regeneration commit
  per repository ([ADR-0015](../../../adr/ADR-0015.md), Consequences).
