# S15.9.2 — A failed deploy is tried once more after a pause

Brief for
[S15.9.2](../F15.9-pages-artifact-per-attempt.md#s1592-a-failed-deploy-is-tried-once-more-after-a-pause),
at `feature/v1` `f657dec6`.

## Goal

In every rendered `docs` job, a `deploy-pages` step that fails is followed by a
30-second wait and one more deploy of the same artifact. The job's result is the
second deploy's. The environment `url` takes whichever deploy succeeded.

## Settled

### The three steps

In each of the three branches of
`src/rn_forge/kiln/modules/cicd/templates/workflows/_docs.yml.j2` (`node-lib`,
the workspace, the single-package archetypes), the one deploy step becomes these
three, in this order, as the last steps of the job. Keep the existing pin
expression for `uses:`.

```yaml
      - name: Deploy to GitHub Pages
        id: deployment
        continue-on-error: true
        uses: [[ pins["deploy-pages"].uses ]]@[[ pins["deploy-pages"].sha ]] # [[ pins["deploy-pages"].version ]]
        with:
          artifact_name: github-pages-${{ github.run_attempt }}

      - name: Wait for the artifact listing
        if: steps.deployment.outcome == 'failure'
        run: sleep 30

      - name: Deploy to GitHub Pages again
        id: deployment-retry
        if: steps.deployment.outcome == 'failure'
        uses: [[ pins["deploy-pages"].uses ]]@[[ pins["deploy-pages"].sha ]] # [[ pins["deploy-pages"].version ]]
        with:
          artifact_name: github-pages-${{ github.run_attempt }}
```

- **`node-lib`:** the two deploy steps have no `name:` (today's deploy step has
  none). The wait step keeps its `name: Wait for the artifact listing`. Key
  order in the two deploys: `id`, then `continue-on-error` or `if`, then
  `uses`, then `with`.
- **Environment `url`, all three branches:**
  `${{ steps.deployment.outputs.page_url || steps.deployment-retry.outputs.page_url }}`.
- Nothing else in the job changes: not the permissions, the concurrency group,
  the environment name, the upload step or the pins.

Rejected (do not build): a wait before every deploy; a separate deploy job; more
than one retry; a retry loop in a `run:` script.

## Current behaviour

Each branch renders one deploy step, `id: deployment`, with no
`continue-on-error`, and the environment `url` is
`${{ steps.deployment.outputs.page_url }}`. So, before the template change:

- `test_docs_job_steps_in_order` fails at the unpacking of the steps (the job
  has 7 steps, the test unpacks 9).
- `test_node_lib_renders_no_docs_yml_and_one_docs_job` fails on the `url`
  comparison.
- `test_docs_job_steps_have_no_id_env_or_if` still passes before the change (it
  only loosens); write it so that it also asserts the wait and retry steps
  exist with that `if`, so it fails too.
- `test_docs_job_permissions_and_environment` and `test_python_lib_docs_job`
  fail on the assertions about the last three steps: `steps[-4]` is not the
  upload, the last step's id is `deployment` rather than `deployment-retry`,
  and no step has `continue-on-error`.
