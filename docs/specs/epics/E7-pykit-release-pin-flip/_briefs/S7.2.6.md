# S7.2.6 — The pin task passes its ref as an option

Brief for
[S7.2.6](../F7.2-kiln-release-and-config-upgrade.md#s726-the-pin-task-passes-its-ref-as-an-option),
at `fc79b96`.

## Goal

`task kiln:pin -- <ref>` works: the rendered task passes the ref to `kiln pin`
as `--ref <ref>`, and with no argument still runs bare `kiln pin`, which follows
`track`.

## Settled

- The CLI does not change. `pin(ref: str = "", show: bool = False)` stays: the
  import contract keeps `typer` out of product code, so `ref` cannot become an
  optional positional argument.
- The fix is the template's first `pin` command, exactly:
  `'{{.KILN}} pin{{if .CLI_ARGS}} --ref {{.CLI_ARGS}}{{end}}'`. `{{if}}` is
  go-task's template syntax and passes through Jinja untouched (kiln's Jinja
  variables are `[[ ]]`). The reviewer checked it with go-task 3.54:
  `task pin -- abc` runs `… pin --ref abc`; `task pin` runs `… pin`.
- The second command, the task's `desc:` and the header comment stay as they
  are.
- Tests are named for behaviour, `test_<subject>_<behaviour>`, with no spec ID
  in a name, docstring or comment.

## Current behaviour

At `fc79b96`:

- `src/rn_forge/kiln/modules/tasks/templates/tasks/kiln.yml.j2` renders the
  `pin` task's first command as `'{{.KILN}} pin {{.CLI_ARGS}}'`.
- `uv run kiln pin --help` lists only options, `--ref <str>` and
  `--show/--no-show`, so `kiln pin <sha>` fails with a usage error about an
  unexpected extra argument.
- `tests/modules/tasks/test_task_doctor.py::test_task_order` asserts the first
  command is `"{{.KILN}} pin {{.CLI_ARGS}}"`.
  `test_the_pin_task_takes_no_argument` asserts the last command only.
- `src/rn_forge/kiln/commands/config.py`, `pin`'s docstring, says "REF" twice
  ("With no REF, follows `track`" and "no REF and no `track`").

## Change

- `src/rn_forge/kiln/modules/tasks/templates/tasks/kiln.yml.j2`: the `pin`
  task's first command, as settled.
- `src/rn_forge/kiln/commands/config.py`: in `pin`'s docstring, "With no REF"
  becomes "Without `--ref`", and "no REF and no `track`" becomes "no `--ref`
  and no `track`". No code change.
- `tests/modules/tasks/test_task_doctor.py`: `test_task_order` expects the new
  first command.
- **Leave alone:** every generated file in this repository (kiln's own render
  has no `pin` task, so `task kiln:apply` here should change nothing; if it
  changes anything, stop and report it), `cli.toml`,
  `.rn-forge/kiln/config.toml`, the standard template, the ADRs.
