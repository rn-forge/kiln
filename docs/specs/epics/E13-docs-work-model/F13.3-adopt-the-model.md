# F13.3 — The seeded rules and kiln's own docs adopt the model

**Status:** planned

Epic: [E13](index.md) · Design: [E13 design](design.md#the-seeded-rules) ·
**Depends on:** [F13.2](F13.2-board-and-scope.md)

S11.4.1 merged three repositories' rules into the seed in the status-line model.
This feature replaces the seed with the work-item model and adds the `reference`
area, then moves kiln's own docs over. After S13.3.2, kiln's own board and
release Scope tables are derived, and `task lint` fails when a feature's state
and its epic's row disagree.

**Build each story by the
[board's procedure](../../index.md#building-a-story).**

## S13.3.2 — kiln's own docs adopt the model

**Status:** planned · **Depends on:** S13.3.1

Work page by page through every `docs/specs/epics/*/index.md`, every
`docs/specs/epics/*/F*.md` and every `docs/releases/release-*/index.md`, E13's
own pages included. The rules below cover every shape these pages have today.

**Build:**

- Copy the seeded `docs/specs/_structure.md` and `docs/releases/_structure.md`
  over kiln's own, byte for byte, and apply the three `docs/_structure.md`
  replacements to kiln's `docs/_structure.md`.

- **Mapping.** Each status becomes:

    | Today | Becomes |
    | -- | -- |
    | `elaborating` | `State` `New` |
    | `planned` | `State` `New` |
    | `in progress` | `State` `Active`, with `Start Date` |
    | `done`, with `**Implemented:** <d>` | `State` `Closed`, `Closed Date` `<d>`; an epic also gets `Start Date` |
    | `deferred` | `State` `New`, `Tags` `deferred`, `Entry criteria` |
    | story `planned`, `in progress`, `done (<d>)`, `deferred` | `**State:** New`, `Active`, `Closed (<d>)`, `New` |

- **Iteration.** Every feature that has a row in a release page's scope table
  today gets `Iteration` linking that release (link text `Release <n>`, target
  `../../../releases/release-<n>/index.md`), whatever its state. A feature on
  no release page gets none. Read the scope tables *before* you replace them.

- **Dates.** `Start Date` is the date of the first commit whose subject names
  the ID. For `S4.3.2`, run
  `git log --reverse --format=%ad --date=short -E --grep 'S4\.3\.2([^0-9.]|$)'`
  and take the first line. When no commit names the ID, use the
  `Closed Date` for closed work, and the date of this conversion otherwise. A
  `Closed Date` is the date already on the page (`**Implemented:**` or
  `done (<d>)`).

- **Epic pages.** Replace the `**Status:** …` paragraph (it may run over several
  lines) with a metadata table holding `State` and its date rows. When the
  page has an `**Entry criteria:** <text>` line, move `<text>` into the
  table's `Entry criteria` row, joined onto one line without a trailing
  period, and delete the line. Every other field that paragraph carried
  (`Releases`, `Release`, `Decisions`, `Decision`, `Phase`, `Estimate`, the
  commit hashes after `Implemented`, free text such as "Absorbs the deferred
  C.2 step 9") goes in one plain line directly under the table, keeping its
  links, with the keys unbolded: `Releases: <its links> · Phase: D`.

- **Epic feature tables.** Rename a `Status` column to `State`, or add a `State`
  column as the last column, and set each cell to its feature's `State`. In a
  fileless row whose old cell carried more than a state word (for example
  `done (the web goldens moved to E5)`), the cell becomes the state word
  (`Closed`), and the parenthetical moves to the end of the row's description
  cell.

- **Feature pages.** Replace the `**Status:**` line and the
  `Epic: … · **Depends on:** …` paragraph with a metadata table: `State`,
  `Parent` (`[E<n>](index.md)`), `Iteration`, `Tags`, `Start Date`,
  `Closed Date`, `Predecessors`, `Source` and `Entry criteria`, as they apply,
  in that order. `Predecessors` is the `**Depends on:**` text, links kept,
  joined onto one line without a trailing period, or `—` when it says
  "nothing". `**Source:**` becomes the `Source` row. Every other field
  (`Decision`, `Design`, `Phase step`) goes in one plain line directly under
  the table, as for epics.

- **Stories.** Rewrite only the status word on each story's line:
  `**Status:** planned · **Depends on:** S11.1.1` becomes
  `**State:** New · **Depends on:** S11.1.1`. Leave everything else on the
  line.

- **The one retired story.** F11.2's `**Retired:**` field becomes a story
  heading placed after its last story and before `## Acceptance`:
  `## S11.2.4 — Moved to F11.5`, then `**State:** Removed`, then the sentence
  "Moved to F11.5 as S11.5.1 on 2026-09-27, so that this feature belongs to
  one release.", with "F11.5" linked to `F11.5-deploy-package-sites.md`

- **Release pages.** Replace `**Status:** <s> [<date>]` with a metadata table:
  `Status` `<s>`, plus `Finish Date` `<date>` when it is `shipped`. Replace
  the hand-kept Scope table with the empty `derived scope` fence, as in the
  seeded release template. Rows that name a fileless feature (release-0's F1.x
  and F2.x rows) cannot be derived: move them into that page's
  `### Done before this release` table, under the fence, with columns
  `Epic | Delivered | Implemented`, one row per epic. Keep the paragraphs
  around the old table.

- **`docs/specs/index.md`.** Replace the `## Board` section, from its heading to
  the end of its `### Done` table, with the empty `derived board` fence and
  the ideas line, exactly as in the seeded `docs/specs/index.md`, and add the
  seeded opening paragraph's last sentence ("The Releases and Backlog sections
  …") to the page's opening paragraph. Keep `## Upstream pins`, `## Order` and
  `## Building a story`; in step 6 of the last, "flip its **Status** to
  `done (<date>)`" becomes "flip its **State** to `Closed (<date>)`". Replace
  `## Conventions` with the seed's, then add back kiln's last bullet, the one
  that begins "**Why things are the way they are**".

- **`docs/specs/ideas.md`.** The seeded text, with these two rows:

    | Idea | Summary | Source |
    | -- | -- | -- |
    | node-docs-site-assembly | The Node archetypes build their MkDocs site and assemble Compodoc and Storybook under it, as E13's design describes | ADR-0012, 2026-10-01 |
    | java-archetype | A Java archetype on the same docs model, with Javadoc assembled under `api/` | ADR-0012, 2026-10-01 |

- Run `task docs:generate`, then `uv run --group docs mdformat docs`, then
  `task validate`. Fix every `docs.work-*` finding in the page it names, and
  never inside a derived fence.

**Do not:** renumber or drop any ID; change any story's acceptance, Build list
or prose; edit `docs/plans/`, `docs/adr/` or `docs/reference/` (kiln's reference
is the normative standard, not generated reference, so the seeded `reference`
rules do not apply to it); edit a page outside `docs/specs/` and
`docs/releases/` other than `docs/_structure.md`.

**Tests:** none new. The `docs-generate` check over kiln's own tree is the test.

**Acceptance:**

- `docs/specs/index.md` and every `docs/releases/release-*/index.md` carry their
  derived fences, and `uv run kiln doctor . --only docs-generate` passes.
- No `**Status:**` line is left under `docs/specs/epics/`.
- The derived release-1 Scope lists exactly the features that the release-1 page
  listed before the conversion, each with the state the mapping gives.
- release-0's F1.x and F2.x work appears in its `### Done before this release`
  table.
- `uv run --group docs mdformat --check docs` passes.
- `task validate` passes.
