kiln keeps one check registry in code. It renders `ci.yml`, validates a new
`[ci.checks]` table, and fills the check matrix in
[the CI architecture page](../../../architecture/ci.md) and in the rendered
`.rn-forge/kiln/standard.md`. `[[ci.jobs]]` gains a `required` flag. Adding a
check later is one registry row plus its task.

## Context

The model, the three switches and the four hook tiers are in
[ADR-0016](../../../adr/ADR-0016.md). A check has one of three switches:
`standard` (always on), `derived` (on when the tree calls for it, no key) and
`configured` (a key in `[ci.checks]`, with a default).

## S15.1.1 — The check registry

**State:** Closed (2026-11-05)

**Build — tests first,** in `tests/modules/cicd/test_registry.py`:

1. `test_s15_1_1_1_names_are_unique`: `[c.name for c in registry.CHECKS]` has no
   duplicate.
1. `test_s15_1_1_2_switch_and_default`: `licenses` and `secret-scan` are
   `configured` with default `True`; `umbrella-release` and `scorecard` are
   `configured` with default `False`; `internal-ranges` is `derived`; every
   other row is `standard`.
1. `test_s15_1_1_3_configured_rows_have_keys`: only `configured` rows are in
   `registry.configured_names()`, and that set is exactly
   `{"licenses", "secret-scan", "umbrella-release", "scorecard"}`.
1. `test_s15_1_1_4_enabled`: `registry.enabled(check, ci, archetype, members)`
   is `False` for a check the archetype does not run; for a configured check
   it is the `[ci.checks]` value (a bool, or `True` when an inline table is
   given), else the default; for `internal-ranges` it is
   `archetype == "python-lib" and members >= 2`, or `archetype == "node-lib"`
   (a `node-lib`'s members are not known at render time, so its check is
   always rendered and finds nothing to do below two members).
1. `test_s15_1_1_5_matrix_rows_match_the_page`: `registry.render_matrix(None)`
   (all archetypes) has one row per registry row, with the header
   `| Check | Verb | lib | tool | app | web-api | web-app | node-lib | Switch and key |`.
1. `test_s15_1_1_6_matrix_for_one_archetype`: `render_matrix("node-lib")` lists
   only rows whose `archetypes` contain `node-lib`, and none of the archetype
   columns.

**Build:** new `src/rn_forge/kiln/modules/cicd/registry.py`:

- `class Switch(StrEnum)`: `STANDARD = "standard"`, `DERIVED = "derived"`,
  `CONFIGURED = "configured"`.

- `@dataclass(frozen=True) class CiCheck` with fields `name: str`,
  `verb: str | None` (the `task` verb; `{stack}` stands for `python` or
  `node`), `archetypes: frozenset[str]`, `cells: Mapping[str, str]` (an
  archetype's matrix cell when it is not `yes`, such as `verify`),
  `switch: Switch`, `default: bool`, `key_note: str` (the page's last column),
  `job: str | None` (the `ci.yml` job it needs, or `None`), `gates: bool`
  (`True` when `ci-ok` needs `job`), `policy: type[StrictModel] | None`.

- `CHECKS: tuple[CiCheck, ...]`: the rows of the "Checks by archetype" table in
  `docs/architecture/ci.md` as it stands when this story starts, row for row
  and cell for cell, then these five rows, in this order:

    | name | verb | archetypes | switch | default | job | gates |
    | -- | -- | -- | -- | -- | -- | -- |
    | `licenses` | `{stack}:lint:licenses` | all six | configured | true | `None` | no |
    | `secret-scan` | `ci:lint:secrets` | all six | configured | true | `secret-scan` | yes |
    | `internal-ranges` | `ci:requirements` | `python-lib`, `node-lib` | derived | true | `None` (a step of `plan`, or of `validate` for `node-lib`) | no |
    | `umbrella-release` | `ci:release:umbrella` | all six | configured | false | `None` (a step of `release`) | no |
    | `scorecard` | `None` | all six | configured | false | `scorecard` | no |

    `licenses` carries `policy = LicensePolicy` (S15.1.2). `scorecard` is for
    public repositories only; the matrix note says so.

- `configured_names() -> frozenset[str]`,
  `for_archetype(archetype) -> list[CiCheck]`,
  `enabled(check, ci, archetype, members) -> bool`, and
  `render_matrix(archetype: str | None) -> str`: a Markdown table; with `None`
  it is the page's table (one `yes`/cell column per archetype), with an
  archetype it has the columns `Check | Verb | Switch and key` and only that
  archetype's rows, the verb with `{stack}` filled in.

- `__all__` lists every public name.

**Acceptance:**

- The six tests pass, and `task validate` passes.

**What the build settled that the story did not say:**

- Only `internal-ranges` and the five new rows are not `standard`; the page's
  own `D:` and `C:` rows (Sonar, Release, Docs strict build, Docs deploy,
  Services, `external-install`) are `standard` in the registry, because test 2
  says every other row is `standard` and test 3 says only four names are
  `configured`. Their page note stays in `key_note`, so the matrix is
  unchanged.
- `LicensePolicy` is created in `cicd/config.py` now, exactly as S15.1.2
  specifies (`deny` with its default list, `ignore` empty), so `licenses`
  carries `policy = LicensePolicy`. S15.1.2 adds `CiConfig.checks`, the
  validator and `licenses_policy()`.
- `CiConfig` has no `checks` field until S15.1.2, so `enabled` reads it with
  `getattr(ci, "checks", {})`; the test passes a stand-in with a `checks`
  table.
- `secret-scan` has `job=None` (owner decision, 2026-11-05); S15.3.3 sets it to
  `"secret-scan"`. Departure from the build list's `secret-scan` job.
- `verb` holds a bare task verb (`lint`, `ci:adapters`, `{stack}:lint:licenses`)
  and the matrix wraps it as `` `task …` ``; a row whose page cell is not a
  single task (`action`, `` `sonar` job ``, the Nx pair) holds that cell text,
  and `ci-ok` has `verb=None`, rendered `none`. `CiCheck` gives `default`,
  `cells`, `job`, `gates` and `policy` defaults so a row names only what it
  sets; `key_note` is the whole last column, including its `S`/`D`/`C` letter.
- Names are display text for the page's older rows (`ruff check and format`);
  `render_matrix` puts code ticks on the names listed in `_CODE_NAMES`.
- `registry.COLUMNS` (heading, archetype) is public, as the matrix needs it.

## S15.1.2 — `[ci.checks]` is validated from the registry

   `ignore = []`.

   `test_s15_1_2_7_umbrella_needs_a_release`: rendering any archetype's config

**Build:** `src/rn_forge/kiln/modules/cicd/config.py`:

- `class LicensePolicy(StrictModel)`: `deny: list[str]` default
  `["GPL", "GPL-*", "AGPL", "AGPL-*", "UNKNOWN"]`, `ignore: list[str]` default
  `[]`.
- `CiConfig.checks: dict[str, bool | dict[str, object]]`, default `{}`, with a
  `field_validator("checks")` that applies tests 2, 3, 5 and 6 using
  `registry.CHECKS` (import inside the validator to avoid a cycle). A table
  value is validated through the row's `policy` model.
- `CiConfig.licenses_policy() -> LicensePolicy`.
- `cicd/artifacts.py` `render`: before rendering, raise the test 7 error when
  `umbrella-release` is enabled and `ci.release == "none"`.

## S15.1.3 — `ci-ok` needs come from the registry and `required`

**State:** New · **Depends on:** S15.1.1

`ci.yml` through `cicd.artifacts.render` for a `python-lib` config with two

1. `test_s15_1_3_1_required_defaults_true`:
   `CiJob(name="x", uses=…).required is True`.
1. `test_s15_1_3_2_required_job_gates`: a declared job with `required = true` is
   in `ci-ok`'s `needs`; with `required = false` it is a job in `ci.yml`
   (still `needs: validate`) and is not in `ci-ok`'s `needs`.
1. `test_s15_1_3_3_registry_jobs_gate`: with `secret-scan` enabled and its job
   rendered (F15.3), `secret-scan` is in `ci-ok`'s `needs`; with `scorecard`
   enabled, `scorecard` is in no `needs` (it is its own workflow, F15.6).
1. `test_s15_1_3_4_default_render_is_unchanged`: for each of the six archetypes
   with no `[ci.checks]` and no declared jobs, the rendered `ci.yml` equals
   the previous render, except for what F15.3 adds (compare with
   `secret-scan = false`).

**Build:**

- `cicd/config.py`, `CiJob`: `required: bool = True` with a docstring: "`False`
  keeps the job out of `ci-ok`'s `needs`".
- `cicd/artifacts.py`: two context keys, `required_jobs` (names of declared jobs
  with `required`) and `check_jobs` (the `job` of every registry row that is
  enabled for the archetype and has `gates = True`, in registry order).
- `ci.yml.j2`, the `ci-ok` job: append `check_jobs` and `required_jobs` to its
  `needs`, after the generated jobs, in that order. Do not change how `ci-ok`
  reads results.
- `docs/architecture/ci.md`'s "Hooks" table row for `[[ci.jobs]]`, and its
  sentence "Every entry gates `ci-ok`", become "Every entry gates `ci-ok`
  unless `required = false`".

**Acceptance:**
