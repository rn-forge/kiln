# ADR-0019 — Cutovers overlay a `kiln new` reference; `kiln init` is retired

**Status:** accepted (2026-11-09) · **Scope:** the cutover of a repository with
a pre-kiln lineage, and kiln's command set

## Decision

A repository with a pre-kiln lineage moves onto kiln by **overlay**. kiln builds
a reference repository with `kiln new` (and `kiln generate package` or another
generator), and its files are brought onto a branch of the existing repository,
which keeps its history and tags. One reviewed diff follows.

- Managed files, and the fenced blocks of shared files, are taken from the
  reference byte-for-byte.
- Each repository-owned or seeded difference the repository keeps is an explicit
  step in that repository's own cutover story, not logic in kiln.
- A difference a repository needs inside a managed file or block goes back to
  kiln as config or code, and the reference is rebuilt.

`kiln init` is removed before the `v0.1.0` tag. pykit and ngkit are the only
repositories with a pre-kiln lineage (owner, 2026-11-07); every other repository
is rebuilt with `kiln new` and its generators.

## Consequences

- `kiln new` is the only path that decides what kiln writes, so a cutover cannot
  drift from a new repository.
- The runbook gets longer: the classification of each file, which `init` did in
  code, is now a reviewed step in each repository's story.
- `init`'s adoption code, its 77 tests and the `adopt` plumbing in the apply
  cycle are deleted.
- The history of the old repository is kept; only a port into a *new*
  repository's history loses it, and the overlay is not that.

## Alternatives considered

- **Keep `init`, and fix its heuristics.** The 2026-11-09 reruns on `45a1e40`
  still left repo-owned config unlike a new repository's: pykit's member
  `pyproject.toml` (uv_build floor, pyright, source-exclude), `.mdformat.toml`
  and the code-workspace; ngkit's `.prettierignore` and `.gitignore` preamble.
  Each fix added a heuristic (overwrite with backup, seed replacement,
  fencing, `.gitignore` dedupe, adopt-mode baseline) that had to track `new`
  by hand.
- **Rebuild into a new repository and port the history.** The 2026-11-07 trial
  lost 48 tags and the history.

## Background

- 2026-11-04: the owner chose an opinionated `init` that overwrites kiln-shaped
  files, taken by
  [F16.1](../specs/epics/E16-init-adopts-by-overwrite/F16.1-opinionated-init.md)
  and
  [F16.3](../specs/epics/E16-init-adopts-by-overwrite/F16.3-cutover-sop.md).
  Merging and prompt-driven mechanical conversions made adoption drift from
  `new`; repository-specific differences instead became reviewed cutover rows.
  Content stayed repository-owned.
- 2026-11-04: the same review chose whole-file ownership of `mkdocs.yml`
  ([F16.2](../specs/epics/E16-init-adopts-by-overwrite/F16.2-kiln-owns-mkdocs.md)).
  Nav choices stay together in `_areas.yml`, rather than splitting Packages
  configuration into `config.toml`; other settings use `[docs.mkdocs]`.
  MkDocs's `INHERIT` was rejected because it replaces lists instead of merging
  them, preventing extension of nav and plugins.
- 2026-11-04: the owner chose sorting the entire dependency group by normalized
  name whenever kiln writes it, including repository-owned entries
  ([S16.4.2](../specs/epics/E16-init-adopts-by-overwrite/F16.4-generated-file-hygiene.md#s1642-the-dependency-group-is-re-sorted-on-every-write-r4)).
  The alternative was uv's conditional insertion: insert in order only when
  the group is already sorted, otherwise append. The owner preferred
  consistent ordering.
- 2026-11-09: the owner retired `init`, after the reruns above.
