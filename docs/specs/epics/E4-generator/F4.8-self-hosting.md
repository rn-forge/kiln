## S4.8.1 — kiln generates itself

**Status:** planned

kiln's config becomes `archetype = "python-lib"` + `lifecycle = true`
([ADR-0005](../../../adr/0005-archetypes.md)). `kiln apply --force` once; the
second apply reports all `UNCHANGED`. kiln's hand-copied skeleton is gone.

**Acceptance:**

- kiln's config records `archetype = "python-lib"` and `lifecycle = true`.
- The one forced apply names only paths the preceding `apply --dry-run`
  reported. The command and its path list are recorded on this story.
- Afterwards, `apply --dry-run --json` lists at least one artifact, all
  `unchanged`.
- `kiln doctor` exits 0, `task validate` passes, and `git ls-files scripts` is
  empty.
- CI passes on the branch with the regenerated workflows, and the run is linked
  here.

## Acceptance

```bash
set -euo pipefail
cd rn-forge/kiln
rg -q '^archetype = "python-lib"' .rn-forge/kiln/config.toml                          # S4.8.1
rg -q '^lifecycle = true' .rn-forge/kiln/config.toml                                  # S4.8.1
uv run kiln apply --dry-run --json \
  | jq -e '(.artifacts | length > 0) and all(.artifacts[]; .action == "unchanged")'   # S4.8.1
uv run kiln doctor                                                                    # S4.8.1
task validate                                                                         # S4.8.1
files=$(git ls-files scripts)
test -z "$files"                                                                      # S4.8.1
```

Not scriptable: the recorded forced paths and the linked CI run.
