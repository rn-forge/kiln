# ADR-0009 — A repository's specs are accepted inside that repository

**Status:** accepted (2026-09-26) · **Scope:** the specs of every repository
kiln generates, kiln's included

## Decision

Every acceptance line in a repository's specs can be checked inside that
repository. When acceptance needs a host, such as an application or a library
workspace, a test builds one in a temporary directory.

A dependency on another repository is a version pin. At most it adds an entry
criterion, stated as something observable from outside that repository, such as
"pykit's release-1 tags exist". Another repository's stories, IDs and internal
status are not restated. No repository writes a handoff page for another to cite
by path, and each repository's docs describe only itself.

The rule is seeded into every generated repository's `specs/_structure.md`,
under "Writing acceptance".

## Consequences

- kiln's board lists the pins kiln needs in place of pykit's work.
- [F6.1](../specs/epics/E6-rebuild-the-repos/F6.1-pykit-skeleton.md) proves that
  `python-lib` can host pykit on a pykit-shaped repository built in a scratch
  directory. The cutover inside pykit is pykit's own work, and release-1 no
  longer exits on a check run inside pykit.
- [E7](../specs/epics/E7-pykit-release-pin-flip/index.md) is entered when
  pykit's tags exist. It no longer depends on an owner declaration or on the
  order in which pykit cuts its tags.
- The cost: kiln's board no longer shows how far pykit has got. A pin that is
  not ready shows up as a failed `uv sync`, not as a status row.

## Influences

The seeded rule is
[S11.4.1](../specs/epics/E11-package-docs/F11.4-cross-repository-rule.md#s1141-seeded-specs-carry-the-rule).
kiln's own pages were corrected when this was accepted. That covered
[the board's pins](../specs/index.md#upstream-pins), E5, E7 and F6.1.

## Alternatives considered

- **Keep the rule for pykit only.** kiln's pages about pykit went wrong three
  ways in one week. The handoff page was deleted, the pins changed, and an ADR
  cited as "pykit ADR-0005" became rule 3 of pykit ADR-0002. None of that was
  visible from kiln.
- **A handoff page in the upstream repository, cited by path.** This was tried
  with pykit's `docs/plans/kiln-dependencies.md`, which is now deleted. Every
  kiln link to it pointed at nothing, and the checks could not say so, because
  the path was in another repository.

## Background

pykit made the same decision for itself on 2026-09-26, as pykit ADR-0008. The
kiln pages it made wrong are listed in
[the pykit docs alignment plan](../plans/pykit-docs-alignment.md#kiln-pages-that-are-now-wrong-about-pykit).
