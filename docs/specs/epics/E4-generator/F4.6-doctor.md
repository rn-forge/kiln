Phase step: D.6 · Design: [doctor checks](design.md#doctor-checks)

**Elaborated 2026-10-14**, when the owner pulled F6.4 and E9 into release-1:
F6.1's pykit-shaped repository needs `--full` and `--all`, and 23 of its
findings are S4.6.5's. **Build order:** S4.6.1 → S4.6.5 → S4.6.3 → S4.6.4 →
S4.6.2. Build each story by the
[board's procedure](../../index.md#building-a-story). Shared facts for every
story:

- `kiln doctor` is `commands.doctor` in `src/rn_forge/kiln/commands.py`, wired
  through `CliApp`. In this framework a defaulted parameter is always an
  option (see `commands.diff`'s note), so a path stays positional and
  required. `kiln doctor --full` is written `kiln doctor . --full` everywhere.
- The registry is `CHECKS` in `src/rn_forge/kiln/checks.py`. Its tests are
  `tests/test_checks_registry.py`. `kiln apply` runs the same checks through
  `commands._fail_on_errors`.
- The render-free import contract (`.importlinter`,
  `tests/test_checks_are_render_free.py`) forbids
  `rn_forge.kiln.modules.*.checks` from importing rendering. Anything that
  renders lives in `src/rn_forge/kiln/doctor.py`, which is not under `checks`.

## S4.6.1 — One report across modules

**State:** Closed (2026-10-14)

Iterates modules in `archetype.toml` order and prints one `Finding` report: the
active checks in the design table, excluding retired entries.

**Build — tests first,** in a new `tests/test_doctor.py` (use the `repo` and
`rendered` fixtures from `tests/conftest.py`):

- `test_s4_6_1_1_each_check_reports_only_its_own_code`: parametrized over every
  name in `checks.names()`. For each, a fixture repo broken for that check
  alone yields at least one error whose code starts with that check's code
  prefix, and no error-severity finding from another check. Reuse the broken
  fixtures the existing per-check test files already build; import their
  helpers rather than copying them.
- `test_s4_6_1_2_full_on_a_fresh_repo_exits_0` and
  `test_s4_6_1_2_full_reports_a_stale_artifact`: on a `rendered("python-app")`
  repo, `commands.doctor(root, full=True)` returns. After changing a config
  value that changes a rendered file (`[ci] sonar = false` in
  `.rn-forge/kiln/config.toml`), it raises `AppException`, and
  `doctor.full(root)` contains a finding with code `artifact.stale` whose
  `path` is the changed file.
- `test_s4_6_1_2_warnings_alone_exit_0`: a check returning only warnings
  (monkeypatch `checks.CHECKS` with one stub `Check`) leaves the exit at 0.
- `test_s4_6_1_3_json_lists_every_finding_in_module_order`: with `json=True`,
  stdout parses as `{"findings": [...]}`. Each item has exactly `code`,
  `severity`, `message` and `path`. The items are in `archetype.toml`'s
  `modules` order.
- `test_s4_6_1_4_apply_fails_on_an_error_finding`: an existing apply test shape
  (`tests/test_apply.py`). A repo whose doctor reports an error makes
  `commands.apply()` raise after applying.

**Build:**

- `checks.run(root, only=None)` orders `CHECKS` by the position of each check's
  `module` in the archetype's `modules` list
  (`archetypes.for_config(config).modules`). A module the archetype does not
  list keeps registry order, after the listed ones.
- New `src/rn_forge/kiln/doctor.py` with `full(root: Path) -> list[Finding]`. It
  calls `cycle.plan(root).changes` and, for each change whose `kind` is not
  seeded, maps the action: `CREATE`, `UPDATE`, `DELETE` → `artifact.stale`;
  `INSERT`, `REMOVE` (block kind) → `block.stale`. `UNCHANGED`, `SKIP`,
  `FORGET`, `DRIFT`, `MISSING` and `CONFLICT` add nothing, because `generated`
  already reports drift and absence. Severity is error. The message says
  `would be <action> by a fresh render — run \`kiln
  apply\``, and `path`is`change.path\`.
- `commands.doctor(path, only=None, full=False, json=False)`. `--full` appends
  `doctor.full(root)` to `checks.run`'s findings (not with `--only`: passing
  both is an `AppException`). `--json` sets `OutputMode.JSON` and emits
  `{"findings": [{"code", "severity", "message", "path"}]}` through
  `console.json`, with `severity` as its string value and `path` as a string
  or `null`. The exit rule does not change: any error-severity finding raises.
- `commands._fail_on_errors` is unchanged: apply already runs the same checks.
- Docs: `docs/reference/standard-repo.md` §6 drops nothing; add to its first
  paragraph *`--json` prints the same findings as one JSON object.*

**Acceptance:**

- For each active check in the design table, a fixture triggers that check's
  code and no other error-severity code. There is one test per check.
- `kiln doctor --full` on a freshly created repo exits 0. With warnings only it
  exits 0, and with any error-severity finding it exits 1.
- `--json` emits every finding with `code`, `severity`, `message` and `path`, in
  `archetype.toml` module order.
- `kiln apply`'s last step runs the same checks, and exits non-zero on an
  error-severity finding.

*What the build settled that the story did not say*

- **The registry still has ten checks.** The test is parametrized over
  `checks.names()` as it stands, `pyproject-tool-config` and `root-hygiene`
  included; S4.6.5 retires them and their rows go with them. Those two report
  warnings only, so their rows assert a finding with the code prefix rather
  than an error.
- **Fixtures start from a copy of `rendered("python-app")`, not a bare
  `repo()`.** A bare repo has no Taskfile or state, so the other checks error
  on it and "alone" could not hold. Each row breaks the copy one way. Edits to
  a managed file that only a non-`generated` check should see re-seed that
  file's `content_hash` in `state.json`. Of the existing per-check helpers
  only `MISSING_REQUIRED` from `test_rn_forge_deps.py` fitted; the suite has
  no test packages, so it is loaded by path.
- **The three docs checks may overlap.** `docs-structure`, `docs-generate` and
  `docs-site` read one tree: a broken link or an orphan page is reported by
  more than one. For a docs break the other two are exempt from "no other
  error"; every non-docs check is still held to it.
- **`--only` with `--full` is
  `AppException("--only and --full cannot be combined")`**, raised before any
  check runs.
- **`--json` mode prints no per-finding lines**, only the object; the exit rule
  is unchanged. Text mode still prints each finding with `console.error`,
  warnings included, as before.
- **`checks.run` sorts with a stable key**, so checks of the same module keep
  registry order. A module the archetype omits sorts last.
- **`doctor.full` keys on the action alone** (`SEEDED` kind skipped), so
  `INSERT`/`REMOVE` give `block.stale` and `CREATE`/`UPDATE`/`DELETE` give
  `artifact.stale`. In the test a `sonar = false` edit makes `ci.yml` and
  similar files `update` and `sonar-project.properties` `delete`; the test
  asserts every `update` path is reported.
- **`commands` imports the module as `doctor_module`**, because the command
  function is itself named `doctor`.
- **The reference sentence** is appended to §6's first paragraph.
- The tests were written with the code in view; run before the implementation
  they fail at collection (`from rn_forge.kiln import doctor`).

## S4.6.2 — The task-graph validator

**State:** Closed (2026-10-14)

`doctor/taskgraph.py` ported from taskkit `validator.py` with its tests.

**Elaborated 2026-10-14.** kiln's `task-layout` check
(`src/rn_forge/kiln/modules/tasks/checks/layout.py`, code prefix `taskgraph`)
already enforces three of the rules: wrappers only at the root
(`taskgraph.not-a-wrapper`), `desc` on every task (`taskgraph.no-desc`) and
check 8 (`gate.shrunk`). This story adds the rest **to that check**, porting the
logic of taskkit's `src/rn_forge/taskkit/core/validator.py` (`_graph_findings`,
`_cycle_findings`, `_check_script`). It does not add `doctor/taskgraph.py`: one
check per concern, and this one exists. taskkit's `tests/core/test_validator.py`
is reference only; its expectations about workspaces and adapters do not apply.

**Definitions:**

- The **include map** is the root `Taskfile.yml` `includes:`, namespace → path
  (a value is a string, or a mapping whose `taskfile` is the path).
- **Repository-owned** task files are the `taskfile` paths in
  `config.tasks.includes`. Every other included file is **managed**.
- The **graph** is every task of the root file and of every included file that
  exists, keyed by qualified name (`<namespace>:<task>`). Repository-owned
  files are in the graph, so a reference into them resolves. Replace
  `load_graph`'s `tasks/*.yml` glob with the include map, and keep `resolve`
  and `reachable_from` as they are.
- Layout rules (`no-desc`, the new `not-internal`) apply to the root file and to
  managed files only. Today's glob also checks repository-owned files; that
  stops (S4.6.5's boundary).

**Build — tests first,** in `tests/modules/tasks/checks/test_layout.py`, copying
its `repo` fixture shape. One test per rule, each asserting its code:

- `test_s4_6_2_1_surface_is_exactly_the_root_verbs`: a root task outside
  `ROOT_VERBS` → `taskgraph.surface`; a missing root verb →
  `taskgraph.surface`.
- `test_s4_6_2_1_reserved_namespace_tasks_are_internal`: a `quality:` or
  `workspace:` task without `internal: true` → `taskgraph.not-internal`. A
  public `docs:`, `api:` or `web:` task is not reported.
- `test_s4_6_2_1_an_include_must_exist`: an include whose file is absent →
  `taskgraph.missing-include`.
- `test_s4_6_2_1_task_refs_resolve`: a managed task calling `quality:nope` →
  `taskgraph.unresolved`. A call into a repository-owned include's task
  resolves.
- `test_s4_6_2_1_no_cycles`: `a → b → a` across two files → one
  `taskgraph.cycle` whose message names the path.
- `test_s4_6_2_1_reserved_namespace_collision`: a `config.tasks.includes`
  namespace equal to a managed include's namespace (`quality`) →
  `taskgraph.reserved-namespace`.
- `test_s4_6_2_1_repository_owned_files_are_not_held_to_layout`: a task with no
  `desc` in a repository-owned include → nothing.
- `test_s4_6_2_2_unresolved_ref_in_a_workflow`: a `run: task nope` in
  `.github/workflows/ci.yml` → `taskgraph.unresolved-ref` with that path and
  `line`. `task --list`, `task validate` and a ref inside a non-managed
  Markdown file are not reported.
- `test_s4_6_2_2_unresolved_ref_in_a_managed_block`: inside `CLAUDE.md`'s kiln
  block (the markers in `state.json`) `task nope` is reported; the same text
  outside the block is not.
- `test_s4_6_2_3_every_rendered_cell_passes`: for each render-matrix cell,
  `checks.run(root, only="task-layout") == []`.

**Build** in `layout.py`:

- The six graph rules above, as private functions called from `check`. Codes:
  `taskgraph.surface`, `taskgraph.not-internal` (namespaces `quality` and
  `workspace` only, as taskkit's `RESERVED_NAMESPACES`),
  `taskgraph.missing-include`, `taskgraph.unresolved`, `taskgraph.cycle`,
  `taskgraph.reserved-namespace`. All error severity.
- `taskgraph.unresolved-ref`: scan every `run:` value in the managed files under
  `.github/` (state.json `managed` entries whose path starts with `.github/`)
  and every managed block's text between its `begin_marker` and `end_marker`.
  Match `(?:^|[;&|(]\s*|\s)task\s+([A-Za-z][\w:-]*)`, skip a token that starts
  with `-`, and report one whose name is not in the graph, with its 1-indexed
  `line`. A `Finding` takes `line=`.
- Keep `NAME`, `CODE`, `task_refs`, `resolve` and `reachable_from` public and
  unchanged in signature: S6.4 and E9 will reuse them.
- `docs/reference/standard-repo.md` §6 already lists these codes; change the
  `taskgraph.*` row's text only if a name differs from what you build, and
  record it.

**Do not** change any template or the task vocabulary. If a rendered cell fails
a new rule, stop and record it: that is a template defect for the owner, not a
reason to loosen the rule.

**Acceptance:**

- Ported validator tests cover managed task files; old expectations that enforce
  repository-owned content are replaced with S4.6.5's ownership tests.
- Each rule has a fixture that reports its `taskgraph.*` code. The rules are:
  exact public surface, wrappers-only root, internal inner tasks except
  `docs:*`, `desc` on every task, includes exist, `task:` refs resolve, no
  cycles, and no reserved-namespace collision. These rules constrain managed
  task files; declared extensions are inputs, not additional owned files.
- An unresolved `task <name>` within a managed workflow or instruction block
  reports `taskgraph.unresolved-ref` with its file and line (check 6).
  References outside those boundaries do not produce findings.
- Removing a `required_validate` task from what `validate` reaches reports
  `gate.shrunk` (check 8).

**What the build settled that the story did not say.**

- Cells: `test_s4_6_2_3_every_rendered_cell_passes` is parametrized over five
  cells (`python-app`, `python-tool`, `python-lib` via `rendered`, and the
  `python-web-api` and `python-web-app` cells rendered with `commands.new` and
  the golden matrix's flags). All five, and kiln itself, report nothing.
- The test fixtures changed shape: the base root Taskfile now carries exactly
  the ten verbs and the base `quality.yml` tasks are `internal: true`, since
  both are now rules. Three existing tests replace a verb's block instead of
  appending a duplicate `build:`.
- `taskgraph.surface` is one finding per extra root task and one per missing
  verb.
- `taskgraph.missing-include` covers every include, repository-owned ones too.
  `load_graph(root)` keeps its signature; its namespaces are now every include
  key, whether or not the file exists.
- `taskgraph.reserved-namespace` fires for a `tasks.includes` namespace equal to
  a managed include's namespace, or to `quality` or `workspace`.
- A `task:` ref containing `{{` or `$` is skipped by `taskgraph.unresolved`
  (dynamic, unverifiable). Refs are read from `cmds:` only, as `task_refs`
  does. Tasks of repository-owned files are not checked for unresolved refs.
- `taskgraph.cycle` is deduplicated by member set, reported against the file of
  the first task in the path, and ignored when every member is
  repository-owned. Its message is `task reference cycle: a -> b -> a`.
- `taskgraph.unresolved-ref` reads `state.json` itself (no import from the
  `generated` check). A block's text is the lines strictly between the lines
  whose stripped text equals the begin and end markers. A missing `state.json`
  yields no findings here (`generated` reports it).
- `taskgraph.unresolved` and `taskgraph.not-internal` findings carry the
  include's path and no `line`; the YAML loader does not keep positions.
- `docs/reference/standard-repo.md` §6 names match what was built; unchanged.

## S4.6.3 — Many repos

**State:** Closed (2026-10-14)

`kiln doctor --all <path>…` runs the same checks, with or without `--full`, over
many repos and reports them together.

**Build — tests first,** in `tests/test_doctor.py`:

- `test_s4_6_3_1_table_has_one_row_per_repo`,
  `test_s4_6_3_2_json_attributes_findings`,
  `test_s4_6_3_3_a_non_kiln_path_is_its_own_error`,
  `test_s4_6_3_4_exit_is_order_independent` (both orders raise), and
  `test_s4_6_3_5_three_repos_clean_warnings_errors`: three repos from
  `rendered("python-app")`, one clean, one with a warning only (monkeypatch a
  warning-only stub check), one with `Taskfile.yml` edited.

**Build:**

- `commands.doctor` takes `paths: list[Path]` (positional, one or more) and
  `all: bool = False` (`--all`). Without `--all`, more than one path is an
  `AppException`.
- With `--all`, each path runs `checks.run` (plus `doctor.full` with `--full`)
  independently. An `AppException` from loading a path's config becomes one
  error finding for that repo, code `config.load`, message the exception text.
- Text output: one `console` table, columns `repo`, `errors`, `warnings`, a row
  per path in the order given, then each repo's findings under its path.
  `--json`:
  `{"repos": [{"path", "findings": [...]}], "summary": {"repos", "errors", "warnings"}}`,
  with `path` as given on the command line.
- Exit: raise if any repo has an error-severity finding.
- E6's acceptance block already uses `kiln doctor --all … --json`. Fix the
  feature acceptance block's `(cd "$s/clean" && kiln doctor --full)` to
  `kiln doctor "$s/clean" --full`.

**Acceptance:**

- Each path is checked independently. The text report is one table with a row
  per repo: path, error count, warning count.
- Every finding is attributed to its repo. In `--json`, `.repos[]` holds `path`
  and that repo's `findings`, and `.summary` holds `repos`, `errors` and
  `warnings` totals.
- A path that is not a kiln repo, or whose config fails to load, is an error for
  that repo only (`config.*`). The remaining repos are still checked.
- The exit status is 1 if any repo has an error-severity finding, and 0
  otherwise, whatever order the paths are given in.
- Tests cover three repos together: one clean, one with warnings only, one with
  errors.

*What the build settled that the story did not say*

- **`CliApp` takes the variadic positional.** `list[Path]` with no default is a
  required positional that takes one or more values. `uv run kiln doctor .`,
  `uv run kiln doctor --all . . --json` and `uv run kiln doctor --all . /tmp`
  all work from the CLI; nothing was worked around.
- **Single-path behaviour is the old code path.** Without `--all` a path whose
  config will not load still raises, text and `{"findings": [...]}` are
  unchanged, and the message is still `N check(s) failed in <path>`. Existing
  callers (`tests/test_lifecycle.py`, `tests/test_doctor.py`) now pass a list.
- **Several paths without `--all` is
  `AppException("several paths need --all")`.** `--all` with one path is
  allowed and gives the table and the `repos`/`summary` JSON.
- **`config.load` has `path: null`.** The finding is not about a file the checks
  reached, so `path` is `None` in `--json`; the message is the exception text.
  Only `AppException` is caught; any other exception still propagates.
- **The parameter is named `all`**, as the story says; ruff does not flag it.
- **The `--all` failure message** is `N check(s) failed across M repo(s)`. The
  findings under each path print on stderr after the table; a repo with none
  prints no heading.
- **Tests use relative paths** (`clean`, `warned`, `broken`, `plain` under one
  working directory), so the table cells do not wrap and `path` in `--json`
  can be compared as given. The warning-only repo comes from wrapping
  `checks.run` for one directory name, since a registry stub would warn in all
  three.

## S4.6.4 — CI runs doctor where the workflow asks

**State:** Closed (2026-10-14)

`task lint` always runs `kiln doctor`, and also runs `kiln doctor --full` when
the `KILN_DOCTOR_FULL` task variable is non-empty. The generated `ci.yml` sets
it on pushes to the default branch and on `workflow_dispatch`, not on pull
requests ([ADR-0006](../../../adr/ADR-0006.md)).

**Build — tests first,** in `tests/modules/tasks/test_artifacts.py` and
`tests/modules/cicd/test_artifacts.py` (copy the S6.3 tests' shape):

  `task --dry lint` in the rendered repo does not print
  `kiln doctor . --full`; `task --dry lint KILN_DOCTOR_FULL=1` does. Skip when
  `task` is not on `PATH`.
- `test_s4_6_4_2_ci_sets_the_variable_on_default_branch_pushes`: the rendered
  `validate` job's `Validate` step has `env.KILN_DOCTOR_FULL` equal to the
  expression below. `actionlint` passes (`test_s4_3_4_1_…`).

**Build:**

- `templates/tasks/quality.yml.j2`, task `lint:generated`: after its existing
  command, add

    ```yaml
          - cmd: uv run kiln doctor . --full
            if: '[ -n "{{.KILN_DOCTOR_FULL}}" ]'
    ```

    inside the same `{% else %}` branch (an override replaces both). Confirm
    `task --dry` honours `if:`. If it lists the command regardless, use the
    single command
    `'{{if .KILN_DOCTOR_FULL}}uv run kiln doctor . --full{{else}}true{{end}}'`
    instead, and record why.

- `modules/cicd/templates/ci.yml.j2`, `validate` job, the step that runs
  `task validate`: add

    ```yaml
            env:
              KILN_DOCTOR_FULL: ${{ ((github.event_name == 'push' && github.ref_name == github.event.repository.default_branch) || github.event_name == 'workflow_dispatch') && '1' || '' }}
    ```

- kiln's own `tasks/quality.yml` and `.github/workflows/ci.yml` are hand-copied
  and their `content_hash` re-seeded in `.rn-forge/kiln/state.json`, as
  `README.md` says (F6.3's stories did the same).

**Acceptance:**

- `task --dry lint` does not list `kiln doctor --full`;
  `task --dry lint KILN_DOCTOR_FULL=1` does.
- The rendered `ci.yml` sets `KILN_DOCTOR_FULL` only for a `push` to the default
  branch and for `workflow_dispatch`, and `actionlint` passes on it.

**What the build settled that the story did not say:**

- `task --dry` 3.54.0 honours `if:`: the guarded command is absent from
  `task --dry lint` and listed under `KILN_DOCTOR_FULL=1`. The single-command
  fallback was not needed.
- The tasks test runs over the five render-matrix cells (`python-app`,
  `python-tool`, `python-lib`, `python-web-api`, `python-web-app`), applied
  into a temp directory. The CI test asserts the `Validate` step's `run` and
  `env` over the three archetype cells.
- kiln's own `tasks/quality.yml` was hand-copied, not applied, and its
  `content_hash` in `.rn-forge/kiln/state.json` re-seeded. kiln's own
  `.github/workflows/ci.yml` was deliberately left without `KILN_DOCTOR_FULL`:
  kiln is not self-hosted until F4.8, so `kiln doctor . --full` fails on this
  repo and would fail every push to `main`. It gets the variable when F4.8
  lets kiln apply to itself.

## S4.6.5 — Doctor respects ownership

**State:** Closed (2026-10-14)

Restrict doctor, including `--full` and the checks after apply, to managed files
and fenced blocks. Declared configuration may be read and validated as input;
that does not authorize checks on all files reached from it.

**Current implementation gap:** the registry still includes pyproject settings
and dependency conformance, docs structure/site checks and root-file hygiene;
the generated-state checker reports missing seeds. These must stop enforcing
unowned content. Keep docs structure and link validation available through
explicit repository quality tasks, separate from doctor's ownership report.

**Build — tests first,** in `tests/test_doctor.py`:

- `test_s4_6_5_1_seeded_edits_and_deletions_are_silent`: on
  `rendered("python-app")`, edit one seeded file (`README.md`) and delete
  another (a seeded starter file under `src/`). `checks.run(root)` and
  `doctor.full(root)` report nothing about either path.
- `test_s4_6_5_2_repository_owned_pyproject_and_layout_are_silent`: change
  `[tool.pyright] typeCheckingMode` to `"basic"` in `pyproject.toml`, add a
  root file `NOTES.txt`, and move `tests/` to `test/`. `checks.run(root)`
  reports nothing.
- `test_s4_6_5_3_quality_checks_run_only_when_named`: break a docs link in a
  seeded page and remove `rn-forge-commons` from `pyproject.toml`.
  `checks.run(root)` reports neither. `checks.run(root, only="docs-site")` and
  `checks.run(root, only="rn-forge-deps")` each report it.
- `test_s4_6_5_4_a_sibling_under_rn_forge_is_ignored`: add
