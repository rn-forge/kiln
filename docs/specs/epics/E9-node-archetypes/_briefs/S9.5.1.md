# S9.5.1 — `node-lib` releases packages independently

Brief for
[S9.5.1](../F9.5-node-lib-release-findings.md#s951-node-lib-releases-packages-independently),
at `79feb43`.

## Goal

A `node-lib` can choose an independent release group in `config.toml`.
`kiln new` then seeds `nx.json` for Nx's independent mode, and `task version`
versions one project at a time. The release job that publishes it is S9.5.6, not
this story. A fixed `node-lib` (the default, and every repository today) renders
exactly as before.

## Settled

Owner, 2026-11-17: a config key, Nx-native.

- **Config.** In `src/rn_forge/kiln/modules/python/config.py` (where
  `ArchetypeConfig` lives), a new model:

    ```python
    class NodeLibConfig(ConfigModel):
        """The `node-lib` archetype's settings."""

        release_group: Literal["fixed", "independent"] = "fixed"
        """How the publishable projects release. `fixed` releases them together
        under one `v<version>` tag; `independent` versions, tags and releases each
        project on its own, as `<project>-v<version>`. `kiln new` seeds `nx.json`
        for it; changing it later re-renders the tasks, CI and standard on
        `kiln apply`, and `nx.json`, which the repository owns, is edited by
        hand."""
    ```

    `ArchetypeConfig` gains
    `node_lib: NodeLibConfig | None = Field(default=None, alias="node-lib")`
    with the docstring `"""The `node-lib` archetype's settings."""`, and
    `__all__` lists `NodeLibConfig`. `KilnConfig`
    (`src/rn_forge/kiln/config.py`) gains a property:

    ```python
    @property
    def release_group(self) -> str:
        """`independent` when a `node-lib` releases each project on its own, else `fixed`."""
    ```

    It reads the section the way `frontend` does (through `archetype_section` and
    an `isinstance` check), and is `"fixed"` for every other archetype or
    without the table. Do not change `ConfigManager`'s defaults: `kiln new`
    writes the table only when the input config has it.

- **`nx.json`.** `modules/node/scaffold.py`: `_configure_nx(root, config)` takes
  the config (its one caller, `_stamp_root`, has it). When
  `config.release_group == "independent"` it seeds `_RELEASE_INDEPENDENT`
  instead of `_RELEASE`:

    ```python
    _RELEASE_INDEPENDENT = {
        "projects": ["tag:publishable"],
        "projectsRelationship": "independent",
        "releaseTag": {"pattern": "{projectName}-v{version}"},
        "version": _RELEASE["version"],  # deep-copied when seeded, as _RELEASE is
        "changelog": {"projectChangelogs": {"createRelease": False}},
    }
    ```

    Spell `version` out as a literal equal to `_RELEASE["version"]` if a shared
    reference is awkward. `_RELEASE` does not change. `setdefault` semantics
    stay: a `release` block `nx.json` already holds is kept.

- **Context key.** `release_group` (`config.release_group`) in the tasks
  module's template context (`modules/tasks/artifacts.py`, beside
  `"node_lib"`) and in the instructions module's
  (`modules/instructions/artifacts.py`, beside `"node_lib"`).

- **`node:version`** (`modules/tasks/templates/tasks/node.yml.j2`). The fixed
  branch is unchanged, byte for byte. Under
  `{% if release_group == "independent" %}` the task's command is, in order:

    1. With no `CLI_ARGS`: print one line `<project> <version>` per publishable
       project (`project.json` with the `publishable` tag; `<project>` is its
       `name`, `<version>` its sibling `package.json`'s `version`), sorted by
       project name. Walk the tree the same way the fixed `read_version` does,
       skipping the same directories.

    1. With `CLI_ARGS`: `set -- {{.CLI_ARGS}}`. Anything but exactly two words
       prints
       `::error::pass a bump and a project: task version -- <patch|minor|major|x.y.z> <project>`
       to stderr and exits `1`. A project that is not a publishable project
       prints `::error::<project> is not a publishable project` and exits `1`.
       Otherwise, with `bump=$1` and `project=$2`, it runs:

        - `pnpm exec nx release version "$bump" --projects="$project" --git-commit=false --git-tag=false --stage-changes=false`
        - reads the project's new version from its `package.json`;
        - `first=" --first-release"` when `git tag --list "$project-v*"` is empty,
          else empty;
        - `pnpm exec nx release changelog "$version" --projects="$project" --git-commit=false --git-tag=false --stage-changes=false$first`.

        The existing `task: :quality:format:markdown` step after it, gated on
        `CLI_ARGS`, applies to both branches.

    The task's `desc:` for independent:
    `Print each publishable project's version, or bump one, write its CHANGELOG.md section and format it (pass -- patch|minor|major|x.y.z <project>); the root version task runs it.`
    The root `version` task's `desc:` in `Taskfile.yml.j2`, under `node_lib`
    and independent:
    `Print each publishable project's version, or bump one, write its CHANGELOG.md section and format it (pass -- patch|minor|major|x.y.z <project>).`
    Both fixed descriptions are unchanged.

- **Standard** (`modules/instructions/templates/standard.md.j2`, §9). The
  `**In nx.json.**` bullet for `release` gets an independent variant: it also
  holds `projectsRelationship: "independent"` and `releaseTag.pattern`
  `{projectName}-v{version}`, and its changelog is per project
  (`changelog.projectChangelogs.createRelease` is `false`). The
  `**Releasing.**` paragraph gets an independent variant:
  `task version -- <patch|minor|major|x.y.z> <project>` bumps one project and
  writes the `CHANGELOG.md` in its folder; commit those and merge;
  `task version` with no argument prints each project's version; on the push
  to the default branch each project whose version is not yet released is
  tagged `<project>-v<version>` and released on its own. The fixed text is
  unchanged. Gate each with
  `{% if release_group == "independent" %}…{% else %}…{% endif %}`.
