## S17.2.1 — The `ci:` tasks follow one grammar

Design decision 2; finding 8.

**State:** Closed (2026-11-06)

**Build — first:** list every `ci:` task each archetype renders on the rebased
tree (`task --list --json` in each golden cell, after
`task self:golden:render`), and reconcile it with
[the design's rename table](design.md#the-ci-names-after-f172). A name the table
does not cover is renamed by the grammar's rule and added to the table.

**Build — tests first,** in `tests/modules/tasks/test_artifacts.py`:

1. `test_s17_2_1_1_grammar`: for each archetype, every public task under `ci:`
   matches `^ci:[a-z][a-z0-9]*(-[a-z0-9]+)*(:[a-z][a-z0-9]*(-[a-z0-9]+)*)?$`,
   and its first level is a stage name or a CI-only check name (a constant
   tuple in the test, copied from design decision 2).
1. `test_s17_2_1_2_one_name_per_idea`: no archetype renders any name in the
   table's left-hand column.
1. `test_s17_2_1_3_workflows_call_the_new_names`: no rendered workflow or
   composite action under `.github/` names a left-hand-column task.

**Build:** rename each task in `modules/tasks/templates/tasks/ci.yml.j2`, and
every caller: `modules/cicd/templates/**`, the registry's `verb` column, the
`ci-entrypoint` and `task-layout` checks if they name tasks,
`docs/architecture/ci.md` (prose; the matrix is regenerated),
`docs/architecture/tasks.md` (its CI surface table),
`docs/reference/standard-repo.md`, and every test. Move `ci:version` (internal)
to `node:version` in `modules/tasks/templates/tasks/node.yml.j2`, still
internal, and make the root `version` call it (finding 14).
`rg -n '<old name>\b' src tests docs` must find nothing for each old name,
except in closed feature pages, which keep their history. Use one `desc:` style
for `ci:` tasks: `CI only: ` followed by a sentence starting with a capital
letter and ending with a period. Run `task kiln:apply` and `task docs:generate`.

**Acceptance:**

- The three tests pass, and `task validate` passes.
- `task self:golden:render && task self:golden:validate`.

**What the build settled that the story did not say:**

- Reconciliation at `173249c`: every `ci:` task the six golden cells render is
  covered by the design table, so no name was added. `ci:release:umbrella`
  (with the `umbrella-release` check on) and `node-lib`'s `ci:release:*` set
  were already in grammar. Python's `ci:lint:workflows` is internal and stays.
- `ci:coverage` is left for S17.2.2. Test 1 allows `coverage` as a first level
  through a one-entry `CI_PENDING` tuple (the design tuple stays whole), and
  test 2's old-name list omits it. `sonar` is allowed as a first level.
- The renames: `sonar-target` to `sonar:target`; `release-state`, `-source`,
  `-publish`, `-build` and `-sign` to `release:state`, `:source`, `:publish`,
  `:build` and `:sign`; `docs-publish` to `docs:publish`; `suite` to `suites`;
  `lint:secrets` to `secret-scan`; `requirements` to `internal-ranges` (Python
  and `node-lib`, and the `validate` step that calls it); `affected` to
  `test`; `has-e2e` to `test:has-e2e`; `playwright` to `test:playwright`;
  `playwright:deps` to `test:playwright-deps`; `package` to `smoke`. The
  `kiln-devops` subcommands (`sonar-target`, `release-state`, `requirements`,
  ...) keep their names; they are not tasks.
- `ci:version` moved to `node:version` in `tasks/node.yml.j2`, inside
  `{% if node_lib %}` after `typecheck`, still `internal: true`; the root
  `version` calls it. The `node.yml` tests that compared the lib and app files
  now also remove `version` from the lib file.
- `node-lib`'s `ci:test` and `ci:smoke` and Python's now share names across
  archetypes; they never render together. The two older tests that asserted
  `affected`/`release:state` absence in Python cells were narrowed to the
  names that stay node-only (`test:*` and `release:author`, and no `nx` in
  `test`).
- Every `ci:` `desc:` is `CI only: ` plus a capitalised sentence ending in a
  period. Fragments that began lowercase ("the checks that...", "the
  repository-wide checks...") became "Run the ...". The `verify-release` desc
  test and the node `desc` tests were updated for the new text.
- The tests render each cell with `cycle.apply` (so `.github/` exists) and cover
  the six archetypes, `python-lib` with `release = "pypi"`, and all six with
  `umbrella-release` on. Test 2 also scans the other `tasks/*.yml` for old
  names and checks `node:version`; test 3 scans every file under `.github/`
  for any `ci:` token in the old list, by whole token, so `ci:suites` does not
  trip `ci:suite`.
- Tests written first failed (3 of 3) before the build. Existing tests changed
  only in their task keys, `ci:` strings and the desc text; the key `"suite"`
  in ci-yml assertions became `"suites"`, and `secret-scan` was added to the
  non-pipeline exclusions in `test_s4_12_2_3`, where `lint:`-prefix filtering
  used to exclude `lint:secrets`.
- Prose updated: `docs/architecture/ci.md`, `docs/architecture/tasks.md` (the CI
  surface table; the "not yet one grammar" paragraph now states the grammar
  and the one `ci:coverage` exception), `docs/reference/standard-repo.md`, and
  the `ci:affected` mention in `docs/specs/ideas/index.md`. Closed feature
  pages, ADR-0014 and `design.md` keep the old names as history.

## S17.2.2 — One coverage task for Sonar

Design decision 8; finding 9.

**State:** Closed (2026-11-06)

**Build — tests first:** `test_s17_2_2_1_sonar_runs_the_root_verb` (every
archetype's rendered Sonar step runs `task test:coverage`) and
`test_s17_2_2_2_node_lib_reports` (`node-lib` renders `ci:sonar:reports` and no
`ci:coverage`, and the Sonar step reads `reports` from it).

**Build:** `node-lib`'s root `test:coverage` must write the lcov reports that
`ci:coverage` writes today. If `node:test` does not, make `test:coverage` run
what `ci:coverage` runs. `ci:sonar:reports` holds only the `find coverage …`
lookup and its `reports=` line. Update both branches of
`modules/cicd/templates/workflows/_sonar.yml.j2`: the `node-lib` step
`task ci:coverage >> "$GITHUB_OUTPUT"` becomes `task test:coverage` followed by
`task ci:sonar:reports >> "$GITHUB_OUTPUT"`, and the Python branch already runs
`task test:coverage`.

**Acceptance:** the tests pass, and `task validate` passes.

**What the build settled that the story did not say:**

- `node-lib`'s root `test:coverage` already wrote what `ci:coverage` wrote: it
  calls `node:test`, which runs `pnpm nx run-many -t test`, the same Nx target
  `ci:coverage` ran (`pnpm exec nx run-many -t test`). Nothing changed in
  `node.yml.j2` or `Taskfile.yml.j2`; the lcov files come from each project's
  `test` target, as before. A `node:test` command override changes both.
- `ci:sonar:reports` holds the `find coverage ...` lookup and its `reports=`
  line, and keeps the guard `ci:coverage` had: it fails with
  `::error::No lcov.info found under coverage/` when the workspace has
  projects but no report, and an empty workspace (`nx show projects` prints
  `[]`) still passes. The brief said "only the lookup"; the build first
  dropped the guard, and review restored it, because without it a broken
  coverage run reaches the scan as an empty
  `sonar.javascript.lcov.reportPaths` and passes silently. The `s9_1_3_2` and
  `s9_2_7_2`–`s9_2_7_4` tests keep every case and now run `ci:sonar:reports`;
  the one that asserted the tests ran lost that assertion, since running the
  tests is `test:coverage`'s job now.
- The task is `sonar:reports` under the `ci:` file, so it is `ci:sonar:reports`
  and the first level `sonar` was already allowed. `CI_PENDING` is gone and
  `ci:coverage` joined `CI_OLD_NAMES`.
- The Sonar job's two steps are `Test with coverage` (`task test:coverage`) and
  `Discover the lcov reports` (id `reports`, was `coverage`); the scan reads
  `steps.reports.outputs.reports`. The Python branch was confirmed, not
  changed.
- The workflow assertion for `node-lib` is in
  `tests/modules/cicd/test_artifacts.py`
  (`test_s9_1_3_1_sonar_job_matches_ngkit`, updated for five steps). The two
  new tests are in `tests/modules/tasks/test_artifacts.py`, next to S17.2.1's,
  because they render every archetype cell with `_ci_cells`.
- Prose: `docs/architecture/ci.md` (two rows) and `docs/architecture/tasks.md`
  (the CI surface row; the "one exception" sentence is gone).
  `docs/reference/standard-repo.md` did not mention `ci:coverage`.
  `registry.py` did not name it.

## S17.2.3 — A switched check is one registry row plus its task

Finding 10.

`test_s17_2_3_1_enabled_names` (`registry.enabled_names(ci, archetype, members)`

**Build:**

  `enabled_names(ci: CiConfig, archetype: str, members: int) -> frozenset[str]`.
- `modules/tasks/artifacts.py` and `modules/cicd/artifacts.py`: replace every
  `next(c for c in registry.CHECKS if c.name == …)` and `*_enabled` context
  key with one key, `checks`, holding `enabled_names(...)`.
- `src/rn_forge/kiln/config.py`: `KilnConfig.licenses_enabled` (F17.1) becomes
  `"licenses" in registry.enabled_names(...)`.
- The keys to replace, at `8202297`: in `tasks/artifacts.py`,
  `licenses_enabled`, `licenses_task`, `licenses_node_task`,
  `secret_scan_enabled`, `internal_ranges_enabled` and
  `umbrella_release_enabled`; in `cicd/artifacts.py`,
  `umbrella_release_enabled`, `internal_ranges_enabled` and the scorecard
  lookup. The `umbrella-release` with `release = "none"` refusal in
  `cicd/artifacts.py` stays, reading `"umbrella-release" in checks`.
- Templates: replace `{% if <name>_enabled %}` with
  `{% if "<name>" in checks %}`. `licenses_task` and `licenses_node_task`
  become `"licenses" in checks and not node_lib` and `… and node_lib`, written
  inline.
- `docs/architecture/ci.md`: the "adding a check" sentence is now true; say what

- `tasks/artifacts.py` needed no new import: it already used `registry`.
- `licenses_task` in `python.yml.j2` became
  `"licenses" in checks and not node_lib` in both its `if` and `elif`;

## S17.2.4 — The pip-audit ignore list moves to `[ci.checks]`

Design decision 7; finding 11.

**State:** New

**Build — tests first,** in `tests/modules/cicd/test_config.py` and
`tests/modules/tasks/test_artifacts.py`. Move the existing
`[[tasks.audit.ignore]]` tests (`test_artifacts.py` around the
`tasks.audit.ignore` cases) to the new key, keeping every case, and add:

1. `test_s17_2_4_1_table_only`: `[ci.checks] pip-audit = false` (or `true`) is
   refused with `ci.checks.pip-audit is always on; set a table with ignore`.
1. `test_s17_2_4_2_old_key_refused`: a config with `[tasks.audit]` is refused
   with `tasks.audit moved to [ci.checks] pip-audit`.
1. `test_s17_2_4_3_ignored_ids_render`:
   `[ci.checks] pip-audit = { ignore = [{ id = "PYSEC-2026-1", reason = "a" }] }`
   renders `--ignore-vuln PYSEC-2026-1` in `tasks/python.yml`.

**Build:**

- `modules/cicd/config.py`: an `AuditPolicy` model with
  `ignore: list[AuditIgnore]`, moving `AuditIgnore` and its validators (unique
  ids, advisory id shape, non-empty reason) from `modules/tasks/config.py`.
  Add the accessor `audit_policy()`, beside `licenses_policy()`.
- `modules/cicd/registry.py`: the `pip-audit` row keeps `Switch.STANDARD`, gains
  `policy=AuditPolicy`, and its note becomes
  `` S; ignore list `[ci.checks] pip-audit` ``. A standard row with a policy
  is a valid `[ci.checks]` key that takes a table only. Change whichever
  validator refuses keys for standard rows, and `configured_names()`'s
  callers, to allow it.
- `modules/tasks/config.py`: remove `AuditConfig`, `AuditIgnore` and the `audit`
  field. Make the old key fail with the message in test 2.
- `modules/tasks/artifacts.py`: `audit_ignore` comes from
  `ci.audit_policy().ignore`.
- This repository's `.rn-forge/kiln/config.toml`: move `[tasks.audit]`, then
  `task kiln:apply`. Update S16.4.7's commented `config.toml` template if it
  explains `[tasks.audit]`. Update `docs/reference/standard-repo.md` §9 and
  the line that mentions `[[tasks.audit.ignore]]` in §8.

**Acceptance:**

- The tests pass, and `task validate` passes.
- `task self:golden:validate`.
