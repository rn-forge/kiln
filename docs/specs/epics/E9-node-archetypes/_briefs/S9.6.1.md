# S9.6.1 — The agent launch template installs go-task

Brief for
[S9.6.1](../F9.6-nx-cloud-agents-run-task.md#s961-the-agent-launch-template-installs-go-task),
at `fc79b96`.

## Goal

Every Nx Cloud agent that a `node-lib`'s rendered `.nx/workflows/agents.yaml`
launches has `task` on its `PATH`, so `targetDefaults.pack`
(`task ci:dist:resolve …`) runs there as it does on a GitHub runner.

## Settled

- The step, inserted after `Install uv` as the last init step of `linux-medium`,
  is exactly (two-space YAML indentation as the surrounding steps):

    ```yaml
          - name: Install go-task
            script: |
              # Tracks the 3.x that the setup action's setup-task step resolves; every node-lib packs with task
              sh -c "$(curl --location https://taskfile.dev/install.sh)" -- -d -b "$HOME/.local/bin" v3.54.0
              echo "PATH=$HOME/.local/bin:$PATH" >> $NX_CLOUD_ENV
              "$HOME/.local/bin/task" --version
    ```

- The version is `v3.54.0`, the go-task this repository's developers run. It is
  written once, in that step, as the uv version `0.13.1` is written once in
  the `Install uv` step. No new context key or constant.

- The step is unconditional, unlike the uv step.

- ngkit at `NGKIT_REF` has no such step, so the ngkit comparison keeps every
  line outside the new step and checks the step on its own.

- Tests are named for behaviour, `test_<subject>_<behaviour>`, with no spec ID
  in a name, docstring or comment.
