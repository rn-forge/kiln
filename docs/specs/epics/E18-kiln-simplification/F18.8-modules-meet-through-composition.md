The module contract (`modules/base.py`) is meant to be the only interface
between modules. Two gaps have opened. Checks are registered twice, and the
registration that doctor does not read hides an unregistered check. And
`.importlinter` now grandfathers nine sibling imports, where its comment said
there would be at most four.

Every story keeps these properties:

1. No rendered file and no doctor finding changes, except as S18.8.1 states.
1. `task lint`'s import contracts pass.

## S18.8.1 — Checks are registered once

**State:** New · **Depends on:** —

`checks.CHECKS` (`checks.py:47-59`) is what doctor runs. Seven modules also
declare `checks()` (`modules/base.py:70`), but no code in `src/` calls it. Only
two tests do (`tests/modules/instructions/test_artifacts.py:151`, `:259`).
`kiln-pin` is reachable only through `CoreModule.checks()`
(`core/__init__.py:45-47`), so doctor never runs it.

**Build.** Delete `checks()` from the Protocol and from every module. The
registry is the one list. Registering `pin` changes what doctor reports, so that
is F18.10's job (S18.10.1). The registry keeps a comment that names the gap
until then.

**Acceptance:**

- No `def checks` remains under `src/rn_forge/kiln/modules/`.
- The properties hold.

## S18.8.2 — The sibling-import allow-list is empty

**State:** New · **Depends on:** —

`.importlinter:87-98` ignores these imports:

- `tasks.artifacts` into `python.artifacts`, `cicd.artifacts`, `cicd.config` and
  `cicd.registry`
- `docs.generate` into `cicd.registry`
- `instructions.artifacts` into `cicd.config`, `cicd.registry`, `docs.config`
  and `tasks.surface`

**Build.**

- Values that one module needs from another are passed by composition. The
  `KilnConfig` accessors from S18.7.1 cover `CiConfig` and `DocsConfig`. The
  CI matrix, the public task list, `load_pins`, the checks list and `gitleaks`
  reach `tasks` and `instructions` through their render context, put there by
  the composer.
- `root_package` is already in `core` (S18.7.1). `load_pins` and `pins.toml`
  move to `core`, which only `cicd` renders.
- The `ci-matrix` region in a docs page gets its rendered text from the
  `docs generate` command, so `docs.generate` stops importing `cicd.registry`.
- `instructions/scaffold.py:14` stops importing `context` from its own artifacts
  module, which pulls in the whole cicd and tasks graph.

**Acceptance:**

- `.importlinter`'s independence contract ignores only the two composition
  entries, `config` and `modules.registry`.
- The properties hold.
