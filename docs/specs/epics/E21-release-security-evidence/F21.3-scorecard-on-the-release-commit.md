Deferred 2026-11-24: Scorecard only reports, with no threshold, and
[F21.1](F21.1-evidence-record.md) records the newest weekly run with the commit
it scored.

Today `scorecard.yml` runs weekly and on dispatch, so its newest score is
usually for an earlier commit than the release. This feature makes a release run
on the default branch produce a Scorecard result for its own commit, which the
evidence record would read instead.

## S21.3.1 — Decide how Scorecard runs at the release

**State:** New

**Acceptance:**

- A reproduction in a scratch public repository answers whether
  `ossf/scorecard-action` with `publish_results: true` runs when
  `scorecard.yml` is called with `workflow_call` from `ci.yml`. The action
  restricts the workflows that publish results.
- It compares three options, and the owner chooses one: call `scorecard.yml`
  from `ci.yml`; dispatch it from the `evidence` job with `gh workflow run`
  and wait for it; or run Scorecard in the `evidence` job without publishing
  and record that score only.
- The choice is recorded as an ADR.

## S21.3.2 — Scorecard runs at the release

**State:** New · **Depends on:** S21.3.1

**Acceptance:**

- With `[ci.checks] scorecard` and `release-evidence` on, a release run on the
  default branch produces a Scorecard result for its pushed commit by the
  option S21.3.1 chose. The weekly schedule stays.
- `kiln-devops evidence collect` records that result. When Scorecard is off, the
  row is `not run`.
- `zizmor` and `actionlint` accept the rendered workflows, and `task validate`
  passes.
