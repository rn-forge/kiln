# S21.2.1 — `kiln-devops evidence render`

Brief for
[S21.2.1](../F21.2-evidence-page.md#s2121-kiln-devops-evidence-render), at
`feature/v1` `46f1bb96`.

## Goal

`task release:evidence -- <run-id> <n>` downloads a run's `security-evidence`
record and writes `docs/releases/release-<n>/security.md`: the release's
evidence page, which passes `task lint` and is the same file each time it is
rendered from the same record.

## Settled

### What exists (F21.1, closed)

- `src/rn_forge/kiln/devops/evidence.py` has `collect` and `table(record)`.
  `table` gives `| Control | Effect | Result | Evidence |` rows, the evidence
  cell `[detail](url)` or `detail`, `|` escaped. Reuse it; do not copy it.
- The record (`security-evidence.json`) is
  `{repository, commit, run, attempt, packages[{name, version, tag}], controls[{name, effect, result, evidence{url, detail}}]}`,
  controls in catalog order. `result` is `passed`, `failed`, `not run` or
  `not checked`.
- `github.api(path) -> (status, body)` reads the GitHub API through `gh api`.
- The `evidence` CI job uploads the record as the artifact `security-evidence`.
- `kiln-devops` imports only the standard library, `packaging` and
  `rn_forge.kiln.devops.*` (`tests/devops/test_boundary.py`).

### The command

In `cli.py`, the `evidence` parser gains `render`: `--run ID` (digits),
`--release N` (digits), `--releases DIR` (default `docs/releases`, checked with
`_inside(…, os.getcwd())` as `_check_umbrella` does). Handler `_evidence_render`
→ `evidence.render_page(...)`; any `ValueError` prints `kiln-devops: <reason>`
on stderr and exits 2; success exits 0 and prints the written path on stderr.

### Download

New in `github.py`:

```python
def download_artifact(run: int, name: str, dest: Path) -> bool:
    """Download artifact `name` of run `run` into `dest` with `gh run download`; return whether it succeeded."""
```

running `["gh", "run", "download", str(run), "-n", name, "-D", str(dest)]` with
`_capture`. In `evidence.py`:

```python
def render_page(run: int, release: int, releases: Path, today: date | None = None) -> Path:
    """Write the evidence page of `release` from run `run`'s record; return its path.

    Raises:
        ValueError: When `releases/release-<release>/index.md` does not exist, or
            the run has no `security-evidence` artifact.
    """
```

Order: check the release page exists (`ValueError(f"no release page {path}")`);
download into a `tempfile.TemporaryDirectory()`; when `download_artifact`
returns False or `security-evidence.json` is not in it,
`ValueError(f"run {run} has no security-evidence artifact")`. Nothing is written
before both checks pass.

### Filling `not checked`

Each control whose `result` is `not checked` is filled from one read,
`github.api("repos/{owner}/{repo}")`, using the caller's own `gh` login:
`body["security_and_analysis"]["secret_scanning_push_protection"]["status"]` →
`enabled` gives `passed`, `disabled` gives `failed`; with any other status, a
missing key (no admin rights) or a non-200 answer the row stays `not checked`. A
filled row's evidence is
`{"url": None, "detail": f"GET repos/{record['repository']} security_and_analysis, {today.isoformat()}"}`.
`today` defaults to `date.today()`; tests pass it. The record file itself is not
changed.

### The page

`docs/releases/release-<n>/security.md`, exactly (`<…>` filled in):

```markdown
# Release <n> — security evidence

|  |  |
| -- | -- |
| **Release** | [Release <n>](index.md) |
| **Repository** | <repository> |
| **Commit** | `<commit>` |
| **Run** | [<run>, attempt <attempt>](https://github.com/<repository>/actions/runs/<run>/attempts/<attempt>) |

Rendered by `task release:evidence` from the run's `security-evidence`
record. Do not edit it by hand.

Passing this baseline is not a claim that the release is secure.

<evidence.table(filled record)>
```

with one trailing newline. The two prose paragraphs are fixed text; if
`mdformat` (via `task format`) re-wraps them, change the line breaks in the
template, never the words. The page must be byte-identical when rendered twice
from the same record with the same `today`.

### The task

kiln renders a developer task file, the way `tasks/sonar.yml` is rendered only
when `[ci] sonar` is on:

- New template `src/rn_forge/kiln/modules/tasks/templates/tasks/release.yml.j2`
  (copy `sonar.yml.j2`'s header and shape):

    ```yaml
    # The release's evidence page, rendered only when `[ci.checks] release-evidence`
    # is on. Not a CI task: the owner runs it in the pull request that marks a
    # release shipped, so it is not under `ci:`.

    tasks:
      evidence:
        desc: "Render docs/releases/release-<n>/security.md from a run's security-evidence record (pass -- <run-id> <n>)."
        cmds:
          - 'set -- {{.CLI_ARGS}}; {{.DEVOPS}} evidence render --run "$1" --release "$2"'
    {% if docs %}      - task: :docs:generate
    {% endif %}
    ```

    (Variables use the engine's `[[ ]]`; `{{.CLI_ARGS}}` and `{{.DEVOPS}}` are
    go-task's and pass through, as in `sonar.yml.j2`.)

- `tasks/artifacts.py`:
  `TemplateArtifact("tasks/release.yml", enabled="release-evidence" in <the enabled checks>)`
  after `tasks/sonar.yml`; use the same enabled-checks value the `ci.yml`
  template's `checks` context key already holds.

- `Taskfile.yml.j2`:
  `{% if "release-evidence" in checks %}  release: tasks/release.yml\n{% endif %}`
  after the `sonar` include line (check the root template has `checks` in
  its context; if not, add it from the same value).

- `tasks/config.py`: `"release"` joins `GENERATED_NAMESPACES`.

Rejected (do not build): writing the page in CI or committing it; a root verb;
filling push protection from a token secret; changing the record file.

## Current behaviour

- `kiln-devops evidence render` exits 2 with argparse's
  `invalid choice: 'render'`; `evidence.render_page` and
  `github.download_artifact` do not exist, so the new devops tests fail at
  attribute lookup.
- With `release-evidence = true`, no `tasks/release.yml` is rendered and the
  Taskfile has no `release` include, so the task tests fail on a missing file.
- `release` is not in `GENERATED_NAMESPACES`; a repo `[tasks]` include named
  `release` is accepted today.
