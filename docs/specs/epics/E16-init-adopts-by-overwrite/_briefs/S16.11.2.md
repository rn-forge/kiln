# S16.11.2 — `kiln apply` records an edited key's new value and layer

Brief for
[S16.11.2](../F16.11-identity-follows-the-config.md#s16112-kiln-apply-records-an-edited-keys-new-value-and-layer),
at `e48c513`. Line references are at `e48c513`.

## Goal

After a key is edited in `config.toml`, the next `kiln apply` records it in
`state.json` `metadata.config_provenance` as
`{"layer": "repo", "value": <committed value>}`, not the stale value from the
layer that first supplied it.

## Settled

All settled by the owner on 2026-11-19.

- **Where.** `prepare` in `src/rn_forge/kiln/modules/core/cycle.py` (lines
  228-288). When `provenance is None`, it copies the previous state's
  `config_provenance` forward unchanged (lines 278-280). Change only that
  branch. Pass the carried-forward mapping through a new private helper,
  placed next to `prepare`:

    ```python
    def _refreshed(
        recorded: Mapping[str, JsonValue], document: Mapping[str, Any]
    ) -> dict[str, JsonValue]:
        """*recorded* provenance, with each key the committed *document* changed re-attributed to the repo."""
    ```

    For each `path, entry` in `recorded`: take
    `committed = DictUtils.flatten(document)` once. If `path` is in `committed`
    and `entry["value"] != committed[path]`, the result maps `path` to
    `{"layer": REPO_LAYER, "value": committed[path]}`. Otherwise it keeps
    `entry` unchanged. A path that is no longer in `document` is kept as it is.
    Import `REPO_LAYER` from `rn_forge.kiln.modules.core.config.manager` (line
    48), beside `PROVENANCE_KEY`. Import `DictUtils` from
    `rn_forge.commons.lang.collections`.

- **`document`** is the committed document `prepare` already has (line 247), or
  the rendered candidate (lines 249-251). Use the same variable in both cases.

- **Callers that pass `provenance`** (`kiln new`, `config-update`,
  `config-upgrade`) are unchanged: line 270's branch wins.

- **The docstring** of `prepare` gains one sentence: carried-forward provenance
  re-attributes a key whose committed value changed to the `repo` layer.

- **Test names** describe behaviour, with no spec ID.

## Current behaviour

- `prepare` copies `config_provenance` forward byte for byte, so after `owner`
  is edited from `rn-forge` to `rn-apps` and applied, `state.json` still
  records `repository.owner` as `{"layer": "flags", "value": "rn-forge"}`.
- `reresolve` (`manager.py:263-292`) already treats a committed value that
  differs from the recorded one as an override, so `config-update --dry-run`
  lists it both before and after this change.
- `tests/commands/test_config_lifecycle.py` has the `repo` fixture (line 83): a
  rendered `python-tool` with `owner = "rn-forge"`, applied, then
  `_seed_flags_provenance` records every committed key under the `flags`
  layer. `test_a_repo_override_survives_update_and_is_listed` (line 160) shows
  how to edit the config and read `config_update(dry_run=True, json=True)`
  through `_last_json`.
