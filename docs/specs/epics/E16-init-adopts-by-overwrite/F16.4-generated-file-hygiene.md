## S16.4.1 — The `.gitignore` block is grouped, and rendered per archetype (R3)

**State:** New

**Build — tests first,** in `tests/modules/core/test_gitignore.py`:

1. `test_s16_4_1_1_groups`: the block for `python-lib` with `docs = mkdocs` is,
   verbatim inside the markers:

    ```text
    # kiln's own state
    .rn-forge/kiln/backups/
    .rn-forge/kiln/rendered/
    .rn-forge/kiln/state.lock

    # macOS
    .DS_Store

    # Python tool caches
    .pytest_cache/
    .ruff_cache/
    .import_linter_cache/
    .uv-cache/

    # Coverage output
    .coverage
    .coverage.*
    coverage.xml

    # Docs build output ([docs] site_dir), and mkdocs's default
    .docs-site/
    site/
    ```

1. `test_s16_4_1_2_node_lib_has_no_python_groups`: `node-lib` has no
   `# Python tool caches` or `# Coverage output` group, and keeps the other
   groups.

1. `test_s16_4_1_3_no_docs`: `docs = none` has no docs group.

1. `test_s16_4_1_4_dedupe_ignores_comments`: `_dedupe_gitignore` still drops a
   repository line that a block line repeats, and ignores blank and comment
   lines.

**Build:** `modules/core/templates/gitignore.j2`: the groups above, each
preceded by its comment line and followed by a blank line, `{% if %}` on
`python` and on `docs` where noted. Pass `python` and `docs` into the render
context in `core/artifacts.py`. Run `kiln apply` here.

**Acceptance:**

- The four tests pass, and `task validate` passes.

## S16.4.2 — The dependency group is re-sorted on every write (R4)

**State:** New

**Build — tests first,** in `tests/modules/python/test_scaffold.py`:

1. `test_s16_4_2_1_add_task_tools_sorts_the_group`: a `dev` group
   `["pytest", "aiosqlite", "zebra"]` with `taplo` missing becomes, after
   `add_task_tools`, every entry sorted by normalized name (`aiosqlite`,
   `pytest`, `taplo`, `zebra`).
1. `test_s16_4_2_2_normalization`: `Foo_Bar` sorts as `foo-bar`; a version
   specifier does not change the order; entries keep their text.
1. `test_s16_4_2_3_include_group_tables_stay_last`: `{ include-group = "x" }`
   entries stay after the strings.
1. `test_s16_4_2_4_no_write_when_nothing_changes`: a sorted group with every
   tool present is byte-identical after the call.
1. `test_s16_4_2_5_comments_survive`: a comment on an entry stays with it.

**Build:** `modules/python/scaffold.py`: `add_task_tools` and the scaffold
writer sort each group they touch, by `rn_forge_deps.distribution(entry)`
(`canonicalize_name`). This is the owner's choice (2026-11-04) over uv's rule of
appending when a list is unsorted. `new` writes sorted groups already.

**Acceptance:**

- The five tests pass, and `task validate` passes.
