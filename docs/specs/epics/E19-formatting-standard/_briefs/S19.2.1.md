# S19.2.1 — `NAV_BLOCK` uses `end_indent`

Brief for
[S19.2.1](../F19.2-nav-block-end-indent.md#s1921-nav_block-uses-end_indent). It
is built **after S16.5.4 has merged**, from the `feature/v1` commit that carries
S16.5.4. Line references are at `019beea` unless they say otherwise.

## Goal

Delete the `_NavBlock` subclass and state the same `mkdocs.yml` nav markers with
`rn-forge-commons` 0.9.0's public `ManagedBlock.end_indent`. The rendered bytes
do not change.

## Settled

- `rn-forge-commons` 0.9.0 is on pypi.org (checked 2026-11-16).
- S16.5.4 has already moved kiln's own commons floor to `>=0.9.0,<0.10` and
  `uv.lock` to 0.9.0, and moved `RN_FORGE_TAGS` and the rendered floors. So
  the story's **Floors** paragraph and its build step 2 are already done: skip
  step 2, and leave `pyproject.toml`, `uv.lock`, `RN_FORGE_TAGS`,
  `standard.md.j2`, ADR-0018 and the floor tests as S16.5.4 left them.
- Nothing a template renders changes, so `task kiln:apply` has nothing to do,
  and no golden or `.rn-forge/kiln/state.json` moves.

## Current behaviour

- `src/rn_forge/kiln/modules/core/derived.py` defines `class _NavBlock` (a
  `ManagedBlock` subclass overriding the private `_marker`) and
  `NAV_BLOCK = _NavBlock("derived nav", indent="  ")`.
- After S16.5.4: `pyproject.toml` has
  `rn-forge-commons[pydantic,markdown,templates]>=0.9.0,<0.10` and `uv.lock`
  has commons 0.9.0. Confirm both before writing tests; if either is not so,
  stop and report.

## Change

1. Tests first (below), shown failing as stated.
1. `src/rn_forge/kiln/modules/core/derived.py`: delete `class _NavBlock`, its
   docstring and its `_marker` override. Replace
   `NAV_BLOCK = _NavBlock("derived nav", indent="  ")` with
   `NAV_BLOCK = ManagedBlock("derived nav", indent="  ", end_indent="")`. Keep
   the docstring below it, keep the `ManagedBlock` import (`DERIVED` uses it),
   and add nothing else.

## Tests first

Append to `tests/modules/core/test_derived.py`. Add `import tomllib`,
`from rn_forge.commons.fs.blocks import ManagedBlock` and
`from rn_forge.kiln.modules.core import derived` to its imports if absent.
`ROOT = Path(__file__).resolve().parents[3]`.

1. `test_s19_2_1_1_nav_block_is_a_plain_managed_block`:
   `type(NAV_BLOCK) is ManagedBlock`; `NAV_BLOCK.name == "derived nav"`;
   `NAV_BLOCK.indent == "  "`; `NAV_BLOCK.end_indent == ""`. Fails before:
   `type(NAV_BLOCK)` is `_NavBlock`.
1. `test_s19_2_1_2_the_markers_are_unchanged`:
   `NAV_BLOCK.begin == "  # BEGIN derived nav"` and
   `NAV_BLOCK.end == "# END derived nav"`. Passes before: it pins the bytes.
1. `test_s19_2_1_3_there_is_no_subclass`: the text of `Path(derived.__file__)`
   contains neither `_NavBlock` nor `_marker`. Fails before.
1. `test_s19_2_1_4_the_nav_block_renders_either_end_form`:
   `NAV_BLOCK.extract("nav:\n  # BEGIN derived nav\n- a\n# END derived nav\n")`
   and the same text with `  # END derived nav` both return `"- a\n"`.
   Passes before if the subclass already handles both; record which.
1. `test_s19_2_1_5_the_commons_floor_admits_end_indent`: `tomllib` reads
   `ROOT / "pyproject.toml"`; its one `project.dependencies` entry starting
   `rn-forge-commons[` ends with `>=0.9.0,<0.10`; and in `ROOT / "uv.lock"`
   the `[[package]]` named `rn-forge-commons` has
   `tuple(int(p) for p in version.split(".")) >= (0, 9, 0)`. Passes before,
   because S16.5.4 moved the floor.
