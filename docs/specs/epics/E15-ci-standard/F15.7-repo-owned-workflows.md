A repository may own a workflow file only for a non-gating or scheduled run
(pykit's `broker-profile.yml`). Its action pins need an updater, and kiln's own
pins must not be bumped from outside `pins.toml`. So Dependabot's
`github-actions` entry is rendered with an `ignore:` entry for every action in
`pins.toml`, and the standard states the rule.

## S15.7.1 — Dependabot watches the repository's own action pins

**State:** New

**Build — tests first,** in `tests/modules/cicd/test_artifacts.py`:

1. `test_s15_7_1_1_github_actions_entry`: every archetype's `dependabot.yml` has
   an update entry `package-ecosystem: github-actions`, `directory: "/"`, with
   the same `schedule`, `cooldown` and `groups` shape as the file's other
   entries.
1. `test_s15_7_1_2_ignore_covers_every_pin`: the entry's `ignore:` has one
   `dependency-name` for the `uses` value of every table in `pins.toml` that
   has one (for example `actions/checkout`), sorted, with no duplicate.
1. `test_s15_7_1_3_new_pin_is_ignored`: adding a table with `uses = "x/y"` to a
   copy of `pins.toml` adds `x/y` to the ignore list.

**Build:** `cicd/templates/dependabot.yml.j2`: the entry, with `ignore:` from a
context key `pinned_actions` (sorted `uses` values, from `load_pins()`). Entries
without `uses` (the `gitleaks` table) are skipped. Run `kiln apply` here.

**Acceptance:**

- The three tests pass, and `task validate` passes.
- `task lint KILN_DOCTOR_FULL=1` passes after `kiln apply`.
