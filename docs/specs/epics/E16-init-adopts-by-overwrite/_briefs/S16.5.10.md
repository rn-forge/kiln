# S16.5.10 — `kiln apply` refuses to render with a kiln the config does not pin

Brief for
[S16.5.10](../F16.5-rebuild-and-port.md#s16510-kiln-apply-refuses-to-render-with-a-kiln-the-config-does-not-pin),
at `feature/v1` after `bf5538e`.

## Goal

`kiln apply` (and `kiln apply --dry-run`) runs the `kiln-pin` check before it
plans anything. When the check reports `kiln.pin-mismatch`, apply raises an
`AppException` naming the finding and `task kiln:pin -- <ref>`, and writes
nothing.

## Settled

- The check is `rn_forge.kiln.modules.core.checks.pin.check(config, root)`, used
  as is; its decisions (kiln's own repository, a missing pin, a matching tag
  or SHA, running from source) are not changed.
- Only `pin.MISMATCH` refuses. `pin.MISSING` (a warning) does not.
- The refusal applies with and without `--dry-run`.
- Rejected (do not build): handing off to the pinned kiln from `apply`; changing
  the generated Taskfile's `KILN` var.

## Current behaviour

- `src/rn_forge/kiln/commands/apply.py:34` calls `cycle.prepare` with no pin
  check. The pin check runs only inside
  `post=lambda: output.fail_on_errors(root)` (line 42), after the files are
  written, and `cycle.execute` skips `post` on a dry run
  (`modules/core/cycle.py:227`).
- So with a SHA pin other than the installed commit: `apply(dry_run=True)` does
  not raise (test 1's `pytest.raises` fails with "DID NOT RAISE"); `apply()`
  writes first (at least `Taskfile.yml`, whose `KILN` var embeds the ref, and
  `state.json`), and any error it then raises is the generic
  `"<n> check(s) failed in <root>"`, which names neither `task kiln:pin` nor
  leaves the tree unchanged.
- `pin.check` returns `[]` when kiln runs from source (`running_install()` is
  `None`), so the tests must use the `fake_install` fixture
  (`tests/conftest.py:463`; installed commit `INSTALLED_COMMIT`) as
  `tests/modules/core/checks/test_pin.py` does, with `kiln_remote_sha` as a
  SHA the local kiln remote knows.

## Change

- **Change:** in `src/rn_forge/kiln/commands/apply.py`:
    - Import `KilnConfig` from `rn_forge.kiln.config` and `pin` from
      `rn_forge.kiln.modules.core.checks`.

    - Add a private helper, called in `apply` right after `root` is found and
      before `cycle.prepare`:

        ```python
        def _refuse_other_kiln(root: Path) -> None:
            """Refuse to render when `[kiln] ref` pins a kiln other than the running one."""
            config = KilnConfig.load(root)
            for finding in pin.check(config, root):
                if finding.code == pin.MISMATCH:
                    raise AppException(
                        "{}: {} — run `task kiln:pin -- {}` to render with the kiln it pins",
                        finding.code,
                        finding.message,
                        config.kiln_pin.ref,
                    )
        ```

        (`config.kiln_pin` is never `None` when `MISMATCH` is reported; narrow it
        for the type checker if pyright asks, e.g. an `assert`, not a new branch.)

    - Add the case to `apply`'s `Raises:` docstring: "the config's `[kiln] ref`
      pins a kiln other than the running one".
- **Leave alone:** `modules/core/checks/pin.py`, `modules/core/cycle.py`,
  `commands/output.py`, every template, every generated file, and every spec
  page except this brief's `## Result`.

1. `test_apply_refuses_when_the_config_pins_another_kiln`: call `fake_install()`
   (installed commit `INSTALLED_COMMIT`), set `[kiln] ref` to
   `kiln_remote_sha`, take `before = snapshot(repo)`; parametrize over
   `dry_run` in `(False, True)`; `commands.apply(dry_run=dry_run)` raises
   `AppException` whose message contains `kiln.pin-mismatch` and
   `task kiln:pin -- <kiln_remote_sha>`; `snapshot(repo) == before`. Fails now
   as **Current behaviour** says.

   `fake_install(kiln_remote_sha)`, set `[kiln] ref` to `kiln_remote_sha`;
   `commands.apply()` does not raise. Passes now; it guards the matching case.
