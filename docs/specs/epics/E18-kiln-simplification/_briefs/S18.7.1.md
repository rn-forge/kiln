# S18.7.1 — `KilnConfig` answers the archetype questions

Brief for
[S18.7.1](../F18.7-one-owner-per-concept.md#s1871-kilnconfig-answers-the-archetype-questions),
at `42f821f`. The feature page's line numbers are at `6b3549b` and are stale;
use the ones here. Paths are under `src/rn_forge/kiln/`.

## Goal

Every module reads the config's sections, its archetype tests, its API member
names and its distribution-to-module conversion from `KilnConfig` (or one core
helper), instead of re-deriving them. Every copy keeps its current answer. No
rendered file changes.

## Settled

- **Section accessors on `KilnConfig`** (`config.py`), each a property returning
  the typed section or its default, which equals today's fallback:
  `ci -> CiConfig` (default `CiConfig()`), `docs -> DocsConfig`
  (`DocsConfig()`: profile `none`, site_dir `.docs-site`, as today),
  `tasks -> TasksConfig` (`TasksConfig()`, from `modules/tasks/config.py`).
  Two more, which the acceptance needs because their sections are also read by
  `getattr` (lead's ruling, 2026-11-17): `kiln_pin -> KilnPin | None` (from
  `modules/core/config/schema.py`, `None` when unset, as callers test today)
  and `archetype_section -> ArchetypeConfig | None`. The existing properties
  (`docs_profile`, `release`, `packages`, `module`, …) use them, so
  `getattr(self.document` appears once per section, inside its accessor.
- **`docs_packages`**:
  `self.packages if self.archetype == "python-lib" else ()`.
- **Archetype tests**: `is_workspace` (`python-lib`), `is_web` (`python-web-api`
  or `python-web-app`), `is_web_app` (`python-web-app`), `is_node_lib`
  (`node-lib`).
- **`api_package`** (`f"{name}-api"` for a web archetype, else `None`) and
  **`api_module`** (`module_name(api_package)`, else `None`), beside
  `api_dir`.
- **`module_name(distribution)`** in a new `modules/core/names.py`, returning
  `distribution.replace("-", "_")`. It replaces `python/artifacts.py`'s
  `root_package`, which is deleted; callers and tests import `module_name`.
- **`web_project`** on `KilnConfig`: `Path(web_dir).name` when `web_dir` is set,
  else `None`, which is what `tasks` uses today. `cicd` keeps its `"web"`
  constant (`modules/cicd/artifacts.py:32`). A test pins both answers until
  F18.10 makes them one.
- Left alone: `devops/uv.py:80` and `archetypes/__init__.py:116` (not a
  distribution name), and archetype tests on a bare `archetype: str` parameter
  (`cicd/config.py:285`, `cicd/registry.py`), which have no `KilnConfig`.

## Change

1. Write the tests (below) and show them failing as stated.
1. Add the accessors and helpers as settled; move `config.py`'s ten internal
   `getattr` uses onto them.
1. Replace every copy listed under **Current behaviour** with the owner. Delete
   `root_package` and each module-local helper that only wrapped a `getattr`
   (`tasks/artifacts.py` `_tasks_config`, `cicd/artifacts.py` `_ci_config`).
   Allowed existing-test edit: `tests/modules/python/test_starter.py` imports

   `modules/tasks/config.py` and `modules/core/config/schema.py`;
   `.importlinter` already ignores
   `rn_forge.kiln.config -> rn_forge.kiln.modules.**`. If an import cycle
   appears, import inside the property, as `load` does, with the same comment.

## Tests first

New file `tests/test_config_owners.py`, using the `write_config` helper from
`tests/conftest.py` (`from tests.conftest import write_config`) to build roots:

1. `test_s18_7_1_1_only_config_reads_the_document_by_getattr`: no `*.py` under
   `src/rn_forge/kiln/` other than `config.py` contains
   `getattr(config.document` or `getattr(self.document`. Fails before, naming
   the eleven files above.
1. `test_s18_7_1_2_sections_default_as_today`: for a `python-tool` config with
   no `[ci]`, `[docs]` or `[tasks]`, `config.ci == CiConfig()`,
   `config.docs == DocsConfig()`, `config.tasks == TasksConfig()`, and
   `config.kiln_pin` is what the file declares. Fails before with
   `AttributeError`.
1. `test_s18_7_1_3_archetype_answers`, parametrised over the six archetypes,
   each root written with `write_config(root, archetype, name="demo", …)` and
   the backend or frontend its archetype requires: `is_workspace`, `is_web`,
   `is_web_app`, `is_node_lib`, `docs_packages`, `api_package` and
   `api_module` each give the expected value (`demo-api`/`demo_api` for the
   web cells, `None` otherwise). Fails before with `AttributeError`.
1. `test_s18_7_1_4_module_name_is_the_one_conversion`:
   `module_name("rn-forge-cli") == "rn_forge_cli"`, and
   `rn_forge.kiln.modules.python.artifacts` has no `root_package`. Fails
   before with `ImportError`.
1. `test_s18_7_1_5_web_project_keeps_both_answers`: a `python-web-app` config
   with `web_dir = "apps/portal"` gives `config.web_project == "portal"`,
   while `rn_forge.kiln.modules.cicd.artifacts._WEB_PROJECT == "web"`. A
   comment says F18.10 makes them one. Fails before with `AttributeError`.
