`main` takes one squashed commit for a clean history, and `feature/v1` is kept
for reference. The release-1 tag
([F7.2](../E7-pykit-release-pin-flip/F7.2-kiln-release-and-config-upgrade.md))
is cut from `main` after this. Every step needs the owner's approval, because
pushing to `main` is outward-facing and hard to reverse.

## S18.4.1 — `feature/v1` is frozen and pushed

**State:** New

**Acceptance:**

- No other session is working in the checkout, and no worktree or branch with
  unmerged work is based on `feature/v1`, or each is listed with the owner's
  call on it.
- The working tree is clean, and `origin/feature/v1` is `feature/v1`'s `HEAD`.
- `task validate` passes at that `HEAD`, and CI is green on it.

## S18.4.2 — One commit on `main`

**State:** New · **Depends on:** S18.4.1

**Acceptance:**

- `main` is `initial commit` plus one commit whose tree is identical to
  `feature/v1`'s `HEAD`. Its message summarises v1 and names `feature/v1` as
  the full history.
- `origin/main` is that commit, and CI and Sonar are green on it.
- `feature/v1` is still on `origin`, unchanged.

## Acceptance

```bash
set -euo pipefail
git fetch origin
test "$(git rev-parse origin/feature/v1)" = "$(git rev-parse feature/v1)"           # S18.4.1
test "$(git rev-list --count origin/main)" -eq 2                                    # S18.4.2
git diff --exit-code origin/main origin/feature/v1                                  # S18.4.2: same tree
```

Not scripted: no other session is working in the checkout (S18.4.1), and CI and
Sonar are green on `main` (S18.4.2).
