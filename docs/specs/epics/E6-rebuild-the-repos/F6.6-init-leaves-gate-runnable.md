After `kiln init`, an adopted repository can run its own gate: `config.toml`
passes kiln's TOML lint, the tools the rendered tasks run are in its dependency
groups, and the adopt prompt and a runbook say what is left to the adopter,
`task format` and the `[kiln] ref` pin included. Today `init` writes a
`config.toml` that kiln's own lint rejects, leaves out `taplo`, and nothing in
kiln's docs says how a developer is meant to use the prompt.

## Context

Revised 2026-10-26 for
[F7.4](../E7-pykit-release-pin-flip/F7.4-kiln-runs-beside-the-repository.md):
kiln no longer lives in any repository's dependency groups. A repository pins it
with `[kiln] ref`, `kiln init` writes that pin, and `kiln.pin-missing` and
`deps.kiln-in-lock` check it. The `rn-forge-kiln` rows below are the 2026-10-19
findings, kept as found; S6.6.2 and S6.6.3 no longer act on them.

Found 2026-10-19 by the owner. `kiln init --force` was run from the kiln working
tree (`feature/v1`, after `1c6cfe2` S4.10.1) on pykit `feature/kiln-adoption`
(`69d79bf`), as `python-lib`, with nine packages and `import_contracts = "own"`.

findings, all in pykit's `main.yml`: 20 `ci-entrypoint` (direct `uv` steps) and

in pykit's cutover.

**Owner decisions, 2026-10-19:**

- `init` adds each task tool the repository lacks to its dependency groups,
  rather than warning about it. `apply` still never edits `pyproject.toml`.
- `init` runs neither `task setup` nor `task format`. Reformatting the
  repository's own files is a separate commit made by the adopter, so `init`'s

  rule that kiln does not reformat repository-owned files stands.

  a new private function, `_multiline_arrays(container)`, that recurses into
  tables. Leave empty arrays (`includes = []`) inline. tomlkit's multi-line

  accepts, as `python/scaffold.py`'s `_multiline_lists` already relies on.
- `new`, `init` and `config-update` all write through `_write_config`

- Do not change `_report`'s console output.

**Acceptance:**

**What the build settled that the story did not say:**

  `kiln generate package`, which writes `config.toml` through
  `DocumentUtils.update` (`commands.py`, `generate package`) and not through

  fits in 80 columns. Left alone, since the story names no change to that
  command.
- F6.6's `State` went from `New` to `Active`, because `kiln docs-generate` fails
  while a story is `Closed` under a `New` feature; the derived regions follow.

In `tests/test_init.py`:

1. `test_s6_6_2_5_init_adds_missing_tools`. On `lib_repo`, delete `taplo` from
   the root `pyproject.toml`'s `dev` group, `_commit(lib_repo)`, then run
   `commands.init` as `test_s6_1_5_1_…` does. `dev` contains `taplo` again,
   and no group names `rn-forge-kiln`.
1. `test_s6_6_2_6_nothing_added_when_every_tool_is_present`. The same, with
   `pyproject.toml` left as `new` wrote it: the file is byte-identical after
   `init`.

**Build:**

- `src/rn_forge/kiln/modules/python/scaffold.py`:

    - A public tuple `TASK_TOOLS`, with the distributions the rendered
      `tasks/ci.yml`, `tasks/python.yml` and `tasks/quality.yml` run through
      `uv run`, in `_DEV_GROUP`'s spelling:
      `("actionlint-py", "import-linter", "pip-audit", "pyright", "pytest", "pytest-cov", "ruff", "taplo", "zizmor")`.
      All nine render for every archetype that has the `python` module, with
      no condition (`ci:lint:workflows` runs `zizmor` and `actionlint`;
      `python:lint:audit` runs `pip-audit`). Its docstring says these are the
      tools `task lint`, `task typecheck` and `task test` invoke. kiln is not
      listed: since F7.4 `{{.KILN}}` runs it with `uvx`, outside the
      repository's lock. `pyyaml` is in `_DEV_GROUP` but no task runs it, so it
      is not listed.
    - A public tuple `DOCS_TASK_TOOLS = ("mdformat",)`, which counts only when
      `config.docs_profile != "none"`. It belongs in the `docs` group, which
      `quality:lint:markdown` runs with `--group docs`.
    - A public function
      `missing_task_tools(root: Path, config: KilnConfig) -> list[str]`. It
      reads the root `pyproject.toml` and collects the normalized names
      (`rn_forge_deps.distribution`) of every string entry in every
      `[dependency-groups]` group, skipping `{ include-group = … }` tables. It
      returns, in tuple order, each tool from `TASK_TOOLS` (then
      `DOCS_TASK_TOOLS`, where they count) that is not among those names. A
      missing `[dependency-groups]` table means every tool is missing.
    - A public function
      `add_task_tools(root: Path, config: KilnConfig) -> list[str]`. It appends
      each name `missing_task_tools` returns, bare and without a version, as
      `_DEV_GROUP` writes them: a `DOCS_TASK_TOOLS` name to the `docs` group,
      every other to `dev`. It creates either group when absent. It edits
      through `DocumentUtils.read_document` and `DocumentUtils.write_document`
      so comments survive, then calls `_multiline_lists`, and returns the names
      it added. With nothing missing it does not write the file.
    - Add all four names to `__all__`.

- `src/rn_forge/kiln/commands.py`, `init`: right after the
  `generate.generate(...)` branch, when `"python"` is in
  `archetypes.for_config(resolved).modules`:

    - Call `add_task_tools(root, resolved)`. For a non-empty result,
      `console.info("added {} to pyproject.toml's dependency groups", ", ".join(added))`.

    `init` already writes `[kiln] ref` through `_resolve_config` (S7.4.1), so it
    adds nothing for kiln and prints no kiln warning.

- Do not change `apply`. Do not add a doctor check. `deps.kiln-in-lock` and
  `kiln.pin-missing` already cover kiln (S7.4.2, S7.4.3).

**Acceptance:**

- The six tests pass, and `task validate` passes.
- `task self:golden:compare BASE=HEAD~1` shows no change. `new` already writes
  every tool, so `add_task_tools` adds nothing in any cell.
- Re-running `init` on pykit adds `taplo` to `dev`, and writes `[kiln] ref`.

**What the build settled that the story did not say:**

- `scaffold.py` may not import `tomlkit` (the import-linter contract "imports no
  YAML, TOML or Markdown parser directly"), so `add_task_tools` edits the
  round-trip document from `DocumentUtils.read_document` and creates a missing
  table or group by assigning `{}` or `[]`, which tomlkit converts.
- `missing_task_tools` imports `distribution` from
  `modules/python/checks/rn_forge_deps.py`, and casts each group to
  `list[object]`, because `DictUtils.as_mapping` types its values as `object`.
- `init` calls `add_task_tools` after the `generate.generate` branch and before
  `_fail_on_errors`, so a repository that lacked a tool is fixed before the
  closing check runs.
- Tests 1 to 4 are parametrized over `_TAPLO_CELLS`, as the story asked, which
  repeats the `python-lib` root for its member row; the checks run on the root
  `pyproject.toml` in every case. Test 2 plants a comment on the `dev` group
  and asserts it survives. Tests 5 and 6 pass `--config` with the two `lib-*`
  packages, as `test_s6_1_5_1_…` does.
- `task self:golden:compare BASE=HEAD` (not `HEAD~1`, the story's line) reports
  every file unchanged, since the working tree holds the change uncommitted.
- The acceptance line "Re-running `init` on pykit" was not run: it needs a pykit
  checkout, and is the owner's.
