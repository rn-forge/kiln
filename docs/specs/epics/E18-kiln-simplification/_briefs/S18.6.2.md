# S18.6.2 — One module per command

Brief for [S18.6.2](../F18.6-commands-package.md#s1862-one-module-per-command),
at `7615239`. Line references are to `src/rn_forge/kiln/commands/__init__.py` at
that commit unless they name another file.

## Goal

Split `commands/__init__.py` (935 lines) into one module per command, each
followed by its own helpers; retire `src/rn_forge/kiln/doctor.py`; and empty the
`ALLOWED` list in `tests/suite/test_commands_surface.py`. No command's flags,
output, exit code or message changes.

## Settled

  where a rename is given.

- **`pin` goes to `config.py`** (lead's ruling, 2026-11-17): the story's table
  does not place it, and it rewrites the config.

- **`doctor.full` goes to `commands/doctor.py`, not into `checks.py`** (lead's
  ruling, recorded on the feature page). `full` imports `cycle`, which loads
  the generation engine, and `tests/suite/test_checks_are_render_free.py`
  keeps `rn_forge.kiln.checks` free of it. In `.importlinter`, the repo-owned
  contract `kiln-never-imports-devops` (below the `# END rn-forge kiln`
  marker, so a hand edit is allowed) drops `rn_forge.kiln.doctor` from
  `source_modules`, and `tests/test_import_contracts.py:89-99` drops
  `"doctor"` from its expected list.

- **`_write_config` and `_CONFIG_HEADER` move to
  `src/rn_forge/kiln/modules/core/config/catalog.py`** as
  `write(directory, config)` and `CONFIG_HEADER`, beside `render`, and join
  its `__all__`. `catalog.py` already imports `rn_forge.kiln.config`, so it
  imports `CONFIG_PATH` from there. **`CONFIG_HEADER`'s text stays byte for
  byte, including "(kiln ADR-0004)"**: it is written into every repository's
  `config.toml`, so it is output, not a docstring.

- **`commands/__init__.py` keeps only re-exports**: a one-line module docstring,
  `from rn_forge.kiln.commands.<module> import <command>` for each public
  command, and today's `__all__` (`:66-79`). Because four re-exported
  functions share a name with their module (`new`, `doctor`, `apply`, `diff`),
  `from rn_forge.kiln.commands import new` yields the **function**. Code and
  tests that need a module's other names import them by module path:
  `from rn_forge.kiln.commands.new import FLAG_NAMES, flag_layer`.

- **The only edge between command modules is `new.py` importing
  `generate.add_package`.** Every module may import `output`.

- **Scaffold steps are imported as modules**, and called through them:
  `from rn_forge.kiln.modules.python import scaffold as python_scaffold`,
  `from rn_forge.kiln.modules.node import scaffold as node_scaffold`,
  `from rn_forge.kiln.modules.instructions import scaffold as instructions_scaffold`,
  `from rn_forge.kiln.modules.docs import scaffold as docs_scaffold`. So a
  test patch at the definition module reaches `new` and `add_package`. In
  `generate.py`, import the docs generator as
  `from rn_forge.kiln.modules.docs import generate as docs_generator`, since
  the module itself is named `generate`.

- **CLI targets name the new modules**, e.g.
  `rn_forge.kiln.commands.doctor:doctor`,
  `rn_forge.kiln.commands.generate:generate_app`,
  `rn_forge.kiln.commands.config:pin`. They change in both
  `src/rn_forge/kiln/cli.toml` and `.rn-forge/kiln/config.toml`
  (`test_packaged_surface_matches_repo_config` holds them equal);
  `config.toml` is the hand-authored input, so edit it, then run
  `task kiln:apply`.

- **Docstrings keep the contract only** (README.md). Drop: the module
  docstring's design paragraphs (`:3-10`); "(kiln ADR-0004)" at `:222`,
  `:418`, `:556` and `:832`; the `typer.Argument` notes at `:590-594` and
  `:654-657`.
