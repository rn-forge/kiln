# S18.1.4 — A new story-named test fails the gate

Brief for
[S18.1.4](../F18.1-tests-named-by-behaviour.md#s1814-a-new-story-named-test-fails-the-gate),
built **after S18.1.1, S18.1.2 and S18.1.3 have merged**. Read the feature
page's properties first.

## Goal

`task validate` fails when a test function is named after a story, or when a
test module's docstring or comment carries a feature or story ID, naming the
file, the function or line, and the rule. The story-building guide stops asking
for story-named tests.

## Settled

Reviewer, 2026-11-17:

- **Where:** a new suite test module, `tests/suite/test_test_names.py`, beside
  the other meta-tests (`tests/suite/test_shared_parsing.py` is the shape to
  copy: `ast` over files, a list of offenders, `assert offenders == []`). No
  pytest hook in `tests/conftest.py`, and no `kiln doctor` check: the rule is
  this repository's, not the standard's.

- **What it scans:** every `*.py` file under `tests/` (resolved from the test
  module's own path, `Path(__file__).parents[1]`), skipping `__pycache__`.

- **Rule 1, names:** a function (`ast.FunctionDef` or `ast.AsyncFunctionDef`, at
  any depth, including methods) whose name matches `^test_s[0-9]+_`. Offender
  text: `<path relative to tests/>::<name>`.

- **Rule 2, docstrings and comments:** a module, class or function docstring
  (`ast.get_docstring`), or a `#` comment (`tokenize`, `COMMENT` tokens), that
  matches `\b(F[0-9]+\.[0-9]+|S[0-9]+\.[0-9]+\.[0-9]+(\.[0-9]+)*)\b`. Epic IDs
  (`E<n>`) are not checked, because `# noqa: E731` would match. String
  literals other than docstrings are test data and are not checked. Offender
  text: `<path relative to tests/>:<line>`.

- **Message:** each assert carries the rule, so a failure reads, for example,
  `tests are named for the behaviour they prove, test_<subject>_<behaviour>, with no spec ID: ['modules/x/test_y.py::test_s1_2_3_z']`
  and
  `test docstrings and comments carry no feature or story ID: ['modules/x/test_y.py:12']`.

- **Scanners are functions** in the module,
  `story_named_tests(root: Path) -> list[str]` and
  `spec_ids_in_prose(root: Path) -> list[str]`, so the tests can run them on a
  `tmp_path` tree.

- **The guide:** step 2 of "Building a story" in `docs/specs/index.md` becomes:

    ```markdown
    1. Write the tests first, in the file the story names, each named for the
       behaviour it proves, `test_<subject>_<behaviour>`, with no spec ID in its
       name, docstring or comments. Every acceptance item a script can check is a
       test, so `task validate` is the whole scripted check. An item no script
       can check is listed as not scriptable, with who judges it.
    ```

## Tests first

In `tests/suite/test_test_names.py`:

1. `test_a_story_named_test_is_reported`: a `tmp_path` tree with `a/test_x.py`
   holding `def test_s1_2_3_thing(): ...` and `def test_thing_works(): ...`,
   and a class method `def test_s4_5_y(self)`; `story_named_tests(tmp_path)`
   returns exactly the two story-named entries.
1. `test_a_spec_id_in_a_docstring_or_comment_is_reported`: a tree whose module
   docstring says `"""S1.2.3 — x."""`, with a `# since F4.5` comment, a
   `# noqa: E731` comment, and a string literal
   `"specs/epics/E1-x/F1.1-a.md"`; `spec_ids_in_prose(tmp_path)` returns the
   docstring's and the `F4.5` comment's lines only.
1. `test_no_test_is_named_after_a_story`: `story_named_tests(TESTS) == []`, with
   the rule message.
1. `test_no_test_prose_carries_a_spec_id`: `spec_ids_in_prose(TESTS) == []`,
   with the rule message.
