# ADR-0020 — Agent instructions live in AGENTS.md

**Status:** accepted (2026-11-10) · **Scope:** the instruction files of every
generated repository, and kiln's

## Decision

The instruction files are split **by audience**. Each prose paragraph has one
home, and a file that needs another file's content imports or links it.

- **`README.md`** is for humans and developers: what the repository is, how to
  set it up, how to work in it, and the conventions everyone follows. It
  carries no directive addressed to an agent.
- **`AGENTS.md`** is the canonical agent-instruction file, because it is the
  cross-tool convention that Codex, Copilot, Cursor and others read. It holds
  rules, guardrails, do and don't lists, worked examples and the story
  workflow, and links to `README.md` for context instead of restating it.
    - Its body is **repository-owned**, seeded once by `kiln new`.
    - **kiln's fenced block lives here**, and nowhere else.
    - A later agent tool (agentkit, when it exists) adds its own fenced block to
      this file. It does not own the file: a repository's own rules must stay in
      the repository. kiln seeds no empty fence for it.
- **`CLAUDE.md`** is repository-owned and carries no kiln block. It is seeded as
  an `@AGENTS.md` import line plus a short "Claude-only" section for what
  other agents should not read. Claude Code loads an `@path` import
  mechanically, so the agent does not have to follow a pointer.

[ADR-0003](ADR-0003.md) holds unchanged: one owner per file or block, and no
paragraph restated in two files. The import is the mechanism that makes a second
reader of the same text possible without a second copy.

## Consequences

- `kiln apply` renders the block into `AGENTS.md`. A repository whose
  `state.json` records the block in `CLAUDE.md` is migrated by the apply that
  follows the upgrade: the engine removes the stale block from `CLAUDE.md` and
  inserts the new one in `AGENTS.md`, with no new migration code. The bodies
  of both files are repository-owned, so rewriting them is a step in that
  repository's own story.
- `CLAUDE.md` is no longer a block file, so it is recorded in
  `metadata.scaffolded`; `AGENTS.md` is a block file and is not.
- The `docs-structure` check accepts an `@path` import as a pointer, and the
  instruction file that carries the docs links is `AGENTS.md`.
- The standard, the reference and the seeded `docs/_structure.md` say which file
  is for which reader.
- A repository's agent rules move out of its `README.md`. For kiln that is a
  split of its own README
  ([F16.10](../specs/epics/E16-init-adopts-by-overwrite/F16.10-agent-instructions-in-agents-md.md)).
- pykit's and ngkit's cutover stories are rewritten to this model before they
  run.

## Alternatives considered

- **`README.md` as the single prose home (the status quo).** Agent directives
  and developer prose then share one file, so a rule meant for an agent is
  read by every human and a human's setup text is in the agent's context for
  nothing. Every instruction file also becomes a pointer, and a pointer works
  only if the agent follows it.
- **`CLAUDE.md` canonical, with `AGENTS.md` a pointer.** Rejected because Codex
  and the other tools that read `AGENTS.md` cannot import another file, so
  they would see a pointer and nothing else. The import works the other way
  round: Claude Code can import `AGENTS.md`.
- **agentkit owns the whole of `AGENTS.md`.** Rejected: a repository's own rules
  would then live in a file the repository does not own, and each edit would
  be drift. A tool contributes a fenced block; the body stays the
  repository's.
- **Two copies, kept in sync by a check.** Rejected by ADR-0003: a check that
  compares two copies is the cost of having made two.
