Added 2026-10-16 with the owner. Existing web applications of several flavours
are expected to move onto kiln, and most are too far from an archetype's shape
for `kiln init` to be the cheaper route. They are rebuilt: `kiln new` renders
the target repository, the old repository's source, tests, configuration and
docs are ported into it, and the result lands as a branch on the **old**
repository. kiln's part is a read-only inventory that is the same for every
flavour, and the rebuild route of the `adopt` prompt. The porting itself,
scripts included, is the agent's, following the prompt. No iteration yet: the
first application, and so the archetype cell the prompt is written against, is
the owner's to name (S6.5.3).

## Design

- **Two routes, one prompt.** `kiln prompt --name adopt` (S6.1.12) chooses: in
  place for a repository already in the archetype's shape, rebuild and port
  for the rest. Both end in the same place, a branch on the existing
  repository, reviewed as one diff.
- **The port's direction keeps the history.** The new repository is built in a
  staging directory and ported into, and its tree then replaces the old
  repository's on a branch. The old repository keeps its history, tags,
  issues, pull requests, remote and deployments; nothing is pushed to a new
  remote.
- **kiln owns only what is the same for every flavour.** kiln knows, for the
  target archetype, which file is managed, seeded, a block or
  repository-owned. Classifying the old repository's files against that is
  deterministic and reusable; mapping one flavour's layout, settings, routes
  and build onto kiln's is not, and is the prompt's.
- **A step becomes kiln code only when two ports repeat it.** The first port
  teaches the prompt; the second shows what is worth automating.

## Considered and rejected

- **A `kiln adopt --path <old repo>` command that brings everything in.** Each
  old repository is ported once, so code that maps one flavour onto kiln runs
  once and is maintained against every later kiln change; a command also makes
  kiln answerable for a port it cannot judge. Rejected 2026-10-16. kiln
  migrating application source stays outside its
  [scope](../E4-generator/design.md#scope-and-ownership).
- **Porting into the new repository's history.** It loses the old repository's
  history, tags and remote. Rejected 2026-10-16.

## S6.5.1 — `kiln diff --from <old repo>`: the port's inventory

**State:** New

Run in the staged new repository. Writes nothing. For each file of the old
repository (Git-tracked, at its path), one class:

- `replaced` — the new repository has a managed file there: kiln's replaces the
  old one, whose content is read for anything to keep;
- `block` — kiln owns a block there: the old content stays outside it;
- `seeded` — the new repository seeded one: the old content goes into it;
- `unmatched` — no counterpart: the port decides where it goes.

`--json` gives one row per file with its class and the new repository's artifact
key. Elaborated when the feature is scheduled.

**Acceptance:**

- On a fixture old repository holding one file of each class, `--json` reports
  each class once and writes nothing.

## S6.5.2 — `kiln prompt adopt` gains the rebuild route

**State:** New · **Depends on:** S6.5.1

The rebuild section of the prompt: render with `kiln new` in staging; take the
inventory; port by class, the source and tests by the target cell's layout, the
specs and decisions by `port-docs`; run the gate in staging; land the tree as a
branch on the old repository.

**Acceptance:**

- `kiln prompt --name adopt` prints the rebuild route, and its test checks the
  section's headings.

## S6.5.3 — The first web application is ported

**State:** New · **Depends on:** S6.5.1, S6.5.2

The owner names the repository and its target archetype cell. An agent given
only `kiln prompt --name adopt` ports it.

**Acceptance:**

- The branch on the old repository passes `task validate` and
  `kiln doctor . --full`.
- Every step where the prompt was not enough is recorded here and fixed in the
  prompt; every step repeated with an earlier port is proposed as kiln code.
