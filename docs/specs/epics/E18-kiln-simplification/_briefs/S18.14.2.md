# S18.14.2 — `kiln pin` moves to a branch's newest commit

Brief for
[S18.14.2](../F18.14-a-pin-is-a-commit.md#s18142-kiln-pin-moves-to-a-branchs-newest-commit),
built **after S18.14.1 has merged**. Read the feature's **Design**, including
the decisions dated 2026-11-17. Paths are under `src/rn_forge/kiln/`.

## Goal

`kiln pin <branch>`, `kiln pin <tag or SHA>` and `kiln pin` write `ref` and
`track` as the Design says. `kiln pin` works on a repository whose `ref` is
still a branch. The rendered `kiln:pin` task takes no argument and re-renders
with the commit it pins.

## Settled

- **`commands/config.py` `pin(ref: str = "", show: bool = False)`**:
    - It reads and writes `.rn-forge/kiln/config.toml`'s `[kiln]` table as a TOML
      document (`DocumentUtils.read_document`/`write_document`, or
      `DocumentUtils.update`), **without** loading or validating the rest of the
      config. That is how a branch-ref repository migrates (owner's decision).
      It keeps the file's other keys, comments and order.
    - `kiln pin <tag>` (`kiln_ref.TAG`) or `kiln pin <sha>` (`kiln_ref.SHA`):
      write `ref`, remove `track`. A tag is checked with `kiln_ref.resolve`, so
      an unknown tag is an error; a SHA is written as given.
    - `kiln pin <branch>` (anything else): `sha = kiln_ref.resolve(branch)`, then
      write `ref = sha` and `track = branch`.
    - `kiln pin` with no argument: read `track`; if there is none, raise
      `AppException("kiln.track-missing: no [kiln] track to follow — pass a branch, tag or SHA")`;
      otherwise resolve it and write `ref` as for a branch.
    - Every error is raised before anything is written.
    - `kiln pin --show` prints the current `ref` (a bare line, `console.print`)
      and writes nothing.
    - It prints `kiln ref <old> → <new>` as today (`console.info`).
- **The rendered task** (`modules/tasks/templates/tasks/kiln.yml.j2`, the `pin`
  task, rendered only when `not kiln_own`): drop the `CLI_ARGS` precondition
  and the first `uvx … kiln version` step. Then
  `'{{.KILN}} pin {{.CLI_ARGS}}'`, then
  `'uvx --from "rn-forge-kiln @ [[ kiln_git ]]@$({{.KILN}} pin --show)" kiln apply'`.
  Update its `desc` and the comment line above `vars:` to say it pins a
  branch's newest commit, a tag or a SHA, and with no argument follows
  `track`. This changes rendered files, so run `task kiln:apply` on this
  repository; kiln's own repo renders no `pin` task (`kiln_own`), so expect no
  change here, and check the goldens with `task self:golden:render`.
- **Tests** use S18.14.1's local-remote fixture. To move the branch, commit to
  the fixture repository's `feature/v1` in the test, then `kiln pin` with no
  argument must pick up the new SHA.

## Current behaviour

After S18.14.1: `pin(ref)` loads the whole config with `ConfigManager().load`,
so it refuses a branch-ref repository, and it writes `ref` only. The rendered
task requires an argument and installs `@<arg>` twice.

## Change

1. Write the tests (below) and show them failing.
1. Rewrite `pin` and the template as settled.

## Tests first

In `tests/test_pin.py`, using the local-remote fixtures and a repository built
with `write_config` (run each through `commands.pin`, with `cwd` at the root):

1. `test_s18_14_2_1_a_branch_pins_its_newest_commit`: `pin("feature/v1")` writes
   `ref = <sha>`, `track = "feature/v1"`.
1. `test_s18_14_2_2_a_tag_or_sha_drops_track`: from a tracked pin,
   `pin("v0.0.1")` writes `ref = "v0.0.1"` and no `track`; `pin(<sha>)`
   likewise.
1. `test_s18_14_2_3_no_argument_follows_track`: after a new commit on the
   fixture's `feature/v1`, `pin()` writes the new SHA.
1. `test_s18_14_2_4_errors_write_nothing`: `pin()` with no `track`,
   `pin("no-such-branch")` and `pin("v9.9.9")` each raise and leave
   `config.toml` byte-identical.
1. `test_s18_14_2_5_a_branch_ref_repository_migrates`: a config whose `ref` is
   `"feature/v1"` (which S18.14.1 refuses at load) is moved by
   `pin("feature/v1")` to the SHA, and then loads.
1. `test_s18_14_2_6_show_prints_the_ref`: `pin(show=True)` prints the `ref` and
   writes nothing.
1. In the tasks tests: `test_s18_14_2_7_the_pin_task_takes_no_argument`: the
   rendered `tasks/kiln.yml` for a non-kiln repository has no `CLI_ARGS`
   precondition on `pin` and ends with the `pin --show` apply step.

Each fails before.
