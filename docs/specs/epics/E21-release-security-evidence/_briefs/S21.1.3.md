# S21.1.3 — An `evidence` job runs it

Brief for [S21.1.3](../F21.1-evidence-record.md#s2113-an-evidence-job-runs-it),
at `feature/v1` `1797912f`.

## Goal

`[ci.checks] release-evidence = true` renders the repository's control catalog
as `.rn-forge/kiln/security-controls.json`, a `ci:release:evidence` task that
runs `kiln-devops evidence collect` on it, and an `evidence` job in `ci.yml`
that runs the task after `release` and `verify-release` on a push to `main`,
uploads `security-evidence.json` as the artifact `security-evidence`, and writes
the table to the job summary.

### The controls file

- In `src/rn_forge/kiln/modules/cicd/controls.py`, add (and export)
  `LINT_JOB = "validate"`, `LINT_STEP = "Validate"`, and:

    ```python
    def manifest(enabled: frozenset[str], release: str) -> dict[str, object]:
        """The controls file `kiln-devops evidence collect` reads, for a repository running *enabled* checks."""
    ```

    It returns `{"generated": GENERATED, "release": release, "controls": [...]}`,
    one entry per control in `CONTROLS` order:
    `{"name", "effect": effect.value, "source": source.value, "runs": ...}`,
    plus `"job": LINT_JOB, "step": LINT_STEP` for `Source.LINT_JOB`, and for
    `Source.JOB` `"job"` = the registry `job` of the control's first check
    (`secret-scan`). `runs` is `True` for a control with no `checks`, else
    whether any of its checks is in *enabled*.

- `GENERATED` is the provenance line, as the first key because JSON has no
  comments:
  `f"Generated by kiln {__version__} from .rn-forge/kiln/config.toml — do not edit; run 'kiln apply'"`
  (the text every kiln header uses; import `__version__` from
  `rn_forge.kiln`).

- `render` appends, when `"release-evidence" in checks`,
  `Artifact(".rn-forge/kiln/security-controls.json", ArtifactKind.MANAGED, json.dumps(controls.manifest(checks, release), indent=2, ensure_ascii=False) + "\n")`
  (the shape of `src/rn_forge/kiln/modules/python/artifacts.py:50`). Use the
  resolved `release`, not `ci.release`. The file's shape is the one
  `kiln-devops evidence collect --controls` reads (S21.1.2); do not change it.

### The task

In `src/rn_forge/kiln/modules/tasks/templates/tasks/ci.yml.j2`, right after the
`release:umbrella` block and gated the same way:

```yaml
{% if "release-evidence" in checks %}
  release:evidence:
    desc: "CI only: Write security-evidence.json for this run and print its table to the job summary."
    cmds:
      - '{{.DEVOPS}} evidence collect --run "$GITHUB_RUN_ID" --attempt "$GITHUB_RUN_ATTEMPT" --sha "$GITHUB_SHA" --controls .rn-forge/kiln/security-controls.json >> "$GITHUB_STEP_SUMMARY"'
{% endif %}
```

### The job

In `src/rn_forge/kiln/modules/cicd/templates/ci.yml.j2`:

- `postrelease_needs()` gains
  `{%- if "release-evidence" in checks %}, evidence{% endif -%}` after the
  umbrella line, so `ci-ok` waits for it.

- After the `umbrella` job block, a new block gated on
  `{% if "release-evidence" in checks %}`:

    ```yaml
      # The release's security evidence: each control's result on this commit,
      # read from the run and the registry's API. A failed control does not fail
      # this job; the job that ran it already failed.
      evidence:
        needs: [release, verify-release]
        if: ${{ !cancelled() && github.event_name == 'push' && github.ref == 'refs/heads/main' }}
        runs-on: ubuntu-latest
        timeout-minutes: 10
        permissions:
          contents: read
          actions: read
          attestations: read
        steps:
          - name: Checkout
            uses: <checkout pin>
            with:
              persist-credentials: false

          - name: Set up the toolchain
            uses: ./.github/actions/setup # zizmor: ignore[self-repository] actionlint rejects the $/ form
            with:
              github-token: ${{ secrets.GITHUB_TOKEN }}

          - name: Collect the security evidence
            run: task ci:release:evidence
            env:
              GH_TOKEN: ${{ github.token }}

          - name: Upload the security evidence
            uses: <upload-artifact pin>
            with:
              name: security-evidence
              path: security-evidence.json
    ```

    Pins are written with the
    `[[ pins["…"].uses ]]@[[ pins["…"].sha ]] # [[ pins["…"].version ]]` form
    the `umbrella` job uses. The upload is a workflow step, not the task (a task
    cannot upload an artifact); the task writes the file and the summary.

- The `validate` job's lint step is named `Validate` today (`ci.yml.j2`,
  `- name: Validate`); a test pins that `LINT_STEP` matches it.

Rejected (do not build): a `checks-ok` dependency (evidence runs after the
barrier), a retry, writing the record to the release (S21.2.3).

## Current behaviour

- `[ci.checks] release-evidence = true` is refused by `CiConfig` as an unknown
  check key (`CiConfig._checks_are_configurable` raises
  `ci.checks.release-evidence is not a configurable check`), so every new
  render test fails at config load.
- `controls.manifest`, `LINT_JOB` and `LINT_STEP` do not exist.
- `tests/modules/cicd/test_registry.py::test_configured_rows_have_keys` lists
  four configured names; it must gain `release-evidence`.

## Change

- **Change:** `registry.py`, `cicd/config.py`, `cicd/artifacts.py`,
  `controls.py`, `ci.yml.j2`, `tasks/ci.yml.j2`; tests below; generated files
  only via `task kiln:apply` and `task docs:generate` (the matrix gains a row

  catalog's rows, every other template.
