## S11.2.1 — The standard and the `python-lib` golden

**State:** New

**Build**, in `tests/fixtures/golden/python-lib/`, for each of `golden-alpha`
and `golden-beta`:

- `packages/<pkg>/mkdocs.yml`: `site_name: <pkg>`, `docs_dir: docs`,
  `exclude_docs: "_*"`, `strict: true`. Use the root's theme and
  `markdown_extensions`, plus `pymdownx.snippets` with `check_paths: true`.
  Add `mkdocstrings` with `paths: [src]`. The nav is `Home: index.md`,
  `Guides` (its pages), `Reference: reference/api.md` and
  `Changelog: changelog.md`.
- `packages/<pkg>/docs/index.md`, `docs/guides/usage.md`, and
  `docs/reference/api.md` (`::: golden_alpha` or `::: golden_beta`).
- `packages/<pkg>/docs/changelog.md`, which holds only
  `--8<-- "packages/<pkg>/CHANGELOG.md"`. Snippet paths are relative to the
  repository root, because every build runs from there.
- `packages/<pkg>/CHANGELOG.md`, in Keep a Changelog form: a `## [Unreleased]`
  heading, then `## [0.1.0] - 2026-09-26`.
- `packages/<pkg>/pyproject.toml` `[project.urls]`, with the four values the
  [E11 design](index.md#design) derives from
  `https://github.com/rn-forge/golden-lib`.
- `packages/<pkg>/README.md`, with only absolute links. It includes one links
  line, "Documentation · Changelog · Source", in which each word links to that
  `[project.urls]` value.

Then at the golden's root:

- `mkdocs.yml` body: add the `monorepo` plugin between `search` and
  `mkdocstrings`. Change the mkdocstrings `paths` to `[packages/*/src]`, so
  that a package added later needs no edit to this repo-owned body. Add
  `pymdownx.snippets` with `check_paths: true`.
- `docs/_areas.yml`: add `{key: packages, title: Packages, nav: include}` after
  `guides`. Run `task docs:generate`.
- `docs/reference/`: remove it. Each package's API reference now lives in its
  own site.
- `docs/index.md`: link `golden-alpha/index.md` and `golden-beta/index.md`. This
  proves root-to-package resolution.
- `docs/_structure.md`: a `## Package docs` section that states R5's shape and
  the published additions. These are: `index.md`; `guides/` of kebab-case
  pages; a generated `reference/`; no `adr/`, `specs/`, `releases/`, `plans/`
  or `runbooks/` inside a package; `CHANGELOG.md` and `docs/changelog.md`;
  `[project.urls]`; and a README with absolute links only.
- `pyproject.toml`: add `mkdocs-monorepo-plugin>=1.1` to the `docs` group, then
  `uv lock`.
- `tasks/docs.yml` (managed): after the root build, `build` runs one standalone
  build per package from the repository root. Each build goes into a scratch
  directory that is then removed:
  `site=$(mktemp -d) && uv run --group docs mkdocs build --strict -f packages/<pkg>/mkdocs.yml --site-dir "$site"; rc=$?; rm -rf "$site"; exit $rc`.
  Re-seed `state.json`.

In kiln, `docs/reference/standard-repo.md`:

- §2's ownership table gains these rows: `packages/<pkg>/mkdocs.yml`,
  `packages/<pkg>/docs/**`, `CHANGELOG.md` and `README.md`, all `python-lib`
  only and seeded by `kiln generate package`. The root `mkdocs.yml` row notes
  the `monorepo` plugin for `python-lib`.
- The archetype catalogue gains a paragraph that states ADR-0008's layout, per
  archetype, and links the ADR.
- §3's `python-lib` row adds `mkdocs-monorepo-plugin` to `docs`.
- §5 says that `docs:build` builds every package site `--strict`.

Re-render the golden's `.rn-forge/kiln/standard.md` if it is rendered from the
reference, and re-seed its hash.

**Acceptance:**

- In the golden, `uv sync && task validate` passes. That run includes the root
  strict build, both standalone strict builds, `docs-generate`,
  `docs-structure` and `docs-site`.
- The golden's derived nav has `Packages` with `golden-alpha` and `golden-beta`
  `!include` entries.
- Adding a link from `packages/golden-alpha/docs/index.md` to
  `../../golden-beta/docs/index.md` fails `task docs:build`. Revert it after
  the check; this line is not scriptable.
- `docs/reference/standard-repo.md` names ADR-0008 and the `include` area kind.

## S11.2.2 — The templates reproduce the root, and `kiln new` starts empty

**State:** New · **Depends on:** S11.2.1

**Build:**

- `kiln new --archetype python-lib` refuses a non-empty
  `[archetype.python-lib] packages`, whether it comes from `--config` or from
  defaults. The error is `config.packages-at-new`, with the message
  `a python-lib repository starts with no packages; add each with 'kiln generate package <name>'`.
  It writes nothing.
- `modules/python/scaffold.py`: with no packages, the root is a bare workspace
  with `members = []`. For `python-lib` under `mkdocs`, `_DOCS_GROUP_MKDOCS`
  gains `mkdocs-monorepo-plugin>=1.1`.
- `modules/docs/scaffold.py`:
    - For `python-lib`, `mkdocs.yml.j2` renders the golden's root body: the
      `monorepo` plugin, `paths: [packages/*/src]` and `pymdownx.snippets`.
    - For every other archetype, `paths` lists `src` plus `<pkg>/src` for each
      entry in `config.packages`. An application's internal packages are
      documented only in the root site (ADR-0008).
- `modules/docs/artifacts.py`: the template context gains `archetype`.
  `_areas.yml.j2` adds the `packages` include area for `python-lib`, and
  `_structure.md.j2` adds the `## Package docs` section for `python-lib`, both
  byte-equal to S11.2.1's golden. `python-lib` seeds no `docs/reference/`.
- `modules/tasks/templates/tasks/docs.yml.j2`: the `build` task renders one
  standalone build per `config.packages` entry for `python-lib`, byte-equal to
  the golden.
- A fresh `python-lib` repository with no packages passes its own gate. Run
  `task validate` in one. Fix each failure in the template or scaffold that
  renders the failing piece, the way
  [S5.3.1](../E5-web-archetypes/F5.3-shipped-web-cells.md#s531-a-fresh-generated-repo-passes-its-own-gate)
  did. A task with nothing to run renders a command that says so and exits
  0; it never skips a failure. Record each fix.

**Tests:** `tests/modules/docs/test_artifacts.py`,
`tests/modules/python/test_scaffold.py`,
`tests/modules/tasks/test_artifacts.py`, and the `kiln new` tests beside
S4.5.1's.

**Acceptance:**

- F4.3 properties 1–5 hold for the `docs`, `python` and `tasks` modules against
  the S11.2.1 golden. The test renders them from that golden's `config.toml`,
  which lists both packages.
- `kiln new <dir> --archetype python-lib --docs mkdocs --yes` writes no member
  under `packages/`, and `uv sync && task validate` passes in it.
- `kiln new` with a `--config` that lists a package exits non-zero with
  `config.packages-at-new`, and `<dir>` does not exist afterwards.
- A `python-app` config with `packages = ["packages/core"]` renders
  `paths: [src, packages/core/src]`.

## S11.2.3 — The package docs checks

**State:** New · **Depends on:** S11.2.2

**Build**, in `modules/docs/packages.py`, as
`check_packages(root: Path, config: KilnConfig) -> list[Finding]`, called from
`checks/structure.py` after `check_structure`.

For `python-lib`, each entry in `config.packages` is checked as follows:

| Code | Rule |
| -- | -- |
| `docs.package-missing-mkdocs` | `<pkg>/mkdocs.yml` exists |
| `docs.package-missing-index` | `<pkg>/docs/index.md` exists |
| `docs.package-missing-guides` | `<pkg>/docs/guides/` exists; its pages are kebab-case (`docs.kebab-case`) |
| `docs.package-governance-area` | none of `adr/`, `specs/`, `releases/`, `plans/`, `runbooks/` is under `<pkg>/docs/` |
| `docs.package-changelog` | `<pkg>/CHANGELOG.md` exists, has `## [Unreleased]`, and every other `## ` heading matches `## [<x.y.z>] - <YYYY-MM-DD>` |
| `docs.package-changelog-page` | `<pkg>/docs/changelog.md` contains `--8<-- "<pkg>/CHANGELOG.md"` and the package's nav names it |
| `docs.package-urls` | `<pkg>/pyproject.toml` `[project.urls]` has `Documentation`, `Source`, `Changelog` and `Issues`, each `https://` |
| `docs.package-readme-relative-link` | `<pkg>/README.md` has no relative link |

`reference/` is treated as generated and is not naming-checked.

Across the workspace, the checks are:

- For `python-lib`, a root `[tool.uv.workspace] members` entry, with globs
  expanded, that is not in `config.packages` reports `docs.package-unlisted`.
- For every other archetype, a workspace member with a `docs/` directory or a
  `mkdocs.yml` reports `docs.package-docs-not-allowed`, with the message
  `package docs sites are python-lib only (kiln ADR-0008); document <pkg> in the root site`.

**Tests:** a new `tests/modules/docs/checks/test_packages.py`, with one fixture
per code.

**Acceptance:**

- Each code above has a fixture that reports it and no other error.
- The S11.2.1 golden reports none of them.
- A `python-app` fixture with `packages/core/docs/index.md` reports
  `docs.package-docs-not-allowed`.
