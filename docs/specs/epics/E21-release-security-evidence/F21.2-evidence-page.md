The evidence record becomes the release's page,
`docs/releases/release-<n>/security.md`, rendered by one command in the pull
request that marks the release `shipped`. The releases standard says the page
belongs there, and `task lint` fails when the newest shipped release has none.
The umbrella release attaches the record. That attachment is the durable copy: a
run artifact expires, a GitHub release asset does not.

## S21.2.1 — `kiln-devops evidence render`

**State:** Closed (2026-11-24)

**Acceptance:**

- `kiln-devops evidence render --run <id> --release <n>` downloads the
  `security-evidence` artifact of that run and writes
  `docs/releases/release-<n>/security.md`: a title, one line saying that
  passing the baseline is not a claim the release is secure, a link back to
  the release page, and a table with `Control`, `Effect`, `Result` and
  `Evidence` columns, one row per control in catalog order.
- A row the record marks `not checked` is filled from the caller's own `gh`
  credentials when they allow it, and otherwise stays `not checked`.
- `task release:evidence -- <run-id> <n>` runs it. The page passes `task lint`,
  and rendering the same record twice gives the same file.
- When the run has no `security-evidence` artifact, it fails, names the run, and
  writes nothing.

The task lives in a `release` namespace, `tasks/release.yml`, rendered only when
`release-evidence` is on, as `tasks/sonar.yml` is for Sonar. A `not checked` row
is filled from `security_and_analysis.secret_scanning_push_protection`.

## S21.2.2 — The releases standard names the page

**State:** Closed (2026-11-24) · **Depends on:** S21.2.1

**Acceptance:**

- The rendered `docs/releases/_structure.md` lists `release-<n>/security.md`
  under "Belongs here" when `[ci.checks] release-evidence` is on. It says the
  page is rendered by `task release:evidence`, never written by hand, and the
  release page's header links it.
- One exit criterion stands on every such release: the evidence page exists and
  every row's result is `passed` or `not run`, or the release page says why
  not.
- With `release-evidence` on, `kiln doctor` fails when the newest release page
  marked `shipped` has no `security.md` beside it, and names the release. Only
  the newest is checked, so turning the check on does not require pages for
  releases shipped before it.

The release page links the evidence with an optional `Security Evidence`
metadata key; the doctor check is `release-evidence`
(`docs.release-evidence-missing`).

## S21.2.3 — The umbrella release attaches the record

**State:** Closed (2026-11-25) · **Depends on:** S21.2.1

**Acceptance:**

- With both `umbrella-release` and `release-evidence` on, `kiln-devops umbrella`
  attaches `security-evidence.json` and its rendered `security.md` to the
  `release-<n>` GitHub release it creates. It takes the record from the run
  that the committed `security.md` names in its `**Run**` row, so the
  attachment is the record the page was rendered from (owner decision,
  2026-11-25: a release page names no tags to search runs by).
- Without the page, a run on it, or that run's artifact, it creates the release
  with no attachment and prints a warning naming the release. The release is
  not held back.

## Acceptance

```bash
set -euo pipefail
task test -- -k "s21_2_1 or s21_2_2 or s21_2_3"   # S21.2.1, S21.2.2, S21.2.3
task docs:build                                    # S21.2.2: the rendered standard builds in strict mode
```

Not scriptable: in an adopting repository, `task release:evidence` against a
real release run writes a page that `task lint` accepts (S21.2.1).
