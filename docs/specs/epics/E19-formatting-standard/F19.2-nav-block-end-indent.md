# F19.2 — The nav block is a plain `ManagedBlock`

|  |  |
| -- | -- |
| **State** | New |
| **Parent** | [E19](index.md) |
| **Iteration** | [Release 1](../../../releases/release-1/index.md) |
| **Predecessors** | [F19.1](F19.1-yaml-formatter.md) |
| **Source** | Owner decision, 2026-11-11; pykit S18.6.1 and S18.6.2 |

The YAML formatter moves a comment that ends a block to the left margin, so the
`# END derived nav` marker in `mkdocs.yml` sits at column 0 while its
`# BEGIN derived nav` marker sits at two spaces. S19.1.2 made `NAV_BLOCK` a
subclass of `ManagedBlock` that overrides the private `_marker` to write that.
`rn-forge-commons` 0.9.0 gives `ManagedBlock` a public `end_indent` field for it
(pykit S18.6.1, released by pykit S18.6.2). This feature deletes the subclass
and states the same markers with the field. The rendered bytes do not change.

## S19.2.1 — `NAV_BLOCK` uses `end_indent`

**State:** New · **Depends on:** pykit S18.6.1, `rn-forge-commons` 0.9.0 on PyPI

A dependency floor and a deletion. Nothing a template renders changes, so
`task kiln:apply` has nothing to do and no golden or `state.json` moves.

**Floors.** Only kiln's own dependency changes. The pin table `RN_FORGE_TAGS` in
`src/rn_forge/kiln/archetypes/__init__.py`, the example in
`src/rn_forge/kiln/modules/instructions/templates/standard.md.j2` (line 190),

rendered repository's floor does not move and its output is byte-identical.
`test_s16_4_3_2_floors_match_the_lock` reads only `_DEV_GROUP` and is not
affected.

## Acceptance

S19.2.1 is the feature's only story, so its acceptance is the feature's. Nothing
needs the owner's judgement beyond reading the diff, which is five files.

## Considered and rejected

- **Keep the subclass.** It overrides a private method of a class in another
  repository, which a rename there breaks without a warning.
- **Raise the rendered floor to 0.9.0 as well.** A rendered repository does not
  use the new field, so raising its floor only forces it to a release it does
  not need.
