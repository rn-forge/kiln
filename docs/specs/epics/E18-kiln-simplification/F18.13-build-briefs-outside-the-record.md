Keeps the specs from growing back after F18.3 cuts them. A story ready to build
gets a brief: a separate, unpublished file with what an implementing agent
needs. The feature page keeps only scope, acceptance and state. The commit that
closes the story deletes its brief, so build lists and verbatim code never
outlive the code they describe. Every repository kiln renders takes the rule and
the check.

## Context

E18 cuts build lists, verbatim code and step-by-step briefs that were needed
while smaller models built the stories and only drift now that the code exists.
The template defines the record but not the brief, so briefs were written into
the feature pages and stayed there. The same need is back for any story handed
to another agent in its own worktree: the agent needs the brief, and the record
does not.

## Design

- **Where:** `specs/epics/E<n>-<slug>/_briefs/S<n>.<m>.<k>.md`, one per story.
  MkDocs' `exclude_docs: "_*"` already keeps it off the site, `load_work`
  reads only `F*.md`, and `underscore-referenced` already forbids a published
  page from linking to it.
- **What:** the sections of the file template below. A brief is written for a
  reader with no other context: it names the commit its line references are
  at, and repeats any repository rule the change could break.
- **When:** only once the story's decisions are settled. A decision still to be
  made stays its own story, so a brief never asks its reader to decide. A
  brief for a decision story asks for the reproduction and the comparison of
  options; the owner decides.
- **Validation is split.** The implementer runs the full gate in its worktree
  and records the results in the brief. The reviewer reads the diff and the
  results, and after the merge re-runs only the brief's targeted tests. The
  full gate runs again once per feature, when it closes.
- **Closing:** the commit that flips the story to `Closed (<date>)` deletes the
  brief and adds at most one outcome line to the story, such as a measurement
  its acceptance asked for. History keeps the brief.

The file template:

```markdown
# S<n>.<m>.<k> — <Title>

Brief for [S<n>.<m>.<k>](../F<n>.<m>-<slug>.md#<anchor>), at `<commit>`.

## Goal

<one or two sentences: the change and why>

## Settled

<each decision this brief relies on, with its source: an ADR, a decision
story, or the owner on a date. A contract settled here is copied into the
story's acceptance when it closes.>

## Current behaviour

<what the code does now, with file:line references>

## Change

- **Change:** <files and what changes in each>
- **Leave alone:** <files and areas the change must not touch>

## Tests first

<each test: its file, its name, what it asserts, and that it fails before the
change>

## Out of scope

<what a reader might reasonably do here and must not>

## Validation

Run in the worktree, in order; each must exit 0:

1. `task setup`
1. `task format`
1. <the targeted test commands>
1. `task validate`

## Review re-run

<the targeted test commands the reviewer runs after the merge>

## Rules

- Do not commit, push, or edit any spec page except `## Result` below.
- Do not edit a file whose header says kiln generated it.
- Do not add a dependency.

## Result

<filled by the implementer: each validation command with its exit code, the
files changed, and any deviation from this brief with its reason>
```

## S18.13.1 — The specs structure defines briefs

**State:** New

Add the design above to `docs/specs/_structure.md.j2`: the brief under *Belongs
here*, build steps and verbatim code on a feature page under *Does not belong
here*, the brief's file template under *File templates*, and its deletion as a
step of *Working on and closing out work*.

**Acceptance:**

- Every archetype with the `mkdocs` docs profile renders a `specs/_structure.md`
  that gives the brief's path, file template, precondition, split validation
  and deletion at close.
- A render test pins those five parts.

## S18.13.2 — Doctor fails on a brief left behind

**State:** New · **Depends on:** S18.13.1

Add the check to work-item validation, beside the state and date rules.

**Acceptance:**

- A brief for a story that is `Closed` or `Removed` is an error that names the
  brief and the story.
- A brief whose name is not a story of a feature in the same epic is an error.
- A brief for a `New` or `Active` story passes, and the brief does not change
  any derived region.
- Each case is a test through `kiln doctor`, and kiln's own repository passes.

## S18.13.3 — The agent instructions point at the rule

**Acceptance:**

## S18.13.4 — `task test` runs a targeted subset

**State:** New

A brief names targeted tests, but the rendered `test` verb runs every package's
whole suite and takes no arguments, and the standard forbids invoking `pytest`
directly. The Python archetypes' `test` verb takes an optional package and
pytest arguments after `--`, as `build` already takes a package.

**Acceptance:**

- `task test -- <package> <pytest args>` runs only that package's suite with
  those arguments, from the package's directory, so its pytest settings apply.
- `task test` with no arguments still runs every package, and an unknown package
  is an error that names it.
- A render test covers both forms for each Python archetype, and
  `task kiln:apply` runs on this repository in the same change.

## Acceptance

- S18.13.1: A rendered `specs/_structure.md` gives a brief's path, file

- S18.13.2: Doctor fails on a brief for a closed story or an unknown story, and
  passes one for an open story.
- S18.13.3: The rendered instruction block points at the brief rule.
- S18.13.4: `task test -- <package> <pytest args>` runs only that package's
