pykit's Release 7 changed `main.yml` and `rn-forge-devops` after kiln ported
them. kiln takes the planner's 0.3.1 changes, a Redis job for the packages that
declare one, and PEP 740 attestations on every PyPI upload, so pykit's cutover
loses none of them.

## Context

**Why now, in release 1.** pykit's F16.3 deletes `main.yml` and requires the
release behaviour of the kiln it pins in full. kiln's planner is a port of
`rn-forge-devops` 0.2.0 ([F6.7](F6.7-kiln-devops.md)); `rn-forge-devops` 0.3.1
is the release this feature reads, at tag `rn-forge-devops-v0.3.1`.

**What pykit changed:**

- **A dependency cycle hangs the planner.** `release_order` follows `requires`,
  which includes dependency groups. A cycle through a dev group never
  resolves. pykit added `release_requires`, which leaves dependency groups
  out.
- **Redis.** `[tool.workspace-ci.redis]` declares a test run against a Redis
  service. `rn-forge-auth` is the first package to declare it.
- **PEP 740.** `uv publish` uploads attestation files it is given and never
  generates them, and `actions/attest-build-provenance` writes GitHub
  attestations only (pykit S21.3.5). `pypi-attestations sign` writes them, and
  a Rekor write can stall into a 502, so each file is signed on its own with
  retries.

**Where kiln differs from pykit.** kiln builds the `.cdx.json` SBOM into
`dist/<name>/`, and pykit keeps it in `sbom/`. So kiln signs and uploads by
suffix, not by globbing `dist/*/*`.

**What stays pykit's.** These are in `main.yml` and are not rendered by kiln.
pykit keeps them through `[[ci.jobs]]`, as it keeps `internal-ranges` (owner
decision, 2026-10-31; idea `ci-security-jobs`):

- `dependency-audit`, `licenses` and `secret-scan`;
- `scorecard.yml` and `broker-profile.yml`, which stay beside `ci.yml`.

**Handoff to pykit** ([ADR-0009](../../../adr/ADR-0009.md): its specs are its
own). F16.3 needs these corrections before Release 8:

- S16.3.1's last step adds kiln as a dev dependency with an override. Since
  [F7.4](../E7-pykit-release-pin-flip/F7.4-kiln-runs-beside-the-repository.md)
  kiln runs beside a repository from `[kiln] ref`, so the step and its
  override go.
- S16.3.2 says `kiln-devops` is `rn-forge-devops` 0.2.0. After this feature it
  is 0.3.1.
- S16.3.2 lists the F21.3 behaviour pykit requires. It gains S21.3.5's
  attestations and the `redis` job, which this feature renders, and names the
  three security jobs as `[[ci.jobs]]` entries.
- S16.3.4 names `kiln.toml`; the file is `.rn-forge/kiln/config.toml`.
- `broker-profile.yml` may invoke `uv` directly. `ci.entrypoint` then reports
  it, as it reported `internal-ranges.yml`.
- `rn-forge-devops` has no `docs/guides/` on `main` or on
  `feature/kiln-adoption-run-3`, and `kiln doctor` fails on it. The older
  adoption branches carry the page.

**Out of scope.** Rendering the security jobs for every repository.

## S6.8.1 — `kiln-devops` takes the 0.3.1 planner

**State:** Closed (2026-11-01)

**Build — tests first.** Port the cases from pykit's
`packages/rn-forge-devops/tests/test_ci.py` and `test_uv.py` at tag
`rn-forge-devops-v0.3.1`, named `test_s6_8_1_<n>_…`, into
`tests/devops/test_ci.py` and `tests/devops/test_uv.py`:

1. `release_order` ignores a cycle through a dependency group.
1. `release_order` raises `ValueError` matching `cycle among \['a', 'b'\]` on a
   runtime cycle.
1. `plan` orders a group-only cycle.
1. `releasable` gates on `release_requires` only.
1. `plan` lists a Redis row `{name, dir, env}` for a selected package with
   `redis_env`, and none otherwise.
1. `Package.checks` includes `{"kind": "redis", "marker": "<name>.redis"}` only
   when `redis_env` is set.
1. A missing `<name>.redis` marker blocks a package.
1. `[tool.workspace-ci.redis]` sets `redis_env`.

**Build**, taking the code from pykit's tag, in `src/rn_forge/kiln/devops/`:

- `ci.py`: `Package` gains `release_requires: set[str]` and
  `redis_env: str | None = None`, with their docstring lines. `checks` gains
  the Redis marker. `release_order` reads `release_requires` and raises
  `ValueError(f"release requirements form a cycle among {pending}")` when
  nothing is ready. `releasable` reads `release_requires`. The plan gains
  `redis`.
- `uv.py`: `release_requirements = list(requirements)`, taken before the
  dependency groups are added, sets `release_requires`, and
  `ci["redis"]["env"]` sets `redis_env`.
- `docs/reference/kiln-devops.md`: the `[tool.workspace-ci.redis]` row and the
  `redis` plan output, beside the `postgres` rows.

Keep kiln's own lines where they differ only by pykit's `# noqa` comments.

**What the build settled that the story did not say:** the cycle is live, not
theoretical. `rn-forge-web`'s dev group requires `rn-forge-auth`, which requires
`rn-forge-web` at runtime, so on pykit's Release 7 `task ci:plan` hung until it
was killed (S6.4.5's rerun, 2026-11-01). That rerun therefore waits on this
story.

**Acceptance:**

- `uv run pytest tests/devops` passes.
- `task validate` exits `0`.

## S6.8.3 — `release = "pypi"` uploads PEP 740 attestations

**State:** New

**Build — tests first.** In `tests/modules/cicd/test_artifacts.py`,
`test_s6_8_3_1_attest_step`: for a `pypi` cell, the release job has a step named
`Attest PyPI publish` between `Generate provenance` and `Publish releases`, with
`if: steps.build.outputs.built != '0'` and `run: task ci:release-sign`. A
`tag-exists` cell has no such step.

In `tests/modules/tasks/test_artifacts.py`, `test_s6_8_3_2_release_sign_task`:
for a `pypi` cell, `tasks/ci.yml` has `release-sign`. It runs
`uvx pypi-attestations==0.0.30 sign "$1"` up to 5 times, with `sleep 20` between
attempts, for each `dist/*/*.whl` and `dist/*/*.tar.gz`, and fails after the
fifth. A `tag-exists` cell has no such task.

In `tests/devops/test_github.py`:

- `test_s6_8_3_3_upload_includes_attestations`: `upload_commands` keeps
  `*.publish.attestation` files, and still drops the `.cdx.json`.

In `tests/devops/test_cli.py`:

- `test_s6_8_3_4_release_assets_leave_out_attestations`: `release-publish`
  passes `publish_commands` every file except `*.publish.attestation`.

**Build:**

- `modules/cicd/templates/ci.yml.j2`: the step, under
  `{% if release == "pypi" %}`, with the comment
  `# uv publish uploads the *.publish.attestation files it is given. One file at a time, because a Rekor write can stall into a 502 and signing never retries.`
- `modules/tasks/templates/tasks/ci.yml.j2`: `release-sign`, under the same
  condition. Each attempt that fails prints
  `::warning::Signing <file> failed on attempt <n>.`
- `rn_forge.kiln.devops.github.upload_commands`: the suffix filter gains
  `.publish.attestation`.
- `rn_forge.kiln.devops.cli`: the files `release-publish` passes to
  `publish_commands` leave out `*.publish.attestation`.
- `docs/reference/kiln-devops.md`, `docs/reference/standard-repo.md` section 8,
  `modules/instructions/templates/standard.md.j2` and
  `docs/architecture/python-lib-ci.md`: the attestations, in the sentence that
  names the upload.
- Run `uv run kiln apply` and `task self:golden:compare BASE=HEAD`.

**Acceptance:**

- `uv run pytest tests/devops tests/modules/cicd tests/modules/tasks` passes.
- `actionlint` passes on a rendered `pypi` cell's `ci.yml`.
- The golden compare passes. No cell sets `pypi`, so no cell changes.
