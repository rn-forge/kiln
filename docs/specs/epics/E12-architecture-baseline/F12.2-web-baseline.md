## S12.2.3 — `.importlinter` enforces B-0004's framework boundary

**State:** New · **Module:** `python` · **Depends on:** S12.2.1

**Build:**

- `modules/python/artifacts.py:render` adds one context key, `framework_edge`,
  which is `config.backend == "fastapi"`.
- `modules/python/templates/importlinter.j2` renders the
  `framework-stays-at-the-edge` contract from
  [design.md](design.md#the-tiers-and-their-contracts) when `framework_edge`
  is true. It comes after `dependencies-point-inward`, with one blank line
  between them, and `{{ package }}` stands in for `demo_api`. The two
  `source_modules` lines are indented four spaces, like every other list in
  the file. If the template's whitespace control strips that indentation,
  pre-join the lines in `render`, as `members_block` does.
- Do not change the forbidden list of `frameworks-come-from-rn-forge`. FastAPI
  is allowed in the API member, and this contract narrows where.

**Tests:** extend `tests/modules/python/test_artifacts.py`, with names
`test_s12_2_3_…`. Each one builds a package `demo_api` under `tmp_path / "src"`,
renders `.importlinter` for a `python-web-api` config named `demo` with
`backend = "fastapi"`, and runs `importlinter.cli.lint_imports` as the existing
`lint_imports` test does:

- **A fresh package passes.** `demo_api/__init__.py` and `demo_api/app.py` only.
- **`domain` importing FastAPI fails.** `demo_api/domain/__init__.py`, and
  `demo_api/domain/rule.py` containing `import fastapi`.
- **`services` importing Starlette fails.** `demo_api/services/__init__.py`, and
  `demo_api/services/use.py` containing `import starlette`.
- **`http` importing FastAPI passes.** `demo_api/http/__init__.py`, and
  `demo_api/http/routes.py` containing `import fastapi`.
- **Only FastAPI cells carry it.** The contract name is absent from the render
  for `backend = "django"`, and for `python-app`.

The known gap in [design.md](design.md#the-tiers-and-their-contracts) is not
tested. An import in `domain/__init__.py` itself passes, by design.

**Acceptance:**

- The four `lint_imports` tests show a fresh package and `http` passing, and
  `domain` and `services` failing.
- `task validate` passes in kiln.
