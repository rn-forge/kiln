A configured check, off by default, for every archetype (every kiln repository
has `docs/releases/`): one GitHub release per shipped release page, tagged
`release-<n>`, made by an `umbrella` job of `ci.yml` that runs after `release`.
It replaces pykit's `umbrella-release.yml`, and revises
[F7.6](../E7-pykit-release-pin-flip/F7.6-release-to-pypi.md)'s "stays pykit's".

**Why a job of its own.** Shipping a release is a docs change: the commit that
marks a release page `shipped` usually bumps no package. `python-lib`'s
`release` runs only when `release-order != '[]'`, so a step inside it would
never see that commit. The `umbrella` job is gated on the barrier and on
`release` not failing, never on which packages were selected.

## S15.5.1 — `kiln-devops umbrella`

**State:** Closed (2026-11-05)

**Build — tests first,** in `tests/devops/test_umbrella.py`, with a fake `gh`
runner copied from `tests/devops/test_github.py`:

1. `test_s15_5_1_1_shipped_page_makes_a_release`:
   `docs/releases/release-2/ index.md` with `| **Status** | shipped |` and the
   title `# Release 2 — Name` leads to
   `gh release create release-2 --title "Release 2 — Name" --notes-file <file> --target <sha>`;
   the notes file is the page from the line after its metadata table to the
   end.
1. `test_s15_5_1_2_planned_page_is_skipped`: `planned` and `in progress` pages
   create nothing.
1. `test_s15_5_1_3_existing_release_is_skipped`: when
   `gh release view release-2` succeeds, nothing is created.
1. `test_s15_5_1_4_dry_run`: `--dry-run` prints the `gh` commands and runs none.

**Build:** `src/rn_forge/kiln/devops/umbrella.py` and an `umbrella` subparser
(`--releases docs/releases`, `--sha`, `--dry-run`), using `devops/github.py`'s
runner. Read the status from the page's metadata table with the same regex the
docs checks use (`modules/docs/work.py`; reuse its parser, do not write a
second).

**Acceptance:**

- The four tests pass, and `task validate` passes.

**What the build settled that the story did not say:**

- **Departure: the status parser is not reused.** `devops/` may not import
  `rn_forge.kiln.modules` ([ADR-0017](../../../adr/ADR-0017.md);
  `tests/devops/test_boundary.py` loads nothing outside
  `rn_forge.kiln.devops`), so `umbrella.py` carries the minimum of
  `modules/docs/work.py`'s metadata reading: a `# title` line and the
  `| **Key** | value |` rows after it, with a comment naming the source. It is
  two regexes, not a second parser.
- `github.release_exists(tag)` (a new, public `gh release view <tag>`
  exit-status check) answers "exists"; a draft counts as existing.
- Notes files are written to a fresh temporary directory, so `--notes-file` is
  not path-checked by `_validate`; `--sha` is checked like `--target`, and
  `--releases` must be inside the working directory.
- `--dry-run` runs no `gh` command at all, including `gh release view`, so it
  prints a `create` for every shipped page.
- Pages are handled in release-number order; a missing releases directory exits
  `2` with `kiln-devops: no release pages at '<dir>'`.

## S15.5.2 — An `umbrella` job runs it

**State:** Closed (2026-11-05) · **Depends on:** S15.1.2, S15.5.1, S15.8.7

**Build — tests first,** in `tests/modules/cicd/test_artifacts.py`:

1. `test_s15_5_2_1_off_by_default`: no archetype's render has a
   `ci:release:umbrella` task or an `umbrella` job.
1. `test_s15_5_2_2_on`: for each Python archetype, with
   `[ci.checks] umbrella-release = true`, `ci.yml` has a job `umbrella` with
   `needs: [checks-ok, release]`, `permissions: { contents: write }`,
   `concurrency` group `release` with `cancel-in-progress: false`, and the
   steps checkout, the setup action, and `task ci:release:umbrella`. No
   `release` job has an `umbrella` step.
1. `test_s15_5_2_3_needs_a_release`: S15.1.2's error with
   `[ci] release = "none"`.
1. `test_s15_5_2_4_docs_only_shipped_transition`: the `umbrella` job's `if` is
   exactly
   `${{ !cancelled() && needs.checks-ok.result == 'success' && needs.release.result != 'failure' && github.event_name == 'push' && github.ref == 'refs/heads/main' }}`.
   It does not contain `release-order`, so a push that only marks a release
   page `shipped` (no package selected, `release` skipped) still runs it, and
   a failed `release` skips it. For `python-lib` the `release` job's `if`
   still contains `release-order != '[]'`.
1. `test_s15_5_2_5_ci_ok`: `ci-ok` needs `umbrella` when it renders.

**Build:** `tasks/ci.yml.j2` (`release:umbrella`, running
`{{.KILN_DEVOPS}} umbrella --sha "$GITHUB_SHA"`); in `ci.yml.j2`, an `umbrella`
job after `release`, with the barrier `if` above; the context key
`umbrella_release_enabled`. Add `umbrella` to S15.8.7's `ci-ok` needs. The
`release` concurrency group puts `umbrella` behind a running `release` of a
later push. `node-lib` is S15.5.3.

**Acceptance:**

- The five tests pass, and `task validate` passes.
- `task self:golden:compare BASE=HEAD`: no cell changes.
- Not scriptable here: on the first repository that turns the check on, a push
  to `main` that only marks a release page `shipped` creates `release-<n>` and
  releases no package.

**What the build settled that the story did not say:**

- The tests are in `tests/modules/cicd/test_artifacts.py`, parametrised over the
  five Python archetypes (`python-lib`, `python-tool`, `python-app`,
  `python-web-api`, `python-web-app`); test 1 adds `node-lib`, which has
  neither task nor job when the check is off.
- The `release:umbrella` task renders whenever the check is on, for every
  archetype including `node-lib` (S15.5.3 adds only the job), from a new
  `umbrella_release_enabled` key in both the `cicd` and `tasks` contexts. The
  job renders for non-`node-lib` archetypes only, after `docs` and before the
  declared `[[ci.jobs]]` calls; `postrelease_needs()` adds `umbrella` between
  `verify-release` and `docs`, under the same condition.
- The task is `{{.DEVOPS}} umbrella --sha "$GITHUB_SHA"` (the story said
  `KILN_DEVOPS`; the variable is `DEVOPS`). The job's checkout has no
  `fetch-depth` (the command reads the working tree and passes `--target`),
  its step carries `GH_TOKEN: ${{ github.token }}` through `env:`, and its
  `timeout-minutes` is 10.
- The `umbrella` job is not a `docs` need: Pages deploys whether or not the
  umbrella release ran.
- The check's registry row, and the error for `release = "none"`, were already
  in place from S15.1.2. `docs/architecture/ci.md` gained the job's row in the
  stages table; the checks matrix is derived and unchanged. The move of the
  design rows to `ci.md` stays F15.5's closing step.
- Kiln's own repository leaves the check off, so `task kiln:apply` changed no
  generated file.

## S15.5.3 — `node-lib`'s `release` stage runs it

**State:** New · **Depends on:** S15.5.2, S15.8.5

`node-lib`'s release runs in `release.yml` today. S15.8.5 moves it into
`ci.yml`'s `release` job, and this story renders S15.5.2's `umbrella` job for
`node-lib` as well.

**Build — tests first,** in `tests/modules/cicd/test_artifacts.py`:

1. `test_s15_5_3_1_node_lib_off_by_default`: a `node-lib` render has no
   `ci:release:umbrella` task or `umbrella` job.
1. `test_s15_5_3_2_node_lib_on`: with `[ci.checks] umbrella-release = true` and
   `[ci] release = "nx-dispatch"`, the `umbrella` job renders as in S15.5.2's
   tests 2 and 4. Its `needs` are `checks-ok` and `release`, not
   `verify-release`: the umbrella notes do not depend on npm's install path.
   `release` has no umbrella step. In `released` mode, which is the docs-only
   push for `node-lib`, `release` succeeds and `umbrella` runs.

**Build:** the `umbrella` job's `{% if %}` in `ci.yml.j2` (or `_release.yml.j2`
after S15.8.9) gains `node-lib`. S15.5.2 already renders the task for every
archetype.

**Acceptance:**

- The two tests pass, and `task validate` passes.
- `task self:golden:compare BASE=HEAD`: no cell changes.
