Decided by the owner on 2026-10-12 ([ADR-0010](../../../adr/ADR-0010.md)): kiln
writes minimal working source into `src/` and `tests/` once, at `kiln new`, as
**seeded** files. They use the rn-forge libraries the repository's dependencies
already declare. After creation they are the repository's own: `apply` never
re-renders them, `doctor` never compares them, and `state.json` records their
presence only. Managed files never go in `src/` or `tests/`. This feature
supersedes the earlier "kiln writes nothing inside `src/`" stance in
[E10](../E10-kiln-generators/index.md) and
[F5.3](../E5-web-archetypes/F5.3-shipped-web-cells.md).

*Numbering.* `F4.5` and `S4.5.1`–`S4.5.9` are the CLI feature; IDs are
permanent, so this feature is F4.9.

**Build a story by the [board's procedure](../../index.md#building-a-story).**
S4.9.1 comes first and builds the shared gate; S4.9.2 and S4.9.3 reuse it.
S4.9.2 and S4.9.3 are the web cells and are built with
[E5](../E5-web-archetypes/index.md), after S4.9.1;
[S4.4.9](F4.4-render-matrix.md#s449-the-goldens-leave-the-repository) needs
S4.9.1 only.

**The seeded-once rule, as built.** A starter file is a `SEEDED`
`rn_forge.tooling.generation.Artifact` returned from its module's `artifacts()`,
so `state.json` records it with `"kind": "seeded"`; `apply` writes it only when
absent. A module emits a starter file only while its package directory is still
a fresh `uv init` package: every `.py` file directly in
`<package dir>/src/<module>/` is either `__init__.py` or a starter file's own
name. A repository that already has product code gets no starter file, so
`kiln apply` on kiln itself (whose package directory does not exist) or on any
mature repository writes nothing new.

**Libraries named here** were read in the sibling checkout on 2026-10-12;
nothing is cited from memory. Where a module path differs from what a reader
might expect, the note says so: `build_tool_app` lives in
`rn_forge.tooling.cli.lifecycle` (rn-forge-tooling), not `rn_forge.cli`;
`CliApp.from_config` is in `rn_forge.cli`.

`product.py.j2` (tool only):

```python
"""This tool as the lifecycle verbs see it.

`[lifecycle]` in `.rn-forge/kiln/config.toml` names `PRODUCT`; the verbs
themselves — `install`, `upgrade`, `uninstall`, `cleanup`, `status`, `doctor` —
come from `rn-forge-tooling`.
"""

from __future__ import annotations

from collections.abc import Sequence
from importlib.metadata import version

from rn_forge.commons.findings import Finding, Severity
from rn_forge.tooling.install import Check, Link, ToolHome, ToolProduct


def check_home(home: ToolHome) -> list[Finding]:
    """Report where this tool is, or would be, installed."""
    return [Finding("{{ name }}.home", Severity.INFO, f"home is {home.product_dir}")]


class Tool(ToolProduct):
    """`{{ name }}`: one command on PATH, one check of its own."""

    def artifacts(self) -> Sequence[Link]:
        """Put the command on PATH."""
        return (Link("bin/{{ name }}", "bin/{{ name }}"),)

    def checks(self) -> Sequence[Check]:
        """Check the install's home."""
        return (check_home,)


PRODUCT = Tool(
    name="{{ name }}", version=version("{{ name }}"), repo="rn-forge/{{ name }}"
)
```

## S4.9.4 — The Angular starter calls the API

**State:** Closed (2026-10-13) · **Depends on:** S4.9.2, S4.9.3

renders the result or the problem response. `web:dev` proxies `/v1` to `api:dev`

**Why plain `HttpClient`, not ngkit's `AbstractHTTPService`** (checked
2026-10-13 against `@rn-forge/ng` v0.1.2 in the rendered cell): its
`getEndpoint` always appends a trailing slash, so it requests `/v1/items/`. The
seeded FastAPI app answers that with a `307` whose `Location` is the backend's

proxy follows cross-origin and fails on CORS. ngkit's `ErrorResponse` is also
Spring-shaped (`timestamp`, `error`, `message`, `path`), not the RFC 9457
problem the API returns (`type`, `title`, `status`, `detail`, `instance`). Both
are ngkit's to change ([ADR-0009](../../../adr/ADR-0009.md)); this story does
not work around them.

```ts
import { HttpClient, HttpErrorResponse } from '@angular/common/http';
import { Component, inject, OnInit, signal } from '@angular/core';
import { RouterModule } from '@angular/router';

/** The page the starter API returns from `GET /v1/items`. */
export interface ItemsPage {
  readonly pageSize: number;
  readonly items: readonly unknown[];
}

/** The RFC 9457 problem body the API returns on failure. */
export interface Problem {
  readonly type: string;
  readonly title: string;
  readonly status: number;
  readonly detail?: string;
}

@Component({
  imports: [RouterModule],
  selector: 'app-root',
  templateUrl: './app.html',
  styleUrl: './app.scss',
})
export class App implements OnInit {
  protected readonly title = '{{ name }}';
  protected readonly page = signal<ItemsPage | null>(null);
  protected readonly error = signal<string | null>(null);
  private readonly http = inject(HttpClient);

  ngOnInit(): void {
    this.http.get<ItemsPage>('/v1/items').subscribe({
      next: (page) => this.page.set(page),
      error: (response: HttpErrorResponse) => {
        const problem = response.error as Partial<Problem> | null;
        this.error.set(problem?.detail ?? problem?.title ?? response.message);
      },
    });
  }
}
```
