# S18.9.4 — `kiln-devops`

Brief for [S18.9.4](../F18.9-large-files-split.md#s1894-kiln-devops), at
`fef6689`. The feature page's line numbers are stale: find each named function

## Goal

`kiln-devops`'s dispatch is one table, its release subcommands are one function
each, release state is an enum, and `ci.py` is pure: no `subprocess` and no
`print`. No command's output, outputs file, message or exit code changes.

## Settled

- **Dispatch.** `cli.main` (`:410-450`) chooses a handler with an
  `if args.command == …` ladder, and `cli.py:171-190` picks behaviour with a
  `hasattr(args, …)` chain. Each subparser sets
  `set_defaults(func=<handler>)`, and `main` calls `args.func(args)`. Each
  subcommand's argument validation moves beside its parser, or into its
  handler. The `hasattr` chain and both ladders go.
- **`_release`** (`:198`) splits into one function per `release-*` subcommand.
- **Release state.** `github.release_draft` (`:68-79`) returns `"true"`,
  `"false"` or `None`. It becomes `release_status(tag) -> ReleaseStatus`, an
  `Enum` with `NONE`, `DRAFT` and `PUBLISHED`.
  `release_state(tag, status, tagged)` (`:103`) takes it and still writes the
  same output strings, e.g. `should-release` is `true` unless the status is
  `PUBLISHED`. Its outputs are byte-identical.
- **Release records.** `ci.released` returns `list[tuple[str, str, str, str]]`
  and `verify_release.py` handles a 5-tuple. Both become one
  `Release(name, dir, module, version, tag)` dataclass in `ci.py`, which every
  caller uses.
- **Git leaves `ci.py`.** A new `devops/git.py` adapter holds
  `changed_files(root, base)`, the base check (today's two `git` calls in
  `select`, `:196-212`), and `tags_at_head(root)` (today's call in `released`,
  `:306`). `select(workspace, changed)` takes the changed files, and
  `released(workspace, tags)` takes the tags. The base revision is validated
  once, in `git.py`. The warning `select` prints today (`:213`) is printed by
  the caller, `cli.py`, with the same text and stream. The
  `devops-core-has-no-adapter` contract in `.importlinter` already keeps `ci`
  from importing `uv` and `github`; `ci` must not import `git` either. Add
  `rn_forge.kiln.devops.git` to that contract's `forbidden_modules` (it is
  below the END marker, so a hand edit is allowed), and update
  `tests/test_import_contracts.py`'s expected list to match. That is an
  allowed test edit.
- **`devops/umbrella.py`** keeps its own parser (ADR-0017: the planner may not
  import kiln's docs module). Add the parity test below.
- **Tests** that call `select`, `released`, `release_draft` or `release_state`
  follow the new signatures, passing the changed files, tags or status they
  used to get from git or `gh`. A test that patched `subprocess.run` inside
  `ci` patches the `git` adapter instead. Every assertion keeps its meaning.
