# S16.5.4 — The pykit floors move to pykit's release 8

Brief for
[S16.5.4](../F16.5-rebuild-and-port.md#s1654-the-pykit-floors-move-to-pykits-release-8),
at `019beea`. Line references are at that commit.

## Goal

Move kiln's pykit pin table, its own three pykit dependencies and the
`standard.md` example to pykit's release 8, so a rendered repository accepts
`rn-forge-commons` 0.9.0.

## Settled

- The table, verified on pypi.org on 2026-11-16 (each is `info.version`):

    | Distribution | Tag |
    | -- | -- |
    | `rn-forge-commons` | `rn-forge-commons-v0.9.0` |
    | `rn-forge-cli` | `rn-forge-cli-v0.1.3` |
    | `rn-forge-tooling` | `rn-forge-tooling-v0.3.2` |
    | `rn-forge-web` | `rn-forge-web-v0.3.1` |
    | `rn-forge-auth` | `rn-forge-auth-v0.1.1` |
    | `rn-forge-django` | `rn-forge-django-v0.6.1` |
    | `rn-forge-fastapi` | `rn-forge-fastapi-v0.4.1` |
    | `rn-forge-sqlalchemy` | `rn-forge-sqlalchemy-v0.2.3` |

- A floor is its tag's version; the ceiling is the next minor
  (`archetypes.requirement`, ADR-0018). So commons becomes `>=0.9.0,<0.10`.

- `docs/adr/ADR-0018.md` keeps its `0.8.1` example: it is a decision record.

- Fixture literals that do not come from `RN_FORGE_TAGS` stay:
  `tests/devops/test_consumer.py` (ngkit `0.3.0` fixture names) and
  `tests/modules/python/checks/test_rn_forge_deps.py` (`:60`, `:79`, `:191`,
  `:412` are check inputs, not pins).
