`commands.py` is 958 lines. It holds ten commands, and their private helpers are
placed in no particular order among them. The helpers serve three unrelated
jobs: staging a new repository, adding a package, and re-resolving the config.
This feature makes `commands/` a package in which each command lives in its own
module, followed by its own helpers. The output code they share goes in a single
module.

Each command stays a plain function. A class with static methods would be the
same namespace with one more level of indentation, so it was rejected (owner
discussion, 2026-11-10). `cli.toml` already resolves `module:function`.

Every story keeps these properties:

1. No command's flags, output, exit code or messages change. The tests from
   [F18.5](F18.5-tests-survive-a-refactor.md) pass unedited, apart from import
   paths.
1. `cli.toml` targets name the new modules. `commands/__init__.py` re-exports
   the public commands, so `from rn_forge.kiln import commands` keeps working.
1. A command module imports only the shared output module, `core` and the
   modules it composes. It never imports another command module, except
   `new.py`, which imports `generate.py` (see S18.6.2).

## S18.6.1 — One output module

**State:** New · **Depends on:** —

Each command sets up the JSON mode itself. The line
`if json: console.set_mode(OutputMode.JSON)` appears nine times, and the
JSON-or-text branch eight times. Four places print findings, count the errors
and raise, each with its own code: `doctor` (`commands.py:140-142` and
`:186-191`), `docs_generate` (`:208-210`) and `_fail_on_errors` (`:946-953`).

**Build,** in the new `src/rn_forge/kiln/commands/output.py`:

- `use_json(flag)`, plus `emit(payload, lines)`, which prints `payload` as JSON
  in JSON mode, or else `lines`.
- `report_findings(findings, where)`, which prints, counts the errors and
  raises, keeping each caller's current message.
- `change_rows(changes)` and `artifact_rows(...)`, which share one
  `{key, path, kind, action}` row builder (`:774-803`). Add `finding_json`
  (`:100-106`).

Move every command onto the module in the same story, while `commands.py` is
still one file, so that the diff is only this replacement.

**Acceptance:**

- `console.set_mode` and `OutputMode.JSON` appear only in `output.py`. A test
  asserts this.
- The properties hold.

## S18.6.2 — One module per command

**State:** New · **Depends on:** S18.6.1

**Build.** Each module below holds its command and the helpers that only it
uses:

| Module | Holds |
| -- | -- |
| `commands/doctor.py` | `doctor`, split into `_run_one` and `_run_all` (`:109-191`), and `_findings` |
| `commands/new.py` | `new`, `_resolve_config`, `_flag_layer`, `_FLAG_NAMES`, `_preview_rows`, `_stage`, `STAGING`, `_record_scaffolded`, `_declared_modules`, `_without_members` |
| `commands/generate.py` | `generate_app`, `generate_package`, `_add_package`, `_package_preflight`, `_PACKAGE_NAME`, `docs_generate` |
| `commands/apply.py` | `apply`, `_validate_force` |
| `commands/config.py` | `config_update`, `config_upgrade`, `_config_reresolve`, `_config_change_rows` |
| `commands/diff.py` | `diff`, split into `_diff_artifacts` and `_diff_inventory`, and `_diffs` |
| `commands/info.py` | `version`, `prompt`, `_prompt_summary` |
| `commands/output.py` | as S18.6.1, plus `fail_on_errors` |

- `_write_config` and `_CONFIG_HEADER`, which `new`, `generate` and `config`
  share, move to `modules/core/config/catalog.py` as
  `write(directory, config)`, beside the `render` it calls.

- `doctor.py` (42 lines, one caller) folds into `checks.py` as
  `checks.run(root, full=...)`, which removes the `doctor_module` alias.

- `new.py` imports `generate._add_package` and renames it `add_package`. That is
  the one permitted edge between command modules.

- Imports of scaffold steps become module imports, for example
  `from rn_forge.kiln.modules.python import scaffold as python_scaffold`, so
  that a test patch at the definition reaches them (S18.5.1).

- Docstrings keep the contract only, per `README.md`. Drop the ADR references
  and design notes at `:8-9`, `:235`, `:432`, `:572`, `:608-611`, `:663-665`
  and `:842`. This is defect 11 of the idea page.

**Acceptance:**

- `src/rn_forge/kiln/commands.py` and `src/rn_forge/kiln/doctor.py` are gone. No
  module under `commands/` is over 350 lines.
- A test asserts that each `cli.toml` target resolves, and that each command
  module imports no other command module except as property 3 allows.
- The properties hold.

## S18.6.3 — Logic the commands borrowed goes back to its owner

**State:** New · **Depends on:** S18.6.2

Some of `new`'s and `generate`'s logic belongs to a module, not to the CLI.

**Build.**

- `_record_scaffolded` (`:321-351`) moves to `modules/core/cycle.py`, beside the
  reader of the same key. It uses `umbrella.STATE_PATH`, `SCAFFOLDED_KEY` and
  `Process.execute` in place of its own literals and `subprocess.run`.
- `_add_package`, `_package_preflight`, `_declared_modules` and
  `_without_members` move to `modules/python/scaffold.py`, beside
  `add_package`. `generate_package` keeps the command and the output.
  `add_package` takes `owner` and `repo` rather than a URL it splits again
  (`python/scaffold.py:195-196`).
- `_resolve_config` (`:354-426`) drops `owner_error` (one caller) and parses
  `Source` once (`:379`, `:425`). The `cli` and `lifecycle` defaults it seeds
  for `python-tool` and `python-app` (`:411-422`) move to `modules/python`, as
  a function `new` calls.
- `_preview_rows` (`:774-790`) and `_config_change_rows` (`:872-889`) become one
  `cycle.preview(root, config)`, which keeps today's selection exactly. The
  starter-policy difference is a defect, fixed in F18.10.

**Acceptance:**

- `commands/` imports neither `subprocess` nor `StateStore`. A test asserts
  this.
- The properties hold.
