# S18.14.1 — The config pins a commit and the branch it follows

Brief for
[S18.14.1](../F18.14-a-pin-is-a-commit.md#s18141-the-config-pins-a-commit-and-the-branch-it-follows),
at `077bead`. Read the feature's **Design**, including the decisions dated
2026-11-17. Paths are under `src/rn_forge/kiln/`.

## Goal

`[kiln] ref` is a release tag or a 40-character commit SHA, optionally with
`[kiln] track` naming the branch the SHA came from. A branch in `ref` is refused
at config load. `kiln new` pins its default branch's newest commit. Every
rendered kiln install names the pinned ref.

## Settled

- **New module `modules/core/kiln_ref.py`**, with `__all__`:
    - `TAG = re.compile(r"^v\d+\.\d+\.\d+$")` (the form `core/checks/pin.py`
      reads; make `pin.py` import it and delete its own `_TAG`), and
      `SHA = re.compile(r"^[0-9a-f]{40}$")`.
    - `REMOTE = archetypes.KILN_GIT.removeprefix("git+")`: the URL `git ls-remote`
      reads. Code reads it as `kiln_ref.REMOTE` at call time, so a test can
      repoint it.
    - `resolve(name: str) -> str`: the commit SHA of the branch or tag *name* on
      `REMOTE`, from
      `git ls-remote REMOTE refs/heads/<name> refs/tags/<name> refs/tags/<name>^{}`
      through `core.process.run` (S18.7.3). An annotated tag resolves to its
      peeled commit (`^{}`). Raise
      `AppException("kiln.ref-unknown: no branch or tag {name!r} at {REMOTE}")`
      when nothing matches.
- **Schema** (`modules/core/config/schema.py` `KilnPin`): `ref: str` and
  `track: str | None = None`. A model validator refuses:
    - a `ref` that matches neither `TAG` nor `SHA`:
      `` kiln.ref: {ref!r} names a branch; run `task kiln:pin -- {ref}` to pin its newest commit ``;
    - a `track` whose `ref` is not a SHA:
      `kiln.track: needs a commit SHA in kiln.ref`. The message must reach the
      user through the config manager's usual dotted-path error, as other field
      errors do. Update `KilnPin`'s docstrings to the new contract.
- **`kiln new`** (`commands/new.py` `_resolve_config`): when the `--config`
  layer does not pin kiln, set
  `kiln = {"ref": kiln_ref.resolve(KILN_REF), "track": KILN_REF}` in place of
  `kiln.ref = KILN_REF`. A layer that pins `kiln.ref` is used as it is (and is
  validated).
- **Rendering**: `tasks/artifacts.py` `_kiln_commands` already builds
  `kiln_command(pin.ref)`, so a SHA pin renders `@<sha>` with no change. A
  config without `[kiln]` keeps today's `KILN_REF` fallback (and `kiln-pin`
  warns).
- **Tests reach a local remote.** In `tests/conftest.py`, add a session-scoped
  fixture that builds a bare git repository under `tmp_path_factory` with one
  commit on branch `feature/v1`, and the tag `v0.0.1` on it. Add an autouse
  fixture that monkeypatches `kiln_ref.REMOTE` to that repository's `file://`
  URL. Every `kiln new` in the suite then resolves for real, offline. Expose
  the commit SHA as a fixture (`kiln_remote_sha`) for assertions.
- **Existing tests that change**: those asserting the rendered or written
  `kiln.ref == KILN_REF`, or `@feature/v1` in a rendered command, now expect
  the remote's SHA and `track = "feature/v1"`. Fixtures that write
  `[kiln] ref = "feature/v1"` by hand write the SHA, or a tag, instead
  (`tests/test_doctor.py`, `tests/test_pin.py`,
  `tests/scripts/test_golden_matrix.py`,
  `tests/modules/core/checks/test_pin.py`; there are 6 `feature/v1` and 8
  `KILN_REF` uses). Every other test passes unedited.
- `commands/config.py` `pin` is S18.14.2's. It may keep failing on a branch
  argument until then, but its existing tests must pass: give them a tag or a
  SHA.

## Current behaviour

- `KilnPin` has only `ref: str`, accepting any string.
- `kiln new` writes `[kiln] ref = "feature/v1"` (`commands/new.py:194`).
- `kiln-pin` reads tags with its own `_TAG` (`core/checks/pin.py:24`).
