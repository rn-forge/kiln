`mkdocs.yml` becomes a managed artifact with a provenance header, rendered whole
from the docs tree, `_areas.yml` and `config.toml`. Nav additions go in
`_areas.yml`. Other settings go in a `[docs.mkdocs]` table. `site_dir` is
rendered from `[docs] site_dir`; `task docs:build` passes `--site-dir` only for
an explicit output directory (`task docs:build -- <dir>`, which CI's `docs`
stage uses). The Packages section is derived from `packages` for every
`python-lib`.

**One file, two writers, one contract.** `kiln apply` owns the file outside the
`derived nav` fence; `docs-generate` owns the fence's body. So:

- The recorded hash in `state.json` covers the file with the fence's body
  emptied, and the `generated` check empties it the same way before hashing. A
  nav rewrite by `docs-generate` is not drift; any other edit is.
- The `docs-generate` check (`docs/checks/derived.py`) keeps checking that the
  fence's body is current.
- `kiln apply` renders the fence's body from `build_nav` over the tree as it is,
  never an empty fence, so an apply after `docs-generate` writes nothing.

## Context

Today `modules/docs/scaffold.py` writes `mkdocs.yml` once, and kiln owns only
the `BEGIN derived nav` fence. mkdocs's `INHERIT:` replaces lists rather than
merging them, so it cannot extend the nav or plugins. First adopters: kiln's own
`mkdocs.yml`, then pykit's and ngkit's.

## S16.2.2 — `[docs.mkdocs]` and `site_dir` render into `mkdocs.yml`

**State:** New · **Depends on:** S16.2.1

**Build — tests first,** in `tests/modules/docs/test_artifacts.py`:

1. `test_s16_2_2_1_provenance_header`: the rendered `mkdocs.yml` starts with the
   `# Generated by kiln … do not edit; run 'kiln apply'` header and is a
   `managed` artifact in `state.json` with `"derived": ["derived nav"]`;
   editing a line outside the fence makes `generated` report drift.
1. `test_s16_2_2_1b_nav_edit_is_not_drift`: rewriting only the fence's body
   leaves `generated` clean; deleting the fence's markers is drift.
1. `test_s16_2_2_2_site_dir`: `[docs] site_dir = ".docs-site"` renders
   `site_dir: .docs-site` in `mkdocs.yml`; unset renders no `site_dir`.
1. `test_s16_2_2_3_docs_mkdocs_table`: `[docs.mkdocs] plugins = ["glightbox"]`,
   `markdown_extensions = ["toc"]`, `extra_css = ["a.css"]` and
   `extra = {k = "v"}` render into the matching top-level keys, appended after
   kiln's own entries; `theme = { logo = "x.png" }` merges into `theme:`.
1. `test_s16_2_2_4_unknown_key`: `[docs.mkdocs] nav = []` is refused by
   validation (nav belongs in `_areas.yml`); so is any key outside `plugins`,
   `markdown_extensions`, `theme`, `extra`, `extra_css`, `extra_javascript`.
1. `test_s16_2_2_5_site_dir_only_when_given`: the rendered `tasks/docs.yml` root
   build is
   `mkdocs build --strict{{if .CLI_ARGS}} --site-dir "{{.CLI_ARGS}}"{{end}}`,
   and its `MKDOCS_SITE_DIR` variable is gone; each workspace package's build
   keeps its temporary `--site-dir`.
1. `test_s16_2_2_6_nav_still_derived`: the nav fence still fills from
   `_areas.yml` and the tree, at render time as well as by `docs-generate`.
1. `test_s16_2_2_7_add_page_cycle`: on a rendered repository, add
   `docs/guides/new.md` and link it from its area index; run `docs-generate`;
   then `generated` and `docs-generate` report nothing; then `kiln apply`
   writes nothing and changes no hash in `state.json`; then a second
   `kiln apply` writes nothing.

**Build:**

- `modules/docs/config.py`: `DocsMkdocs(StrictModel)` with the six keys above,
  each optional, and `DocsConfig.mkdocs: DocsMkdocs`.
- `modules/docs/artifacts.py`: render `mkdocs.yml.j2` as a managed artifact (not
  a seed) whose state entry carries `derived = ["derived nav"]`; merge the
  table in Python with PyYAML-free text emission: put the user entries through
  the existing YAML writer that `nav.py` uses. Pass
  `build_nav(root / "docs", packages)` into the render.
- `modules/core/checks/generated.py` and the engine that records hashes: one
  helper, `managed_digest(text, derived)`, empties each named block's body
  (with `ManagedBlock`) before `digest`; both the recorder and
  `_check_managed` call it. An entry without `derived` hashes as today.
- `mkdocs.yml.j2`: the header, `site_dir`, the extra entries and the nav fence,
  filled with the passed nav; `docs-generate` still rewrites the fence.
- `modules/docs/scaffold.py`: `scaffold` no longer writes `mkdocs.yml`; keep
  `PACKAGE_SEEDS` for packages' own `mkdocs.yml`.
- `modules/tasks/templates/tasks/docs.yml.j2`: the root build passes
  `--site-dir` only when given an argument; drop `MKDOCS_SITE_DIR`. The
  `site_dir` context key stays for `task clean`.
- Run `kiln apply` here: kiln's own `mkdocs.yml` becomes managed, with its
  S16.2.1 extras in `[docs.mkdocs]` and `_areas.yml`.

**Acceptance:**

- The nine tests pass, and `task validate` passes.
- `task docs:build` builds into `site_dir` from config,
  `task docs:build -- "$(mktemp -d)"` builds into the given directory, and
  `task lint KILN_DOCTOR_FULL=1` passes.
