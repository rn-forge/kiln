# ADR-0016 — Every archetype's CI follows one contract, planned by rn-forge-devops

**Status:** accepted (2026-10-18) · **Scope:** the generated CI of every
archetype

## Decision

The flow and logic of CI are the same in every kiln-managed repository, whatever
the stack. Only what runs under each `task` differs.

- **Triggers:** pull request into the default branch, push to it, and manual
  dispatch. A newer push to a pull request cancels its run; default-branch
  runs queue.
- **`validate`** (repository-wide checks, through `task`) gates everything.
- **A plan** selects changed units plus their dependents. An empty, invalid or
  non-ancestor base, or a change outside every unit and outside docs, selects
  all; docs-only selects none. A pull request diffs against its base, a push
  against the last green run, a dispatch selects all.
- **Per selected unit:** verify (lint, typecheck, test), declared extra jobs
  (services, install smoke), then workspace-wide suites.
- **Sonar** with `sonar.qualitygate.wait=true`, skipped for fork pull requests.
- **Publishing** happens only from the default branch, only for units whose
  every check passed and whose selected prerequisites are releasable, after
  the quality gate; never from a pull request. Release is idempotent and
  follows version bumps: the release, not the tag, is the record. A dispatched
  release on the default branch gated on a green CI run
  ([ADR-0015](ADR-0015.md)) satisfies this.
- **After release:** install each new release from outside the workspace, then
  deploy docs once.
- **`ci-ok`** is the single required check; a skipped job is not a failure.
- **Every step goes through `task`.** An exemption needs an ADR; ADR-0015's Nx
  calls are the existing one.

**rn-forge-devops is the standard CI planner for every archetype**, as MkDocs is
the standard docs tool ([ADR-0012](ADR-0012.md)). It holds the planning and
orchestration behind `task ci:*`. `node-lib` may keep its Nx-native affected CI
while it meets the contract. A future archetype (Java, Maven) meets it by
rn-forge-devops gaining a planner for that ecosystem, not by hand-written logic.

## Consequences

- `python-lib`'s `release` runs only on a push to the default branch and waits
  on `sonar`; before, it also ran on pull requests and dispatch, and could
  ship while the gate failed.
- A pull request still proves packaging: `smoke` installs every selected
  package's wheel with no extras, plus each declared extra. That needs an
  upstream change, pykit's: `plan` emits a no-extras smoke entry per package.
- `node-lib` carries an audit against this contract
  ([F9.1](../specs/epics/E9-node-archetypes/F9.1-node-lib-hosts-ngkit-ci.md)).
- Logic that lives in a repository's workflow, not in `task`, is drift.

## Influences

- [Standard, section 8](../reference/standard-repo.md#8-ci-shape): states the

- [S6.4.7](../specs/epics/E6-rebuild-the-repos/F6.4-workspace-pipeline.md#s647-release-publishes-from-the-default-branch-after-the-quality-gate):
  brings `python-lib` to the release rule.
- [E9](../specs/epics/E9-node-archetypes/index.md): `node-lib` must meet it.
- [How a `python-lib` CI run flows](../architecture/python-lib-ci.md).

## Alternatives considered

- **Each archetype's CI as its stack's tooling prefers.** Three pipelines would
  hold three sets of selection and release rules, and a fix to one would not
  reach the others.
- **Hand-written planning logic per stack.** It would sit in the repository's
  workflow, outside `task`, and drift per repository.
- **Move `node-lib` onto rn-forge-devops now.** It would discard Nx's own
  affected graph for no gain while ngkit's CI meets the contract.

## Background

- 2026-10-18: owner decision. [ADR-0014](ADR-0014.md) chose rn-forge-devops for

  match the standard's "`release` depends on `sonar`".
