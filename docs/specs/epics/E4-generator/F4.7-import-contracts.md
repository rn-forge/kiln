Phase step: D.7

kiln's own `.importlinter` already holds two contracts and `task lint` runs
`lint-imports` (`tasks/quality.yml`, `lint:imports`). `no-kit-imports` forbids
`typer`, `jinja2`, `click`, `django` and `fastapi` anywhere in `rn_forge.kiln`;
`render-free-checks` forbids `jinja2` in the checks packages
([ADR-0006](../../../adr/ADR-0006.md)). The rn-forge half of the boundary — no
`rn_forge.django`, `rn_forge.fastapi`, `rn_forge.web` — cannot be an
import-linter contract, because import-linter rejects subpackages of external
packages; `kiln doctor`'s rn-forge-deps rule enforces it at the dependency
declaration ([ADR-0005](../../../adr/ADR-0005.md)), and
`tests/test_checks_are_render_free.py` enforces the
`rn_forge.tooling.generation` half of the render-free rule. This feature closes
the two gaps that remain, and settles where a repo's own contracts live once
kiln regenerates its own skeleton.

## S4.7.2 — A repo's own contracts survive `kiln apply` (owner decision)

**State:** Closed (2026-10-14) · Must close before [F4.8](F4.8-self-hosting.md)

The `python` module renders `.importlinter` as a whole-file `managed` artifact
from `importlinter.j2`. That template holds only the generic
`frameworks-come-from-rn-forge` contract, plus `packages-are-independent` for a
workspace. When F4.8 runs `kiln apply --force` on kiln itself, it replaces the
hand-authored file. That drops `render-free-checks` and
`concern-modules-are-independent`, and F4.8's acceptance still passes because
`lint-imports` keeps whatever contracts are left. Any generated repo that wants
a contract of its own has the same problem.

**Decided 2026-10-14 (owner): `.importlinter` becomes a `block` artifact.** It
uses `ManagedBlock("rn-forge kiln")`, the same `#` markers as `.gitignore`;
`configparser` reads `#` lines as comments. kiln's block holds `[importlinter]`
and the generic contracts, and the repo adds its own `[importlinter:contract:…]`
sections below the end marker. A block is the ownership model kiln already has
for a file it shares with the repo (`.gitignore`, `CLAUDE.md`), so this adds no
new mechanism and no config key. The build is
[S4.7.3](#s473-importlinter-is-a-block).

Rejected:

- **A config key listing extra contracts.** A schema addition with one consumer.
- **A second, repo-owned config run by a second task.** `lint-imports` reads one
  config per run, and the generated `lint:imports` task would change for every
  repo.

**Acceptance:**

- The choice and the reason are recorded on this story, and the build story it
  implies is written with a Build list.

## S4.7.3 — `.importlinter` is a block

**State:** New · **Depends on:** S4.7.1, S4.7.2

A block appended to a file that already holds an unfenced `[importlinter]`
section would leave two `[importlinter]` sections, which `configparser` rejects.
So kiln refuses to append its block to an existing `.importlinter` that has no
markers, and says how to fence it. Once the repo has fenced it, the first apply
reports the block as a `conflict`, and `kiln apply --force .importlinter`
rewrites the block's body. That is the defined first apply for an existing repo,
kiln's own included (F4.8). `kiln new` writes the block into an empty file and
needs nothing extra.

**Build:**

- `src/rn_forge/kiln/modules/python/artifacts.py`:

    - Add `IMPORTLINTER_BLOCK = ManagedBlock("rn-forge kiln")`, with the docstring
      `"""kiln's fenced block in the repo's `.importlinter`."""`, the way
      `core/artifacts.py` declares `GITIGNORE_BLOCK`. Add it to `__all__`.
    - `render` returns the artifact as
      `Artifact(".importlinter", ArtifactKind.BLOCK, engine.render("importlinter.j2", context), block=IMPORTLINTER_BLOCK)`.
    - The module docstring becomes
      `"""The artifacts `python`renders: kiln's block in`.importlinter`."""`.

- `src/rn_forge/kiln/modules/python/templates/importlinter.j2`: replace the
  first line with these two lines. Change nothing else in the template.

    ```ini
    ; Generated by kiln {{ kiln_version }} from .rn-forge/kiln/config.toml — do not edit inside this block; run 'kiln apply'.
    ; A contract of this repo's own goes below the END marker, as its own [importlinter:contract:<name>] section.
    ```

- `src/rn_forge/kiln/modules/core/cycle.py`:

    - Add, below `STATE_SCHEMA_VERSION`:

        ```python
        """Files a block may not be appended to: a second `[importlinter]` section is
        a `configparser` error, so an unfenced file is refused instead."""

        ```

      `def _without_converted(entries: Mapping[str, StateEntry], artifacts: Sequence[generation.Artifact]) -> dict[str, StateEntry]`.
      It returns *entries* without every entry whose `kind` is not

      `block` is not `None`. Docstring: a file kiln used to own whole and now
