# S18.10.5 — Provenance compares like with like

at `feature/v1` after `86e36ef`.

## Goal

A config whose audit reason carries trailing whitespace re-resolves with no
override reported, and a test keeps it so.

## Settled

- Owner decision (2026-11-24): the defect does not reproduce at `86e36ef` (the
  only stripping validator, `AuditIgnore._reason_is_given`, runs inside
  `CiConfig.audit_policy()`, never on the document), so this story is a
  regression test only. The test passes before and after; that is expected.
- No production change. `ConfigManager._merge` keeps recording provenance from
  the merged document, which is also what `KilnConfig.to_document()` writes.
- The test lives beside `test_re_resolution_keeps_and_lists_a_repo_override`.
- Rejected (do not build): stripping the reason in the document, and recording
  provenance from `resolution.config.to_document()`; neither changes
  behaviour.

## Current behaviour

- The test below passes before and after. State that in `## Result`.
- It would fail if a later change made the written document and the recorded
  provenance differ for a normalised field.

## Tests first

`test_re_resolution_of_an_untrimmed_audit_reason_lists_no_override`:

- `write_layer(layer, {"ci": {"checks": {"pip-audit": {"ignore": [{"id": "GHSA-aaaa-bbbb-cccc", "reason": "accepted  "}]}}}})`
  where `layer` is `tmp_path / "profile" / "config.toml"`.
- `commit(repo, ConfigManager().resolve(flags=FLAGS, source=Source(str(layer)), base=repo), source=str(layer))`
  with `repo = tmp_path / "repo"`, as
  `test_re_resolution_keeps_and_lists_a_repo_override` does.
- `resolution = ConfigManager().reresolve(repo)`. Assert
  `resolution.overrides == ()` and
  `resolution.config.ci.audit_policy().ignore[0].reason == "accepted"`.
