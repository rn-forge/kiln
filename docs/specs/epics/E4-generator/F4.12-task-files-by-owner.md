Each generated task file belongs to one toolchain or one concern, and a check
lives in the file of whatever owns the thing it checks
([ADR-0007](../../../adr/ADR-0007.md), revised 2026-10-21). kiln is a toolchain
in that sense: its own checks run as one internal task, `kiln:doctor`, not as
one task per check. This does not change the ten root verbs. The public surface
changes in two places: `docs:structure` is removed, so the public docs verbs are
`docs:build`, `docs:serve` and `docs:generate` (S4.12.1 renamed it `docs:lint`,
and S4.12.6 removes that), and `web:lint`, `web:test` and `web:build` move into
an internal `node` namespace.

## Context

Raised by the owner on 2026-10-21, reading `task --list`. `tasks/quality.yml`
holds every lint, format, typecheck and test primitive, whatever it acts on: the
docs checks, the CI checks, the uv toolchain, and the repository-wide checks.
`tasks/workspace.yml` holds the rest of the uv toolchain (sync, build, version),
and also, for `python-web-app`, `pnpm install`. `tasks/web.yml` mixes the Nx
toolchain (`lint`, `test`, `build`) with the frontend dev server. So uv commands
are spread over three files, pnpm over two, and a module cannot add its own
checks without editing `quality.yml`. `docs:structure` is also the only public
check verb that is not named after the root verb it feeds, and it runs only one
of the three docs checks.

**Why S4.12.5–S4.12.7 (2026-10-21).** After S4.12.4 the owner read the root
`lint` task. Nine of its entries were tasks whose whole body was
`uv run kiln doctor . --only <check>`, spread over three files, each with its
own `command_overrides` key, and a public `docs:lint` that only called three of
them. Bare `kiln doctor` ran just six of the nine checks, so a task per check
was the only way to run the other three. The owner decided that bare
`kiln doctor` runs every render-free check (each takes under half a second,
measured 2026-10-21: about 0.25–0.5 s per `--only` call and about 0.6 s for
`--full`, so a fast tier would buy nothing), that kiln's checks are one task
because kiln is a toolchain like uv, and that `--only` then has no caller.
S4.12.5 makes doctor run them, S4.12.6 replaces the tasks with `kiln:doctor`,
and S4.12.7 removes `--only`. [ADR-0003](../../../adr/ADR-0003.md) and
[ADR-0007](../../../adr/ADR-0007.md) were revised the same day.

**Why now, in release-1.** `docs:structure` is public, and ADR-0007 makes
renaming a public verb a breaking change. Today nothing calls it outside kiln:
pykit's real `kiln init` waits for the release-1 tag
([F7.2](../E7-pykit-release-pin-flip/F7.2-kiln-release-and-config-upgrade.md)).
After the tag, every adopting repository would need the rename. `node-lib`
([F9.1](../E9-node-archetypes/F9.1-node-lib-hosts-ngkit-ci.md)) has not had its
stories written yet, so it can start from `node.yml` instead of inventing a
second Nx file.

## Design

### The layout after this feature

| File | Namespace | Holds | Public |
| -- | -- | -- | -- |
| `tasks/python.yml` | `python` | the uv toolchain: `install`, `lint`, `lint:imports`, `lint:audit`, `format`, `typecheck`, `test`, `test:coverage`, `build`, `version` | none |
| `tasks/node.yml` (`python-web-app`) | `node` | the pnpm/Nx toolchain: `install`, `lint`, `test`, `build` | none |
| `tasks/kiln.yml` | `kiln` | kiln's own checks, run once: `doctor` | none |
| `tasks/docs.yml` (`mkdocs`) | `docs` | the site's verbs | `build`, `serve`, `generate` |
| `tasks/ci.yml` | `ci` | `lint:workflows` (zizmor, actionlint); for `python-lib`, the CI-only pipeline tasks as today | `python-lib`'s CI-only tasks only |
| `tasks/quality.yml` | `quality` | the tree's formatting: `lint:markdown`, `lint:toml`, `format:markdown`, `format:toml` | none |
| `tasks/workspace.yml` | `workspace` | `clean` | none |
| `tasks/api.yml` (web) | `api` | `dev`, and `migrate` for Django | all |
| `tasks/web.yml` (`python-web-app`) | `web` | `dev` | all |

This is the layout after S4.12.7. S4.12.5–S4.12.7 supersede parts of S4.12.1 and
S4.12.2: they built `docs:lint` and a task per doctor check, and S4.12.6 removes
both. The closed stories below record what each built at the time.

Root wrappers keep their order. Each of S4.12.1–S4.12.4 replaces a ref **in
place**: the renamed task is called from the same position its old name was. The
exception is the three docs refs in `lint`, which S4.12.1 collapsed into a
single `docs:lint` at the first one's position. S4.12.6 then reorders `lint`
once, to the order it gives.

### Decisions

- **kiln's checks are one task.** `kiln:doctor`, in `tasks/kiln.yml`, runs
  `kiln doctor` once and is called by the root `lint`. It has no
  `command_overrides` key, so a repository cannot switch off a single kiln
  rule. The ten tasks that ran one check each (`quality:lint:generated`,
  `quality:lint:rn-forge-deps`, `quality:lint:task-layout`,
  `ci:lint:entrypoint`, `ci:lint:pins`, `ci:lint:hooks`, `docs:lint`,
  `docs:lint:site`, `docs:lint:structure`, `docs:lint:generate`) and the
  public `docs:lint` are removed by S4.12.6. The public docs verbs are
  `docs:build docs:serve docs:generate`. The doctor checks are not renamed.
- **Bare `kiln doctor` runs every render-free check.** The six ownership checks
  (`generated`, `task-layout`, `ci-entrypoint`, `ci-pins`, `ci-hooks`,
  `docs-generate`) and the three that read repository-owned content
  (`rn-forge-deps`, `docs-structure`, `docs-site`), by owner decision of
  2026-10-21 and [ADR-0003](../../../adr/ADR-0003.md)'s revision. `--full`
  adds the render diff and `--all` takes several paths, both as before.
  `--only` is removed (S4.12.7) and no flag is added.
- **`kiln new`, `kiln init`, `kiln apply` and `kiln config update|upgrade` run
  only the ownership checks.** Their shared `_fail_on_errors` calls
  `checks.run(root, scope="ownership")` (S4.12.5), so a broken link or a
  dependency edit in repository-owned content never fails a regeneration. The
  `Check.scope` field stays for that.
- **`rn-forge-deps` stays a kiln check.** Archetype dependency policy is kiln's
  ([ADR-0002](../../../adr/ADR-0002.md)), and the check is the only
  enforcement of ADR-0002's rule that a product never imports a peer product,
  which import-linter cannot express. A repository not built with kiln is
  outside the standard whatever kiln does; [the ideas list](../../ideas.md)
  holds a pykit-side check for such repositories.
- **Markdown and TOML stay in `quality`.** Markdown lint does not go into
  `docs.yml`: `docs.yml` renders only under `profile = "mkdocs"`, but a `none`
  or `external` repository still has `README.md`. Both are file-format checks
  over the whole tree. Neither gets its own file, because each is two tasks.
- **`ci.yml` renders for every archetype**, because the workflow check applies
  to every archetype (S4.12.2 put four checks here; S4.12.6 leaves
  `lint:workflows`). `python-lib`'s public CI-only tasks stay
  `python-lib`-only, inside `{% if workspace %}`. `ci` is not added to
  `RESERVED_NAMESPACES`, because it has public tasks (as `docs` does). It is a
  managed namespace, so a `[tasks] includes` entry still cannot take it
  (`_check_includes`).
- **`python` and `node` join `RESERVED_NAMESPACES`**, so `task-layout` requires
  every task in them to be `internal: true`, as for `quality` and `workspace`.
- **`web:lint`, `web:test` and `web:build` leave the public surface.** Root
  `lint`, `test` and `build` already run them, and no generated workflow calls
  them (checked 2026-10-21: `cicd/templates` names no `web:` task).
- **`command_overrides` keys are renamed with no alias or migration.** A key
  names an internal task, so the key changes when the task is renamed, and the
  old key fails the way any unknown key does:
  `tasks.command_overrides.<key>: unknown task — this archetype renders …`,
  listing the new names. No adopted repository sets an override (checked
  2026-10-21: kiln's own config has none, and pykit and ngkit carry no kiln
  config yet). The two documented examples (`"quality:test:python"`, in
  `docs/reference/standard-repo.md` and `docs/runbooks/creating-a-repo.md`)
  are updated by S4.12.4. S4.12.6 removes the keys of the ten tasks above the
  same way.
- **Out of scope.** `python-lib`'s `ci:verify` keeps its own `uv run` lines. It
  runs the toolchain for one member at a time with CI's own arguments, and
  folding it into `python:*` would mean a per-package parameter on every
  `python` task. `node-lib`'s use of `node.yml` belongs to F9.1. The doctor
  check names are not touched.

### Rules for every story

- **Serial.** S4.12.1–S4.12.4 and S4.12.6 each edit `Taskfile.yml.j2` and
  `tasks/artifacts.py`, and S4.12.5 and S4.12.7 edit `checks.py` and
  `commands.py` that the generated tasks call, so they run in order: S4.12.1 →
  S4.12.2 → S4.12.3 → S4.12.4 → S4.12.5 → S4.12.6 → S4.12.7.
- **Old names in tests.** Every existing test or fixture that names a task the
  story renames is updated to the new name in the same story. Find them with
  `grep -rn -e '<old name>' tests src` for each row of the story's map. A test
  that only asserted where a task used to live (for example S4.11.2's
  `quality[f"lint:{name}"]`) is pointed at the new file. It is not deleted.
- **Moved tasks keep their bodies.** A task that moves between files keeps its
  `desc`, its comments, its `env`, every `{% if workspace %}` /
  `{% elif web %}` branch, and its `overrides.get(...)` branch line for line.
  Only the override key changes, to the new full name. The test for this is
  the golden compare: a moved task's commands appear in the diff only as a
  move.
- **kiln's own files are hand-copied.** kiln's `Taskfile.yml`, `tasks/*.yml`,
  `CLAUDE.md` block and `.rn-forge/kiln/standard.md` are owned by the golden
  until [S4.8.1](F4.8-self-hosting.md#s481-kiln-generates-itself). Each story
  copies them from the rendered `python-tool` cell (`task self:golden:render`,
  then `.goldens/working/python-tool/`), changing only the provenance line to
  `kiln golden`. It re-seeds each changed entry's `content_hash` in
  `.rn-forge/kiln/state.json`, and adds a `managed` entry for each new file,
  as S4.11.2's record does. `tasks/self.yml` is kiln's own and is not touched.
- **The design inventory.** Each story updates its rows of
  [design.md's template inventory](design.md#template-inventory) to the layout
  above.
