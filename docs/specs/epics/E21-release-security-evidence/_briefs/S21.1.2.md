# S21.1.2 — `kiln-devops evidence collect`

Brief for
[S21.1.2](../F21.1-evidence-record.md#s2112-kiln-devops-evidence-collect), at
`feature/v1` `f0653949`.

## Goal

`kiln-devops evidence collect` reads a release run through the GitHub API (and
PyPI's and Scorecard's public APIs), and writes `security-evidence.json`: the
result and evidence of every security control on the pushed commit. It also
prints the record as a Markdown table, for the job summary.

## Settled

### The boundary

`kiln-devops` may import only the standard library, `packaging` and
`rn_forge.kiln.devops.*` (ADR-0017; `tests/devops/test_boundary.py`). It must
**not** import `rn_forge.kiln.modules.cicd.controls`. The catalog reaches it as
a JSON file that kiln renders (owner decision, 2026-11-24; the rendering is
S21.1.3). This story defines that file's shape and reads it; it does not render
it.

### The controls file (input, `--controls FILE`)

```json
{
  "release": "tag-exists",
  "controls": [
    {"name": "Dependency audit", "effect": "fails the build", "source": "lint-job",
     "runs": true, "job": "validate", "step": "Validate"},
    {"name": "Secret scan", "effect": "fails the build", "source": "job",
     "runs": true, "job": "secret-scan"},
    {"name": "Push protection", "effect": "blocks the push", "source": "not-checked",
     "runs": true}
  ]
}
```

- `release` is the repository's `[ci] release` mode (`pypi`, `tag-exists`,
  `npm`, `nx-dispatch`, `none`).
- One entry per control, in catalog order. `effect` and `source` are the
  catalog's `Effect` and `Source` values (strings; the collector treats
  `effect` as opaque text and dispatches on `source`). `runs` is whether this
  repository runs the control. `job` is present for sources `lint-job` and
  `job`; `step` for `lint-job`.
- A missing file, invalid JSON, or an unknown `source` exits 2 with
  `kiln-devops: <reason>` on stderr and writes nothing.

### The record (output, `--out FILE`, default `security-evidence.json`)

```json
{
  "repository": "rn-forge/kiln",
  "commit": "<sha>",
  "run": 123,
  "attempt": 1,
  "packages": [{"name": "rn-forge-kiln", "version": "0.4.0", "tag": "rn-forge-kiln-v0.4.0"}],
  "controls": [
    {"name": "Dependency audit", "effect": "fails the build", "result": "passed",
     "evidence": {"url": "https://github.com/.../job/9", "detail": "job validate, step Validate"}}
  ]
}
```

- `controls` has one entry per controls-file entry, same order. `result` is one
  of `passed`, `failed`, `not run`, `not checked`. `evidence.url` is a string
  or `null`; `evidence.detail` is a string.
- Written with `json.dumps(record, indent=2) + "\n"`, keys in the order shown.

### How each source is read

All GitHub reads go through one new adapter function in
`src/rn_forge/kiln/devops/github.py`:

```python
def api(path: str) -> tuple[int, Any]:
    """Return the HTTP status and JSON body of `gh api <path>`; the body is None unless 200."""
```

It runs `["gh", "api", path]` with `_capture`. Exit 0 →
`(200, json.loads(stdout))`. Otherwise it takes the status from `HTTP (\d{3})`
in stderr, or `0` when there is none, and returns `(status, None)`. Paths use
gh's `{owner}/{repo}` placeholders, so `gh` resolves the repository from
`GH_REPO` or the checkout. Two public-API helpers go beside `indexed_files` in
the same module, with `urllib` like it:

```python
def pypi_provenance_status(name: str, version: str, filename: str) -> int:
    """Return the HTTP status of PyPI's integrity API for `filename` of `name` at `version`."""
    # GET https://pypi.org/integrity/{name}/{version}/{filename}/provenance

def scorecard_result(repository: str) -> dict[str, Any] | None:
    """Return the Scorecard API's newest result for `repository`, or None for any answer other than 200."""
    # GET https://api.securityscorecards.dev/projects/github.com/{repository}
```

New module `src/rn_forge/kiln/devops/evidence.py` (imports `github` only from
kiln) holds the logic. Rules, with `R = repos/{owner}/{repo}`:

1. **Repository.** `api(R)` → `full_name`, `default_branch`.
1. **Jobs.**
   `api(f"{R}/actions/runs/{run}/attempts/{attempt}/jobs?per_page=100")` →
   `jobs[]` with `name`, `conclusion`, `html_url`. A job matches a control's
   `job` when its `name` equals it or starts with `f"{job} / "`.
1. **Packages.** `api(f"{R}/git/matching-refs/tags")` → refs. A ref whose
   `object.type` is `commit` and `object.sha == sha` is a tag at the commit;
   for `object.type == "tag"`, `api(f"{R}/git/tags/{object.sha}")` and use its
   `object.sha`. Each tag `t` gives a package:
   `name, _, version = t.rpartition("-v")`; when `name` is empty (`v<version>`
   tags), `name` is the repository name (the part of `full_name` after `/`)
   and `version` is `t[1:]`. Packages in tag-name order.
1. **Releases.** For each package, `api(f"{R}/releases/tags/{tag}")` →
   `html_url` and `assets[]` with `name` and `digest` (`sha256:…`, may be
   missing). A 404 means the package has no release.

Per control (`runs: false` → always `not run`, evidence
`{"url": null, "detail": "not run by this repository"}`):

| `source` | `result` | `evidence` |
| -- | -- | -- |
| `lint-job`, `job` | matching job's `conclusion`: `success` → `passed`; `failure`, `cancelled`, `timed_out` → `failed`; `skipped`, `null`, or no matching job → `not run` | url: the job's `html_url` (null if none); detail: `job <job>, step <step>` (`lint-job`) or `job <job>` (`job`) |
| `not-checked` | `not checked` | url null; detail `not read by CI` |
| `release-asset` | no packages → `not run`; every package has a release with an asset ending `.cdx.json` → `passed`; else `failed` | url: the first release's `html_url` (null if none); detail: `<tag>: <asset>, <asset>` per package joined by `; `, `<tag>: no SBOM` or `<tag>: no release` where missing |
| `attestation` | no packages → `not run`; else every checked file status 200 → `passed`, else `failed` | url null; detail: `<file> <status>` per file joined by `; ` |
| `file` | `api(f"{R}/contents/SECURITY.md?ref={sha}")`: 200 → `passed`, 404 → `failed` | url: `https://github.com/<full_name>/blob/<sha>/SECURITY.md`; detail `SECURITY.md` |
| `scorecard-run` | `api(f"{R}/actions/workflows/scorecard.yml/runs?branch={default_branch}&status=completed&per_page=1")`: no run → `not run`; run `conclusion == "success"` → `passed`, else `failed` | url: the run's `html_url`; detail: `commit <head_sha>` plus, when `scorecard_result(full_name)` is not None, `, score <score>, Scorecard <scorecard.version>` |

- Attestation files: every release asset of every package (skip names ending
  `.publish.attestation`). Status is `api(f"{R}/attestations/{digest}")`'s
  status, or `0` for an asset with no `digest`. When `release` is `pypi`, add,
  for each package, each wheel in `indexed_files("pypi.org", name, version)`
  with `pypi_provenance_status(name, version, filename)` as its status.
- Any other non-200 answer from the repository, jobs, matching-refs or
  `git/tags` reads exits 2 with
  `kiln-devops: GitHub API <path>: HTTP <status>` and writes nothing. Releases
  (404 allowed), contents (404 → `failed`) and attestations (status recorded)
  never exit.
- The collector never writes to any API: only GET reads.

### The table (stdout)

`evidence.table(record) -> str` returns:

```text
| Control | Effect | Result | Evidence |
| -- | -- | -- | -- |
| Dependency audit | fails the build | passed | [job validate, step Validate](https://...) |
```

The evidence cell is `[detail](url)` when `url` is set, else `detail`. Any `|`
in a cell is written `\|`. `collect` prints it, followed by a newline, after
writing the file. S21.2.1 will reuse `table`.

### The command

In `src/rn_forge/kiln/devops/cli.py`, a new `evidence` parser with its own
required subparsers (`dest="evidence_command"`); `collect` takes `--run ID`
(digits), `--attempt N` (digits, default `1`), `--sha SHA` (`^[0-9a-f]{7,40}$`),
`--controls FILE` (required), `--out FILE` (default `security-evidence.json`).
Validate the patterns with the existing `_checked` helper in a `validate=`
function, as `_check_umbrella` does. Exit 0 when the file is written, whatever
the results.

Rejected (do not build): downloading assets for `gh attestation verify` (the
attestations API by digest needs no download); parsing job logs; writing to
`$GITHUB_STEP_SUMMARY` directly (S21.1.3's task redirects stdout); retries.
