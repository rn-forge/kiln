## S11.3.1 — `kiln generate package <name>` for `python-lib`

**Status:** planned

**Build:**

- The CLI is `kiln generate package <name> [path]`, with `path` defaulting to
  `.`, wired in `main.py` and `commands.py` the way `apply` is. It takes
  `--json`, which lists the paths written and the apply result.
- Preflight runs before anything is written, and each failure exits non-zero:
    - The archetype is not `python-lib`: `generate.unsupported-archetype`.
    - `<name>` is not a kebab-case distribution name, is already in
      `config.packages`, or `packages/<name>` exists: `generate.package-exists`
      or `generate.invalid-name`.
    - `git remote get-url origin` fails or is not a GitHub remote:
      `generate.no-remote`, with the message
      `a published package needs the repository's GitHub remote: git remote add origin https://github.com/<owner>/<repo>`.
      Both `https://github.com/<owner>/<repo>[.git]` and
      `git@github.com:<owner>/<repo>[.git]` are accepted.
- Once preflight passes, the command runs these steps in order:
    1. It appends `packages/<name>` to `[archetype.python-lib] packages` in
       `.rn-forge/kiln/config.toml`. The file is edited in place with its
       comments kept, the way S4.5.4's `config update` writes it.
    1. It runs
       `modules/python/scaffold.py:add_package(root, config, name, remote)`. This
       runs `uv init` and `_reconcile` for the member, exactly as `scaffold`
       does per member today. It then appends the member to the root
       `[tool.uv.workspace] members`, adds `<name> = { workspace = true }` to
       `[tool.uv.sources]`, and adds `<name>` to the `workspace` dependency
       group. Last, it writes the member's `[project.urls]` from *remote*, using
       the [E11 design](index.md#design)'s table. The remote is read only here,
       which is a scaffold function.
    1. It runs `modules/docs/scaffold.py:add_package(root, config, name)`, which
       renders these seeds once each, skipping any that exist, from
       `modules/docs/templates/package/`: `mkdocs.yml`, `docs/index.md`,
       `docs/guides/usage.md`, `docs/reference/api.md`, `docs/changelog.md`,
       `CHANGELOG.md` and `README.md`.
    1. It runs the apply cycle in-process, so the managed files that depend on
       `config.packages` are updated. These include the nav block,
       `tasks/docs.yml`, the task files and the workflows.
- `kiln new --archetype python-lib` also seeds
  `docs/runbooks/adding-a-package.md`, which is added to `SEEDS` for
  `python-lib` only. The runbook says to set `origin`, run
  `kiln generate package <name>`, then fill the package's guides. Add it to
  the golden first.

**Tests:** a new `tests/test_generate_package.py`. It uses
`tests/modules/python/test_scaffold.py`'s `uv` fixture pattern for the scaffold
steps.

**Acceptance:**

- In a fresh `kiln new` `python-lib` repository whose `origin` is
  `https://github.com/rn-forge/golden-lib`, the command runs
  `generate package golden-alpha`, then `generate package golden-beta`. The
  resulting files equal the S11.2.1 golden's, apart from name and
  provenance-version lines. Seeded pages that the golden extended by hand must
  contain the seed's lines in order, as in S4.3.2.
- `uv sync`, `task validate` and `kiln doctor` pass in that repository, and a
  second `kiln apply --dry-run --json` is all `unchanged`.
- An `ssh` remote and an `https` remote for the same repository write the same
  `[project.urls]`.
- With no `origin`, the command fails with `generate.no-remote`, and
  `git status --porcelain` is unchanged.
- A repeated name fails with `generate.package-exists`, and a `python-app`
  repository fails with `generate.unsupported-archetype`. Neither writes
  anything.

## Acceptance

```bash
set -euo pipefail
fails_with() { local out rc=0; out=$("${@:2}" 2>&1) || rc=$?; [ "$rc" -ne 0 ] && grep -qF -- "$1" <<<"$out"; }
cd rn-forge/kiln
kiln_dir=$PWD
kiln() { uv run --project "$kiln_dir" kiln "$@"; }
uv run pytest -q tests/test_generate_package.py                                       # S11.3.1
s=$(mktemp -d)
kiln new "$s/lib" --archetype python-lib --docs mkdocs --yes </dev/null
cd "$s/lib"
git init -q
before=$(git status --porcelain)
fails_with generate.no-remote kiln generate package alpha                            # S11.3.1
[ "$(git status --porcelain)" = "$before" ]                                           # S11.3.1
git remote add origin git@github.com:rn-forge/f11-proof.git
kiln generate package alpha                                                           # S11.3.1
rg -q 'Documentation = "https://rn-forge.github.io/f11-proof/packages/alpha/latest/"' packages/alpha/pyproject.toml
test -f docs/runbooks/adding-a-package.md                                             # S11.3.1
fails_with generate.package-exists kiln generate package alpha                       # S11.3.1
uv sync && task validate                                                              # S11.3.1
kiln apply --dry-run --json | jq -e 'all(.artifacts[]; .action == "unchanged")'       # S11.3.1
```
