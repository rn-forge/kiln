# ADR-0021 — Each file type has one formatter, run through quality tasks

**Status:** accepted (2026-11-10) · **Scope:** the formatting of every generated
repository, and kiln's

## Decision

**One formatter owns each file type, in every archetype the type occurs in.**
The same file is never formatted one way in a Python repository and another way
in a Node one, and no file kiln generates is left out of the check.

- **A type that no language toolchain owns gets a uv-installed formatter and a
  pair of internal tasks**, `quality:lint:<type>` and `quality:format:<type>`,
  fed by the file list the existing Markdown and TOML tasks already use. The
  root `lint` and `format` verbs call the pair. Markdown (mdformat) and TOML
  (taplo) already work this way; YAML joins them.
- **A language toolchain's formatter stays in the toolchain's namespace**: ruff
  for Python in `python:`, and Prettier for TypeScript, HTML, SCSS and JSON in
  `node:`. A file type is owned by one of the two kinds, never by both. Each
  tool's ignore file or config lists the types it does not own
  ([ADR-0012](ADR-0012.md) did this for Markdown).
- **YAML is formatted by one uv-installed formatter in every archetype**,
  including the Node ones, which carry Python and uv anyway. Prettier no
  longer formats YAML. The expected tool is Google's `yamlfmt`, installed from
  PyPI as the `google-yamlfmt` wheel, with `yamlfix` as the fallback.
  `google-yamlfmt` is a third party's repackaging of Google's Go binary (not
  Google's own publication), which is a supply-chain risk, accepted because
  the version floor and the lock pin one release and S19.1.1 tried it on every
  rendered file.
- **The formatter covers kiln-owned YAML too**: workflows, `Taskfile.yml`,
  `tasks/*.yml`, `mkdocs.yml` and the composite actions. kiln's templates are
  fixed until a fresh render of every archetype is clean for Markdown, TOML
  and YAML, and a test proves it. `pnpm-lock.yaml` is excluded, because pnpm
  writes it, through the formatter's own generated config.
- **JSON is parked.** Prettier keeps JSON in the Node archetypes, and the Python
  archetypes get no JSON formatter yet.

The table says which tool owns which type before and after this decision.

| Type | Tool | Where it runs | Archetypes | After this ADR |
| -- | -- | -- | -- | -- |
| Python | ruff | `python:` | the Python archetypes, and the backend of `python-web-app` | unchanged |
| Markdown | mdformat | `quality:` | every archetype | unchanged |
| TOML | taplo | `quality:` | every archetype | unchanged |
| TypeScript, HTML, SCSS | Prettier | `node:` | `node-lib`, the frontend of `python-web-app` | unchanged |
| JSON | Prettier | `node:` | the Node archetypes | unchanged; none in the Python archetypes |
| YAML | Prettier in the Node archetypes (kiln-owned files excluded); none in the Python ones | `node:` | the Node archetypes | the YAML formatter, in `quality:`, in every archetype |

## Consequences

- A rendered repository is clean under mdformat, taplo and the YAML formatter in
  every archetype. A template that renders unformatted YAML is a defect in the
  template, found by a test, not by the first repository to run `task format`.
- `task format` can rewrite a kiln-owned file in the same run that `kiln doctor`
  flags it as drift, so the templates must already be in the formatter's form.
  The fix for a diff is always in the template.
- Every archetype's dev dependencies gain the YAML formatter, and every
  archetype's `quality.yml` gains the task pair. The Node archetypes'
  `.prettierignore` block lists `*.yml` and `*.yaml` under "Formatted by other
  tools".
- `pnpm-lock.yaml` and anything else a package manager writes are excluded by
  the formatter's config, not by a kiln check.
- The Python archetypes still format no JSON. A repository that has hand-written
  JSON adds its own task through `[tasks] includes` ([ADR-0007](ADR-0007.md)).
- Adding a type later is one decision of this shape: a formatter, a task pair,
  an ignore line wherever another tool would otherwise touch the type.

## Alternatives considered

- **Prettier for YAML in every archetype.** Prettier is Node. A Python
  repository would need Node, a package manifest and a lockfile for one file
  type, against `uv`, which every archetype already has.
- **A formatter per archetype** (Prettier for YAML in the Node archetypes, a
  Python tool in the others). The same template would then be formatted two
  ways, and a kiln-owned file could not be clean under both.
- **Exclude kiln-owned YAML from the formatter.** It is the quickest way to a
  green first run, and it leaves every template unchecked: the file a
  repository reads most often would be the one nothing formats. F16.9 found a
  generated `config.toml` that taplo rejected; the same can hold for YAML.
- **A JSON formatter in the Python archetypes now.** Deferred, not refused.
  Python repositories hold almost no hand-written JSON, and the one common
  file, `*.code-workspace`, is JSONC with comments, which a strict JSON
  formatter rejects. Revisit when a Python archetype renders JSON that people
  edit.
- **`yamllint`.** It reports and does not rewrite, so `task format` could not
  fix what `task lint` found.
- **`yamlfmt` from PyPI.** An unrelated ruamel-based tool with the same name,
  not Google's. The wheel to install is `google-yamlfmt`.

## Background

- 2026-11-10: the owner set the rule while looking at why the Node archetypes
  format YAML with Prettier and the Python ones format it with nothing, and
  chose a uv-installed formatter for every archetype, covering kiln's own
  files. The tool is proposed pending the spike story of E19.
- 2026-11-10: S19.1.1 tried google-yamlfmt on every rendered YAML file and
  accepted it.
