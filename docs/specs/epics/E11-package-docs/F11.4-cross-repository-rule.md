# F11.4 — The docs rules are one standard, and kiln owns them

Decision: [ADR-0009](../../../adr/ADR-0009.md)

kiln's own `docs/specs/_structure.md` gained the cross-repository rule on
2026-09-26, when the ADR was accepted. By then pykit and ngkit had adopted the
docs tree from the seed and each had diverged from it and from kiln. This
feature merges the three into one set of `_structure.md` files, seeds that set,
and then makes kiln own it, so every repository kiln scaffolds carries the same
rules and doctor reports a local edit as drift.

**Build each story by the
[board's procedure](../../index.md#building-a-story).**

## S11.4.1 — Seeded specs carry the rule

**State:** Closed (2026-09-28)

**Build:**

- In each of the three goldens, rewrite the seven `docs/**/_structure.md` files
  and `docs/specs/index.md` as the merged standard; copy them byte for byte to
  `modules/docs/templates/docs/**.j2`, and the `_structure.md` files to kiln's
  own `docs/`.
- Bring kiln's own specs into line with the merged rules.

**Tests:** F4.3's property 4 for the `docs` module, which already compares this
seed byte for byte.

**Acceptance:**

- The three goldens' copies and the template carry the bullet
  `Every acceptance line is checkable inside this repository.`
- `tests/modules/docs/test_artifacts.py` passes, with the seed equal to each
  golden.
- `task validate` passes in each golden.

*What the build settled that the story did not say:*

- The merge took kiln's seed as the base, with these changes. From pykit: the
  release structure (a feature carries its own `**Status:**` and the release
  scope table mirrors it), `**Implemented:**` in place of `**Shipped:**` on
  done work, `backlog.md` as a parking lot for ideas not yet agreed as work,
  the status table, "`done` means implemented, not released", the
  removed-behaviour check, and `</dev/null` on `absent`'s `rg`, which
  otherwise reads stdin when stdin is not a terminal. From ngkit: the
  cross-repository rule as its own `## Other repositories` section, and an
  area table in the root file.
- Feature files are never folded into their epic when done. Only an epic whose
  specs were written after its code keeps its features as rows.
- The root file no longer names repo-specific areas. An area a repo adds keeps
  its rules in its own `_structure.md`, so the root file is the same
  everywhere; kiln's `plans/` routing moved out of it.
- kiln's "Keeping it honest" asked for an ADR `History` entry, but the section
  is `## Background`; fixed. The seeded `specs/index.md` said the same, and
  its board group `Shipped` is now `Done`.
- kiln's features gained `**Status:**` lines, taken from their release rows;
  E1–E3 carry `**Implemented:**`.

## S11.4.2 — kiln owns the `_structure.md` files

**State:** Closed (2026-10-01)

**Depends on:** S11.4.1, and
[S13.3.1](../E13-docs-work-model/F13.3-adopt-the-model.md#s1331-the-seeded-rules-carry-the-work-model),
so that kiln starts owning the rules only once they carry the work model.

**Build:**

- In `modules/docs/artifacts.py`, render the seven `docs/**/_structure.md` paths
  as `ArtifactKind.MANAGED`, carrying kiln's provenance header.
  `docs/_areas.yml`, `docs/index.md` and every area's `index.md` stay
  `SEEDED`: a repo extends the areas and grows the indexes.
- The provenance header is an HTML comment, so it renders nowhere and MkDocs
  already excludes `_*.md`.
- In `docs/reference/standard-repo.md` §2, move the `_structure.md` files from
  the seeded row to a managed row, and say that an area a repo adds keeps its
  rules in its own, repo-owned `_structure.md`.
- Re-seed `state.json` in the three goldens and in kiln, as `README.md` says.

**Tests:** `tests/modules/docs/test_artifacts.py`, a case that each
`_structure.md` artifact is `MANAGED` and each `index.md` and `_areas.yml` is
`SEEDED`.

**Acceptance:**

- `kiln doctor` in a golden reports drift after one word of
  `docs/specs/_structure.md` is changed, and passes again once it is restored.
- `kiln doctor` reports nothing for an edited `docs/specs/index.md`.
- `docs/plans/_structure.md` in kiln, an area kiln does not seed, stays
  repo-owned.
- `task validate` passes in each golden and in kiln.

*What the build settled that the story did not say:*

- The story says seven `_structure.md` paths; the seed has eight (`docs/` plus
  seven areas, `reference` included). All eight are `MANAGED`, selected in
  `artifacts.py` by the `/_structure.md` suffix of the `SEEDS` path.
- The header is
  `<!-- Generated by kiln <version> from .rn-forge/kiln/config.toml — do not edit; run 'kiln apply' -->`
  followed by a blank line, as the first lines of each of the eight `.j2`
  templates, with `kiln_version` added to the render context. The goldens and
  kiln's own files carry `golden` as the version, as their other managed files
  do.
- The seed test (`property4`) now compares rendered and golden with the header's
  version normalised, as the `tasks` tests do.
- `state.json` was re-seeded by script, not `kiln apply`: the seven (kiln) or
  eight (goldens) `_structure.md` entries became `managed` with the SHA-256 of
  the file bytes, the scheme the existing managed entries use. The goldens'
  state had no entry for `docs/reference/_structure.md`; one was added so the
  file is drift-checked. kiln's own tree has no `docs/reference/_structure.md`
  and `docs/plans/_structure.md` is repo-owned, so neither is tracked as
  managed.
- `standard-repo.md` §2: the `_structure.md` files left the seeded rows for a
  managed row; the prose paragraph below the table was reworded to match.
- Drift is `Action.DRIFT` in the plan, so the test asserts that, and that an
  edited `index.md` stays `SKIP`.
- By hand in `python-tool`: a changed word in `docs/specs/_structure.md` made
  `kiln doctor .` fail (exit 1, "managed artifact has drifted"); restored, it
  passed; an edited `docs/specs/index.md` left it passing. Both files were
  restored.
