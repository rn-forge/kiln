# S7.8.1 — `kiln deps-upgrade` moves the rn-forge ranges and validates

Brief for
[S7.8.1](../F7.8-existing-repos-take-the-pin-table.md#s781-kiln-deps-upgrade-moves-the-rn-forge-ranges-and-validates),
at `dcfe75c`. Line references are at that commit.

## Goal

Add a `kiln deps-upgrade` command. It rewrites a repository's rn-forge
requirements to kiln's pin table, re-locks, and runs `task validate`. If
anything fails, it rolls the working tree back to `HEAD`, unless `--force` is
passed. It also prints each moved package's release notes.

## Settled

All settled by the owner on 2026-11-18. See the feature's `## Design`.

- **`archetypes.floor`.** Add `floor(requirement: str) -> str | None` to
  `src/rn_forge/kiln/archetypes/__init__.py`, next to `requirement()` (line
  168), and export it in `__all__`. It returns the lower bound a requirement
  declares:

    - The first `>=`, `==` or `~=` clause's version, matched by
      `(?:>=|==|~=)\s*(\d+(?:\.\d+)*)`, in the specifier part (before any `;`).
    - For a direct URL (`name @ git+…@<tag>`), the version from the tag's
      `-v(\d+\.\d+\.\d+)`.
    - `None` otherwise.

    Add a helper `version_key(version: str) -> tuple[int, ...]`, which splits on
    `.` and pads to three parts. Export it too.

- **New module `src/rn_forge/kiln/modules/python/ranges.py`.** Its `__all__` is
  `Move`, `plan`, `write` and `release_notes`.

    - `@dataclass(frozen=True) class Move`: `path: str` (POSIX-relative, as
      `archetypes.pyproject_paths` gives it), `distribution: str`, `old: str`,
      `new: str`, `old_floor: str | None`, `breaking: bool`. `breaking` is true
      when `old` had no ceiling equal to the new one: `old` is a URL pin, or its
      `<` clause differs from `<{archetypes.ceiling(table_version)}`.

    - `plan(config: KilnConfig, root: Path) -> list[Move]`. It goes through each
      path in `archetypes.pyproject_paths(config)` that exists, and through
      every string in these three places:

        - `[project] dependencies`
        - each `[project.optional-dependencies]` list
        - each `[dependency-groups]` list

        Entries that are not strings, such as `{ include-group = … }`, are skipped.
        An entry moves when all of these hold:

        - `rn_forge_deps.governed(name)` is true.
        - `name` is a key of `archetypes.RN_FORGE_TAGS`.
        - `name` is not in `rn_forge_deps.workspace_members(config, root)`.
        - `floor(entry)` is `None` or its `version_key` is below the table
          version's.

        `name` is `rn_forge_deps.distribution(entry)`; import both helpers from
        `rn_forge.kiln.modules.python.checks.rn_forge_deps`. Moves come in file
        order, then entry order.

    - **The new string** is built from the entry. Take the name as written; the
      extras group `[...]` if present, verbatim; and the marker after `;` if
      present, stripped. The result is
      `f"{name}{extras}>={version},<{ceiling(version)}"`, plus `f"; {marker}"`
      when there is a marker. `version` is the table tag's `-v` suffix, the same
      way `requirement()` gets it. Example:
      `rn-forge-commons[pydantic]>=0.9.0,<0.10; python_version >= "3.12"`
      becomes
      `rn-forge-commons[pydantic]>=0.10.0,<0.11; python_version >= "3.12"`. A
      URL entry such as
      `rn-forge-cli @ git+https://github.com/rn-forge/pykit@rn-forge-cli-v0.1.3#subdirectory=packages/rn-forge-cli`
      becomes `rn-forge-cli>=0.2.0,<0.3`.

    - `write(root: Path, moves: list[Move]) -> None`. For each path, it reads with
      `DocumentUtils.read_document`, replaces each array item equal to
      `move.old` in the same three places with `move.new` (index assignment on
      the tomlkit array), and writes with `DocumentUtils.write_document`. It
      does not call `tidy` and reorders nothing.

    - `release_notes(move: Move) -> str`. The URL is
      `f"https://raw.githubusercontent.com/rn-forge/pykit/{RN_FORGE_TAGS[d]}/packages/{d}/CHANGELOG.md"`.
      Fetch it through a module-level `_fetch(url: str) -> str | None`, which
      uses `urllib.request.urlopen(url, timeout=10)` and decodes UTF-8. It
      returns `None` on `OSError`, which covers `URLError`. On `None`, return
      `f"release notes: {url}"`. Otherwise return the `## [X.Y.Z]` sections,
      each heading through to the line before the next `## `, whose version is
      above `move.old_floor` (all of them when that is `None`) and at or below
      the table version. Join them with a blank line. `## [Unreleased]` is never
      included.

- **Run the commands with output streaming.** Add a
  `capture_output: bool = True` parameter to `run` in
  `src/rn_forge/kiln/modules/core/process.py` (line 14). Pass it through to
  `Process.execute(…, capture_output=capture_output)`, and document it in the
  docstring's Args.

- **New command module `src/rn_forge/kiln/commands/deps.py`.** Its docstring is
  `"""`kiln deps-upgrade`."""`, and it defines
  `deps_upgrade(force: bool = False, tree_checked: bool = False) -> None`.

    1. `root = umbrella.find_root(Path.cwd())`, and
       `config = KilnConfig.load(root)`.

    1. Unless `tree_checked` is set, run
       `process.run("git-status", "git", "status", "--porcelain", cwd=root)`. If
       its `stdout` is not blank, raise
       `AppException("deps-upgrade.dirty: the working tree has uncommitted changes — commit or stash them, so a failed upgrade can be rolled back to HEAD")`.

    1. Compute `moves = ranges.plan(config, root)`.

        - If it is empty, print `rn-forge ranges already at kiln's pin table`.
        - Otherwise, print one line per move, `{path}: {old} → {new}`, with
          ` (breaking range)` appended when `breaking`. Call
          `ranges.write(root, moves)`. Then, for each move, print a heading line
          `{distribution}:` followed by `ranges.release_notes(move)`.

    1. Run `task setup`, then `task validate` only if setup exited 0. Use
       `process.run(label, "task", verb, cwd=root, check=False, capture_output=False)`
       and read `.return_code`. Both run even when `moves` is empty, because
       `task kiln:upgrade` relies on the validate run.

    1. If both exit 0, return.

    1. On a failure with `force`, raise
       `AppException("deps-upgrade.kept: task {} failed; the upgrade is kept because of --force — fix what it reports", verb)`.

    1. On a failure without `force`, roll back:

        - `git restore --source=HEAD --staged --worktree -- .`
        - `git clean -fdq -- .`

        Run each with `process.run(…, cwd=root)`. Then run `task setup` again with
        `check=False, capture_output=False`, so the environment matches the
        restored lock. Then raise
        `AppException("deps-upgrade.failed: task {} failed; the working tree is restored to HEAD — the release notes above list what changed; rerun with --force to keep the upgrade and fix it", verb)`.

    Print through `rn_forge.commons.runtime.console.console.print`.

- **Wiring.**

    - Export `deps_upgrade` from `src/rn_forge/kiln/commands/__init__.py`, and add
      it to `__all__` in sorted order.

    - Add a command to the `[cli]` table in `.rn-forge/kiln/config.toml`, after
      the `pin` entry:

        ```toml
        [[cli.commands]]
        name = "deps-upgrade"
        target = "rn_forge.kiln.commands.deps:deps_upgrade"
        ```

        Then run `task kiln:apply`, which re-renders `src/rn_forge/kiln/cli.toml`.
        Never edit `cli.toml` by hand.

    - If `tests/commands/test_cli_surface.py` lists the commands, add
      `deps-upgrade` there.

- **Test names** describe behaviour, `test_<subject>_<behaviour>`, and carry no
  spec ID in a name, docstring or comment.

## Rules

- Do not commit, push, or edit any spec page except `## Result` below.
- Do not edit a file whose header says kiln generated it; `task kiln:apply`
  writes them.
- Add no dependency. `urllib` is the standard library's.
- Use only `task` verbs. Never call `uv`, `pytest`, `ruff`, `pyright` or `kiln`
  directly.
- Read and write TOML in `src/` only through
  `rn_forge.commons.fs.documents.DocumentUtils`. The import contract
  `documents-come-from-rn-forge` forbids `tomlkit`. Tests may use `tomllib`.
- Start a subprocess only through `rn_forge.kiln.modules.core.process.run`.
- Run every validation step in the foreground, one at a time, and wait for it.
  Leave no background run behind.
