The drift check already covers every file that kiln renders. A doctor rule over
those files therefore tests kiln's templates, not the repository, and it belongs
in kiln's own tests. A rule that depends only on the config belongs in config
validation. What is left in doctor reads content the repository owns.

Every story keeps this property: no rule is lost. Each one becomes either a
render test over every archetype or a config-load error, and the story names
which.

## S18.11.1 — `task-layout` reads only what the repository owns

**State:** New · **Depends on:** —

**Build.**

- Rules 1 and 2 (`tasks/checks/layout.py:56-100`, `:217-253`, `:256-281`) become
  render tests over each archetype. These are `_check_surface`, `_check_desc`,
  `_check_wrapper_only` and `_check_internal`.
- Rule 3, `required_validate` reachability (`:128-205`, `:283-347`), becomes a
  check in `TasksConfig` on `extra_refs` and the archetype's
  `required_validate`. This removes `load_graph`, `resolve` and
  `reachable_from`.
- Doctor keeps `extra_refs` and the checks on owned includes.

**Acceptance:**

- `layout.py` is under 150 lines.
- An `extra_refs` change that breaks reachability is refused at config load.

## S18.11.2 — `ci-pins` skips managed files
