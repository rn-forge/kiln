# S9.5.6 — The independent release job

Brief for
[S9.5.6](../F9.5-node-lib-release-findings.md#s956-the-independent-release-job),
at `4ff5282`.

## Goal

When a `node-lib`'s `release_group` is `independent`, a push to the default
branch releases each publishable project whose version is not yet released: its
own `<project>-v<version>` tag, its own draft-then-published GitHub Release
carrying only its tarball and its notes, published to npm under its own
dist-tag. Projects go in dependency order. `verify-release` installs every tag
the run released. A fixed `node-lib` renders exactly as before.

## Settled

Owner, 2026-11-17: Nx-native independent mode, no rolling `latest` release.
Reviewer, for the build:

- **One job, loops in the tasks.** The `release` job in `_release.yml.j2` keeps
  its steps and their order. Under `{% if release_group == "independent" %}`
  each step's condition and `env:` change as below, and the `release:*` tasks
  in `modules/tasks/templates/tasks/ci.yml.j2` get independent bodies that
  loop over a space-separated list of tags. Task names do not change.
  `release_group` is the context key S9.5.1 added; add it to the cicd module's
  context (`modules/cicd/artifacts.py`, beside `node_lib`) too.

- **A tag** is `<project>-v<version>`. A step that has a tag `t` splits it as
  `project=${t%-v*}` and `version=${t##*-v}`.

- **`release:state`** (independent) walks the publishable projects the way
  `node:version` does (`project.json` with the `publishable` tag; name from
  `project.json`, version from the sibling `package.json`). For each, with
  `tag=<project>-v<version>`, the mode is the fixed task's rule: `new` when
  the tag does not exist, `released` when its GitHub Release is published
  (`gh release view "$tag" --json isDraft --jq .isDraft` prints `false`), an
  error when the tag exists and is not at `HEAD` (the fixed message, with that
  tag), else `resume`. It prints
  `::notice::<project>: <mode> (<tag>, npm tag <dist>)` per project, and
  appends to `$GITHUB_OUTPUT`:

    - `tags=` the `new` and `resume` tags, space-separated, in dependency order;
    - `new=` the `new` tags only, same order;
    - `tag=` the first of `tags`, or empty.

    **Dependency order:** a project comes after every publishable project its
    `package.json` names in `dependencies`, `peerDependencies` or
    `optionalDependencies` (matched by the `package.json` `name`); ties go by
    project name. Do it in the same `node -e` script that walks the tree. A
    cycle is an error: `::error::dependency cycle among publishable projects`.

- **`release:tag`**: `for t in $NEW_TAGS; do git tag "$t"; done`.

- **`release:push`**: one `git push origin "refs/tags/$t"` per `NEW_TAGS` entry.

- **`release:verify`**: unchanged (it rebuilds every publishable project).

- **`release:github`**, per `TAGS` entry: delete an existing draft as the fixed
  task does; notes from
  `{{.DEVOPS}} notes "<project dir>/CHANGELOG.md" "$version"`; the asset is
  the project's own tarball, `dist/tarballs/<packed name>-<version>.tgz`,
  where `<packed name>` is the project's `package.json` `name` with a leading
  `@` dropped and the first `/` turned into `-` (`@s/a` gives `s-a`), which is
  how `npm pack` names it; then
  `gh release create "$t" "$tarball" --verify-tag --title "$t" --notes-file "$RUNNER_TEMP/notes.md" --draft`.
  A missing tarball is an error naming it.

- **`release:publish`**, per `TAGS` entry, in order:
  `pnpm exec nx release publish --projects="$project" --tag="$dist" --excludeTaskDependencies$first`,
  where `dist` is `latest`, or the prerelease identifier, from `version`
  (the fixed rule), and `first` is ` --first-release` when no tag but `t`
  matches `$project-v*`.

- **`release:finalize`**: `gh release edit "$t" --draft=false` per `TAGS` entry.

- **`release:latest`**: not rendered under independent, and neither is its
  workflow step.

- **Workflow steps (independent):** the steps the fixed job gates on
  `mode != 'released'` gate on `steps.state.outputs.tags != ''`, with
  `TAGS: ${{ steps.state.outputs.tags }}` in `env:` where the fixed step has
  `TAG`; the steps gated on `mode == 'new'` gate on
  `steps.state.outputs.new != ''` with `NEW_TAGS`. The Publish step drops
  `DIST_TAG` and `FIRST_RELEASE_FLAG` (the task works them out). The "Already
  released" step runs when `tags == ''` and prints
  `::notice::every publishable project's version is already released`.

- **Outputs.** `_release.yml`'s `workflow_call.outputs` and the job's `outputs:`
  gain `tags` (independent only); `tag` becomes
  `${{ steps.state.outputs.tag }}`.

- **`verify-release`.** `ci.yml.j2`'s `verify-release` job passes
  `tags: ${{ needs.release.outputs.tags }}` beside `tag` (independent only).
  `_verify-release.yml.j2` (node branch) declares a required `tags` input
  under independent and passes `TAGS` to `task ci:verify-release`, whose
  independent body downloads each tag's `*.tgz` into `dist/tarballs` and then
  runs the same `verify-consumer` command.

- Tests are named for behaviour, `test_<subject>_<behaviour>`, with no spec ID
  in a name, docstring or comment.

   commit → non-zero, `is not at HEAD`.

   and `tag=` empty.
