A derived check: a workspace with two or more members verifies that members
depend on each other by range, not by exact pin. It is
`kiln-devops requirements`, and it replaces pykit's `internal-ranges.yml`.
`python-lib` runs it in the `plan` job; `node-lib` runs it as a step of
`task ci:validate`, under the same derived switch (a `node-lib`'s members are
not known when kiln renders, so the step is always rendered and finds nothing to
do below two members).

## S15.4.1 — `kiln-devops requirements`

**State:** New

**Build — tests first,** in `tests/devops/test_requirements.py`, each building a
tmp workspace (root `pyproject.toml` with
`[tool.uv.workspace] members = ["packages/*"]`, and member `pyproject.toml`
files):

1. `test_s15_4_1_1_range_passes`: member `a` depends on `b>=0.2,<1` and `b` is
   version `0.3.0`: exit `0`, no output.
1. `test_s15_4_1_2_no_lower_bound`: `a` depends on `b`: exit `1`, output line
   `a -> b: no lower bound`.
1. `test_s15_4_1_3_exact_pin`: `b==0.3.0`: `a -> b: exact pin`.
1. `test_s15_4_1_4_floor_above_current`: `b>=0.4` while `b` is `0.3.0`:
   `a -> b: lower bound 0.4 is above 0.3.0`.
1. `test_s15_4_1_5_extras_and_optional`: `b[x]>=0.2` and an entry under
   `[project.optional-dependencies]` are checked; entries under
   `[dependency-groups]` are not.
1. `test_s15_4_1_6_non_members_ignored`: `requests` is never checked.
1. `test_s15_4_1_7_cli`: `main(["requirements", "--root", str(root)])` returns
   the exit code of tests 1 and 2.

**Build:** `src/rn_forge/kiln/devops/requirements.py`
(`check(root) -> list[str]`) and a `requirements` subparser in `devops/cli.py`
(`--root`, default `.`). Read members through `devops/ci.py`'s `Workspace` if it
exposes their `pyproject.toml` paths and versions; otherwise parse with
`tomllib` and `packaging.requirements.Requirement`. A member's name is
normalized (`packaging.utils.canonicalize_name`) before comparison.

**Acceptance:**

- The seven tests pass, and `task validate` passes.

## S15.4.3 — `kiln-devops requirements --stack node`

**State:** New · **Depends on:** S15.1.1, S15.4.1

For `node-lib`: an internal dependency must use `workspace:^` or `workspace:~`.
`workspace:*` publishes as an exact pin, and a literal version does not follow
the member's version. The members come from `pnpm ls -r --depth -1 --json` on
stdin, so kiln reads no YAML.

**Build — tests first,** in `tests/devops/test_requirements_node.py`, each
building a tmp workspace with member `package.json` files and passing the
`pnpm ls` JSON (`[{"name":"@s/a","version":"1.0.0","path":"<dir>"}, …]`) on
stdin:

1. `test_s15_4_3_1_caret_and_tilde_pass`: `@s/a` depends on `@s/b` as
   `workspace:^` and `@s/c` as `workspace:~`: exit `0`, no output.
1. `test_s15_4_3_2_star_fails`: `workspace:*` gives
   `@s/a -> @s/b: workspace:* publishes as an exact pin`.
1. `test_s15_4_3_3_literal_version_fails`: `^1.0.0` gives
   `@s/a -> @s/b: use workspace:^ or workspace:~, found ^1.0.0`; so does
   `workspace:1.0.0`.
1. `test_s15_4_3_4_fields`: `dependencies`, `peerDependencies` and
   `optionalDependencies` are checked; `devDependencies` is not (it is not
   published).
1. `test_s15_4_3_5_non_members_ignored`: `rxjs` is never checked.
1. `test_s15_4_3_6_one_member`: a listing of one member exits `0`.
1. `test_s15_4_3_7_cli`: `main(["requirements", "--stack", "node"])` with the
   JSON on stdin returns `1` for test 2's input and `0` for test 1's.
   `--stack` defaults to `python`.
1. In `tests/modules/tasks/test_artifacts.py`, `test_s15_4_3_8_node_task`: a
   `node-lib` `tasks/ci.yml` has `requirements` running
   `pnpm ls -r --depth -1 --json | {{.KILN_DEVOPS}} requirements --stack node`
   (preceded by `set -o pipefail;`), `ci:validate` calls it, and no other
   archetype's `ci:validate` does.

**Build:** `devops/requirements.py` gains `check_node(members, ...)`, and the
`requirements` subparser a `--stack {python,node}` option (default `python`;
`node` reads the JSON from stdin). `tasks/ci.yml.j2`: the `requirements` task
under `node_lib`, and one line in `validate`.

**Acceptance:**

- The eight tests pass, and `task validate` passes.
- `task self:golden:compare BASE=HEAD`: only the `node-lib` cell changes.
