# ADR-0020 — Agent instructions live in AGENTS.md

**Status:** accepted (2026-11-21) · **Scope:** the instruction files of every
generated repository, and kiln's

## Decision

The instruction files are split **by audience**. Each prose paragraph has one
home, and a file that needs another file's content imports or links it.

- **`README.md`** is for humans and developers: what the repository is, how to
  set it up, how to work in it, and the conventions everyone follows. It
  carries no directive addressed to an agent.
- **`AGENTS.md`** is the canonical agent-instruction file, because it is the
  cross-tool convention that Codex, Copilot, Cursor and others read. It holds
  rules, guardrails, do and don't lists, worked examples and the story
  workflow, and links to `README.md` for context instead of restating it.
    - Its body is **repository-owned**, and kiln seeds none of it.
    - **kiln's fenced block lives here**, and nowhere else. When `AGENTS.md` is
      absent, inserting the block creates the file with only the block.
    - agentkit adds its own fenced block to this file. Neither tool owns the file:
      a repository's own rules stay the repository's.
    - **The order of the blocks does not matter.** kiln's block comes first in a
      file `kiln new` creates, because the first apply writes it. Where another
      tool's block is already there, kiln appends its block and never moves or
      rewrites anything outside its own markers.
- **`CLAUDE.md`** is repository-owned, and kiln neither seeds nor writes it.
  agentkit's block in it carries the `@AGENTS.md` import (agentkit ADR-0002).
  Claude Code loads an `@path` import mechanically, so the agent does not have
  to follow a pointer.
- **kiln's checks read only kiln's block.** Drift, and the docs-pointer check,
  look inside the `rn-forge kiln` block and nowhere else in an instruction
  file. Advice on the rest of the file is agentkit's advisory `review`
  command.

[ADR-0003](ADR-0003.md) holds unchanged: one owner per file or block, and no
paragraph restated in two files. The import is the mechanism that makes a second
reader of the same text possible without a second copy.

## Consequences

- `kiln apply` renders the block into `AGENTS.md`. A repository whose
  `state.json` records the block in `CLAUDE.md` is migrated by the apply that
  follows the upgrade: the engine removes the stale block from `CLAUDE.md` and
  inserts the new one in `AGENTS.md`, with no new migration code. The bodies
  of both files are repository-owned, so rewriting them is a step in that
  repository's own story.
- `kiln new` scaffolds `README.md` only. `AGENTS.md` gets kiln's block from the
  first apply, and `CLAUDE.md` is left to agentkit and the owner. Neither file
  is recorded in `metadata.scaffolded`.
- The `docs-structure` check finds the docs links in kiln's block in
  `AGENTS.md`. `CLAUDE.md` is no longer one of its instruction files, and a
  body edit never fails it.
- Repositories that already have the old seeded bodies keep them as the owner's
  text. agentkit's `review` flags placeholder lines left in them.
- The standard, the reference and the seeded `docs/_structure.md` say which file
  is for which reader.
- A repository's agent rules move out of its `README.md`. For kiln that is a
  split of its own README.
- pykit's and ngkit's cutover stories are rewritten to this model before they
  run.

## Supersedes

- The rule that `README.md` is the single prose home, `CLAUDE.md` points at it
  and carries kiln's block, and `AGENTS.md` points at `CLAUDE.md` (plan
  decisions D57 and D58, the owner answer of 2026-11-09, and a cutover
  finding).
- The `CLAUDE.md`, `AGENTS.md` and `README.md` seeds that rule produced.

## Alternatives considered

- **`README.md` as the single prose home (the status quo).** Agent directives
  and developer prose then share one file, so a rule meant for an agent is
  read by every human and a human's setup text is in the agent's context for
  nothing. Every instruction file also becomes a pointer, and a pointer works
  only if the agent follows it.
- **`CLAUDE.md` canonical, with `AGENTS.md` a pointer.** Rejected because Codex
  and the other tools that read `AGENTS.md` cannot import another file, so
  they would see a pointer and nothing else. The import works the other way
  round: Claude Code can import `AGENTS.md`.
- **agentkit owns the whole of `AGENTS.md`.** Rejected: a repository's own rules
  would then live in a file the repository does not own, and each edit would
  be drift. A tool contributes a fenced block; the body stays the
  repository's.
- **Two copies, kept in sync by a check.** Rejected by ADR-0003: a check that
  compares two copies is the cost of having made two.

## Background

- 2026-09-11: kiln took over seeding the instruction files from agentkit (D58),
  and made `README.md` the one prose home (D57).
- 2026-11-09: the owner confirmed that rule for the cutovers.
- 2026-11-10: the owner reversed it, on the grounds above.
- 2026-11-21: the owner ruled that neither kiln nor agentkit owns an instruction
  file. Each contributes only fenced blocks, and its checks read only those
  blocks. kiln stopped seeding the `AGENTS.md` and `CLAUDE.md` bodies, and the
  `CLAUDE.md` import moved to agentkit's block.
- 2026-11-23: the owner ruled that the order of kiln's and agentkit's blocks in
  `AGENTS.md` does not matter, and that kiln never reorders them.
