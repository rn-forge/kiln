Parked 2026-11-21 by the owner: off its release until the owner picks it up.

Release 1 ships when the owner lands `feature/v1` on `main`; there is no tag.
After that, `feature/v1` stops moving, so the ref `kiln new` pins and the ref
every repository on kiln tracks move to `main`. A repository still pins a commit
SHA; `main` is only its `[kiln] track`, which `task kiln:pin` with no argument
follows.

## S7.9.1 — `kiln new` and every repository track `main`

**State:** New · **Depends on:** —

**Why.** `archetypes.KILN_REF = "feature/v1"` is what `kiln new` resolves to a
SHA and records as `[kiln] track` (`commands/new.py`). Once release 1 is on
`main`, a new repository would track a branch that no longer moves, and so would
every repository pinned from `feature/v1`.

**When.** After `feature/v1` is on `main`, as the first commit on `main`. Set
earlier, on `feature/v1`, `kiln new` would resolve `main` to the commit before
release 1.

**Build — tests first:**

- `tests/test_archetypes.py`, `test_kiln_new_tracks_main`:
  `archetypes.KILN_REF == "main"`.
- `tests/conftest.py`, the `kiln_remote` fixture: the local bare remote also has
  a `main` branch at the same commit, so `kiln_ref.resolve("main")` resolves
  in every test. Its docstring and `kiln_remote_sha`'s name both branches. The
  tests that pass `"feature/v1"` as a literal branch keep it; it is still a
  branch on that remote.
- `tests/commands/test_new_flags.py`: the two assertions that expect
  `{"ref": kiln_remote_sha, "track": archetypes.KILN_REF}` pass unchanged; no
  edit.

**Build:**

- `archetypes/__init__.py`: `KILN_REF = "main"`, docstring "The branch
  `kiln new` pins the newest commit of, and records as `[kiln] track`."
- `task kiln:apply`, then `task lint KILN_DOCTOR_FULL=1`. Re-seed any golden
  cell whose render changes.
- `docs/specs/index.md`, **Upstream pins**: a row that kiln's `main` carries
  release 1, with the `main` commit.
- Each repository on kiln moves with `task kiln:pin -- main`: pykit and ngkit
  (`rn-forge`), agentkit (`rn-tools`), apollo, phototidy, twinpath and
  spendlens (`rn-apps`). That is each repository's own commit
  ([ADR-0009](../../../adr/ADR-0009.md)); kiln records only that it happened.
- Once every repository tracks `main`, the owner deletes the remote
  `feature/v1`.

**Acceptance:**

- `test_kiln_new_tracks_main` passes, and `task validate` passes.
- `kiln new` from `main` writes `[kiln] ref = "<main SHA>"` and
  `track = "main"`, and the new repository passes
  `task setup && task validate`. Not scriptable here; judged by the owner.
- Every repository named above has `track = "main"` in its
  `.rn-forge/kiln/config.toml`. Not scriptable here; judged by the owner.
