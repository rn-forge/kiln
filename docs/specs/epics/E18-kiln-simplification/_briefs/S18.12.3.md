# S18.12.3 — `generate package` checks before it writes

Brief for
[S18.12.3](../F18.12-release-1-review-defects.md#s18123-generate-package-checks-before-it-writes),
at `5733688`. Paths are under `src/rn_forge/kiln/`.

## Goal

`kiln generate package` on a repository with drift exits 1 and writes nothing.

## Settled

- **The preflight is the apply's own refusal, run first.** At the top of
  `commands/generate.py` `add_package` (before `DocumentUtils.update` writes
  `config.toml`), run the same refusal `cycle.apply(root)` makes on a plan
  with unapproved drift, conflict or a missing artifact. Use
  `cycle.apply(root, dry_run=True)` if, and only if, a dry run raises that
  refusal for drift; confirm it with a test first. If a dry run does not
  raise, add `cycle.refuse(root)` to `modules/core/cycle.py`: it plans the
  repository as `apply` does and raises the exact exception and message
  `apply` would raise, without writing. In both cases the message is the one
  `kiln apply` prints today.
- The preflight sits after `python_scaffold.package_preflight(...)`, so a bad
  name is still reported first, with its own message.
- `kiln new` calls `add_package` for each `python-lib` member, in a staged
  repository that has just been applied and has no drift, so the preflight
  passes there. Confirm with the `tests/commands/test_new_packages.py` tests.

## Current behaviour

- `commands/generate.py` `add_package` runs `package_preflight`, then writes
  `config.toml` (`DocumentUtils.update` and `catalog.write`), runs
  `python_scaffold.add_package` and `docs_scaffold.add_package`, and only then
  `cycle.apply(root)`, which refuses on drift. The package is left half added:
  `config.toml` lists it and `packages/<name>/` exists.
