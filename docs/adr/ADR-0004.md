# ADR-0004 — Render only from committed configuration

**Status:** accepted (2026-09-15) · **Scope:** every kiln render and every
verification run

## Decision

A repository declares its archetype and options explicitly. Kiln resolves
defaults, configuration sources and command-line overrides once, into committed
configuration at `.rn-forge/kiln/config.toml`.

`apply`, `diff` and `doctor` then read that committed configuration. They do not
rediscover the repository's shape, consult machine-local defaults, or fetch a
configuration source.

Refreshing a shared configuration source, or migrating its schema, is an
explicit command that produces a reviewable change. Resolution preserves
repository overrides and validates every input against the running kiln's
schema.

## Consequences

- The same checkout and the same pinned kiln render the same bytes on any
  machine and in CI. This is what makes drift a meaningful signal at all
  ([ADR-0003](ADR-0003.md)) and what lets CI verify by rendering
  ([ADR-0006](ADR-0006.md)).
- A change to a shared profile reaches a repository only through an explicit
  update in that repository. Fleet-wide changes cost one commit per
  repository.
- Nothing infers intent. Adding auto-detection later would reintroduce the
  failure this decision exists to prevent.
- `config.toml` is the only durable hand-authored input, so it must carry
  everything a render depends on.

## Influences

The configuration schema is normative in
[the reference, §9](../reference/standard-repo.md#9-configuration); merge rules,
provenance and the commands are in
[the config lifecycle](../specs/epics/E4-generator/design.md#the-config-lifecycle);
`kiln new --config` and `kiln config upgrade` are specified in
[F4.5](../specs/epics/E4-generator/F4.5-cli.md).

## Alternatives considered

- **Infer the archetype from the files present.** Ambiguous layouts need
  ever-more-complex detection and still select the wrong standard sometimes —
  and the wrong standard is applied silently, as a generated commit.
- **Read shared configuration live during a render.** Two identical checkouts
  then produce different artifacts depending on when they ran, so a drift
  finding no longer means anyone changed anything.
- **Layer in machine-local configuration, as a home-directory profile.** Makes a
  developer's machine part of the build inputs, and the CI render diverges
  from every local one.
- **No committed resolved configuration; re-resolve on each command.** Every
  command becomes a network and filesystem dependency, and `doctor` can no
  longer answer what the repository was generated from.

## Background

Layered configuration resolved once and committed was D64, revised by D70 to add
the `[source]` table so a repository records which source and commit it resolved
from. The private namespace rule (kiln owns `.rn-forge/kiln/` and no more) was
D28 and now lives with the ownership decision ([ADR-0003](ADR-0003.md)), where
it belongs.
