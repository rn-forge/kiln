# S18.1.1 — The cicd and tasks module tests

Brief for
[S18.1.1](../F18.1-tests-named-by-behaviour.md#s1811-the-cicd-and-tasks-module-tests),
at `d1fea26`. Read the feature page's properties first; this brief repeats them.

**Your tree:** `tests/modules/cicd`, `tests/modules/tasks`. Every file you
change is in it.

## Goal

Rename every test function in your tree that is named after a story
(`def test_s<digits>_…`, 590 of them) to the behaviour it proves, and take spec
IDs out of the tree's docstrings and comments. The change is renames and comment
text only, so a reviewer checks names, not logic.

## Settled

From the feature page (owner decision, 2026-11-06):

1. A test's body, parameters, decorators and fixtures are unchanged; only its
   name moves.
1. A new name says what the test proves, `test_<subject>_<behaviour>`, e.g.
   `test_s16_7_1_2_web_root_skips_site_dir` →
   `test_site_dir_is_skipped_for_a_web_root` (illustrative). It is unique
   within its module, and no part of it is a spec ID or a bare acceptance
   number (`_1_`, `_property2_`).
1. The number of collected tests in your tree is unchanged: 1239 at `d1fea26`.

Settled for this brief (reviewer, 2026-11-17):

- **Collisions.** Dropping the ID makes some names collide (near-twins such as
  `test_s5_1_1_4_*`, `test_s16_6_8_1_*`). Resolve each by naming what each
  test proves, never with a numeric suffix.
- **Other identifiers.** A helper, fixture, constant or class in your tree whose
  name carries a spec ID (e.g. `S16_7_1_WEB`, `_s16_7_1_root`,
  `_s4_12_1_root`) is renamed the same way, with every use in your tree
  updated.
- **Docstrings and comments.** A spec ID is `E<n>`, `F<n>.<m>` or `S<n>.<m>.<k>`
  (any depth). Remove each from module, class and function docstrings and from
  `#` comments in `.py` files in your tree. Where the ID carried meaning
  ("since S7.2.4 the file starts from…"), rewrite the sentence to say the
  behaviour without it; where a docstring was only the ID and a title
  (`"""S4.2.1 — the archetype manifests."""`), keep the title
  (`"""The archetype manifests."""`). ADR references (`ADR-0020`) stay.
- **Test data stays.** A spec ID inside a string literal that a test uses as
  input or expected output (e.g. `"specs/epics/E1-x/F1.1-a.md"`) is data, not
  a name: leave it.
- **Naming rule override.** Step 2 of "Building a story" in
  `docs/specs/index.md` still says to name tests after the story. Ignore it;
  S18.1.4 retires it. Your new names carry no story ID.
