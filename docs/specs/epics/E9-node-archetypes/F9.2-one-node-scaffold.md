`node-lib` and `python-web-app` get the same pnpm, Nx and Angular workspace, the
same toolchain pins and the same task surface. They differ only by code: a
`node-lib` starts with no projects, and a `python-web-app` starts with the
`@rn-forge/ng` package and its application. A new `node-lib` passes its own CI
before it has a library, and its generated documents describe a Node repository.

## Context

The owner set the rule on 2026-10-30, and it is recorded in
[ADR-0015](../../../adr/ADR-0015.md) by S9.2.2. A review of the two golden cells
that day found the code did not meet it. S9.1.8 built what it was asked to: it
stops `node-lib` after `create-nx-workspace`, so the cell has no Angular,
ESLint, TypeScript or Vitest, and `nx g @nx/angular:library` fails in it.
`tests/e2e/ngkit_shape.sh` copies ngkit's root files over the scaffold, so that
gap never reached a test.

Two statements in closed S9.1.8 are replaced here, and the closed story keeps
its text: `scaffold_nx_workspace` having "nothing after" its two steps for
`node-lib` (S9.2.2), and "Nx writes `packageManager`", which it does not
(S9.2.3).

Nothing here changes what ngkit's own repository-owned files contain. F9.1's
S9.1.12 is re-run after S9.2.7 and S9.2.8, because each adds a labelled hunk to
`.goldens/ngkit.diff`.

Each story is sized for one session on a Sonnet-class model. Every decision a
story needs is made on this page.

[F9.3](F9.3-node-ci-holds-for-every-node-lib.md) holds what a review of the
built scaffold found on 2026-10-31.

## Design

### What was proved

These were run on 2026-10-30, with kiln's pinned commands in a scratch directory
and `CLAUDECODE`, `OPENCODE` and `CLAUDE_CODE_ENTRYPOINT` unset.

| Check | Result |
| -- | -- |
| `@nx/angular:init`, `@nx/js:init`, `@nx/eslint:init` on a bare workspace | writes no `eslint.config.mjs` or `tsconfig.base.json`, and no Angular dependencies. Rejected |
| The application scaffold, then `nx g @nx/workspace:remove web --forceRemove --interactive=false` | leaves the web-app cell's root, apart from `@rn-forge/ng` and `tsconfig.base.json`'s JSON layout, and removes `apps/` |
| `nx run-many -t lint`, `test`, `build`, `typecheck` with no projects | each exits 0 |
| `nx show projects --json` with no projects | prints `[]` |
| `nx g @nx/angular:library libs/foo --name=foo --publishable --importPath=@rn-forge/foo --unitTestRunner=vitest-angular --linter=eslint --interactive=false` on that root | generates; `test` and `build` pass; `lint` reports one `@nx/dependency-checks` error for an unused `@angular/common` peer in the stock library template, a repository matter |
| `targets.test` of a generated library and a generated application | a library uses `@nx/angular:unit-test`, an application `@angular/build:unit-test`; neither writes coverage by default |
| Coverage switched on through `nx.json` `targetDefaults` | fails until `@vitest/coverage-v8` is installed; an unpinned add resolves `^5`, which fails against `vitest` `^4`; `@vitest/coverage-v8@^4.0.8` passes and writes `coverage/<project>/lcov.info` for both executors |

### Decisions

1. **The application is always scaffolded.** `node-lib` removes it afterwards,
   because only the application generator writes the root files, and this way
   the root cannot differ from the web-app cell's.
1. **`node-lib` is always Angular.** It has no `frontend` key; `scaffold_node`
   uses the `angular` scaffolder for it.
1. **`task typecheck` is the Angular build.** Neither a generated project nor
   ngkit has a `typecheck` target, so `nx run-many -t typecheck` passes while
   checking nothing. The Angular compiler checks templates too, which `tsc`
   does not.
1. **Nx Cloud is opt-in through the repository variable.** `USE_NX_CLOUD` is
   already the switch, so no config key is added, and `ci-local` becomes the
   path when it is unset. ngkit sets `USE_NX_CLOUD=true` when it adopts kiln.
   The `nx_cloud` key that nothing reads is removed.
1. **An empty `node-lib` keeps its directories.** `libs/.gitkeep` and
   `apps/.gitkeep` are written once, because `sonar-scanner` fails on a
   `sonar.sources` folder that does not exist.

## S9.2.3 — Every node repository pins pnpm and Node

**State:** Closed (2026-10-30) · **Depends on:** S9.2.2

1. Neither file is a managed artifact: neither key is in `render(config)`.

**Build:** `modules/node/scaffold.py`: add `PNPM_VERSION = "12.15.0"` beside
`NODE_MAJOR`, with a one-line docstring naming `packageManager` and
`pnpm/action-setup`, which fails without it. Move the `.nvmrc` write above the
`if lib:` return, and add the `packageManager` write beside it with
`DocumentUtils.read` and `DocumentUtils.write`. Reword `NODE_MAJOR`'s docstring
and `reconcile_node`'s docstring, which say `node-lib` only.

**Acceptance:**

- The tests pass.
- After `task self:golden:render`, both cells have `.nvmrc` and
  `"packageManager": "pnpm@12.15.0"`, and `pnpm install --frozen-lockfile`
  exits 0 in both.

**What the build settled that the story did not say:**

- **The spec's design failed its own acceptance, and one step was added.**
  Written only by `reconcile_node`, `packageManager` arrives after pnpm has
  written the lockfile, and pnpm 12 records `packageManagerDependencies` in
  `pnpm-lock.yaml` only when `packageManager` is present at write time. The
  rendered web-app cell failed `pnpm install --frozen-lockfile` with
  `ERR_PNPM_FROZEN_LOCKFILE_WITH_OUTDATED_LOCKFILE`. `scaffold_node` now also
  pins `packageManager` in the workspace's `package.json` after the scaffolder
  and before `nx-remove-app` or `ngkit-core`, the last lockfile writers. No
  command is added; `reconcile_node` still pins as the story says, to the same
  value. The pin is one private helper, `_pin_package_manager`, used by both.
- **Tests.** `test_s9_2_3_1`–`3` are the three Build items, each for both
  archetypes; `test_s9_2_3_4` covers the added pin in `scaffold_node`. The
  `_scaffold_calls` helper now seeds an empty `package.json` in the mocked
  workspace, since `scaffold_node` reads it; S9.2.2's assertions are
  unchanged.
- **No test asserted the absence** of `.nvmrc` or `packageManager`, so none was
  corrected.
  `test_s9_1_8_3_reconcile_node_folds_the_workspace_and_writes_nvmrc` passes
  unchanged.
- **`package.json` key order.** `DocumentUtils.write` sorts keys, so the pinned
  `package.json` is alphabetical, not Nx's order (`name` first). Two spaces,
  trailing newline. Nothing in the cell lints JSON layout.
- **Closed S9.1.8 text stays.** Its "Nx writes `packageManager`" and F9.1's
  "`.nvmrc` is never rewritten" are replaced by this story. `.nvmrc` is not in
  the workspace, so the conflict check never sees it; it is only written, in
  `reconcile_node`, and `kiln new` is its only caller (`init` does not
  reconcile), into a fresh staging directory.
- **No other doc said `.nvmrc` is `node-lib` only.** The statement lived in
  `NODE_MAJOR`'s and `reconcile_node`'s docstrings, both reworded. Nothing in
  `docs/reference/standard-repo.md` or any template depends on it.
- **Running `pnpm --version` inside a golden cell rewrites its lockfile** (it
  adds `packageManagerDependencies`), so acceptance was checked with
  `pnpm install --frozen-lockfile` only, run before anything else touched the
  cell.

  ([F9.1](F9.1-node-lib-hosts-ngkit-ci.md#the-golden)), and templates would be

- **An `[archetype.node-lib] nx_cloud` key.** It would add a config table and a

  ngkit compare would need a second cell.

  would be a target kiln writes into repository-owned project files.
