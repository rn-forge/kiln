A repository may own a workflow file only for a non-gating or scheduled run
(pykit's `broker-profile.yml`). Its action pins need an updater, and kiln's own
pins must not be bumped from outside `pins.toml`. So Dependabot's
`github-actions` entry is rendered with an `ignore:` entry for every action in
`pins.toml`, and the standard states the rule.

## S15.7.1 — Dependabot watches the repository's own action pins

**State:** Closed (2026-11-05)

**Build — tests first,** in `tests/modules/cicd/test_artifacts.py`:

1. `test_s15_7_1_1_github_actions_entry`: every archetype's `dependabot.yml` has
   an update entry `package-ecosystem: github-actions`, `directory: "/"`, with
   the same `schedule`, `cooldown` and `groups` shape as the file's other
   entries.
1. `test_s15_7_1_2_ignore_covers_every_pin`: the entry's `ignore:` has one
   `dependency-name` for the `uses` value of every table in `pins.toml` that
   has one (for example `actions/checkout`), sorted, with no duplicate.
1. `test_s15_7_1_3_new_pin_is_ignored`: adding a table with `uses = "x/y"` to a
   copy of `pins.toml` adds `x/y` to the ignore list.

**Build:** `cicd/templates/dependabot.yml.j2`: the entry, with `ignore:` from a
context key `pinned_actions` (sorted `uses` values, from `load_pins()`). Entries
without `uses` (the `gitleaks` table) are skipped. Run `kiln apply` here.

**Acceptance:**

- The three tests pass, and `task validate` passes.
- `task lint KILN_DOCTOR_FULL=1` passes after `kiln apply`.

**What the build settled that the story did not say:**

- The template already rendered a `github-actions` entry for hook directories,
  only when hooks named some. It is kept exactly as it was, with no `ignore:`
  and no `/`, so Dependabot still updates the actions inside the repository's
  hook directories. The new root entry (`directory: /`, with `ignore:`) is a
  second `github-actions` entry, always rendered, after it. Dependabot allows
  two entries of one ecosystem with different directories. The ignore list
  would have blocked updates to hook actions such as `actions/setup-node` had
  both shared one entry.
- Departure: the story says one `dependency-name` per `uses` value. Dependabot
  names a sub-path action by its repository (`github/codeql-action`, not
  `github/codeql-action/upload-sarif`), so `pinned_actions` keeps `owner/repo`
  and drops duplicates. Tests 2 and 3 compare against that form.
- `pinned_actions()` is a function in `cicd/artifacts.py` beside `load_pins()`;
  tables without `uses` (`gitleaks` and its sub-tables) are skipped.
- Tests s4_11_4_2, s4_11_4_4, s9_1_1_3 and the `npm` substring tests (s9_1_1_2,
  s9_2_5_5) assumed no `github-actions` entry without hooks; they now expect
  the root entry. s4_11_4_3 and s4_11_7_6 keep their old assertions through a
  `_hook_entry` helper. s4_11_6_6 skips `dependabot.yml` in its "attest"
  substring check.
- kiln's own `.github/dependabot.yml` changed (root directory and the ignore
  list) and was re-rendered with `kiln apply`.

## S15.7.2 — The standard states the rule

**State:** Closed (2026-11-05)

**Build — tests first,** in `tests/modules/instructions/test_artifacts.py`:

1. `test_s15_7_2_1_standard_states_repository_workflows`: every archetype's
   `standard.md` contains the sentence "A repository-owned workflow is allowed
   only for a scheduled or non-gating run; it keeps its own action pins
   current through Dependabot, which ignores the actions kiln pins."

**Build:** `instructions/templates/standard.md.j2`, in the CI section, after the
hook tiers. Add the same sentence to `docs/architecture/ci.md`'s "Hooks" section
(tier four). Run `kiln apply`.

**Acceptance:**

- The test passes, and `task validate` passes.

**What the build settled that the story did not say:**

- The standard has no hook-tiers text, so the sentence sits in the
  `## CI checks` section S15.1.4 added, after the check matrix. It is a plain
  paragraph, so it renders in every archetype, `node-lib` included; the test
  checks all five Python archetypes and `node-lib`, comparing with whitespace
  collapsed because the sentence wraps.
- In `ci.md` the sentence follows the hook tier table in "Hooks". The closing
  step moved this feature's one row (tier four) there: `design.md` keeps its
  hook-tier table as it was, as for tiers one to three.
