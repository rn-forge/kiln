# ADR-0015 — `node-lib` renders ngkit's CI: one release group, a dispatched release, and generated CI helpers

**Status:** accepted (2026-10-14) · **Scope:** `node-lib` repositories

## Decision

`node-lib` is the archetype for a pnpm and Nx workspace of published libraries.
ngkit is its first repository. It is built in release-1. `node-web-app` stays
deferred.

- **One release group.** Every publishable library releases together under one
  version, tagged `v<version>`, as ngkit's ADR-0003 decides. There is no
  per-package tag option.
- **A dispatched release.** `[ci] release` gains a third value, `nx-dispatch`,
  which `node-lib` uses by default. The release runs on `workflow_dispatch`
  with bump, exact-version, dist-tag and dry-run inputs. It is gated on a
  green CI run for the commit, and pushes its release commit with a GitHub App
  token, because a branch ruleset blocks `GITHUB_TOKEN`. `tag-exists` stays
  the default for every other archetype.
- **Nx Cloud has a named exemption.** `nx start-ci-run` runs before install, and
  `nx fix-ci` and the agents file are Nx Cloud orchestration, not build steps.
  The generated setup action and CI workflow may call those two commands
  directly. `ci-entrypoint` allows them by name and nothing else.
- **CI helpers are generated.** ngkit's `tools/ci/*.mjs` (site assembly, release
  notes, dist verification and workspace-dependency resolution) are rendered
  by kiln as generated files under `tools/ci/`.
- **Docs tooling runs through uv**, as [ADR-0012](ADR-0012.md) decides. A
  `node-lib` repository carries a root `pyproject.toml` with no package of its
  own, whose dev group pins MkDocs, mdformat and kiln. `uv` is installed only
  for those tasks.
- **Every other build step is `task`.** The root verbs map onto Nx
  (`nx run-many` and `nx affected`). The CI-only steps are internal `ci:*`
  tasks.

## Consequences

- ngkit can adopt kiln without losing its CI or its release.
- `ci-entrypoint` gains an archetype-scoped allow-list. Each name on it is a
  hole in the rule, so it is kept to the two Nx Cloud commands.
- A helper fix needs a regeneration commit in each `node-lib` repository
  ([ADR-0006](ADR-0006.md) accepts this for workflows). There is one such
  repository today.
- A Node repository has two lockfiles, `pnpm-lock.yaml` and `uv.lock`.
- ngkit's `check-template` job is dropped: `doctor`'s generated-file check
  replaces it.

## Alternatives considered

- **Per-package tags `<package>-v<version>`.** ngkit rejected independent
  versions: the exact peer pin keeps a matched pair. No repository in scope
  needs them.
- **Release on push, as `tag-exists` does.** ngkit's release takes inputs (bump,
  dist-tag, dry run), and a push cannot carry them.
- **Drop Nx Cloud, rendering only `ci-local`.** ngkit would lose its distributed
  path when it adopts kiln.
- **Wrap the Nx Cloud commands as tasks.** `start-ci-run` has to run before
  `pnpm install`, when there is no installed `nx` for a task to call.
- **Publish the helpers as an npm package.** A second package to release and
  pin, while npm publishing is off.
- **A separate uv project under `docs/`.** More files for the same pins. The
  root `pyproject.toml` also carries kiln, which `doctor` needs.

## Background

- 2026-10-18: [ADR-0016](ADR-0016.md) requires every archetype's CI to meet one
  contract. `node-lib` keeps its Nx-native affected CI while it meets it; a
  dispatched release gated on a green CI run satisfies its release rule.
- 2026-10-30: `node-lib` and `python-web-app` share one pnpm, Nx and Angular
  scaffold. They differ only by code: a `node-lib` starts with no projects, a
  `python-web-app` with `@rn-forge/ng` and its application.
