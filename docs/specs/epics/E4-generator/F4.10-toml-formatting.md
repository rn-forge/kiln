Every generated repository checks its TOML formatting in `task lint` and fixes
it with `task format`, the same way it already handles Markdown. The formatter
is Taplo, the engine behind the Even Better TOML editor extension, so the gate
and the editor produce the same bytes.

## Context

Found 2026-10-18 by the owner: the five `archetypes/*/archetype.toml` files were
formatted inconsistently, and nothing in `task lint` caught it. Taplo with its
default settings fails 6 of kiln's 10 tracked `.toml` files.

**Why Taplo, not Prettier.** Prettier needs a plugin to read TOML, and that
plugin runs Taplo underneath. It would also bring Node into every Python
repository. Taplo ships on PyPI as a prebuilt binary (`taplo`, 0.9.3 on
2026-10-18), so it is pinned and run through `uv` like ruff.

**Why these settings.** `uv init`, `uv add` and tomlkit (which kiln uses to
reconcile `pyproject.toml`) all write multi-line arrays with a 4-space indent, a
trailing comma, and one item per line even when the array is short. Taplo's
defaults are a 2-space indent and collapsing short arrays onto one line. With
the defaults, every `uv add` would fail `task lint`. With
`indent_string = "    "` and `array_auto_collapse = false`, `uv add` output
passes as it is. That was checked on 2026-10-18 against a fresh `uv init --bare`
followed by `uv add ruff` and `uv add --dev pytest`.

**What the matrix showed.** The 2026-10-18 `.goldens/HEAD` render was checked
under those settings. Excluding `.mdformat.toml`, only two kinds of difference
remain, and both are in `pyproject.toml` text that kiln writes:

```text
-    { name = "…", email = "…" }          # project.authors, from uv init: no trailing comma
+    { name = "…", email = "…" },
-    {include-group = "workspace"},       # python-lib root dev group, from tomlkit
+    { include-group = "workspace" },
```

The seeded `.mdformat.toml` fails too, because its template indents with 2
spaces.

- `src/rn_forge/kiln/modules/core/templates/taplo.toml.j2`, new, with this
  content. The header comment copies the style of `mdformat.toml.j2`:

    ```toml
    # Seeded by kiln — this file is yours.
    #
    # Taplo formats every TOML file in the tree; `task lint` checks it and
    # `task format` applies it. Even Better TOML reads this file too, so the
    # editor and the gate agree. `exclude` is authoritative — taplo runs over
    # the tree, not over a file list.
    #
    # The style matches what `uv init`, `uv add` and kiln itself write into
    # `pyproject.toml`: 4-space indent, one item per line, trailing comma.
    include = ["**/*.toml"]
    exclude = [
        "**/.venv/**",
        # Tool caches — the same set `task clean` removes and `.gitignore` ignores.
        "**/.uv-cache/**",
        "**/.pytest_cache/**",
        "**/.ruff_cache/**",
        "**/.import_linter_cache/**",
        "**/node_modules/**",
        ".docs-site/**",
        "site/**",
        "dist/**",
        ".nx/**",
        ".rn-forge/kiln/rendered/**",
        # `kiln apply` keeps the managed files it replaced here.
        ".rn-forge/kiln/backups/**",
    ]

    [formatting]
    indent_string = "    "
    array_auto_collapse = false
    ```
