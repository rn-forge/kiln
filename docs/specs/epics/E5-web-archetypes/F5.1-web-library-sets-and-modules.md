# F5.1 — Library sets, and the modules gain the web shapes

Epic: [E5](index.md) · **Depends on:**
[S4.3.3, S4.3.4, S4.3.5, S4.3.7](../E4-generator/F4.3-concern-modules.md) (the
templates this feature branches), [S4.5.1, S4.5.2](../E4-generator/F4.5-cli.md)
(`kiln new` and `kiln apply`, so a rendered repo can be synced and gated);
pykit's web pins resolvable ([E5](index.md))

**Build a story by the [board's procedure](../../index.md#building-a-story).**
There is no golden to diff against: each template gains `{% if web %}` and
`{% if web_app %}` branches beside its `python-lib` branch, and the shape below
is what those branches render. [F4.4](../E4-generator/F4.4-render-matrix.md)'s
validate is where the result is proven runnable; until it exists, the feature
block below syncs and gates one rendered repo by hand.

## Design

**The two shapes.** Both are a uv workspace whose root `pyproject.toml` is bare
(`uv init --bare`, `[tool.uv] package = false`) with one member at `api_dir`
(default `apps/api`), exactly as `python-lib` has members under `packages/`. The
member's distribution is `<name>-api` and its module `<name>_api`
(`root_package`). `python-web-app` adds a pnpm-managed Nx workspace whose root
files (`package.json`, `pnpm-workspace.yaml`, `nx.json`, `tsconfig.base.json`,
the eslint and prettier configs) sit at the repo root and whose one application
is the Nx project at `web_dir` (default `apps/web`, project name `web`). Every
file the frontend scaffolder writes is repo-owned; kiln renders nothing under
`web_dir` and nothing the scaffolder wrote.

**Context, in addition to F4.3's:** `web` (either web archetype); `web_app`
(`python-web-app`); `framework`; `frontend`; `api_dir`; `api_package`
(`<name>-api`); `api_module`; `web_dir`; `web_project` (the basename of
`web_dir`).

**What each module renders differently.** Relative to `python-app`:

| Module | `python-web-api` | `python-web-app` adds |
| -- | -- | -- |
| `python` — `.importlinter` | `root_package = <api_module>`; the forbidden list drops the chosen `framework` (an API imports its framework) and keeps `typer jinja2 click` and the other framework | — |
| `python` — config | `[archetype.python-web-api]`: `framework` (`fastapi` \| `django`, default `fastapi`), `api_dir`, `admin_ui = false` | `[archetype.python-web-app]`: `framework` (default `django`), `frontend` (`angular` \| `react` \| `svelte`, default `angular`), `api_dir`, `web_dir`, `nx_cloud = false` |
| `python` — scaffold | `uv init --bare` root + `uv init --package` at `api_dir`; workspace table; the required set into the **member's** `[project] dependencies`; for `fastapi`, `uvicorn>=0.30` in the member's dev group so `api:dev` runs | the frontend scaffold, [S5.2.1](F5.2-kiln-new-web-end-to-end.md) |
| `tasks` — `quality.yml` | the `python-lib` form specialised to one member: `uv run --directory <api_dir> --package <api_package> …` written literally, no `for:` loop | — |
| `tasks` — `workspace.yml` | `install`: `uv sync --all-packages --group dev --group docs`; `build`/`version`: `--package <api_package>` | `install` also `pnpm install --frozen-lockfile`; `clean` also removes `.nx` and `<web_dir>/dist` |
| `tasks` — `api.yml` (new, public) | `api:dev` — `fastapi`: `uv run --package <api_package> uvicorn <api_module>.app:app --reload --port 8000`; `django`: `uv run --package <api_package> python <api_dir>/manage.py runserver 8000`, plus `api:migrate` (`… manage.py migrate`). The `app.py` module is the repo's; the standard says so | — |
| `tasks` — `web.yml` (new, public) | — | `web:lint` `pnpm nx run-many -t lint`; `web:test` `pnpm nx run-many -t test`; `web:build` `pnpm nx run-many -t build`; `web:dev` `pnpm nx serve <web_project>` |
| `tasks` — `Taskfile.yml` | `includes` gains `api: tasks/api.yml` | gains `web: tasks/web.yml`; `lint` ends with `- task: web:lint`, `test` with `- task: web:test`, `build` with `- task: web:build` |
| `cicd` — setup action | — | after `setup-task`: `pnpm/action-setup` then `actions/setup-node` with `cache: pnpm`, both SHA-pinned in `pins.toml` (`pnpm-setup`, `setup-node`); resolve a SHA with `gh api repos/<owner>/<repo>/git/ref/tags/<version>` and record the version comment |
| `cicd` — `ci.yml` | unchanged | unchanged: every step is already `task …` |
| `cicd` — `sonar-project.properties` | `sonar.sources=<api_dir>/src`, `sonar.tests=<api_dir>/tests` | `sonar.sources` also lists `<web_dir>/src` |
| `instructions` — block, `standard.md` | the **Archetype** bullet names the framework; the verb table gains the `api:*` rows | a **Frontend** clause (`angular`, pnpm + Nx) and the `web:*` rows |
| manifests | `forbidden_tools` unchanged; `required_validate` unchanged | `forbidden_tools` adds `pnpm npx nx ng`; `required_validate` adds `web:lint`, `web:test` |

The task vocabulary gains two public namespaces, `api:*` and `web:*`, beside
`docs:*`. The taskgraph rule "inner tasks are internal except `docs:*`" reads
"except `docs:*`, `api:*` and `web:*`" (design, doctor check 5).

## S5.1.1 — Web library sets

**Status:** planned

`python-web-api`/`python-web-app` take commons → web → `rn-forge-fastapi` or
`rn-forge-django` (+ `rn-forge-cli` for management commands).

**Build:**

- `archetypes/python_web_api/archetype.toml` and
  `archetypes/python_web_app/archetype.toml`, the six modules in the same
  order as `python_app`.
  `[dependencies] required = ["rn-forge-commons", "rn-forge-cli", "rn-forge-web"]`,
  `allowed` the same; `for_config` adds `rn-forge-<framework>` to both, as
  it adds `rn-forge-tooling` for `lifecycle`. `forbidden_tools` and
  `required_validate` per the table above.
- `[untested]` tables: `python_web_api`: `framework = ["django"]`;
  `python_web_app`: `frontend = ["react", "svelte"]` (and
  `framework = ["django"]` if [F5.3](F5.3-shipped-web-cells.md)'s question is
  answered that way). `Archetype.untested: dict[str, list[str]]` and
  `kiln new`'s refusal already exist from S4.5.1; this story fills the tables.
- `modules/python/config.py`: `WebApiConfig` and `WebAppConfig` (`StrictModel`,
  the fields and defaults in the table), and `ArchetypeConfig` gains
  `python_web_api` / `python_web_app` with the same alias pattern.
  `KilnConfig` gains `framework`, `frontend`, `api_dir`, `web_dir`, each
  `None` outside the web archetypes, and `packages` returns `(api_dir,)` for
  them so every existing per-member code path applies.
- `PythonModule.options()` gains
  `Option("framework", "archetype.<archetype>.framework", …)` and
  `Option("frontend", "archetype.<archetype>.frontend", …)`; `kiln new`
  substitutes `<archetype>` (S4.5.1).
- `archetypes.pyproject_paths` already returns the root plus each member.
- `rn_forge_deps`: a `[codegen]` extra of the chosen framework is accepted in a
  dependency group and refused in `[project] dependencies`. Nothing renders
  it.

**Acceptance:**

- For each web archetype and framework, `for_config(...).dependencies.required`
  is commons, cli, web and the framework package, in that order; `allowed`
  equals it (plus `rn-forge-tooling` with `lifecycle`).
- The dependency check refuses a member `pyproject.toml` that lacks
  `rn-forge-web`, one that names the other framework, and one with `[codegen]`
  in runtime dependencies; it accepts `[codegen]` in the dev group (one test
  each).
- A config naming `framework = "flask"` or `frontend = "vue"` fails to load
  naming the key. A `[archetype.python-web-app]` table under a `python-app`
  config is rejected.

## S5.1.2 — Modules gain the web shapes

**Status:** planned

Every row of the design table, as template branches and scaffold steps.

**Build:** the `python`, `tasks`, `cicd` and `instructions` modules per the
table; templates `tasks/api.yml.j2` and `tasks/web.yml.j2`; `pins.toml` gains
`pnpm-setup` and `setup-node`. F4.3's five properties apply, with property 4
read as: the `python-app` render is byte-identical before and after this story
(the new branches change nothing outside the web archetypes).

**Tests:** in each module's `tests/modules/<module>/test_artifacts.py`,
`test_s5_1_2_…` names, over `python-web-api` + `fastapi` and `python-web-app` +
`fastapi` + `angular`.

**Acceptance:**

- `python-web-app` renders `tasks/api.yml` and `tasks/web.yml`; `python-web-api`
  renders `tasks/api.yml` and no `tasks/web.yml`. `task --list --json` on each
  shows the ten root verbs, `docs:*` for `mkdocs`, `api:dev` (and
  `api:migrate` for `django`), and `web:lint web:test web:build web:dev` for
  the app only.
- `task-layout` passes on both, and `gate.shrunk` fires on a `python-web-app`
  `Taskfile.yml` whose `lint` no longer calls `web:lint`.
- Only `python-web-app`'s setup action sets up pnpm and node; `ci-pins` and
  `actionlint` pass on both archetypes' workflows.
- A workflow that calls `pnpm`, `npx`, `nx` or `ng` directly fails
  `ci-entrypoint` under `python-web-app`.
- `.importlinter` for `fastapi` forbids `django` and not `fastapi`, and the
  reverse for `django`; `lint-imports` passes on a scaffolded member.
- The three `python-*` archetypes' renders are byte-identical to their renders
  before this story (assert against the goldens, as property 4 already does).

## S5.1.3 — `framework` stays a flag

**Status:** planned

`framework = fastapi|django` changes only `tasks/api.yml`'s primitives, the
`.importlinter` forbidden list, and the scaffold's dependency lines — never
topology or the task graph ([ADR-0005](../../../adr/ADR-0005.md)).

**Acceptance:** for `python-web-app` with `angular`, `django` and `fastapi`
render the same artifact keys and the same public and internal task names. Their
managed artifacts differ only in `tasks/api.yml` and `.importlinter`; every
other artifact's content is byte-identical between the two renders.

## Acceptance

```bash
set -euo pipefail
cd rn-forge/kiln
kiln_dir=$PWD
kiln() { uv run --project "$kiln_dir" kiln "$@"; }
task test                                                                             # S5.1.1, S5.1.2, S5.1.3
s=$(mktemp -d)
for fw in django fastapi; do
  kiln new "$s/$fw" --archetype python-web-app --framework "$fw" --frontend angular --docs none --yes --json --allow-untested </dev/null \
    | jq -r '.artifacts[].key' | sort >"$s/$fw.keys"
  (cd "$s/$fw" && task --list-all --json) | jq -r '.tasks[].name' | sort >"$s/$fw.tasks"
done
test -s "$s/fastapi.keys"
diff "$s/django.keys" "$s/fastapi.keys"                                               # S5.1.3: same artifacts
diff "$s/django.tasks" "$s/fastapi.tasks"                                             # S5.1.3: same task graph
kiln new "$s/api" --archetype python-web-api --framework fastapi --docs mkdocs --yes </dev/null
(cd "$s/api" && uv sync && task validate && actionlint)                              # S5.1.2: a synced, gated api repo
```

Not scriptable: the `python-web-app` cell's `pnpm install && task validate` is
[F5.2](F5.2-kiln-new-web-end-to-end.md)'s; `--allow-untested` above is only
needed while `django` is untested.
