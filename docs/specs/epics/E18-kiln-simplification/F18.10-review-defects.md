Each story fixes one defect that is still present at `6b3549b`. Each one changes
what kiln renders or reports, so the work belongs in release 2 under the split
proposed on 2026-11-10: behaviour-preserving work goes in release 1, and
behaviour changes come after the tag. The owner moved S18.10.1, S18.10.8 and
S18.10.10 to release 1 on 2026-11-13, as
[F18.12](F18.12-release-1-review-defects.md). Defects 1 and 9 on the idea page
are already fixed. The suites gate is at `cicd/templates/ci.yml.j2:5-8`, and
`cycle.py:227-246` refuses an unfenced block.

Every story keeps these properties:

1. The first test reproduces the defect and fails before the fix.
1. A test goes through the command or through doctor, never through a single
   check or helper alone.
1. Where a rendered file changes, `task kiln:apply` runs on this repository in
   the same change, and `task lint KILN_DOCTOR_FULL=1` passes.

Line numbers are at `6b3549b`.

## S18.10.2 — `doctor --full` reports every blocking action

**State:** New · **Depends on:** —

`doctor.py:14-20` maps no code to `CONFLICT`, `DRIFT` or `MISSING`, so `--full`
silently drops them (defect 2).

**Acceptance:**

- `kiln doctor --full` exits 1 and names the path, for each of the three
  actions.

## S18.10.3 — A config source ref may contain `/`

**State:** New · **Depends on:** —

`core/config/sources.py:39-41` refuses a ref that contains `/`, so
`git+https://…@feature/profile` is not split (defect 3).

**Acceptance:**

- `Source.parse` splits `git+url@feature/profile` into the URL and
  `feature/profile`. A `git+ssh://` URL with no ref keeps its `@`.

## S18.10.4 — A wildcard `==` is a floor

**State:** New · **Depends on:** —

`devops/requirements.py:16-29` gives `==0.3.*` no lower bound (defect 4). **Open
question, owner:** must a sibling's version satisfy the whole specifier, or only
the floor?

**Acceptance:**

- `==0.3.*` has the floor `0.3`, and the range check passes a sibling at
  `0.3.2`.

## S18.10.5 — Provenance compares like with like

**State:** New · **Depends on:** —

`core/config/manager.py:308-312` records provenance from the raw merged
document, and `reresolve` compares it with the normalised one (defect 5).

**Acceptance:**

- A config whose audit reason has trailing whitespace re-resolves with no
  override reported.

## S18.10.6 — Task overrides are serialised

**State:** New · **Depends on:** —

The about 26 `[[ overrides[X] ]]` interpolations in
`tasks/templates/tasks/*.yml.j2` insert raw text, so `echo "a: b"` parses as a
mapping (defect 6). One Jinja `override(name)` macro replaces them, with safe
YAML output. The `_*_TASKS` tuples (`tasks/artifacts.py:23-55`) are derived from
one table.

**Acceptance:**

- An override `echo "a: b"` renders as one command, and `task` runs it.

## S18.10.7 — Test arguments keep their quoting

**State:** New · **Depends on:** —

`devops/ci.py:275-280` builds `PYTEST_ARGS` and `SUITE_ARGS` with `shlex.join`,
and `tasks/templates/tasks/ci.yml.j2:328`, `:345` expand them unquoted. As a
result, `-m 'not slow'` splits into three arguments (defect 7).

**Acceptance:**

- A plan with `-m 'not slow'` runs pytest with `-m` and `not slow` as two
  arguments.

## S18.10.11 — Every entry point runs the same pipeline

**State:** New · **Depends on:** S18.6.3

There are two gaps:

- The config preview selects artifacts without apply's starter policy.
- `apply` skips the docs finalisation that `new` runs, so a switch from
  `docs = "none"` to `mkdocs` fails the first apply.

**Acceptance:**

- `kiln config-update` previews exactly the changes that `--apply` makes.
- Switching `docs` from `none` to `mkdocs` and running `kiln apply` passes
  `kiln doctor`.

## S18.10.12 — Every name kiln renders is reserved

**State:** New · **Depends on:** —

Three things go wrong today:

- `cicd/config.py:30-46` `GENERATED_JOBS` lacks `test-cloud`, `test-local` and
  `umbrella`, which `ci.yml.j2` renders at `:185`, `:217` and `:527`.
- `STAGE_WORKFLOWS` and `cicd/artifacts.py:152-159` repeat the stage names.
- Task includes have no reserved-name check before rendering.

**Acceptance:**

- A test asserts that every top-level job in each rendered `ci.yml` is in the
  reserved set. That set and the stage names are declared once.
- A declared job or task include that takes a reserved name is refused at config
  load, naming the key.

## S18.10.13 — The config refuses what it cannot render

**State:** New · **Depends on:** S18.7.1

**Acceptance:**

- `archetype = "python_tool"` is refused at load (`archetypes/__init__.py:64`
  accepts it today).
- `ci.release = "pypi"` on `python-app` is refused with an `AppException` naming
  the key, not a raw `ValueError` (`config.py:84-94`).
- A malformed `_areas.yml`, whether a non-mapping entry or an unknown key, is
  refused with an `AppException`. Today `docs/areas.py:56-82` raises a raw
  `ValueError`, which `structure.py:352` does not catch. The manifest is a
  strict model.
- A `python-app` with `lifecycle = true` gets the starter that its `AGENTS.md`
  describes (`instructions/artifacts.py:102-106` against
  `python/starter.py:58`).

## S18.10.14 — One distribution-name canonicaliser

**State:** New · **Depends on:** S18.7.3

`python/checks/rn_forge_deps.py:65-68` lowercases names and swaps `_` for `-`,
but does not collapse `.`. The result is that `rn.forge.commons` escapes the
allow-list.

**Acceptance:**

- `rn_forge_deps`, the scaffold and devops use the one `canonicalize_name`
  helper, and `rn.forge.commons` is governed.

## S18.10.15 — Docs links are checked once, against the real `.gitignore`

**State:** New · **Depends on:** S18.9.1

There are two problems:

- `docs/structure.py:225-255` and `site.py:174-239` both emit `docs.broken-link`
  and `docs.broken-anchor`, so one broken link is reported twice.
- `site.py:59-72` reads `.gitignore` lines as literal paths.

**Acceptance:**

- A broken link is reported once, by `docs-site`.
- A link to a page under a `.gitignore` glob, such as `site/**`, counts as
  generated.
