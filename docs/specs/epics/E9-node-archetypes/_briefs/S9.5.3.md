# S9.5.3 — `node-lib` ships an SBOM and an attestation per package

Brief for
[S9.5.3](../F9.5-node-lib-release-findings.md#s953-node-lib-ships-an-sbom-and-an-attestation-per-package),
at `8dfe984`.

## Goal

Every `node-lib` release, fixed or independent, `nx-dispatch` or `npm`,
generates a CycloneDX SBOM per released package, attests each tarball and SBOM
with the pinned `attest` action before anything is published, and attaches the
SBOM to the GitHub Release beside its tarball. A release whose SBOM is missing
fails before its GitHub Release is created.

## Settled

- **The SBOM tool is pnpm's own `pnpm sbom`** (no new dependency). Per package,
  from the workspace root:

    ```sh
    pnpm --filter "$name" sbom --sbom-format cyclonedx --sbom-spec-version 1.5 --prod --lockfile-only --out "dist/tarballs/$packed-$version.cdx.json"
    ```

    `$name` is the package's `package.json` `name`, `$version` its version, and
    `$packed` the packed name S9.5.6 uses (`@s/a` gives `s-a`), so a tarball
    `dist/tarballs/s-a-1.2.3.tgz` sits beside
    `dist/tarballs/s-a-1.2.3.cdx.json`. **Check first** that the pnpm the
    generated setup installs (kiln's `PNPM_VERSION`, `12.15.0`, in
    `modules/node/scaffold.py`) has `pnpm sbom`. The reviewer saw it in pnpm
    12.21.0 but could not run 12.15.0. If you cannot confirm it either, build to
    the settled command and say so in `## Result`; do not change `PNPM_VERSION`.

- **A task** `release:sbom` in `modules/tasks/templates/tasks/ci.yml.j2` (node
  release block),
  `desc: "CI only: Write a CycloneDX SBOM beside each released package's tarball in dist/tarballs."`.
  Fixed: one SBOM per publishable project. Independent: one per `TAGS`
  entry's project. Walk projects the way `release:state` does.

- **Workflow** (`_release.yml.j2`, node job), after "Rebuild and verify" and
  before "Push the tag", two steps, gated like "Rebuild and verify" (fixed:
  `mode != 'released'`; independent: `tags != ''`):

    1. `- name: Generate SBOMs` running `task ci:release:sbom` (with `TAGS` env
       under independent);
    1. `- name: Attest the tarballs and SBOMs` using
       `[[ pins["attest"].uses ]]@[[ pins["attest"].sha ]] # [[ pins["attest"].version ]]`
       with `subject-path: |` listing `dist/tarballs/*.tgz` and
       `dist/tarballs/*.cdx.json`, and the comment the python job carries above
       its attest step ("Attested before …").

- **Permissions.** The node `release` job, in `_release.yml.j2` and in
  `ci.yml.j2`'s caller, has `attestations: write` and `id-token: write` under
  both release modes. S9.5.2 dropped `id-token` under `nx-dispatch`; it comes
  back, with the comment `# attest build provenance` under `nx-dispatch` and
  the existing npm comment plus attestation under `npm`.

- **Assets.** `release:github` attaches each tarball's SBOM with it: fixed
  `dist/tarballs/*.tgz dist/tarballs/*.cdx.json`; independent, the project's
  tarball and `dist/tarballs/$packed-$version.cdx.json`. Before
  `gh release create`, a tarball without its SBOM is an error:
  `::error::No SBOM for <tarball>`.

- `release:latest` (fixed only) is unchanged.

- No `devops/` change: the fixed and independent asset lists live in the task.

- Tests are named for behaviour, `test_<subject>_<behaviour>`, with no spec ID
  in a name, docstring or comment.
