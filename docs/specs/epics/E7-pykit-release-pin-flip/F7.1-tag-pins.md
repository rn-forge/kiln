## S7.1.2 — Application roots resolve pykit without its workspace sources

**State:** Closed (2026-10-16)

Added 2026-10-16, after S7.1.1's golden validate failed. pykit tags each package
on its own commit (ADR-0004). Each pykit package also keeps
`[tool.uv.sources] <sibling> = { workspace = true }`, and uv resolves those
sources relative to the tag it fetched, so one distribution arrives under two
URLs. `[tool.uv] no-sources = true` makes uv resolve every dependency from its
declared, published metadata, which is what a consumer outside pykit should see.
Proved by hand on 2026-10-16 (uv 0.13.1) against a copy of the rendered
`python-web-api-backend=fastapi` cell. Without the setting, `uv lock` fails with
the conflict. With it, `uv lock` resolves 90 packages, each rn-forge package at
its own tag, and `rn-forge-commons` keeps the `pydantic` extra that
`rn-forge-web` asks for.

Rejected: `[tool.uv] override-dependencies` naming each distribution at its tag.
An override replaces the requirement, extras included. The lock dropped
`rn-forge-commons[pydantic]`, and pykit packages ask for extras conditionally
(`rn-forge-commons[excel,pandas]`, `rn-forge-web[auth,security]`). A fixed
override list either drops extras that are needed or pulls pandas into every
repository.

`python-lib` is left out. A library workspace wires its own members with
`{ workspace = true }` sources ([ADR-0014](../../../adr/ADR-0014.md)), and
`no-sources` would resolve each sibling from git instead of from the checkout.
No other archetype has sources of its own: `rn-forge-deps` rejects an
`[tool.uv.sources]` entry for an rn-forge package.

**Build — tests first**, in `tests/modules/python/test_scaffold.py`. Copy the
shape of the nearest test there that reads a reconciled root `pyproject.toml`.

- `test_s7_1_2_1_application_roots_ignore_sources`: for `python-app`,
  `python-app` with `lifecycle`, and the FastAPI `python-web-api` cell, the
  root `pyproject.toml` has `[tool.uv] no-sources = true`.
- `test_s7_1_2_1_members_do_not_set_it`: in the FastAPI `python-web-api` cell,
  `apps/api/pyproject.toml` has no `no-sources` key.
- `test_s7_1_2_2_python_lib_keeps_sources`: for `python-lib`, no
  `pyproject.toml` has a `no-sources` key.
- `test_s7_1_2_1_build_backend_survives`: for `python-app`, `[tool.uv]` still
  holds `build-backend` beside `no-sources`.

**Build:**

- `src/rn_forge/kiln/modules/python/scaffold.py`, `_reconcile`: when `is_root`
  and not `lib`, set `tool["uv"]["no-sources"] = True`, merged into the
  `build-backend` table that a non-workspace root already gets. Add one
  comment line that says why, and link this story.
- `docs/reference/standard-repo.md` §3, after the pin-table paragraph, add:
  *Every root outside `python-lib` sets `[tool.uv] no-sources = true`. pykit's
  tags sit on different commits, and pykit's own workspace sources would
  otherwise make uv resolve a shared dependency once per tag. A repository
  scaffolded before kiln did this adds the line by hand.* Mirror the sentence
  in `modules/instructions/templates/standard.md.j2`, hand-copy it into
  `.rn-forge/kiln/standard.md`, and re-seed its `content_hash` as `README.md`
  says.

**Do not** change `rn_forge_deps.py`, add a doctor check for the setting, change
kiln's own `pyproject.toml` (it reaches only `f3d1757`), or move a pin.

**Acceptance:**
