## S7.1.1 — One pin table of pykit release tags

**State:** New

kiln's `uv.lock` already resolves commons, cli and tooling at `f3d1757`, the
commit tagged `rn-forge-commons-v0.5.0`, `rn-forge-cli-v0.1.0` and
`rn-forge-tooling-v0.2.0`, so kiln's own flip changes no code it runs.

**Build — tests first:**

- In `tests/test_archetypes.py`:
  `test_s7_1_1_1_requirement_names_the_release_tag`:
  `archetypes.requirement("rn-forge-cli")` is
  `rn-forge-cli @ git+https://github.com/rn-forge/pykit@rn-forge-cli-v0.1.0#subdirectory=packages/rn-forge-cli`.
  `test_s7_1_1_1_every_tag_is_pinned`: every value in `RN_FORGE_TAGS`
  matches `^<key>-v\d+\.\d+\.\d+$` for its key, and the keys are exactly the
  seven rn-forge distributions below.
  `test_s7_1_1_1_an_unpinned_distribution_is_refused`:
  `requirement("rn-forge-nope")` raises `KeyError`.
- `test_s7_1_1_2_kiln_takes_pykit_by_tag`: kiln's own `pyproject.toml` has no
  `pykit@main`; its three rn-forge requirements equal `requirement(...)` (with
  `[pydantic]` on commons).
- Update the two tests that spell `pykit@main` (`tests/test_generate_package.py`
  and `tests/modules/python/checks/test_rn_forge_deps.py`'s `BASE_URL`) to the
  tag form. A test of the check's rules may keep a branch URL where the branch
  itself is the point; say so in a comment.

**Build:**

- `src/rn_forge/kiln/archetypes/__init__.py`: replace `RN_FORGE_SOURCE` with
  `PYKIT_GIT = "git+https://github.com/rn-forge/pykit"` and

    ```python
    RN_FORGE_TAGS = {
        "rn-forge-commons": "rn-forge-commons-v0.5.0",
        "rn-forge-cli": "rn-forge-cli-v0.1.0",
        "rn-forge-tooling": "rn-forge-tooling-v0.2.0",
        "rn-forge-web": "rn-forge-web-v0.2.0",
        "rn-forge-django": "rn-forge-django-v0.4.0",
        "rn-forge-fastapi": "rn-forge-fastapi-v0.2.0",
        "rn-forge-sqlalchemy": "rn-forge-sqlalchemy-v0.2.0",
    }
    """pykit's release tags, read from pykit on 2026-10-14. Moving a pin is a change here alone."""
    ```

    `requirement(distribution)` returns
    `f"{distribution} @ {PYKIT_GIT}@{RN_FORGE_TAGS[distribution]}#subdirectory=packages/{distribution}"`.
    Update every importer of `RN_FORGE_SOURCE`.

- kiln's own `pyproject.toml`: the three rn-forge requirements take the tag
  form, then relock (`uv lock`). The lock's pykit commit must stay `f3d1757`;
  if it moves, stop and record why.

- `modules/instructions/templates/standard.md.j2`: the TOML example shows the
  tag form (`@rn-forge-commons-v0.5.0`), and the sentence "Until the owner
  declares pykit stable, they name its branch:" becomes "Each names its
  package's release tag:". Hand-copy the change into kiln's own
  `.rn-forge/kiln/standard.md` (kiln renders `python-tool`) and re-seed its
  `content_hash` in `.rn-forge/kiln/state.json`, as `README.md` says.

- `docs/reference/standard-repo.md` §3: the example uses the tag form; replace
  the paragraph "**Until pykit's release-1 tags exist, repos consume it from

  tag, from kiln's pin table (E7). A new kiln release moves the pins;
  `kiln config upgrade --apply` takes them into a repository.* Keep the
  sentence about the checker accepting a branch or path source with a warning
  only if `rn_forge_deps.py` still does that; it does not today, so drop it.

- `docs/specs/index.md` Upstream pins: E7's row stays as observed. In the Order
