# S16.5.9 — A single-member repository's CI test job runs its tests

Brief for
[S16.5.9](../F16.5-rebuild-and-port.md#s1659-a-single-member-repositorys-ci-test-job-runs-its-tests).

## Goal

The single-member `ci:test` task calls `:test` with `CLI_ARGS` cleared, so
`task ci:test -- <member>` runs `pytest -q` and not `pytest -q <member>`.

## Settled

- The design, the rejected options and both tests are on the story; follow them
  verbatim.
- "Every non-workspace cell" in test 1 means the cells that render the
  single-member branch of `tasks/ci.yml.j2` (the `test` task whose `desc` is
  "CI only: Run the repository's tests (the plan's one member)."):
  `python-app`, `python-tool`, `python-web-api` and `python-web-app`. The
  `node-lib` `test` task (Nx targets, which reads `CLI_ARGS` on purpose) and
  the `python-lib` workspace `test` task do not change.
- `ci.yml.j2` does not change.

## Current behaviour

- `src/rn_forge/kiln/modules/tasks/templates/tasks/ci.yml.j2:501-504` renders:

    ```yaml
      test:
        desc: "CI only: Run the repository's tests (the plan's one member)."
        cmds:
          - task: :test
    ```

- The template's own variables are `[[ ]]`; `{{ }}` is go-task's, so a literal
  `{CLI_ARGS: ""}` needs no escaping.

- Test 1 fails before the change because the command has no `vars` key
  (`KeyError` or an assertion on `None`, depending on how it reads the dict;
  make it an assertion). Test 2 fails because the `--dry` output holds
  `pytest -q apollo-api`.

- The `--dry` precedent is
  `test_dry_run_prints_doctor_with_full_only_when_asked` in
  `tests/modules/tasks/test_node_tasks.py:461`: render with `cycle.apply`, then
  `task -t <root>/Taskfile.yml --dry ...`. The cell roots come from
  `tests/modules/tasks/support.py` (`_root`, `WEB_CELLS`, `ALL_CELLS`).

## Change

- `ci.yml.j2`, the single-member `test` task only:

    ```yaml
      test:
        desc: "CI only: Run the repository's tests (the plan's one member)."
        cmds:
          - task: :test
            vars: {CLI_ARGS: ""}
    ```

- Run `task kiln:apply` here; kiln itself is a `python-tool`, so its own
  `tasks/ci.yml` changes with it.

- **Leave alone:** `ci.yml.j2`, the workspace and node `test` tasks, every other
  template, every spec page except `## Result` below.

## Tests first

In `tests/modules/tasks/test_task_ci.py`, named exactly as the story names them:

1. `test_single_member_ci_test_does_not_forward_cli_args`, parametrized over the
   four cells above (the web ones with their `WEB_CELLS` extras): the rendered
   `tasks/ci.yml`'s `test` task has exactly one command,
   `{"task": ":test", "vars": {"CLI_ARGS": ""}}`. For `python-lib`, the `test`
   task holds no `vars` key with `CLI_ARGS` (unchanged).
1. `test_single_member_ci_test_runs_pytest_without_the_member`,
   `@requires("task")` (import it as `test_node_tasks.py` does): for the
   `python-web-app` fastapi/angular cell and a `python-app` cell, render with
   `cycle.apply`, run `task --dry ci:test -- apollo-api`; the output holds
   `pytest -q` and, on that line, nothing after `pytest -q` contains
   `apollo-api`.

Confirm both fail before the change, as above.
