# S9.5.2 — `[ci] release = "npm"`

Brief for [S9.5.2](../F9.5-node-lib-release-findings.md#s952-ci-release-npm), at
the commit that lands S9.5.6.

## Goal

A `node-lib` chooses whether its release reaches npm. `nx-dispatch` (the
default) is a GitHub-only release: it tags, creates the GitHub Release with the
tarballs and publishes it, and never calls npm. `npm` does the same and
publishes to npm by trusted publishing (OIDC) in a GitHub environment named
`npm`. Both work for fixed and independent release groups.

## Settled

Owner, 2026-11-17: `nx-dispatch` = GitHub only; `npm` adds the publish. npm's
docs (checked 2026-11-17): the trusted publisher validates the **calling**
workflow, so it names `ci.yml`; both caller and called workflow need
`id-token: write`; provenance is generated automatically; npm CLI 11.5.1+ is
required.

- **Config.** `modules/cicd/config.py`: `CiConfig.release` is
  `Literal["tag-exists", "pypi", "nx-dispatch", "npm", "none"] | None`; its
  docstring names `npm` ("`npm` is the `node-lib` flow that also publishes to
  npm by trusted publishing"). `resolve_release` refuses `npm` off `node-lib`
  with `ci.release = 'npm' needs the node-lib archetype`. The default for
  `node-lib` stays `nx-dispatch`. `modules/cicd/registry.py` line 154's value
  list names `npm`.

- **A node release** is `release in ("nx-dispatch", "npm")`. Every template gate
  that today reads `release == "nx-dispatch"` for the node release
  (`tasks/ci.yml.j2` line 167, `standard.md.j2`'s variables table and "Once
  per repository" bullets) covers both. Add a context key `npm_publish`
  (`release == "npm"`) to the tasks, cicd and instructions contexts.

- **Under `nx-dispatch`:**

    - no `release:publish` task is rendered (fixed or independent);
    - `_release.yml`'s node job has no `Publish` step, no
      `id-token: write # npm OIDC trusted publishing` line and no `registry-url`
      input to the setup action;
    - `ci.yml`'s `release` job has no `id-token: write` line.

- **Under `npm`:** today's rendering (the `Publish` step, `release:publish`,
  both `id-token: write` lines, `registry-url`), plus `environment: npm` on
  the `_release.yml` node `release` job, placed after `timeout-minutes:` as
  the pypi job places its `environment:`.

- **Standard (§9).** Remove the sentence that tells the owner to add
  `"dryRun": true` to `nx-release-publish` (lines ~353–355: "Until npm
  publishing is set up, add … publishes to npm."). In `**Releasing.**` (both
  release-group variants), "publishes to npm under the dist-tag …" is said
  only under `npm_publish`; under `nx-dispatch` say instead that the release
  creates the GitHub Release with the tarballs and does not publish to npm.
  Under "Once per repository", when `npm_publish`, add:

    ```markdown
    - npm trusted publishing: create a GitHub environment `npm` with deployment
      branch `main`, and on npmjs.com add a trusted publisher to each package
      naming this repository, the workflow `ci.yml` (npm checks the calling
      workflow, not `_release.yml`) and the environment `npm`. No npm token is
      stored.
    ```

    The `**CI:**` line at the top (line 33) says
    `, release to npm by trusted publishing` when `npm_publish`, as it does for
    PyPI.

- Tests are named for behaviour, `test_<subject>_<behaviour>`, with no spec ID
  in a name, docstring or comment.
