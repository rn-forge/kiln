# S5.5.2 — `task web:client` regenerates the client, and CI checks it

Brief for
[S5.5.2](../F5.5-web-app-api-client.md#s552-task-webclient-regenerates-the-client-and-ci-checks-it),
at `02d4407`. Line references are at `02d4407`.

## Goal

A `python-web-app` + FastAPI repository has `task web:client`. It writes the
API's OpenAPI document and regenerates the frontend's typed Angular client from
it. `task lint`, and so `task validate` and CI, fails when the committed client
differs from what the API produces. `kiln new` seeds the generator and a first
client.

## Settled

All settled by the owner on 2026-11-19 (S5.5.1). The lead ran a spike on the
render matrix's FastAPI + Angular cell. Every number and text below comes from
that spike.

- **The generator** is `@hey-api/openapi-ts`, pinned exactly at `0.99.0`. Its
  Angular client is bundled into the output, so no runtime dependency is
  added. Generating twice from the same document gives identical bytes.

- **Paths.** The document is `<web_dir>/src/app/api/openapi.json` and the client
  is `<web_dir>/src/app/api/client/`. Both are committed.

- **`openapi-ts.config.ts`** at the repository root is a `SEEDED` artifact. The
  `node` module renders it for `python-web-app` with `backend == "fastapi"`,
  from a new template `modules/node/templates/openapi-ts.config.ts.j2`. It
  sits next to `.prettierrc` in `modules/node/prettier.py:render`, which
  already returns the node artifacts for `python-web-app`. Its text, with
  `<web_dir>` substituted, is exactly:

    ```ts
    import { defineConfig } from '@hey-api/openapi-ts';

    export default defineConfig({
      input: '<web_dir>/src/app/api/openapi.json',
      output: '<web_dir>/src/app/api/client',
      plugins: [{ name: '@hey-api/client-angular', baseUrl: false }],
    });
    ```

    `baseUrl: false` is required. Without it the generator writes
    `baseUrl: 'apps'`, taken from the input path. The starter calls the API on
    relative `/v1` URLs through `proxy.conf.json`.

- **`modules/tasks/templates/tasks/web.yml.j2`** gains, when
  `backend == "fastapi"`:

    - a public `client` task. Its `desc:` is exactly
      `Regenerate the frontend's API client from the API's OpenAPI document.`
      Its `cmds`, in order:
        1. `mkdir -p [[ web_dir ]]/src/app/api`
        1. `uv run --package [[ api_package ]] python -c "import json; from [[ api_module ]].app import app; print(json.dumps(app.openapi(), indent=2, sort_keys=True))" > [[ web_dir ]]/src/app/api/openapi.json`
        1. `pnpm openapi-ts`
    - an internal `client:check` task. It runs `task: client`, then fails with
      `the API client is stale — run task web:client and commit the result` when
      the repository has a commit (`git rev-parse -q --verify HEAD`) and
      `git status --porcelain -- [[ web_dir ]]/src/app/api/` prints anything.
      Before the first commit there is nothing to compare against, so it passes.
      This is what lets a fresh `kiln new` repository's first `task validate`
      pass.

    Add any context key the template lacks (`backend`, `api_package`, `api_module`
    and `web_dir` are already in `tasks/artifacts.py`'s context, lines 125-133).

- **Where it joins the gate.** `web:client:check` is a step of the root `lint`
  composition (`Taskfile.yml.j2`, line 59). It goes right after
  `node:lint:format`, only when `web_app` and `backend == "fastapi"`. The web
  app's `lint` `desc:` gains `, the generated API client` after
  `Prettier formatting` in that case.

- **The generated code stays out of the linters.** The spike measured this.
  Unignored, the client fails the web app's ESLint (2 errors:
  `no-empty-interface` and `no-inferrable-types`), and Prettier flags 16 files
  under `src/app/api/`, `openapi.json` included. With the ignores below,
  `node:lint` and `node:lint:format` pass, and strict `tsc` passes on the
  client. So:

    - **`.prettierignore`** (`modules/node/templates/prettierignore.j2`, kiln's
      block): under `# Generated or installed`, add `<web_dir>/src/app/api/`
      when `web_app` and `backend == "fastapi"`. Add the context keys
      `prettier.py:render` needs.
    - **ESLint.** `eslint.config.mjs` is the Nx scaffold's and is repo-owned, so
      the scaffold edits it once. In `modules/node/scaffold.py`, add a private
      `_ignore_generated_client(root: Path)`. `reconcile_node` calls it after
      `_place_app` for `python-web-app` with `backend == "fastapi"`. It replaces
      the single `export default [` in `root / "eslint.config.mjs"` with
      `export default [\n  { ignores: ['**/src/app/api/client'] },`. If that
      anchor is not there exactly once, it raises `AppException` naming the
      file. The glob is relative because Nx runs ESLint from the app's
      directory. The spike found that `apps/web/src/app/api/` matches nothing
      there.
    - **Sonar.** `modules/cicd/artifacts.py`: for a web app with
      `backend == "fastapi"`, `sonar_exclusions` gains
      `<web_dir>/src/app/api/**` after `_WEB_APP_EXCLUSIONS`.
    - `.mdformat.toml` and the Python lint configs need no change: there is no
      Markdown or Python under `src/app/api/`.

- **The scaffold adds the generator and a first client.**

    - `modules/node/angular.py`: add `OPENAPI_TS_VERSION = "0.99.0"` and
      `OPENAPI_TS = f"@hey-api/openapi-ts@{OPENAPI_TS_VERSION}"` (both in
      `__all__`), with docstrings in the file's style.
    - `modules/node/scaffold.py:scaffold_node`: in the `python-web-app` branch,
      after `add_ngkit(workspace)` and only for `backend == "fastapi"`, run
      `run("openapi-ts", "pnpm", "add", "-D", OPENAPI_TS, cwd=workspace, env=scaffold_env())`.
    - New public `generate_client(workspace: Path, config: KilnConfig) -> None` in
      `modules/node/scaffold.py`. For `python-web-app` with
      `backend == "fastapi"` it runs
      `run("web-client", "task", "web:client", cwd=workspace, env=scaffold_env())`.
      Otherwise it does nothing. `commands/upgrade.py:67` already shells out
      to `task`.
    - `commands/new.py` calls `node_scaffold.generate_client(workspace, resolved)`
      right before `node_scaffold.format_node(workspace)` (line 126), inside the
      same `if frontend_workspace is not None:`. Use whichever config variable
      that call site already passes to the node scaffold.

- **`standard.md`** (`modules/instructions/templates/standard.md.j2`). Right
  after the `**Frontend:**` paragraph (lines 62-66), when `web_app` and
  `backend == "fastapi"`, add this paragraph, with `{{ web_dir }}` templated
  and one blank line after it:

    ```markdown
    **API client:** generated, never written by hand. `task web:client` writes
    the API's OpenAPI document to `{{ web_dir }}/src/app/api/openapi.json` and
    regenerates `{{ web_dir }}/src/app/api/client/` from it with
    `@hey-api/openapi-ts`. Both are committed, and `task lint` fails when they
    differ from what the API produces.
    ```

    If the instructions module refills `standard.md`'s paragraphs (`_refill`),
    write the source so the rendered result is mdformat-clean.

## Rules

- Do not commit, push, or edit any spec page except `## Result` below.
- Do not edit a file whose header says kiln generated it. `task kiln:apply`
  writes them.
- Add no Python dependency. The npm generator goes only into the scaffolded
  repository, through `pnpm add` at `kiln new`.
- Use only `task` verbs. Never call `uv`, `pytest`, `ruff`, `pyright`, `pnpm` or
  `kiln` directly. The scaffold code that shells out from a `scaffold`
  function is the product, not this rule's subject.
- Test names describe behaviour, with no spec ID in the name, docstring or
  comments.
- Run every validation step in the foreground, one at a time, and wait for it.
  Leave no background run behind. If `golden:compare` or `golden:validate`
  leaves Nx daemons under `.goldens`, kill them before you finish.
