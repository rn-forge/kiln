## S4.8.2 — A single-package repository declares its import module

**State:** New

Found 2026-10-16, reviewing whether agentkit can be generated by kiln. A
`python-app` or `python-tool` repository's import module is derived from its
repository name (`kiln` → `kiln`, `agentkit` → `agentkit`), in every place that
names it: the `uv init` layout, `module-name`, the script entry, the starter
source, the sample test, `.importlinter`'s `root_package`, `--cov=`, and
`docs/reference/python-api.md`. A repository whose module is a namespace package
(`rn_forge.kiln`, `rn_forge.agentkit`) cannot be described, so S4.8.1 would
render `root_package = kiln` for kiln itself, and `lint-imports` would fail with
`Could not find package`. S6.1.3 solved this for `python-lib` members; this
story is the same solution for the one package of a single-package archetype.
The module is declared in config, never read from `pyproject.toml`
([ADR-0004](../../../adr/ADR-0004.md)).

**Build — tests first.** Copy the shape of S6.1.3's tests (`test_s6_1_3_*` in
`tests/modules/python/test_artifacts.py` and `tests/test_generate_package.py`).

- In `tests/modules/python/test_artifacts.py`:
    - `test_s4_8_2_1_module_defaults_from_the_name`: a `python-tool` config named
      `demo-tool` with no `module` key: `config.module == "demo_tool"`.
    - `test_s4_8_2_1_module_is_read_from_config`: with
      `[archetype."python-tool"] module = "rn_forge.demo"`:
      `config.module == "rn_forge.demo"`; the same for `python-app`.
    - `test_s4_8_2_1_an_invalid_module_is_a_config_error`: `module = "Rn-Forge"`
      raises `AppException`.
    - `test_s4_8_2_1_module_is_single_package_only`: parametrised over
      `python-lib`, `python-web-api`, `python-web-app`: a `module` key in that
      archetype's table raises `AppException`.
    - `test_s4_8_2_2_importlinter_names_the_declared_module`: a `python-tool`
      config with `module = "rn_forge.demo"` renders `.importlinter` with
      `root_package = rn_forge.demo` and
      `name = rn_forge.demo imports no framework or CLI toolkit directly`.
- In `tests/test_new.py`:
    - `test_s4_8_2_3_new_with_a_module` (the slow path, as
      `test_s4_5_1_yes_creates_and_passes_every_check`):
      `commands.new(tmp_path / "demo-tool", archetype="python-tool", docs="mkdocs", module="rn_forge.demo", yes=True)`.
      Assert: `src/rn_forge/demo/__init__.py`, `py.typed`, `main.py`,
      `commands.py` and `product.py` exist; `src/rn_forge/__init__.py` and
      `src/demo_tool/` do not; `pyproject.toml` has
      `module-name = "rn_forge.demo"` and
      `[project.scripts] demo-tool = "rn_forge.demo.main:app"`;
      `tests/test_package.py` contains `import rn_forge.demo\n`;
      `tests/test_cli.py` contains `from rn_forge.demo.main import app`;
      `tasks/quality.yml` contains `--cov=rn_forge.demo `;
      `docs/reference/python-api.md` contains `::: rn_forge.demo`; `config.toml`
      has `[archetype."python-tool"] module = "rn_forge.demo"`,
      `[[cli.commands]] target = "rn_forge.demo.commands:hello"` and
      `[lifecycle] product = "rn_forge.demo.product:PRODUCT"`; and
      `checks.run(directory) == []`.
    - `test_s4_8_2_3_new_without_a_module_is_unchanged`: the `rendered` fixture's
      `python-tool` repository has no `module` key in `config.toml` and has
      `src/python_tool/py.typed`.
    - `test_s4_8_2_3_an_invalid_module_is_refused_before_writing`:
      `module="Rn-Forge"` with `yes=True` raises `AppException`, and neither the
      target directory nor `.staging/` exists afterwards.
    - `test_s4_8_2_3_module_on_another_archetype_is_refused`:
      `archetype="python-lib", module="rn_forge.demo"` raises `AppException`
      before writing.

**Build:**

- `src/rn_forge/kiln/modules/python/config.py`: a new
  `AppConfig(PackagesConfig)` with `module: str | None = None`, and an `after`
  validator that raises
  `ValueError(f"module: {module!r} is not a dotted import module name")` when
  it is set and does not match `MODULE_PATTERN`. `ArchetypeConfig.python_app`
  and `python_tool` become `AppConfig | None`. `python-lib` and the web
  archetypes keep their classes, so the key there is refused by `StrictModel`
  as an extra input, as S6.1.4's `import_contracts` is. Add
  `ArchetypeConfig.module_of(archetype) -> str | None`: the `AppConfig`
  table's `module`, else `None`.
- `src/rn_forge/kiln/config.py`: `KilnConfig.module` property: the declared
  `module_of(self.archetype)`, else `self.name.replace("-", "_")` (not
  `root_package`, for the import-cycle reason S6.1.3 recorded). With no
  `archetype` section, the derivation.
- Route each of these through `config.module`, and change nothing else in them:
    1. `python/scaffold.py` `scaffold_backend`, the single-package `else` branch:
       `_uv_init(raw, name=config.name, bare=False, module=config.module)` and
       `_write_sample_test(raw, config.name, config.module)`. `_uv_init` already
       moves `src/<derived>/` for a dotted module (S6.1.3).
    1. `python/scaffold.py` `_reconcile_pyproject`: for a `python-tool` or
       `python-app` root, `module = config.module` (the `else` branch's
       `name.replace("-", "_")` stays for every other case); the
       `[project.scripts]` entry is `f"{config.module}.main:app"`.
    1. `python/starter.py` `render`: `package = config.module` in the
       `python-tool`/`python-app` branch.
    1. `python/artifacts.py` `render`: the single-package `else` branch is
       `members = [config.module]`.
    1. `tasks/artifacts.py`: `"package": config.module`.
    1. `docs/artifacts.py`: `"module": config.module`.
- `commands.py`: `new` and `init` gain `module: str | None = None` (`--module`),
  passed to `_resolve_config(..., module=module)`. There, when `module` is not
  `None`, `DictUtils.set(flags, f"archetype.{archetype}.module", module)`, and
  `package = module or root_package(name)` feeds the `[cli]` and `[lifecycle]`
  targets it already writes. Validation is the schema's: an invalid value or a
  wrong archetype fails at `manager.resolve`, before anything is written. Do
  not add `module` to `_FLAG_NAMES`: like `repository.name`, it is not a
  module `Option`.
- `docs/reference/standard-repo.md` §9: an `[archetype."python-tool"]` example
  with one line,
  `module = "rn_forge.agentkit"  # optional: dotted import module; default is the repository name with '-' as '_'`.
- `new`'s and `init`'s docstrings: one sentence for `--module`, as
  `generate_package`'s has.

**Do not** change the web archetypes' derivation
(`root_package(f"{config.name}-api")`), `python-lib`'s `modules`, any template,
or kiln's own config (S4.8.1 sets it).

**Acceptance:**

- The tests pass, and `task validate` passes.
- `task self:golden:render`: no cell changes (no cell declares `module`).
- `kiln new ../agentkit --archetype python-tool --module rn_forge.agentkit --yes`
  renders a repository where `uv sync` and `task validate` pass,
  `lint-imports` included. Record the command and its exits here.
