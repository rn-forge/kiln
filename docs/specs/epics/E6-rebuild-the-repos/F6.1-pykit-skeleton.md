**Reshaped 2026-09-26** under [ADR-0009](../../../adr/ADR-0009.md). This feature
used to build a candidate from pykit's tree and then replace pykit's skeleton,
with acceptance run inside pykit. kiln's part is now to prove that the
`python-lib` archetype renders a repository that can host pykit, using a
pykit-shaped repository built in a scratch directory. The cutover inside pykit
is pykit's own feature. S6.1.2, the cutover, is withdrawn; its ID is not reused.

## S6.1.1 — A pykit-shaped repository passes its own gate

**State:** Active

Build a scratch `python-lib` repository with the shape that makes pykit hard to
host:

- Seven packages named as pykit's are: `rn-forge-commons`, `rn-forge-cli`,
  `rn-forge-tooling`, `rn-forge-web`, `rn-forge-django`, `rn-forge-fastapi`
  and `rn-forge-sqlalchemy`. Each is added with `kiln generate package`.
- The workspace dependencies run cli → commons, tooling → cli, and web, django,
  fastapi and sqlalchemy → commons, all as `{ workspace = true }`.
- Three of the member names are also dependencies of `rn-forge-kiln`. The root
  sets `[tool.uv] override-dependencies` so that kiln resolves to the
  workspace copies ([ADR-0006](../../../adr/ADR-0006.md)).
- A root guide links a page in each package's site.

**Elaborated 2026-10-14.** This story builds the script and runs it. It does not
fix kiln. A failure the run finds is triaged by the owner: one that also
reproduces in an empty `python-lib` repository becomes its own kiln story
(S6.1.2 onward), with a regression test, and this story is rerun after it. One
known risk: pykit's members declare `[tool.uv.sources] … = { workspace = true }`
for rn-forge packages, and `kiln doctor`'s `rn-forge-deps` check rejects an
`[tool.uv.sources]` entry for an rn-forge package
([standard §3](../../../reference/standard-repo.md)). Expect that to be the
first finding.

**Revised 2026-10-14.** The first run is recorded below. The members now carry
pykit's own code and dependency declarations, so the run is a rehearsal of
pykit's cutover rather than a synthetic shape. The `rn-forge-deps` finding is
ruled a kiln defect regardless of the triage rule: it cannot reproduce with a
`demo-pkg`, because `demo-pkg` is not an rn-forge name
([ADR-0014](../../../adr/ADR-0014.md), S6.1.2).

**Build:**

- `tests/e2e/pykit_shape.sh`, mode `0755`, is the script. It was first written
  verbatim from this story, then **revised on 2026-10-14** after the first
  run, for four defects that run found in the script itself (recorded below):

    1. `kiln new` runs from the scratch directory's parent, because it stages
       under the directory it is invoked from (S4.5.9). Run from the kiln
       checkout, it left `.staging/pykit-shape/` behind, and a second run failed
       with `staging is never reused`.
    1. The `override-dependencies` line is written before the first member.
       Written after the `uv add` calls, uv saw two URLs for `rn-forge-cli` and
       stopped.
    1. Each member's `pyproject.toml`, `README.md`, `CHANGELOG.md`, `src/` and
       `tests/` come from a shallow clone of pykit (third argument, default
       `main`), over what `kiln generate package` wrote. The overrides make kiln
       import the workspace commons, cli and tooling, so empty generated stubs

       `pyproject.toml`.
    1. kiln is this checkout, added with `uv add --dev --editable`. The template
       pins the pushed `feature/v1`, which lagged the checkout, so the run
       tested an older kiln.

    Change nothing else in it except to fix a defect in the script itself, and
    record every such fix.

- Add `tests/e2e/` to nothing else: no pytest wiring, no Taskfile verb, no CI
  job. The script is run by hand and by the feature's acceptance block.

- Run it: `s=$(mktemp -d); tests/e2e/pykit_shape.sh "$s/pykit-shape" "$PWD"`,
  then, inside `$s/pykit-shape`: `uv sync`, `task validate`,
  `uv run kiln doctor --full`, and the feature's acceptance block. Note:

## S6.1.2 — `rn-forge-deps` exempts the repository's own workspace members

**State:** Closed (2026-10-14)

[ADR-0014](../../../adr/ADR-0014.md). The contract governs rn-forge packages
from outside the repository. A library workspace wires its own members the way
pykit does: a pinned direct URL in `[project]` dependencies, which is what a
consumer of the wheel resolves, plus a `{ workspace = true }` source for local
development, and bare names in dependency groups, which never reach a wheel.

A **workspace member** is the `[project] name` of each `pyproject.toml` under
`config.packages`, normalized as `distribution()` normalizes. Membership is by
that name, never by the `rn-forge-` prefix.

**Build — tests first,** in `tests/modules/python/checks/test_rn_forge_deps.py`,
using `_lib_root` and `run` from that file. The fixture is a `python-lib` root
with three members: `packages/commons` named `rn-forge-commons` with no
dependencies; `packages/cli` named `rn-forge-cli`, depending on
`pinned("rn-forge-commons")`; and `packages/tooling` named `rn-forge-tooling`,
depending on `pinned("rn-forge-commons")` and `pinned("rn-forge-cli")`. Each
member that depends on a sibling has
`[tool.uv.sources] <sibling> = { workspace = true }` for each sibling, and
`packages/tooling` has `[dependency-groups] dev = ["rn-forge-tooling[x]"]`. The
root has
`[dependency-groups] workspace = ["rn-forge-commons", "rn-forge-cli", "rn-forge-tooling"]`
and a `{ workspace = true }` source for each.

- `test_s6_1_2_1_a_pykit_shaped_workspace_passes`: `run(root) == []`.
  (`rn-forge-cli` is outside `python-lib`'s allowed set; it passes because it
  is a member.)
- `test_s6_1_2_2_a_sibling_in_runtime_dependencies_still_needs_a_pinned_url`:
  with `packages/tooling`'s `rn-forge-cli` dependency changed to the bare name
  `"rn-forge-cli"`, a finding names `rn-forge-cli` and contains
  `without a direct URL`.
- `test_s6_1_2_3_a_non_workspace_source_for_a_member_is_still_refused`: with
  `packages/cli`'s source changed to `{ path = "../commons" }`, a finding
  contains `overrides an rn-forge dependency`.
- `test_s6_1_2_4_membership_is_by_name_not_prefix`: drop `packages/cli` from
  `config.packages` (and its directory). `packages/tooling` still depends on
  `pinned("rn-forge-cli")` with no source for it: a finding contains
  `not in this archetype's allowed set`.
- `test_s6_1_2_5_an_extra_on_a_member_in_a_group_may_be_bare`: covered by test
  1's `rn-forge-tooling[x]`; assert separately that removing the dev group
  leaves `run(root) == []` too.

**Build** in `src/rn_forge/kiln/modules/python/checks/rn_forge_deps.py`:

- Add `workspace_members(config: KilnConfig, root: Path) -> frozenset[str]`: for
  each `p` in `config.packages`, read `root / p / "pyproject.toml"` if it
  exists, and collect `distribution(name)` of its `[project] name` when that
  is a string.
- Split `every_dependency` into `published_dependencies(document)` (runtime plus
  every optional-dependency list: what a wheel carries) and
  `group_dependencies(document)` (every dependency group). Keep
  `every_dependency` as their concatenation for `_check_allowed`.
- `_check_allowed` takes `members` and permits `allowed ∪ members`.
- `_check_direct_url` takes `members`. It checks every published requirement as
  today. It checks a group requirement as today unless its distribution is in
  `members`.
- `_check_no_shadowing_source` takes `members`. It skips a source whose name is
  in `members` and whose value is a table with `workspace = true`. Every other
  rn-forge source is still refused.
- `check` computes `members` once and passes it. The `required` rule is
  unchanged.
- Update the module docstring's rule 2 and rule 3 to say a workspace member is
  exempt, with ADR-0014's reason in one line each.

**Build** in docs:

- `docs/reference/standard-repo.md` §3: after the paragraph that begins "Never
  `[tool.uv.sources]`", add: *The repository's own workspace members are the
  exception (ADR-0014, linked as `../adr/ADR-0014.md`). A member's dependency
  on a sibling keeps its pinned direct URL in `dependencies`, may add a
  `{ workspace = true }` source for local development, and is outside the
  allowed set. A dependency group may name a sibling bare.*

- `src/rn_forge/kiln/modules/instructions/templates/standard.md.j2`: after
  "overrides, which do not survive into a built wheel." insert, on the same
  line:

    ```jinja
    {% if workspace %} A sibling workspace member is the exception: it keeps that URL, may add a `{ workspace = true }` source, and may be named bare in a dependency group.{% endif %}
    ```

    and reflow nothing else. kiln's own `.rn-forge/kiln/standard.md` does not
    change (kiln is not a workspace).

**Do not** change the `required` rule, `archetype.toml`, or any other check.

**Acceptance:**

- The five tests pass, and every existing test in the file still passes.
- Rerun S6.1.1's script: `kiln doctor .` in the shape reports no `deps.*`
  finding.
- `task self:golden:render` shows the `python-lib` standard gains the sentence,
  and no other cell changes.

**What the build settled that the story did not say.**

- The fixture builder is `_workspace_root` with keyword switches for the four
  variants (`tooling_cli`, `cli_source`, `members`, `tooling_group`), plus
  `_member_toml`, so each test states only its difference from test 1. The
  members' `[project]` carry `version = "0.1.0"`.
- Tests 2 and 3 pass before the change as well (the sibling is already rejected
  as bare, and a `path` source already shadows); they pin the exemption's
  limits rather than prove a new behavior. Tests 1 and 5 failed first, as
  expected.
- `workspace_members` skips a package whose `pyproject.toml` is missing, and one
  whose `[project] name` is not a string, silently; the missing file is
  already `deps.pyproject-missing`.
- `_check_direct_url` filters out group requirements naming a member before
  iterating, so a published requirement and a non-member group requirement are
  checked as before.
- The workspace-source test is by `distribution(name)` of the source key and
  `source.get("workspace") is True`, so `workspace = false` or a source table
  without it is still refused. A `cast` narrows the TOML table for pyright
  strict.
- Template sentence sits on the same line as specified; the golden diff against
  the previous `.goldens/` contents was unusable (stale, unrelated working
  files), so the observation below is per-cell.
