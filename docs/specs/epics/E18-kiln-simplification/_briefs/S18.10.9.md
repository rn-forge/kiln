# S18.10.9 — Publish recovery uploads only what is missing

Brief for
[S18.10.9](../F18.10-review-defects.md#s18109-publish-recovery-uploads-only-what-is-missing),
at `feature/v1` after `523016f`.

## Goal

`kiln-devops release-publish --upload pypi|testpypi` asks the index which files
of the version it already holds and uploads only the others, so a lost sdist is
retried and an uploaded wheel is not sent twice.

## Settled

- In `src/rn_forge/kiln/devops/github.py`,
  `on_index(host, name, version) -> bool` becomes
  `indexed_files(host, name, version) -> frozenset[str]`. It reads the same URL,
  `https://{host}/pypi/{name}/{version}/json`, returns the `filename` of every
  entry in the JSON `urls` list, and returns `frozenset()` on a 404. Any other
  HTTP error still raises.
- `upload_commands(index, name, version, files, indexed: frozenset[str])` drops
  a file when its basename is in `indexed`, and drops a `.publish.attestation`
  file when the basename of its distribution (the name without
  `.publish.attestation`) is in `indexed`. It returns `[]` when no `.whl` or
  `.tar.gz` is left; otherwise one `uv publish` command over the remaining
  files, in order, as today.
- `_upload` in `devops/cli.py` calls `indexed_files` and passes the result.
- Rejected (do not build): deleting and re-uploading a version, and comparing
  hashes.

## Current behaviour

- `on_index` returns `True` for any 200, so `upload_commands` returns `[]` and
  nothing uploads, whichever file is missing.
- Test 1 below fails: with the index JSON listing only the wheel,
  `cli.main([*PUBLISH, "--upload", "pypi", "a.whl", "a.tar.gz"])` runs no `uv`
  command, and `commands[0]` is the `gh release create` command.

## Change

- **Change:** `on_index` and `upload_commands` in `devops/github.py`, and
  `_upload` in `devops/cli.py`.
- **Update:** the tests that name `on_index` (see **Tests first**).
- **Leave alone:** `publish_commands`, `release_status` and every other file.

## Tests first

In `tests/devops/test_cli.py`, which has `_upload_stubs` and `PUBLISH`:

1. `test_upload_pypi_uploads_only_the_files_the_index_lacks`: call
   `_upload_stubs(monkeypatch, ReleaseStatus.NONE, False, frozenset())`, then
   replace the index with
   `monkeypatch.setattr(github.urllib.request, "urlopen", ...)` returning a
   context manager whose `read()` is
   `json.dumps({"urls": [{"filename": "a.whl"}]}).encode()` and whose `status`
   is 200. Run
   `cli.main([*PUBLISH, "--upload", "pypi", "a.whl", "a.whl.publish.attestation", "a.tar.gz"])`.
   Assert the one `uv` call ends with `[_real("a.tar.gz")]` and holds
   neither the wheel nor its attestation.
1. `test_upload_pypi_skips_a_version_whose_files_are_all_on_the_index`: same
   stub with both `a.whl` and `a.tar.gz` listed, so no `uv` call is made.

Update the existing tests to the new signature:

- `_upload_stubs`: its `on_index: bool` argument becomes
  `indexed: frozenset[str]`, stubbing `github.indexed_files` and recording
  `["indexed_files", host, name, version]`. Callers pass `frozenset()` for
  `False` and `frozenset({"a.whl"})` for `True`. Fix the one assertion on
  `["on_index", "pypi.org", "pkg-a", "1.2.0"]`.
- `tests/devops/test_github.py`: the `upload_commands` tests pass `frozenset()`
  for `False`; `test_nothing_is_uploaded_when_the_index_has_the_version`
  passes the basenames of `PYPI_FILES`'s wheel and sdist; the two `on_index`
  tests become `test_indexed_files_reads_the_json_endpoint` (the fake
  `_Response` gains `read()`) and
  `test_indexed_files_is_empty_on_404_and_raises_otherwise`. Add
  `test_upload_commands_drop_the_indexed_files_and_their_attestations` calling
  `upload_commands` with `{"x.whl"}` indexed, and assert the command ends
  `["x.tar.gz", "x.tar.gz.publish.attestation"]`.

Test 1 fails before the change as **Current behaviour** says.
